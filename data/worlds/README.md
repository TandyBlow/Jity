**龙族展示世界：自由一日·钟楼争夺战**

主文件：[dragon-raja-free-day.world.json](dragon-raja-free-day.world.json)。它是静态的完整 `WorldState`，不是剧本 JSON、提示词或逐步写好的故事。载入后，行动、反应、结果和正文仍需由实际游戏运行路径产生。

格式直接使用 `backend/app/schemas/world/contracts.py` 中的 `WorldState`，其 `initial` 是现有的 `WorldInitialState`；协议 v2 仍复用这个状态模型，状态的 `schemaVersion` 保持 1，不与 HTTP 响应的版本混同。开局快照为 S₀，无预置增量、隐藏的行动脚本或叙事答案。

规模为 26 个地点、14 个人物、74 件物品、73 个任务，其中 4 个任务在开局前已经完成。这是公开开发与展示材料，不能当作未见的独立终验世界。

**进入时的局势**

15:20，距离本局15:45停赛还有25分钟。路明非与诺诺在西侧服务巷；路明非尚未选择阵营，也没有可立即射击的枪。凯撒在红方集结点筹划接近钟楼，楚子航在二层平台组织蓝方防守。白旗还卡在外廊底座里，双方自己的旗都没有插上旗台，所以没有一方已经完成最终占领。

西回廊的林亦舟实际扭伤脚踝，不能自行站稳；他的求助只发出了位置，没有讲清伤情。诺诺的短讯机没电，适用电池在红方集结点。器材笼中有担架、绳和梯，钥匙在中立值班员秦越身上。芬格尔知道地下路线，却也知道钟楼地下门闩在门内。

路明非可以参战、协作、运送补给、救助伤员、尝试地下路线或向观察席请求安全处理。文件没有规定唯一解、必胜路线、固定盟友或接下来必定发生的行动。

**状态为什么存在**

| 状态组 | 可支持的观察与决定 |
|---|---|
| 庭院、喷泉与东西回廊 | 不同射界、掩体、绕行与撤退；进入哪个小地点会改变可见的人物与物品 |
| 钟楼分层与旗台 | 共同结算、窄路错身、守备配合、锁扣操作、持旗和安装旗的区别 |
| 检修口、地道、门闩 | 可以选择绕路，但路短不等于能直接开门；需要联络内部人物或改变方案 |
| 林亦舟、担架、医护白线 | 真实受伤与演习淘汰的区别、救援协作、暂时停火与撤离后的资格变化 |
| 故障短讯机与两种电池 | 设备能否恢复、跨人物补给、相机电池不能替代短讯机电池 |
| 枪械、弹匣、护目镜 | 空枪与可射击状态、换弹与防护、装备领用和归属变化 |
| 旗、底座、释放杆、安全绳 | 有旗不等于占领、操作需要顺序与合作、失败可以是卡住或需要撤退 |
| 双方指挥、观察席与已退出人员 | 竞争、协作、可信报告、局部停火、中立与退出规则 |
| 每人的任务树和初始个性 | 同一事件对不同人物的意义、是否求援或让步、任务达成后的个性/理智检查 |

人物外貌包含装备、弹痕、伤势和可见姿态，用于识别当前处境与后续变化；地点说明提供通路、遮挡和限制；物品描述给出可操作条件与差异。人物个性还登记关系、已知情况与顾虑。它们不是要求叙事逐条念出的清单。

本展示场景的可见性单位是人物位置沿容器链解析到的最内层 `location`，`slot` 只表示地点内部的位置与掩体，不另切可见范围；同一上级地点下的不同子地点仍分别处理。路明非与诺诺都在西侧服务巷，虽分处不同槽位，仍属于同一可见场景。容器或物品说明中的遮挡不能凭空扩展可见集；需要进一步遮蔽规则时，应另行版本化并用数据验证。

完整世界需经过与训练数据一致的投影和序列化才能输入叙事模型，不能直接铺开全部实体。现有语料实际只纳入变化物品，并不纳入同地点全部物品；旧 YuYan 转换还存在结果块漏写。旧权重的兼容路径、新版修复和开局无变化场景的处理要求见 [叙事输入适配规格](../../design/world-engine-reports/components/narration-input-adapter.md)，不能仅凭本页自行重写取数规则。

当前格式没有单独的生命值、弹药数、阵营或门锁布尔字段；这些事实沿用现有的自然语言外貌/个性和任务表示，位置仍只认 `position`。运行中弹药、设备、伤势、旗台或通路发生变化时，应提交相应外貌变化与位置变化，不能只改正文。读取当前值时必须结合生效变化，不能把 `initialAppearance` 当作永远不变的现状；容器中的现有物件应从位置图枚举，不能只凭背景句推断。

**如何读取和校验**

```powershell
python -X utf8 scripts/build_free_day_world.py
```

默认只检查文件：现有 Pydantic 状态契约、实体/容器/槽位与相对位置引用、任务父子与归属、名称唯一性、本展示文件的槽位与实体 ID 不重名，以及“文件快照等于从其 initial 重建的 S₀”。本文件的槽位统一采用 `slot_` 前缀；槽位本来按容器定位，运行时索引仍应使用 `(containerId, slotId)`。此处避开重名是素材的防误用措施，不修改通用世界契约。命令会输出实体数量、文件 SHA-256 和按现有规范计算的状态摘要。

浏览器后续应直接加载 JSON，不执行 Python 构建脚本。运行时应沿用同一状态语义；这个检查结果只证明静态资产通过现有契约，不证明浏览器加载器、非叙事能力、叙事质量或完整流程已经交付。

需要编辑本展示素材时，修改 `scripts/build_free_day_world.py` 中人工编写的固定内容，审阅后显式运行：

```powershell
python -X utf8 scripts/build_free_day_world.py --write
```

这是开发期静态素材的可复现构建，不调用模型、网络或随机数，也不在游戏开局动态创造世界。不要无意覆盖已经被别人修改过的素材；先比对并保留新版本。

读取文件时顶层是现有 `WorldState`：`time`、`locations`、`items`、`characters` 是当前状态；名称、初始描述和初始任务在 `initial` 中。不能把只有 `WorldInitialState` 字段的文件直接当作这个快照，也不能从当前表缺少 `name` 推断人物匿名。源契约与 `design/world-protocol/v1/world-protocol.schema.json` 中的 `WorldState` 定义就是格式依据，不额外引入包装层。

准备独立输入包时，复制其对应静态世界并登记文件哈希、玩家输入、会话边界和骰点种子。该世界与本说明已经公开，针对它调试的输入只能算公开开发题；独立评审应按 goal 中的隔离规则另选未参与优化的题。

后续内容审阅重点是：引用一致、初始事实无冲突、每个细节支持可观察差异或行动选择；增加实体前应说明它会改变什么，不靠批量套外貌、重复目标或空地点凑规模。

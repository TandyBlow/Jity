# Design: G8 交付验收

## 运行形态

- 生产构建（Next 15.5.19）：`npm run build` → `next start -p 3177`。构建通过记录在任务与 ledger；dev server 不作为验收栈。
- 验收驱动仍是 `accept-world-local.mjs`：只操作可见控件，逐回合记录输入、前后状态、Δ、原始叙事、计时、模型身份与网络请求。

## 输入矩阵

- `turns-20.json`：16 个语义例（s01–s16）+ 4 个场景例（g8-t1..t4），无重复输入。
- 5 个四回合 session；验收允许「3 组连续回合按需」，不要求 20 输入在同一世界。
- 每块 `--fresh` 开始新世界；证据逐块保存，失败/超时保留。

## 判定

- 60 秒首段：`firstReadableAt - inputAt ≤ 60,000 ms`；300 秒单点：`pointTextFinishedAt - pointCommittedAt ≤ 300,000 ms`。
- 计时以驱动记录的逐点时钟为准；超过 5 分钟记失败，不删样本。
- D-019：用户签字与 10 次独立输入取消；报告中写明。
- R01–R16 每项有代码路径、运行记录与页面证据；未达标项明确列出。

## 风险

- 宿主内存：生产栈仍需模型权重（0.6B + 1.7B ≈ 1.5 GB）+ 浏览器；内存不足会被回收。4 回合块与逐回合落盘把损失限制在一块。
- 模型延迟：judge 默认下普通回合常到 295 秒；60 秒首段在宿主负载下曾 63–154 秒。D-018 点级六阶段与 240 秒预算已降低结算成本；0.6B 叙事臂（`?narrationModel=semantic`）待实测。

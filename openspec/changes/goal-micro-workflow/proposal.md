# Proposal: goal-micro-workflow

## Why

D-032：Jity 的 AI 工作流由多个微型专用模型协同完成是产品技术目标，不是可选优化。现有语义任务全部走 0.6B LLM；需要用真实游戏回合验证「规则 / 微型模型 / LLM 回退」的分工能否在不降质量的前提下减少等待。

## What Changes

- 在 `game-model` 与动作语义层加微型端口：任务先走规则/微型模型，失败或无置信时回退 LLM，并记录原因。
- 第一版优先 targets、results、updates、continuation；action/reaction 先保留 LLM，随后拆分（开放式文本仍可用 LLM）。
- 微型任务之间传结构化值（目标 id、结算事实、状态增量），后续任务读前序任务的真实输出。
- 统计分三类：规则执行、微型模型推理、LLM 回退；各自次数与耗时；首载耗时与回合耗时分开。
- 用真实 20 输入回合驱动验收；现有 LLM 路径原样保留作对照。

## Impact

- 产品默认路径不变（微型端口未接页面时行为等价）；实验开关默认关闭。
- 风险：微型模型在浏览器需要 JS 分词器与 ORT 资产；覆盖率不足时回退会抬高 LLM 调用数。

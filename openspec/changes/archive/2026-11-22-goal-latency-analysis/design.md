# Design: goal-latency-analysis

## Context

D-024 的候选改造是「玩家自己的点结算并叙事完成就交还，其余角色后台结算」。现有语义证据（run27–run35）逐点记录了 `pointNarration`：每个点有 `startedAtMs` 与 `completedAtMs`。玩家在计划顺序里永远排第一（`session.ts` 的 order 数组），因此第一点的叙事完成时间就是早交还的测量上界（不含交还自身的 UI 开销，也不含后台尾部）。

## Goals / Non-Goals

- Goals：用已有证据量化早交还上界；区分笔记本档与移动模拟档。
- Non-Goals：不实现调度原型；不验证后台结算的一致性；不测量交还后的下一次提交。

## Decisions

1. **以第一点叙事完成时间作为上界**：玩家点第一，且当前回合在整轮结束才交还，所以「第一点完成」是早交还能达到的最早时刻。替代方案（先写原型再量）成本更高，且 D-024 尚未授权原型。
2. **分档报告**：笔记本臂 run27–run34 与移动模拟 run35 分开列；移动模拟的 4× CPU 与核显条件不同，不能混在一个区间里。
3. **不改 D-024 状态**：测量只补充事实，是否改造仍由用户决定。

## Risks / Trade-offs

- [第一点完成后仍有后台尾部] → 分析里写明：下一次提交仍要等尾部结算完成；玩家的阅读时间只能部分重叠。
- [run35 s05 的第一点完成在 150 秒] → 明确标出移动档单靠早交还过不了 60 秒。

## Migration Plan

不适用（无代码改动）。

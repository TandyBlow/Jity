# Design: goal-refused-gate

## Context

见 proposal。检查器已有 `knownNames`（从叙事提示的 `（id=`、`名字：`、`让X做的事`、`屋里有X的` 提取），可直接复用来判断「输入引入的名字是否世界已知」。玩家输入里的引入位置用「给/向/让/跟」标记；`和/与/对` 会捕获普通名词（实测「和胸袋」误报），已排除。

## Goals / Non-Goals

- Goals：命中「被拒/未知实体仍写成已发生」的正文；s05 这类普通回合不误报。
- Non-Goals：不判断动作是否真的被拒（那是结算门的事）；不覆盖所有未知实体的表述方式。

## Decisions

1. **以输入中的引入标记 + 提示已知名单判断**：简单、可解释；替代方案（NER 或人名库）超出开发期工具的成本。
2. **否定/拒绝措辞豁免**：同一句里出现 `没有/未能/未被/被拒/拒绝/无法` 不算声称。
3. **只报不改**：dev gate 输出 JSON，不进运行期（D-021）。

## Risks / Trade-offs

- [漏报] 玩家用「把…交给」或代词引入时可能捕获不到 → 报告里写明局限。
- [误报] 名字与世界已知名重合时会被过滤 → 宁可漏报不误报。

# Design: goal-repair-sample

## Context

见 proposal。叙事提示末尾有 `正文：`，把「上一稿 + 修订要求」插在它前面即可复用原提示（事实、场景、规则都在）。生成用产品同款 wllama、同模型、temperature 0.45。

## Goals / Non-Goals

- Goals：判断自修复能否修掉「被阻止的动作」，以及它救不了结算错误。
- Non-Goals：不接进产品；不测多轮修复；不评估时间预算。

## Decisions

1. **只测两个对照用例**：run40-e（叙事层错，修复有可能）与 run37（结算层错，修复不可能）。两个用例就能划出路线边界。
2. **每例 3 次**：观察稳定性，不追求统计显著。
3. **单次修复**：只做一遍，不迭代——产品候选也是「第二遍」，不是循环。

## Risks / Trade-offs

- [提示过长] → 修复提示含原提示全文，prefill 略增；不影响结论。
- [模型可能整段重写] → 修订要求写明「其余尽量保持」，输出仍按原样记录。

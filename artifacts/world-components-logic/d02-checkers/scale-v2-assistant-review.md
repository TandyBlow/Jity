## 3. 本轮发现并修正

| 问题 | 修正 |
|---|---|
| `unknown_entity` 与 `ambiguous_entity` 标签都由同一个 `unresolved_role_object` 推导，未知实体被误标为歧义 | 按提及 `status` 推导标签；未知/歧义分开 |
| 生成的多步骤样本只有“先观察四周”一个步骤，原核心动作缺失主语绑定 | 增加带主体的第一步骤，并把核心动作中的执行人出现次数后移一位 |
| 生成引用样本统一是“我已经完成了”，没有实体，无法测试引用内容中的实体绑定 | 优先引用核心对象，例如“我已经处理好了木箱”；没有物品对象时才回退到通用句 |
| 条件样本把条件中的同一实体只标一次，动作中的第二次出现未绑定 | 绑定动作中的第二次出现，条件提及保留在问题跨度中 |
| `harbor-lamp-oil:special`、`archive-cart:special` 的未知实体被标签系统误记为歧义 | 与第一条同一修复；重建后标签一致 |

此外补了 80 条实体解析压力样本：40 条未登记对象、40 条“它”指代两个候选；使未知/歧义从个位数提升到 47/42。

## 4. 仍需人审确认的语义点

1. **来源 vs 接收人**：`从乙那里取物` 中的乙必须是 source；程序只检查“接收人是人物”，不能阻止把乙写成 recipient。
2. **静态场所 vs 目的地**：`在仓库等待` 中的仓库是 static_location；程序只检查“目的地是地点”，不能阻止把仓库写成 destination。
3. **工具 vs 对象**：`用钥匙拨动铁片` 中钥匙是 tool；`把钥匙交给乙` 中钥匙是 object。程序不按类型反推角色，必须由标注判断。
4. **请求别人行动 vs 共同主体**：`请乙帮忙` 中乙是请求接收人；`甲和乙一起抬` 中两人都是 subject。需要人审确认边界。
5. **完成体动词**：本批继续把“拿起／放进／递给”当计划步骤，把“已经／好了／到位／接过／封好”当结果；这条规则尚未人审定稿。
6. **生成变体是否自然**：multi／condition／quote／result2／unknown-object／ambiguous-object 是模板生成，覆盖结构但语言重复；人审应判断是否足够代表真实输出。

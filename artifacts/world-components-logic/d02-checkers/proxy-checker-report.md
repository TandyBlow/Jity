# D02 API 代理检查实验 B0

2026-11-10。分支 `codex/d02-role-expression-20261110`。这是一次**一次调用、无修复、非思考模式**的 API 代理实验，不是计划中的 B 臂，不是训练后 M1／M2，也不是生产 API 版本。

## 1. 设置

- 模型：`deepseek-flash`，`thinking` 关闭，JSON 模式，temperature 0。
- 数据：`pilot-v1`，120 条助手草稿标注；20 个场景组，60/10/10/20 样本切分；其中 100 条针对性样本、20 条 API 自然首输出。
- 任务：同一 API 在给定完整原文、步骤边界、实体登记和当前执行人后，一次输出 M1 `roleAudit` 与 M2 `expressionAudit`；程序按冻结契约校验。
- 无修复：一次返回不合法即记 `incomplete`；没有第二次 API 复核或行动重写。
- 阈值未用于调参；本批全部助手草稿，不是金标准。

## 2. 针对性样本（100 条）

| 指标 | 数值 |
|---|---|
| HTTP 成功 | 99 / 100 |
| JSON 可解析 | 98 / 100 |
| 决策与助手草稿一致 | 15 / 100 |
| `accept` / `upgrade` / `incomplete` | 7 / 14 / 77 |
| 应接受且接受 | 4 / 39 |
| 应升级且升级 | 11 / 61 |
| **错误放行** | **3** |
| 错误升级（本应接受） | 3 |
| 结构/契约未完成 | 77 |

三条错误放行都来自**语义角色被写成另一个合法公开角色**，程序核对 ID、跨度和类型后无法发现：

| 样本 | 原文 | 错误 | 正确 |
|---|---|---|---|
| `harbor-key:role` | 林澈从周岚那里取回铜钥匙。 | 周岚 → `recipient` | 周岚 → `source`（诊断） |
| `archive-cabinet:role` | 余荞在阅览室等待。 | 阅览室 → `destination` | 阅览室 → `static_location`（诊断） |
| `signal-radio:role` | 周苇从谢迟那里取回电池。 | 谢迟 → `recipient` | 谢迟 → `source`（诊断） |

这三条正是方案中“来源不是接收人、静态场所不是目的地”的困难样本。程序只看到“接收人是人物、目的地是地点、ID 和跨度都对”，不能凭类别反推语义角色；因此**程序检查不能替代 M1 的角色语义正确性**。首版验收要求 M1 自动采纳绑定精确正确率 ≥99%，该要求是必要的，不是形式指标。

主要失败原因：

| 程序码 | 次数 | 说明 |
|---|---:|---|
| `surface_mismatch` | 51 | 大量跨度起点整体偏 1，属检查器输出精度问题 |
| `inconsistent_result_label` | 19 | 标签与问题码不一致，或使用了未约定的结果码 |
| `unsettled_result_assertion` | 14 | API 自造的结果问题码，语义上相关但不在首版词表 |
| `mention_without_role` | 13 | 把背景提及写成无角色、无诊断角色的条目 |
| `invalid_diagnostic_roles` | 11 | 使用 `location` 等未约定诊断角色名 |
| `actor_mismatch` | 4 | 主体确实不是当前执行人，属正确发现 |
| 其他 | — | 别名、指代、类型、重复 ID 等 |

## 2.1 当前文本的三条语义点检

复核修正后的数据又对三条关键样本做了一次同提示点检（3 次调用）：

| 样本 | 当前文本 | 本次结果 |
|---|---|---|
| `archive-cabinet:role` | 余荞在阅览室等待。 | **错误放行**：阅览室仍被写成 `destination` |
| `harbor-key:role` | 林澈从周岚那里取铜钥匙。 | `incomplete`：跨度偏移 |
| `signal-radio:role` | 周苇从谢迟那里取电池。 | `incomplete`：跨度偏移 |

因此“静态场所冒充目的地”的错误在修正后的文本上仍可复现；另外两条本次被结构错误挡住，不能据此说角色语义已修复。

## 5. 解释与限制

1. **单次 API 检查不可直接作为 B 臂**：结构错误和角色语义错误都很高；计划中的 B 还应包含同一规则下的有限修复和重新检查。本次没有运行该修复，因此不能把 15/100 当作 B 的最终成绩。
2. **程序检查是必要的，但不是充分的**：它能抓主体、跨度、ID、类型和表达结构，不能抓“来源冒充接收人”“静态场所冒充目的地”这类语义角色错误。后者必须由 M1 自身学会，或由 API 复核。
3. **提示与词表适配本身是变量**：51 次偏移错误、19 次结果码不一致说明“API 会不会按契约输出”与“API 会不会判断”是两件事。正式 B 比较前必须冻结提示、词表和一次修复规则；否则测到的是提示工程差异。
4. **自然集太小**：20 条只能作为下一轮种子，不能估计线上升级率；针对性集故意偏难，也不能估计自然错误率。
5. **数据版本**：B0 r1 在助手复核前运行；复核随后修正了别名冲突、来源文本的“取回”、未知实体样本的“修好”等，当前 `samples.jsonl` 是修订后的 r2。没有完成 r2 全量重跑；3 条当前文本点检只覆盖关键语义样本。故本报告只把 r1 作为代理基线，不作为当前数据口径或最终成绩。
6. **封存污染**：20 条 `sealed` 试点样本已被本次 API 代理检查打开，不能再作为最终封存测试；最终验收必须新建封存集。

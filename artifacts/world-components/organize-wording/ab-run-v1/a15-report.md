# 同更新次数补充对照：A epoch 15（90 次更新）对 B_h epoch 15（2026-11-06）

状态：只补生成 A epoch 15 的 12 个固定留出输出，不重跑 B_h，不重新选点。原来的独立选点成绩（A epoch 3）保留；本文件叫**同更新次数的补充对照**，这批材料仍是固定回归，不是新的盲确认。

## 1. 结束状态（先查记录）

原始运行没有保存 token id 或停止原因；重新分词后的长度和句末标点**不能确认是否生成了 EOS**。因此原输出一律记为“停止原因未记录”，`train-r4` 记为“疑似触顶”（正好 128 token，结尾停在“泥”）。不给出 EOS 数量，也不把遗漏分成“正常结束”和“截断”。

| 输出集 | 条数 | 停止原因 | 说明 |
| --- | --- | --- | --- |
| A（选中 epoch 3）固定留出 | 12 | 未记录 | `train-r4` 疑似触顶 |
| B_h（选中 epoch 15）固定留出 | 12 | 未记录 | — |
| 计划响应（B_h） | 8 | 未记录 | P1/P2 各 4 |
| A15 固定留出（本次补评） | 12 | EOS 12、触顶 0 | 准确 stop 记录 |

所以只能写：A 的 `train-r4` 疑似触顶，f3/f4 可能没生成到；它的遗漏不能和其他“正常结束后的遗漏”分开统计。

## 2. A15 是怎么来的

原始运行只把选中的 A epoch 3 状态留在内存里，没有保存 epoch 15 的权重。为了补评，按同一份数据、同 seed、同优化器、同 mask/曝光配置，把 A 重新训练到 epoch 15；第 15 轮的 dev 指标与原始日志相同：

```
原始日志 epoch 15: dev_loss 0.3581  dev_fact 0.875
复现     epoch 15: dev_loss 0.3581  dev_fact 0.875
```

两个数值相同支持“复现接近”，**不能证明权重或完整训练轨迹相同**。A15 的身份是“按原配置复现后补评”，不是原始保存的 checkpoint。B_h 没有重跑；用的还是原结果里的 epoch 15 输出。

## 4. 回答：同更新次数时，B_h 还剩多少优势？

- **事实通过**：6/12 对 4/12，B_h **多 2 个源**（对 A epoch 3 时是 6 对 2，多 4 个）。
- **表达偏好**：B_h 4、A15 3、相当 5，B_h 的净优势从 +5 缩到 **+1**。
- **计划结构**：4/12 对 3/12，B_h 多 1 个源；关系两边都是 1/3。
- **计划响应**：B_h 仍是 **0/4**，P1/P2 输出逐字相同；A15 没有计划块，不能做这项。

所以，把曝光对齐后，B_h 的事实和表达优势都缩小了，但仍略好；这还不能归因给计划。A15 在 `fixture-r5` 上**没有计划块也做对了分组和“随后”**；这只能说明 A 在这一例无需计划也写对，**不能外推到全部材料**，也不能据此说计划不是必要条件。

A 选中 18 次更新这件事，不能解释成“训练不充分导致重复”：A15 的留出输出比 A epoch 3 干净得多（不再有 11 次“围巾”），但它的 dev 事实分（0.875）低于 epoch 3（0.885），所以按预登记的 dev 规则仍然会选 epoch 3。**选点规则与留出质量在这里不同步**；原因是训练轨迹还是选点规则，当前数据分不开。

## 5. 不能越过的边界

- 四组计划响应还是 **0/4**；同更新补评没有改变这一点。
- B_h 的 +2 事实、+1 表达，仍可能是训练轨迹、目标文本和选点共同作用；不能写成“模型学会按计划组织”。
- A15 是**按原配置复现的检查点**（原运行未保存权重）；dev 数值相同只支持接近，不证明权重或完整轨迹相同，仍应记为“复现后补评”。
- 这批 12 源是固定回归，不是新盲确认；没有人工参考正文，表达偏好是逐条读正文的相对判断。

**下一步若继续，值得验证的假设**：同一事实输入配不同合法计划及对应正文，让计划成为必须使用的条件。本轮不制作这批材料，不启动下一轮训练。

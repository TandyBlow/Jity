# 新建独立来源：生成前协议

支持 R16；这是评测数据准备，不是模型实验、生产接线或 R16 整体验收。

用户在本轮授权：先检查项目所有分支；没有合适来源则自行提供。人工核验由用户承担。

1. 全分支和工作树审计先于新材料生成，结果固定在 `../source-search/audit.json`。未知用途的历史世界不作未使用来源。
2. 新世界从本次专门编写的检修站设定建立，不复制学校或训练世界再改名。来源类型是 **新建、人工编写、评测专用注册夹具**，作者为本会话 Codex；不是 R01 模型生成，不是历史玩家记录。
3. 固定六个场景 c8e01–c8e06；覆盖多人分工、多地点与可见性、复合任务、实体空间关系、持有关系与外貌、合成玩家关注。长期人际关系无权威字段，不声称覆盖。
4. 用现有 A 侧 Python 服务在本目录的新 SQLite 库创建并提交。只允许服务写入、合法 ID 分配、完整 checkpoint、settlement、commit 和 get_state；不直接修改 SQL 伪造点位。
5. 全量 get_state 是核验依据，**不是自动给模型的输入**。模型可用事实清单和上下文另列。未提供字段不要求模型主动说出，隐藏状态只作人工依据。
6. 运行 N1 抽取及事实绑定只检查夹具和程序接口。视角检查单列 N2 结果。无模型运行、无生成质量成绩，不修改投影或判分器。
7. 两版 R1 都记录；主筛采用更严格的原版 v1，R2 使用 new-world（不豁免名字）；R3 使用真实变化事实并显式标注 phase。命中后保留失败，不改名字、时长或添事实求过闸。R3 只证明当前转换口径的形状，不证明来源关系。
8. 新名字和任务原文额外与来源审计中全部可读文本做精确包含核对。该有限检查不声称证明仓库外的使用史，也不声称排除语义改写。
9. 材料隔离在 fresh-eval，不传给调参任务；禁止训练、调参或用输出修题。全量输入、生成器、导入依赖、来源审计、读回记录写 SHA-256 清单。
10. 六条全部交用户核验；程序不能替用户签通过。不因程序检查通过称正式题。人工确认后一次性冻结来源和输入；冻结后的内容变动必须新版本，旧版保留。

时长取值是夹具工序参数（转运 90 秒、巡检 45 秒、校准 180 秒、对位 30 秒、换封签 60 秒、关注窗口 120 秒）；在第一次筛查前声明，不能为规避旧题签名修改。

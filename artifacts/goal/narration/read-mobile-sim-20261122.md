# 移动模拟档第一组数据：单 0.6B + 4× CPU + 核显（2026-11-22，run35）

## 条件

- 页面 `/world-local`，Edge 158 headless，`--gpu-lite`（不强制独显）→ 实际 adapter：Intel gen-12lp（核显）。
- CDP `Emulation.setCPUThrottlingRate = 4`。
- 移动档配置：`narrationModel=semantic`（语义与叙事共用 Qwen3-0.6B，单引擎），`offscreenPolicy=skip`。
- 题目：s05/s06（与 run27–34 同输入）。

## 结果

| 指标 | s05 | s06 |
|---|---|---|
| 整轮等待（提交→再次可行动） | 296.3 s | 298.5 s |
| 首段草稿可见 | 52.9 s | 4.1 s |
| 通过校验的可读正文 | 150.2 s | 39.7 s |
| 回合结束方式 | 正常完成 | 触发 295 s 页面时限，停止自动推进 |
| 语义调用 | results 3 / updates 10 / continuation 1 | results 3 / updates 5 / continuation 1，updates 一次 `AbortError` |
| 驱动标记 | `prose_not_identical_to_record`、`accepted_over_60s` | `internal_note_in_prose` |

模型加载就绪 21.7 s；JS heap 就绪约 11.8 MB、回合中 15–43 MB（不含 GPU 显存）。

## 正文质量（人工读评）

- s05：把序列化输入整段念回（「他现在在西侧服务巷…屋里有路明非的护目镜…」），中途断句；「时间到了15:21，过去0秒」原样入文。
- s06：把法定失败的「递电台给阿豹」写成已发生（「并让其转交给裁判。这一回合的结算结果确认了这一动作」），并出现内部注记句式，触发 `internal_note_in_prose`。

## 追加：去掉 CPU 限速的对照（run36，同日）

同一单 0.6B + 核显，仅去掉 4× CPU 限速：s05 整轮 283.8 s（草稿 52.7 s、可读正文 153.0 s）、s06 267.9 s（草稿 47.6 s、可读 149.7 s）。与 run35 的 296.3/298.5 s 只差 5–10%。

结论修正：移动模拟档的瓶颈不是 CPU 限速，而是核显 + 0.6B 流水线本身；去掉限速也仍是约 4.5 分钟一轮。移动档必须靠调度改造（D-024）与减少调用，而不是换线程/限速参数。

## 结论

1. 移动模拟档（单 0.6B + 核显）整轮约 **268–298 秒**（run35 加 4× CPU 限速 296–299 s；run36 去掉限速 268–284 s），是「再次可行动 ≤60 秒」的约 4.5–5 倍；s06 在 run35 靠 295 秒页面时限收尾。CPU 限速不是主因，核显 + 0.6B 流水线本身才是。
2. 质量同时下降：0.6B 叙事复述输入、把被拒动作写成已发生、夹内部注记；比 1.7B 更差。
3. 移动端要成立，第一步不是换模型，而是 D-024 的调度改造（交还时机 + 每点调用数）；改造后仍需重新测量移动模拟档。
4. 模拟的局限：没有真实手机散热降频与 iOS 标签页回收；核显是近似而非真机 GPU。真机抽验不可省。

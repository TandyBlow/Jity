# 自修复原型：一遍修复救不了（2026-11-22）

## 条件

- 独立脚本 `repair-sample.mjs`：从 run40-e 与 run37 的 s06 证据取叙事提示与草稿，插「上一稿 + 修订要求」后再生成一次；同款 wllama、1.7B、temperature 0.45、每例 3 次。
- 修订要求：只改与事实矛盾处；没有发生/被阻止的动作不得写成已发生；其余尽量保持。

## 结果

| 用例 | 原稿 | 3 次修复输出 |
|---|---|---|
| run40-e（结算判 blocked） | 「阿豹接住后转交给了裁判」 | 3/3 仍保留该句；s1 几乎原文复制，s2/s3 只删了首句 |
| run37（结算判成功） | 「阿豹接住后转交给了裁判」 | 3/3 原文复制 |

- 6/6 次输出没有删掉被阻止的动作。模型把修订要求当成了「保持原样」。
- 生成耗时 2.5–7.9 s/次，不是时间问题，是遵从问题。

## 结论

1. 「同一模型、同一提示、一遍修复」这条自修复路线在 s06 上无效；不能作为 D-022 的答案。
2. 修复若要生效，需要程序先判「哪句与事实矛盾」（运行期校验，设计变更）或换更强的模型/微调——都回到 D-022 的其他分支。
3. 提示层与轻量修复都已实测为弱杠杆；剩余候选：定向微调、换运行时、改门槛、收尾。

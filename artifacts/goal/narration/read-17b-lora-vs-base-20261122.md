# D-020 首次微调对照：Qwen3-1.7B + LoRA（历史 199 行配方，2026-11-22）

训练：集群 4090D，历史 `train_qwen.py` + `rows-xy.jsonl`（199 行）+ `instruction.md`，LoRA r16，3 epoch，dev loss 3.26→2.03、test 1.97，峰值 11.2 GB，141 秒。合并、f16 转换、Q4_K_M 量化（1050 MiB）全部在集群完成；模型 sha256 `9beece58…768d7c`，bytes 1,107,408,640。页面新增评估臂 `qwen3-1.7b-narr-lora`（默认不变，D-007）。

## 产品格式（s05/s06，skip 调度，同输入）

- **基座 1.7B（run27）**：s05 写「镜片无裂纹…肩上没有阵营识别带」，与状态一致；s06 电台交接正常。
- **1.7B + LoRA（run28）**：
  - s05 给护目镜**凭空加了一道细痕**（状态：镜片无裂纹），并把诺诺的**红发写到路明非身上**（「他伸手把那条红发理了理」），又凭空加了短讯机对话。
  - s06 电台交接写成大段自造对话（「这是什么。」「这是演习用的。」），动作细节多为模型补写。
- 回合时长：LoRA 100.3 / 145.3 s，基座 137.6 / 168.7 s（LoRA 更快）。

开发期事实检查器只报了 run27 的一条输入回声；「镜片细痕 / 红发转移」不在检查器现有的识别带/门/回声类别里，属人工读评发现。

## 结论

1. 历史 199 行配方换到 1.7B 底模上**不解决**产品格式的事实保真，反而新增状态矛盾（镜片细痕）与跨人物属性转移（红发）。
2. 训练/合并/转换/量化流水线已在集群跑通，可复用；下一次微调必须按当前叙事输入投影构造数据，并针对「状态矛盾、跨人物转移、凭空对话」做训练与评测（D-020 的原计划）。
3. 交付默认保持 raw 1.7B；LoRA 仅作评估臂，换默认需新决定（D-007）。

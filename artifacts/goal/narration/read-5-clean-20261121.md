# 干净复跑技术读评（s02–s06，2026-11-21）

范围：run22（s02）、run23（s03/s04）、run24（s05/s06），全部干净 S0（进度服务停用、无远端恢复），当前代码（D-018 点级六阶段 + G5 事实层修复 + s07 收窄 + G7 同步修复）。五个 reader 对着 `t.after`/`t.snapshotAfterTurn`、results 尝试、judgments、updates Δ 与正文逐项核对。

结论：**hard 5/5，G5 未通过。** 事实层的定向拒绝生效（s02 两次尝试被「给路明非识别带但已结算外观说没有」拒绝），但正文仍写出该识别带；generic「看懂了规则牌」事实与 judgment/fact 矛盾仍是系统性问题。

反复出现的类型：

1. 正文把已结算状态改写或转移（识别带、红痕、枪、物品），尽管叙事 prompt 已有「物品/伤势/衣物只属于本人」「只有结算里的动作才算发生」。
2. 小模型用泛句（「看懂了规则牌」「没有判定」「未被阻止」）替代该成员的实际结果，reader 接受，judgment 理由与 fact 互相矛盾。
3. 事实挂到本回合没有行动的成员（memberIds/actorId 与动作主语不符）。
4. 重复/回声（同一外观句多次出现）。

证据限制：`submission.calls` 只有 results 的原始尝试（raw），没有序列化「被接受的事实」；reader 的 fact 级判断可能把被 `droppedFacts` 丢弃的尝试当成已提交。正文与 `t.after` 的冲突不受此限制。要把 fact 级结论做成硬证据，需要把 results 接受结果（facts + droppedFacts）写进回合记录（待办）。

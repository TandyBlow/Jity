- 超过 5 分钟的等待不可接受。
- R01–R16 每项有代码路径、运行记录、真实页面证据。
- 禁用游戏计算端点与保存服务后仍可游玩与本地保存。

## 2. 20 次页面输入协议

### 驱动

- 页面：真实 `/world-local`，RTX 4060 Laptop 8 GB + Edge（D-010），开启 COOP/COEP。
- 驱动：`frontend/scripts/product-acceptance/accept-world-local.mjs`，通过 `--turns` 指定输入文件；优先扩展 `turns-10.json` 与新增 turns 文件，不重写驱动。
- 服务器：可用 `--base` 指向本地页面；服务器关闭场景单独记录。
- 输入来源：脚本夹具必须标注 `fixture`；D-019 取消用户 10 次独立输入要求，20 次输入由夹具与真实运行记录组成，逐条标注来源。

### 覆盖矩阵

20 次输入是下限；本版只做 `dragon-raja-free-day`（D-011），不加 held-out 世界；离线、服务器关闭、两设备分叉是跨回合检查，不重复计入输入数。

| 场景 | 至少要发生 | 记录 |
|---|---|---|
| 普通行动点 | 读场景、移动、对话、等待/时间推进、被拒绝命令 | 输入、前后状态、Δ、正文、计时 |
| 任务达成 | 至少 1 次任务目标达成，触发个性/理智检查 | 六阶段顺序、全人物扫描范围 |
| 共同结算 | 至少 1 次连锁共同结算；未准入也是有效观测 | 目标、骰点、冻结顺序、反应、结果 |
| 自动链 | 至少 1 次 `continue` 产生多个点；至少 1 次 `handback` | 输入只消费一次，不重复消费 |
| 暂停/恢复 | 结算中途刷新或暂停→继续 | 不重掷、不重复行动、不重复应用 Δ |
| 历史 | 查看已提交点与叙事 | 历史只读，不回写状态 |
| 删叙事重生 | 删除叙事缓存→重新生成 | 只读已提交 S_{t-1}/Δ/S_t，不读旧正文 |
| 合法失败 | 非法或越界行动按设计失败 | 失败不写成世界事实 |
| 六阶段依赖 | 位置→外貌→任务→新小任务→个性→理智 | 后续阶段读取更新后的工作态 |
| 离线 | 首次资源与模型就绪后断网 | 仍可游玩与本地保存 |
| 服务器关闭 | 禁用游戏计算端点与保存服务 | 请求日志只有静态资源与可选 `/local-progress` |
| 两设备分叉 | 两个浏览器配置从同一快照出发 | 父链、CAS、选择、另一支恢复 |

### 每条输入必须记录

- 输入文本、输入时间、玩家角色、当前点 ID。
- 提交前后状态、原始 Δ、是否合法、拒绝原因。
- 原始模型输出（语义任务与叙事分别保存）。
- 结构错误、语义错误、重试、回退、实际调用次数。
- 模型身份（文件、sha256、量化、上下文）、浏览器/设备。
- 计时字段与峰值内存。

## 3. 计时协议

逐点记录以下字段；统一写 `artifacts/goal/timing-baseline.json`。

| 字段 | 定义 |
|---|---|
| `inputAt` | 玩家提交输入 |
| `pointCommittedAt` | 该点状态提交完成 |
| `narrationStartedAt` | 叙事调用开始 |
| `firstReadableAt` | 页面出现第一段非空可读模型正文 |
| `pointTextFinishedAt` | 该点正文完成 |
| `firstTokenAt` | 模型返回首个 token |
| `longestStreamGapMs` | 流式输出最长空档 |
| `stages` | action/targets/reaction/results/updates/continuation/narration 分阶段耗时 |
| `peakMemoryMB` | 页面峰值内存（可用 `performance.memory` 或浏览器任务管理器记录） |

判定：

- 首段：`firstReadableAt - inputAt ≤ 60,000 ms`。
- 单点：`pointTextFinishedAt - pointCommittedAt ≤ 300,000 ms`。
- 冷启动单独报告，不混入正常点。
- 未达标：登记失败、保留原始记录、给出下一候选决策；不宣称通过，不带病进入 G4/G8 的通过路径。
- 三次调度或提示迭代仍不达标时，只允许改模型或步骤组合，不得改门槛。

## 4. 叙事验收

### 4.1 原样输出边界

按 2026-11-11 决定（D-004）：

- 产品实际路径的正文逐字等于模型返回；页面可核对。
- 运行期只判断空与全空白；不检查、不裁句、不替换、不降级、不程序补写。
- 不把历史正文、摘要、priorText 喂回下一次调用。
- 正文不参与结算。
- `narration-quality`、`gate`、checker 只留开发期，不进运行时代码路径。

### 4.2 硬事实错误

出现任一项即记失败：

- 人物对调、张冠李戴。
- 方向反转、位置/移动与已提交状态相反。
- 数字、时长、次数错误。
- 无已结算依据的站立位置、移动、任务声称。
- 新增未结算事件、往事、承诺、线索。
- 视角泄露：写了主角不可见的人物、内心、秘密。
- 把未公开变化写成已公开事实。

### 4.3 四类跨回合检查

1. **状态一致**：正文不得与已提交的 S_{t-1}/Δ/S_t 矛盾。
2. **无捏造**：不得出现无已结算依据的事件、往事、承诺、新线索。
3. **视角/秘密**：只写当前投影可见的实体与信息；允许省略与暗示，不允许泄露。
4. **文风/自然度**：中文通顺，无字段名、数值、任务 goal/ID、模板腔；接近训练材料中的优质范文。

阈值（0–3 分制的通过线、四项权重）在 G6 冻结；当前按用户读感 + 四类检查记录（D-012）。未冻结前只记录分数与原始样本，不作通过判据。

### 4.4 输入依赖配对

对同一状态做「有某事实 / 无某事实」的配对输入；正文必须随已结算事实变化。若两版正文几乎相同，说明模型没有读取事实，记失败。

### 4.5 泄漏与锚定

若启用独立参考叙事：

- 检查提示/输入是否泄漏参考正文或评测答案。
- 检查模型是否只复述参考句；逐句复制不是目标。
- 记录检索、模板、编辑、重试各自贡献；不得把程序辅助包装成纯模型能力。

### 4.6 失败处理

- 没有候选达标：登记失败、保留原门槛、继续模型/提示/训练；不降级为运行时检查或程序叙事。
- 连续三轮无改善：只做一次有证据的模型/数据变更，并交用户决定。
- 不得删场景、缩小输入、改评分口径来制造通过。

## 5. 状态与回放检查

每次提交后：

- 从 S₀ 重放全部已提交 Δ，`replayWorld` 的 `stateDigest` 必须等于服务/页面当前状态摘要。
- 同点同实体只合并为一份增量；不重复应用。
- 六阶段顺序固定：位置→外貌→任务达成→新小任务→个性→理智；后续阶段读取更新后的工作态。
- 任务扫描覆盖所有人物；任务达成后的个性检查覆盖所有人物；允许合法不变化。
- 骰点由程序持有；阈值与 requestId 去重按 G2 冻结的协议；恢复不重掷、不重采样。
- 已行动人物不第二次行动；其骰点仍影响攻击者结果。
- 非法候选被内核拒绝并记录；拒绝不是通过。

## 6. 离线与服务器关闭

- 首次静态资源与模型就绪后，禁用游戏计算端点与保存服务。
- 仍可推进、暂停、恢复、查看历史、删除叙事并重生、本地保存。
- 请求日志只允许静态资源与可选 `/local-progress`；出现游戏计算 API 调用即失败。
- 服务器恢复后，本地存档优先；远端只提供不透明进度头。

## 7. 两设备分叉同步

- 部署与鉴权：单用户 Bearer + 本地/内网服务；服务器只存不透明快照；不做多用户鉴权、GC、分页或公网部署（D-013）。
- 两个浏览器配置从同一快照出发。
- 各自离线推进若干点，再并发上传。
- 服务器检测分叉；页面展示两支；选择 `keep-remote` 或 `keep-local-fork`。
- 未选择的一支仍可恢复；重复上传幂等；重试不重复结算、不重掷骰。
- 服务器关闭时仍可本地推进与保存。
- 记录两端快照、父链、修订号、选择记录到 `artifacts/goal/sync/`。

## 8. 证据格式与存放

- 目录：`artifacts/goal/`；G8 交付另放 `artifacts/local-game-delivery/manifest.json`。
- 每次运行一个 JSON：代码 SHA、数据哈希、模型哈希、配置、命令、设备、浏览器、时间、逐点记录。
- 原始输出、失败、重试、回退全部保留；不静默截断。
- 大文件、权重、原始日志不入 git；仓库内保存清单、哈希、取得方法与必要证据。
- 失败运行与成功运行分开登记；不得只保留成功样本。

## 9. 独立输入与用户签字（D-019 变更）

- 用户 2026-11-21 明确放弃签字与 10 次独立输入；G8 改为技术证据验收。
- 20 次输入由脚本夹具与真实运行记录组成，逐条标 `fixture`/`run`；用户读评不再作为通过条件。
- 技术自检给出未覆盖项、失败项与限制，不得只报通过；G8 报告如实记录用户放弃签字。

## 10. 复现

从新 clone 开始：

1. 安装前端依赖，启动 `npm run dev`，打开 `/world-local`。
2. 按 G3 清单与外部下载脚本获取模型资产（D-010），校验 sha256/bytes；仓库不直接托管权重。
3. 启动页面，确认 `crossOriginIsolated` 与 `__worldArm` 模型身份。
4. 运行 `accept-world-local.mjs` 指定 turns 文件与设备参数。
5. 保存 `artifacts/goal/` 与 manifest；记录无法复现的步骤。
6. 服务器关闭与两设备场景按第 6、7 节单独跑。

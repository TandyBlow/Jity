## 4. 同源和跨用途问题怎么处理

同一原例的改写、换名、骰点对照和后续完整输入都归同一来源组。来源相同而题号、标题或哈希不同，仍不能拆算独立组。需要同时检查新卡彼此、新卡与旧 D 42 题，以及开发与封存候选之间的同源关系；这些检查目前均待人工和来源证据。

发现同源时记录全部相关题号、来源组、用途及依据，再归并组关系。派生项不得跨 `development` 与 `sealed_candidate`；已经用于开发或调参的同源材料不能留作未见封存候选。由主执行登记处置和受影响回执，再以新的独立来源补足配额、生成新版本并重核相关内容。不能只改 ID、移动 split 或删除命中记录来声称仍有 90 个独立组。

用户可将本文件、上述三份 D 材料，以及交接包中的 `ownerRequests.B` 或 `ownerRequests.C` 对象交给相应负责人。**每个对象都自带本版提交、三文件身份、数量、所需保护范围和未填写的回执模板**，不依赖另一条线的请求。当前两个请求均为 `prepared_not_sent`；负责人、人审、实际接收、方法和结论均未代填。

| 来源方 | 必须冻结并覆盖的范围 |
|---|---|
| B | hv/nv/ns、训练/开发/校准、整链和叙事评测、代码内嵌样本、历次提示词/阈值调参用例；包括原例、改写、已消耗封存及未提交内容的适当冻结快照 |
| C | N2/N3/N4 的训练、开发、校准、封存、改写及历次调参来源；包括历史版本、同源组关系和未提交内容的适当冻结快照 |

负责人在自己的隔离环境先冻结完整来源清单及比对方法，再与 D 版本比对：原始/规范化摘要、近重复候选、人工同源判断依次记录。不能只交当前分支尖端、两个样本文件或一份 holdout；历史入口身份不是完整性证明。

回传只含身份、范围、方法、命中标识及结论。**B/C 保护题原文、改写、封存正文和原始模型答案不回传给 D 的出题/标注流程。** 命中使用保护来源内部 ID、冻结版本及不泄露正文的理由；需要复查时由来源负责人在隔离环境处理。

| 回执字段 | 负责人填写的内容 |
|---|---|
| 回执身份 | B/C、负责人、日期、回执版本；接收/检查本版 D 三文件的结果 |
| 完整来源 | 每份清单的 commit 或冻结快照、路径、SHA-256、历史范围、原例/改写组关系；未覆盖范围及原因 |
| 方法 | 工具及版本、规范化规则/版本、近重复算法与阈值、人工同源规则和实际复核人 |
| 逐项发现 | D 的题号/来源组/split，保护来源内部 ID/同源组/版本，命中类型、处置建议、不泄露正文的依据；数量为 0 也须有实际检查证据 |
| 限定结论 | `unverified`、`needs_revision` 或 `verified_for_declared_scope`；仅对登记范围有效，并列残余限制 |
| 收录确认 | 用户/协调人及独立复核者对真实回执的核验记录；尚未核验时留空 |

模板中的 `null` 代表尚无证据，不能改成空数组或 0 来表示“没有命中”。如果实际检查后确为 0，可以填写 0 和空发现列表，同时给出完整范围与方法证据。缺来源、方法或人工判断时保留 `unverified`，不写“零污染”。B/C 各自的回执不互相覆盖，也不代替 D 内部及跨 split 审查；旧 42 题的回执即使后续收到，也不覆盖新版 90 卡。

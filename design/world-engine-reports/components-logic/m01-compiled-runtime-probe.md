# D / 固定编码器计算图执行探针

日期：2026-11-03；起点`d34874e`。用户“继续”授权处理剩余编码热点。模型仍是event2两层M01与原两个判断头；训练0步、FP32、原权重不变。沿用快速分词和追加日志，完整事实/窗口/人物保留，新90组与B/C材料不使用。

## 固定比较和执行范围

- fast：上一批快速分词+单次装箱+SDPA，原PyTorch模块执行。
- compiled：同输入、同嵌入/编码层/判断头，将原嵌入与编码栈通过Torch 2.7.1的`jit.trace(check_trace=False)`与`jit.freeze(optimize_numerics=False)`转换为计算图，保存到D本地忽略目录后重新加载。仅支持CPU/int64、batch=1、3–512 token、完整无padding/无注意力屏蔽、合法词表与类型ID；调用前检查，超范围明确拒绝。专用图在原完整注意力范围内跳过外层通用掩码装配，原池化和头不变。

每臂4个已公开开发场景各20次，共160项业务推理/预期640窗口；正反顺序交替，不挑最快次。source/compiled均对全部窗口重新分词与前向，无跨题/跨次特征缓存。每题原子事实/顺序/窗口/token/跨度必须与原event2一致。

## 转换与输入检查先于业务推理

转换使用第一份保留开发输入的第一个完整窗口，编码栈hook记录实际trace前向次数，要求1次。`check_trace=False`仅避免工具内部未记账的重复执行；随后对旧20组的全部83窗口逐个运行fast/compiled比较完整hidden states，预登记atol=1e-5、rtol=1e-5。若不一致，停止业务推理并保留失败。参考与转换图的实际输入、输出摘要、调用数/状态和时间记录在独立setup事件流，转换及核对均计准备开销。

两个方案的业务概率对原event2逐项记录：fast要求逐值相同；compiled最大绝对概率差≤1e-6、全部行动/目标判断一致，精确相同与容差内相同分开报告。容差在运行前固定，超限保留失败、不改阈值。源编码器/头前后SHA不变，记录计算图文件/图摘要、实际运行时和精度；转换不会作为新训练或新题质量成绩。

## 计时、资源和验收边界

CPU单线程/并发1，用户本次运行窗口，子进程120秒/RSS2048MiB，不用GPU/B/C资源、不安装额外依赖。主指标包含分词、装箱、适配检查、编码、池化、头、结果flush/fsync及尾部遥测。准备包含加载、转换/保存/重载与20组完整hidden核对，不能把准备成本写成0；业务计时为已加载/已核验路径。批末汇总和监督重放计时范围继续明确披露，冷启动3次、浏览器及完整500ms未测。

逐题报告20次p50/p95/max，任何一次超50ms则该规格局部失败；全在预算内也只描述这4种已公开工作负载的热判别观察，不升级为独立语义质量或完整组件/500ms通过。该批尚无行动描述、反应、共同结果与动态链路，不省略它们。若无收益或超预算则继续定位更小任务/模型与执行方式。

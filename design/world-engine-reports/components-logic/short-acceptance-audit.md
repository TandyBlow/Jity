## 3. 本次新增发现

`validate_fact_mapping` 审查版本使用 set 做覆盖，未要求映射行的 factId 唯一。例如同一事实 f 同时标为 `state`（合法 positionSet 目标）和 `unchanged`（空目标），完整覆盖时被接受；同一行重复一个目标也被接受。这是可复现的结构边界缺口，不是需要模型解决的语义问题。

已新增三项工程反例：

1. 同一 factId 的冲突 disposition 必须拒绝：审查版本失败。
2. 同一事实内重复 target 必须拒绝：审查版本失败。
3. 不同事实共同支持同一合法候选：审查版本通过，应继续允许。

窄输出桥 `_mapping` 逐事实构造单行，已排除单行重复目标，因此正常窄头路径不直接产生此问题；公共聚合校验仍应防御复合 provider 或恢复材料。该缺口已在 r3 完全结束后修复，未修改运行中冻结 CODE。补丁及复验状态在本文末尾登记。

另一项接线注意事项：`_world` 是 D 所需字段校验，不是 A 全量 WorldState 验真器；当前状态、旧记录和实际判定必须来自 A/B 的正式读取和来源验证。调用者不能把“D 本地摘要一致”视为 A 已确认该事实。现有实验适配明确注明此责任；生产 adapter 尚未提供。

**r3 的语义未完成出口缺口。** 通用 `Completion.incomplete` 和程序异常隔离已经实现，但 r3 已训练 D02.1 标签仅 `act/skip`，D05.2.label 仅 `achieved/partial/not_achieved`，本地 backend 的 argmax 不可能主动选择“语义上无法确定”。模型不可用、错误、截断或非法输出变为 incomplete 的工程机制，不能当作已训练的语义弃答能力。这不只是缺少验收成绩：该冻结版本的窄头词表/解码接口也没有该出口。r3 完成后已补显式编排分支与新助手草稿；训练代理另行扩展词表、实际训练并验证其与 skip、未达成的区别。新接口工程测试通过不表示语义弃答已学会。

## 2. 输入和资源绑定

M02 固定 revision 的六文件在 D 独立模型目录完整 SHA-256 复核，含约310 MB权重。文件读取验真不产生推理或性能成绩。包缓存、权重与 venv 不提交、不共享给 B/C 写入。

开发专用文件 [development-inputs.jsonl](../../../experiments/world-components-logic/data/round1-inputs/development-inputs.jsonl)只含 `development`，不包含封存候选。准备快照显式选择 `r1-dev-d02-01`、`r1-dev-d03-04`、`r1-dev-d04-01`、`r1-dev-d05-01`；它们仍待完整输入人审。选择只登记准备范围，不向模型曝光题目。校验器拒绝混入封存、守卫题、未知题、重复题及版本漂移。

新业务适配、短链动态执行器、真实 API/RPC 展开及 G03 服务适配均未实现。首次无业务加载检查不要求90组全部完成；业务批按它实际使用的材料逐项准备，不靠材料数量替代核验。

## 3. M01 训练协议草案

训练来源与这90组、旧42题及B/C保护来源隔离：每个头先拟40个新来源组，32训练、8训练内验证，两头合计80组。该数量只是待审的小批计划，实际创建为0；同原例、改写及同一源的多个候选人物对不得跨用途。原90组训练配额始终为0。

拟先冻结约10M编码骨干、仅训练两个头：AdamW，学习率0.0002，batch16，最多200步，每20步验证；连续3次验证不改善就停止并保留最佳检查点。固定种子42，分别使用二分类损失。拟 CPU 单线程、单并发，墙钟120秒、内存2048MiB；资源保护程序尚未实现，数值不表示已批准的计算窗口。出现取消、损失非有限值、资源超限或数据异常即停止，保留失败记录。超时不是完成。

上述内容在快照的 `protocolDraft`，实际执行的 `protocol` 仍未冻结，数据/标签/签署/检查点哈希为null。正式使用前需要按实际数据校准并审阅，不能照抄草案直接训练；训练后的检查点另验真、另建推理批次。没有预测质量或速度会通过。

## 4. 静态检查与性能边界

```bash
python3 experiments/world-components-logic/prepare_run_batch.py --check
```

PASS仅表示准备快照身份与边界一致；随后打印的 BLOCKED 是尚缺的运行条件，不是模型执行失败。`--write-new` 只发布新文件，拒绝覆盖旧证据。准备工具没有模型调度入口；修改授权字段也会被拒绝，实际执行另按已有四段准入办理。

500 ms完整请求目标及局部预算保持原协议；v4中的完整参考预算S3为810 ms加真实等待、S4为1620 ms加两次独立等待，仍超目标。所有数字都是预算，毫秒性能尚未实测。未来实测记录队列、分词、模型协同、程序交接、重试、必要等待及自动轮的完整墙钟，局部通过不能代替完整流程通过。

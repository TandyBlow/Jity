# 完整回合联合接入验收（2026-11-04，未训练）

一次真实混合回合从已提交事实走到最终文本，单入口、无人工搬运。结论：**流水线骨架通过验收**；同时这轮真实输出暴露了两个质量问题，属于下一阶段的优化对象，不是连接规则能解决的。

## 1. 入口

一条命令，四个阶段，全部记录在 `mixed-result.json` 里：

```
round_input.py       读权威库 → units + points（事实、姓名、时间、证据引用）
authorize_round.py   服务端校验器 → authorization（verdict / 证据 / 版本）
n4_pipeline.py       绑定 → 生成 → 两层编辑 → 完整记录
                    --round --ckpt --out [--timeout-fact fN]
```

事实、姓名、时间推进、证据 ID 全部来自 `world.db`，没有中间人工文件。产物里同时保留：**原稿**（生成句拼接）、**最终稿**、**逐条操作记录**、**各组件版本**（`n4-pipeline/1`、`world-relation-validator/1`、`relation-edit/1`、`edit-layer/2`）。

## 2. 混合回合的真实数据

`build_mixed_round.py` 用权威写入路径建了 4 个点（p1 走完整 service 流程，p2–p4 走 `store.transact`），6 条已提交事实：

| factId | 主体 | 事实 | 点 | 时间推进 |
| --- | --- | --- | --- | --- |
| f0 | 林川 | 指节发白 | point_7 | 2 s |
| f1 | 林川 | 袖口沾了雨 | point_7 | — |
| f2 | 周宁 | 斗篷下摆湿了一片 | p2 | 3 s |
| f3 | 陈默 | 鞋底沾了泥 | p3 | 1 s |
| f4 | 陈默 | 袖口湿到肘部 | p3 | — |
| f5 | 沈禾 | 帽檐压得很低 | p4 | 2 s |

计划只请求两条关系：`f2→f3`（跨主体，p2→p3 有 1 秒推进）和 `f5→f4`（**故意写反**）。

授权结果（逐条判定，一条失败不牵连其他）：

- `f2→f3`：通过，`elapsedSeconds = 1`；
- `f5→f4`：拒绝 —「两端证据点不在同一 chain，无法比较」；
- 汇总 `verdict = partial`。

## 3. 两层编辑的边界

| 层 | 规则 | 本轮表现 |
| --- | --- | --- |
| 同主体合并 | 相邻同主体、**端点不参加** | `f0+f1` 合并：`林川的指节发白，袖口沾了雨。` |
| 端点保留句界 | 参与 `before` 的单元不合句 | `f3+f4` 被拦下，原因 `endpoint-keeps-boundary` |
| 连接 | 加“随后”前**再查一次当前相邻关系** | `f2→f3` 插在**块级**边界上：`…湿了一片。随后，陈默的鞋底沾了泥。` |
| 未授权 | 原样 | `f5` 不变；被拒的 `f5→f4` 没有产生连接词 |

最终稿：

```
林川的指节发白，指节发白，袖口沾了雨。周宁的斗篷下摆湿了一片。随后，陈默的鞋底沾了泥。陈默的袖口湿到肘部。沈禾的帽檐压得很低，袖口还带着硬币。
```

## 4. 失败路径

| 场景 | 结果 |
| --- | --- |
| `f4` 生成超时（非端点） | 整源 `sourceComplete=false`、`incompleteFacts=["f4"]`；`f2→f3` 不涉及 f4，**连接照常**；f4 文本残缺但未被伪装成完成 |
| `f3` 生成超时（**是端点**） | 整源未完成；`droppedForIncomplete=["f3"]`，该关系被丢弃，`connectorOps=[]`，**正文没有“随后”** |
| 授权失败（`f5→f4`） | 只影响这一条，`f2→f3` 的连接与 `f0+f1` 的合并不受影响 |

## 5. 耗时（完整，不是单次模型调用）

HPC 作业 `239307`，排队后运行 15 秒（21:59:27–21:59:42）：

| 阶段 | 耗时 |
| --- | --- |
| 读事实 + 来源绑定 | 0.008 s |
| 授权（服务端预计算，随输入带入） | ~0 s |
| 模型加载（u240，77M，fp32） | **3.67 s** |
| 生成 6 条短句 | **0.82 s**（单条 0.07–0.37 s） |
| 编辑（两层） | < 0.01 s |
| **进程内合计** | **≈ 4.5 s** |

明确说明：**1.36 s / 0.10 s 只是单条模型调用**；浏览器端完整响应还要加上排队、上传下载、页面与网络开销，本轮没有测这部分（HPC 排队时长随负载变化，不能当作固定值）。

## 6. 这轮输出暴露的两个问题（不是连接规则能修的）

1. **u240 会自己重复/加料**：`f0` 生成「林川的指节发白,指节发白。」（同一短语重复）；`f5` 生成「…袖口还带着硬币。」（凭空多出一个物件）。这两处都是**模型行为**，本轮规则层没有掩盖它们，如实留在最终稿里。
2. **换域生成质量下降**：本回合的舞台是协议 fixture 世界（走廊/外套/校徽），不是 `world.json` 的龙族设定，模型对可见物件列表的贴附更差（`硬币` 就是这么来的）。

这两点直接决定下一阶段做什么：不是继续加连接词或编辑规则，而是**按完整回合的真实质量与延迟**去优化生成与表达。

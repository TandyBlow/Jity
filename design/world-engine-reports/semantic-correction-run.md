# 独立语义纠错 C：20 源 A0→C（2026-11-04，未训练）

**结论：C 没有展示出可靠的语义纠错职责，结束这版纠错任务。** 最终应用层只改了 1 个源、删了 1 处；A1 参考的 13 处里还有 12 处没消。更关键的是，模型原文提出了 **7 个要删合法事实**的删除、3 个找不到的 span、3 个歧义 span、6 个会造语病的句号风险；这些都被程序守卫拦下。守卫生效不等于模型会纠错。

## 5. 关键失败

### 5.1 模型会提“删合法事实”

7 个提案要删的是授权事实：

- train-r3：“叶知微的鞋跟磨塌了。”——f3 合法；
- v03：“四下安静，没有新的事情发生。”——f3 合法 no_change；
- v06：“沈砚的袖口沾了雨。”——f1 合法；
- t01：“，指尖沾了墨”——f1 合法；
- t05：“，把雾警钟敲响，”——f1 合法；
- fixture-r3：“周宁的指缝里塞着泥”——f2 合法，但 span 找不到；
- t19：“、鱼筐”——f2 合法，但 span 找不到。

程序靠事实覆盖检查把它们拦成 pending。**没有守卫，这些就是 7 次误删合法内容、并造成必述遗漏。** 这正是“守卫生效”和“模型会纠错”的区别。

### 5.2 重复项定位不精确

fixture-r1/r2、train-r1 提出删“，指节发白/，掌心出汗”，但同一子串在 A0 出现两次，程序无法判断删哪一处，pending。模型没有给出唯一位置；这不是程序吹毛求疵，是“精确删除范围”没做到。

### 5.3 span 带句号，删除会拼句

fixture-r4、train-r4、fixture-r5、v05、train-r2 的删除内容本身是对的（重复或新增），但 span 把句号也包进去：

- “，发白发白。”删掉后，“脸色发白周宁的背上……”；
- “，袖口被雨浸透。”删掉后，“衣领被雨浸透随后……”；
- “，玻璃上不再有雾。”删掉后，“擦得透亮塔顶的灯……”。

首轮程序漏检，实际执行了 4 个 run-on；修正后全部 pending。模型原文的 span 精度问题仍在。

### 5.4 类型混淆

模型把 4 个新增删除都标成 `repetition`：

- “袖口被雨浸透”不是“衣领被雨浸透”的复述，是另一个对象的新增；
- “玻璃上不再有雾”不是“把灯罩擦得透亮”的复述，是未经支持的结果；
- “手背上沾着水沫”不是“鬓发被雾打湿”的复述；
- “钟绳绷直了”不是“把松脱的钟绳重新系紧”的复述。

类型是输出的一部分；4/4 新增都标错，说明模型没有稳定区分“复述”和“越权新增”。

## 6. 判定

| 检查 | 结果 |
| --- | --- |
| 20/20 JSON 可解析 | 是 |
| 应用层误删合法内容 | 0（守卫拦下 7 个提案） |
| 应用层必述遗漏 | 0（守卫拦下） |
| 应用层删除后语病 | 0（修正检查后） |
| 正确消除的重复 | 0 |
| 正确消除的新增 | 1（v01 一处，类型错） |
| A1 参考 13 处中**应用** | 1 / 13 |
| A1 参考 13 处中**提案触及** | 9 / 13（1 应用 + 8 pending） |
| 模型提案层要删合法事实 | **7** |
| 模型 span 精度 | 3 歧义、3 找不到、6 句号风险 |

**按应用层最低条件，C 有 1 个正确删除、0 个应用误删/遗漏/语病；但它只覆盖 1/13，而且模型原文有 7 个要删合法事实的提案、3 个找不到的 span、3 个歧义 span、6 个句号风险。守卫后的零错误不是模型能力。**

所以：**结束这版纠错任务，不写新确认集，不训练，不沿失败句逐轮补提示词。** 当前证据不能证明“第二个模型能承担纠错职责”；它证明的是“程序守卫能拦住一部分错误提案”。如果以后还要做，需要把任务缩到更可验证的粒度（例如先只做“定位重复项”或“判断一句话是否越权”），但这不是本轮的任务，也不在本轮启动。

本轮没有改 A0/A1/u240、没有接服务、没有训练、没有提示词搜索。A1 的独立人工复核尚未完成，如实记录。

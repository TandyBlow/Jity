# 同模型对照：D 直接表达 vs W 协同表达（2026-11-04，未训练）

两臂同一个 7B 检查点（qwen2.5:7b，温度 0、320 token 上限）、同一授权信息、同一强约束。唯一差别：**W 多给一份 u240 中间短句**。

评分以**权威事实**为准，u240 短句不是标准答案。

## 1. 判定（按你给的顺序）

**第 1 步：事实完整、未授权新增、顺序与关系违规**

| 项 | D 直接表达 | W 协同表达 |
| --- | --- | --- |
| 事实完整 | **19/20**（`double-d011` 整条丢失：顾行舟手背／帽檐沾泥被写成“在簿子上书写”） | **20/20**（基本逐字复用 u240 短句） |
| 顺序违规 | 0 | 0 |
| 无授权却用先后词 | **4 源**（v01、v03、t05、t19） | **4 源**（v03、v05、v06、t05） |
| 推测性措辞（仿佛／似乎／显然／为了／可能） | **9 源** | 7 源 |
| 未授权新增（源数） | **约 14/20**：场景铺陈、解释性从句、动作细节（“灯芯跳动”“准备售卖”“为遮挡晨光”） | **约 14/20**：与 D 同类，且**继承 u240 的加料** |
| 字段名泄露 | **1 源**：v01 写成“沈砚移动潮渡至雾堤” | 0 |

**W 是否保留或扩大 u240 原有的加料：保留，共 5 源**（train-r2 的“手腕上沾着盐沫／手背上沾着水沫”、train-r4 的“发白发白”、train-r5 与 fixture-r5 的“袖口被雨浸透”、v05 的“玻璃上不再有雾”）。没有一例被整合阶段清掉。

**第 2 步：连贯性**

按规则，只有在“事实安全”的输出之间才比较连贯性。**两臂都不满足事实安全**（D 丢过一条事实、两臂都有新增与无授权先后词），所以这一步**不做正式比较**，只记录观察：D 的段落更像叙事（有场景开头、句子长短有变化），W 多数是把 u240 短句连起来加少量连接词，读起来仍偏罗列；t19、v03 这类 W 反而更自然。

**第 3 步：结论**

W 既没有“保真不退”（保留了 5 源上游加料，自己又新增），也没有在事实安全前提下显示连贯性优势 → **这个“独立整合模型”的任务定义尚未成立**。这**不否定**多模型协同路线，只说明“把 u240 短句交给一个通用模型去组织”这一版任务定义不成立。

## 2. 两臂各自暴露的问题

| | 主要问题 |
| --- | --- |
| D 直接表达 | 会**复述字段**（“移动潮渡至雾堤”）、会**整条丢事实**（d011）、会用推测填空（“仿佛沾染了某种无形的水汽”） |
| W 协同表达 | 会**原样搬运上游缺陷**（加料、重复），并且同样会加推测与场景尾巴；v03 还编了“笔尖在干纸上划过，留下一行行工整的字迹”“叶知微走进了房间” |

一个重要观察：**W 不会自动过滤上游的错误**。u240 的加料在 W 里 5/5 全保留，说明“多一层整合”不是纠错层。

## 3. 成本（单列，不作为淘汰依据）

| | D | W |
| --- | --- | --- |
| 7B 调用 | 1 次／源 | 1 次／源 |
| 输入长度（平均字符） | 较小 | 多出 5 条 u240 短句（每源 +40～120 字） |
| 7B 用时合计 | 104.7 s | 86.1 s |
| 额外调用 | — | **u240 每源 3–5 次逐事实生成**（本实验复用已有输出，没有重跑） |

W 的 7B 用时反而更短，是因为输入里已经有成句、模型写得少；但**总成本要加上 u240 的逐事实生成**（此前实测约 0.5 s／源 + 模型常驻加载 0.29 s）。

## 4. 这一轮确立了什么

1. **“给 u240 短句 + 让通用模型整合”这一版任务定义不成立**：保真没提升，还继承了上游缺陷。
2. **整合层不是纠错层**：上游加料 5/5 原样穿过。
3. **D 路线也不安全**：直接给事实让通用模型写，会丢事实（1/20）、会泄露字段名（1/20）、会大量推测。

要往下走，任务定义得改：整合模型要么被约束到“只能改标点、指代、同义替换、插入白名单背景”（形式化到可机械检查），要么先把“哪些内容允许写”变成结构化字段再交给它。**本轮不训练、不换模型、不修缓存、不接服务。**

## 0. 先给一个具体例子

以 t19 为例。四条已提交事实，按顺序是：

```
f0 阿棠的袖口沾了鱼鳞。
f1 沈砚的外袍下摆沾了泥水。
f2 阿棠把银鳞鱼装进鱼筐。
f3 沈砚把油纸伞收拢靠在摊棚边。
```

v1 的编辑层只能做两件事：相邻同主体合句、已授权关系加“随后”。这四条没有同主体相邻，也没有授权关系，所以 v1 只能四句罗列。

v2 允许把它写成：

```
清晨的薄雾里，棚下散着光。阿棠的袖口沾了鱼鳞，沈砚的外袍下摆沾了泥水。阿棠把银鳞鱼装进鱼筐；沈砚把油纸伞收拢靠在摊棚边。
```

这里发生了什么：

- 开头的背景来自授权场景 `清晨`、`薄雾`、`棚下散光`，没有新增人物、事件或人物与物件的位置关系。
- 第 1、2 条用逗号并列，第 3、4 条用分号并列；两条的主体都写出来了，顺序没变。
- 读者会读成“两个人各做了两件事”，但文本**没有**写“同时”“各忙各的”。并列是“两件事都成立”，不是“两件事同时发生”。

v2 放开的就是这类操作。跨主体不只指两个人：`灯罩蒙了灰，铁链生了锈` 也可以只是并列陈述，两个物件名都保留；写成“两样东西同时蒙了灰”才是同时关系。没有放开的是：把 f0/f2 归到阿棠、f1/f3 归到沈砚的**事实重排**；那会改变事实顺序，本轮仍单独留作后续变量。

## 1. 术语与责任边界

| 术语 | 在本文里的意思 |
| --- | --- |
| 事实单元 | 一条已提交事实。u240 把它写成一句短句；表达层不能改它的内容、主体、方向、结果和顺序。 |
| 授权原子 | 已提交状态里 `地点`／`地点可见`／`场景` 的一个完整片段；`场景` 按 `；` 切开，每段是一个原子。 |
| 完整授权描述 | 一个授权原子，或几个原子并置成的名词短语（不产生谓词；**每个原子都必须有依据**）。**引用**它，不是从它**扩写**。 |
| 关系授权 | 只认 `before` 且 `verdict == pass` 的服务端结论；带校验器版本。 |
| 操作账本 | 逐片段的记录：用了哪个操作、引用了哪些 factId／原子／关系 ID。没有账本就不能把收益归给组织。 |
| pass／review／reject | 机械通过／需要语义复核／硬违规。`review` 不算通过。 |
| 组织收益 | 在不改事实的前提下，让段落更顺：背景落点、局部衔接、跨主体并列。 |
| 纠错 | 去掉 u240 的重复、加料、病句。独立记账，不算组织收益。 |

本文说的 **v1**，指现行 `edit-layer/2`＋`relation-edit/1` 和它对应的旧契约；不是另一个代码分支。

v2 **不替代** `relation-edit/1` 和端点规则；它是在它们之上增加 `bg/1`、`coord/1`、`ref/1`、`seg/1`、`recast/1` 五个组织操作。

本轮 20 源对照里的 **A1 是人工纠错条件**：只在 u240 原稿上做必要纠错（去重、删加料、修病句），不润色。它不是模型纠错层，也不代表自动纠错已经解决。

责任分工：

| 层 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| u240 | 单条事实成句 | 段落组织、纠错、跨主体衔接 |
| A1（人工，本轮）／未来纠错层 | 去重复、删加料、修病句 | 组织收益、事实改写 |
| 规则层 | 同主体合句、已授权“随后”、端点句界 | 背景选择、跨主体并列、指代、断句 |
| v2 组织层（本文的模型任务） | 背景落点、局部衔接、跨主体并列、指代替换、同主体重断句 | 事实重排、同时关系、人物-物件位置、背景扩写、因果/目的 |
| 核对层 | 机械不变量＋复核标记 | 证明段落“写得好” |

推荐的离线顺序：

```
u240 原稿 → A1（人工纠错，仅本轮；去重/删加料/修病句）→ 规则层（同主体合句/授权随后/端点）→ v2 组织层 → 核对
```

规则层先跑，v2 组织层在规则结果上做重断句、背景落点、跨主体并列和指代；端点的句界/方向随文本传入，模型不能跨端点。先纠错再组织，是为了不让组织模型“顺手删掉 u240 的加料”然后被记成组织收益。本轮 A1 由人工完成；纠错片段在账本里单独一行，组织模型的输入是 A1 的干净单元。

## 2. 授权单位：什么叫“完整授权描述”

这是 v2 最关键的收口。5 例里最容易混淆的几句话，都出在这里。

### 2.1 三类授权，权限不同

| 授权 | 授权什么 | 不授权什么 |
| --- | --- | --- |
| `地点` | 地点名、地点链（如 `潮汐档案馆>长桌`） | 人物在某个具体物件旁/下/边 |
| `地点可见` | 这个物件**在这个地点存在** | 物件的状态（亮着、蒙灰）、颜色、人物与它的位置关系 |
| `场景` | `；` 切开的每个完整片段（如 `夜`、`小雨`、`铜灯`、`棚下散光`） | 片段之间的新关系（雨落在窗外）、持续时间（还没散）、新事件 |

### 2.2 引用，不是扩写

一个背景片段要成立，必须满足：

1. **内容词**来自被引用的授权原子；普通功能词可以加。`里`、`着` 不按词表自动放行：`里` 可能建立位置关系，`着` 可能改变状态表达，要判完整表达。
2. 不出现人物姓名或人物代词。
3. 不产生新的谓词、事件、状态变化、因果关系、目的关系。
4. 不建立人物与具体物件的位置关系。
5. **不把 `可见` 物件当方位锚点**：`铜灯下`、`天窗旁`、`案板边` 这类短语，除非这个方位关系本身写在授权场景/完整描述里，否则不算背景。`棚下散着光` 的来源是“棚下散光”这个场景原子；但它要进复核，因为“着”是状态表达。
6. **场景框架必须属于当前场景**：`浓雾里` 只能用于当前地点的雾；不能把起点的天气套到终点，也不能据此添加人物看见、感到或受到影响。

具体判定：

| 写法 | 授权 | 判定 | 原因 |
| --- | --- | --- | --- |
| `浓雾里` | 场景=`浓雾` | 通过 | 雾属于当前场景；只作背景框架，不添加人物看见/感到/受影响 |
| `棚下散着光` | 场景=`棚下散光` | 复核 | 完整原子，但“着”是状态表达；要判断完整表达是否改变状态/时间 |
| `清晨的薄雾` | 场景=`清晨`、`薄雾` | 通过 | 两个原子都在场景里；不能从“薄雾”补出“清晨” |
| `小雨落在天窗外` | 场景=`小雨`；可见=`天窗` | **超出 v2** | “落”“外”不在授权原子；这是把两个原子扩写成一个新事件＋方位关系 |
| `沈砚在铜灯下` | 可见=`铜灯`；场景=`铜灯` | **超出 v2** | 可见只授权“铜灯存在”；场景里的 `铜灯` 仍是物件/光源，不是“人物在铜灯下”的位置事实。需要位置事实或完整描述 |
| `薄雾还没散` | 场景=`薄雾` | **超出 v2** | “还没散”是持续时间/状态，原子没有这个断言 |
| `铜灯亮着` | 场景只写`铜灯` | **超出 v2** | 只授权物件存在，没授权“亮着” |
| `铜灯亮着` | 场景=`塔顶铜灯已点亮` | 通过 | 原子本身写了“已点亮”，状态有来源。注意：v05 的“灯还亮着”来自无变化事实，不是背景；“还”由那条事实授权 |

最后两行的对比很重要：**同样是铜灯，v05 的场景写了“塔顶铜灯已点亮”，所以“灯还亮着”有来源；t01 只写了“铜灯”，就不能写“铜灯亮着”。** 授权是按具体记录判的，不是按词义猜的。

`着` / `里` 的处理不是词表豁免：`棚下散着光` 进复核，因为“着”把“散光”写成了持续状态；`浓雾里` 通过，因为雾是当前场景的环境框架，不是人物与具体物件的位置关系。判断对象是**完整表达**，不是单个字。

### 2.3 “完整描述”缺口

当前 `场景` 是原子列表，不是句子。本轮**不新增世界字段**：

- 如果已有完整描述，就整句引用；
- 如果没有，就不写带谓词的背景（例如“小雨落在天窗外”），只做“引用＋落点”。

这不是永久规则，而是本轮的边界：不为这一轮改世界协议。

## 3. 操作表

### 3.1 规则层（不交给模型，继续由程序做）

| ID | 操作 | 前置 | 允许 | 禁止 | 失败回退 |
| --- | --- | --- | --- | --- | --- |
| `merge/1` | 同主体合句 | 相邻、同主体、都不是关系端点、中间没有别人插进来 | 逗号连接，省掉后一句主语 | 合并端点；合并异主体；在多人段落里省主语 | 原样分开 |
| `conn/1` | 已授权“随后” | `relation-edit/1` 五条：相邻、方向一致、`verdict=pass`、校验器版本一致、后一句以自己的姓名开头 | 在后一句前插“随后，” | 其他连接词；移动后一句；合并端点；关系不成立时猜关系 | 原文不变 |

| --- | --- | --- | --- | --- | --- |

| `ref/1` | 指代替换/补主语 | 重复的姓名换成“他/她”；或把规则合句时省掉的零主语补回来 | 段落内同性别/同数人物唯一、紧邻前一个主语、不是关系端点 | 实际指代是否清楚；中文零主语 | 保留姓名/保持零主语 |
| `seg/1` | 断句 | 改标点、拆句、把规则合过的同主体块重新分开 | 只动标点/句界；事实顺序和覆盖不变；不跨端点 | —（节奏作为质量观察，不影响合法性） | 原句界 |
| `recast/1` | 单事实内局部改写 | 同一条事实内改“把”字句、调对象/动词位置、加逗号 | 主体/动作/对象/结果/方向/顺序不变；无新增内容 | 句式改写是否等价 | 原句 |

#### `bg/1` 背景穿插

- **可以**：引用一个 `场景` 原子或 `地点` 名；把两三个 `场景` 原子并置成名词短语，**每个原子都要有依据**；放在段首、两个事实块之间、句首状语位置；用方位词描述**场景原子本身**（`浓雾里`）。`可见` 物件只有在 `场景` 里也出现时才算背景原子（如 v05 的 `塔顶铜灯已点亮`）；不能拿它做锚点（`铜灯下`）。
- **不可以**：加人物；加谓词/事件；把“可见的物件”变成人物的位置（`沈砚在铜灯下`）；写状态变化（`灯灭了`）；写持续时间（`还没散`、`一直`、`仍然`）；写因果/目的；写新的感官细节（`雨声`、`铜油味`）；添加人物看见/感到/受影响；把起点的天气套到终点。
- **`着`/`里` 不是自动放行**：`着` 可能改变状态表达（`棚下散着光` 进复核），`里` 可能建立位置关系（`浓雾里` 只在雾属于当前场景、且只作框架时通过；`天窗外` 不行）。
- **落点**：段首独立短句（`棚下散着光。`）；第一句的句首状语（`浓雾里，沈砚……`）；两个事实块之间（句界）；段尾独立短句。不能插进一条事实的主谓之间，不能跨关系端点，不能把同一条事实拆成两半。有“随后”的连接句，背景只能放在“随后”之前或整句之后，不能插在“随后，”和姓名之间（否则 `conn/1` 的“姓名开头”就不成立）。
- **用量**：同一个原子本轮最多用一次；不靠重复背景凑字数。
- **回退**：不放背景。不要用另一个编造的背景替代。

#### `coord/1` 跨主体并列

- **可以**：相邻两条异主体事实，用 `，` 或 `；` 并成一句；两条的主体都写出来；`也/都` 只能在两个原有断言的主体、对象、否定、模态、取值都保持时用，不能仅凭谓语字面相同。人物-人物（`阿棠…，沈砚…`）和物件-物件（`灯罩蒙了灰，铁链生了锈`）都算；物件不用“它”代替。
- **不可以**：任何时间/顺序词（`随后`、`然后`、`接着`、`之后`、`片刻后`、`不久`、`过了一会儿`；`随后` 只能由 `conn/1` 加，不能重复/移动）；`同时`、`与此同时`、`一边……一边`、`各忙各的`、`这时`；省掉第二个主体；人物-物件混合并列（容易暗含关系，本轮进复核，复核不通过就拒绝）；把关系端点并进来；改事实顺序；换谓语/结果；加新动作。
- **它断言什么**：两件事都成立。它**不**断言两件事同时发生。读者可以自己推断，但文本没有写时间关系。
- **范围**：本轮只定义**两条**的并列；三条以上先按相邻两两组合，不新增“三合一”操作。逗号/分号都允许，区别只是停顿强弱，不表示时间关系。
- **块级**：如果规则层已经把相邻同主体事实合成一个块，`coord/1` 按“块”处理：两个相邻块、主体不同、各自块内顺序不变；块内的多件事不拆开。
- **机械检查**：相邻、异主体、两个主体名都在、无禁用连接词、非端点、事实覆盖和顺序不变。
- **`也/都` 的检查**：逐项对齐两个原有断言的主体、对象、否定、模态、取值；任一项变了就 `review`/`reject`，不能因为谓语字面相同就放行。`都` 的范围只能是句中明确列出的对象，不能扩大成全场人物。v05 通过，是因为两句的主体（叶知微的袖口／沈砚的手背）、对象（铜油）、否定（无）、模态（无）、取值（沾了）都保持。
- **质量观察（不改变合法性）**：并列后读者是否读成同时，交给人/判分器做连贯性评分；它不影响 `coord/1` 的 `pass`，因为文本本身没有写“同时”。

#### `ref/1` 指代替换/补主语

- **可以**：`他/她`；同一段里同性别/同数人物唯一，且是紧邻的前一个主语；不是关系端点。
- **可以补零主语**：规则合句时省掉的主语，在重新断句后需要补回来（t01 的“他合上簿子”）；只能用 `他/她`，且满足唯一指代条件。
- **不可以**：`它`（物件指代容易歧义）；换姓氏/头衔/职业称谓；多人段落里用代词；关系端点的后一句用代词（`conn/1` 要求姓名开头）；跨段指代。
- **机械检查**：段落内人物姓名计数；紧邻主语；端点标记。没有性别字段时，只按“同段只有一个人”放行；多人一律 `review`。
- **复核**：实际指代。中文零主语很常见，检查器只能数名字，不能证明读者一定指对人。
- **回退**：保留姓名；或保持零主语。

t01 的“他”能用，是因为全段只有沈砚一个人；t19/v05 有两个人物，目标稿里两处都保留了姓名，没有用代词。这就是规则的直接体现。

#### `seg/1` 断句

- **可以**：把一句拆成两句；把规则合过的同主体块重新分开；改逗号/分号/句号。只做句子层面。
- **不可以**：改变事实顺序；把关系端点拆开或并进去；把一条事实的内容分到两个不相邻的位置；借断句之名加词；新起一句时留下无主语残句（需要补主语就走 `ref/1`，用姓名或唯一代词）。
- **段落划分不在本轮**：5 例都是单段，旧规划器 0/20 使用；不把段落划分混进 `seg/1`。
- **判定**：机械判定只看标点/句界；节奏好坏是质量观察，不改变 `pass`。
- **说明**：同主体合句是规则层的活；模型不需要再“选”一次合句。模型可以做的是**反过来**：规则合过的块，如果读起来太长，可以重新断句。t01 就是把 `补全／沾墨／合上推` 三句同主体事实从一句里分开，后两句用分号隔开。

#### `recast/1` 单事实内局部改写

- **可以**：`把簿子合上` → `合上簿子`；加逗号；把一条事实内部的两个动作按原顺序分开写；同主语零指代。
- **不可以**：跨事实移动内容；改主体/对象/结果/方向；加新动作；改肯定/否定；改数量；改时态/体貌（`沾了` 不改成 `沾着`）；改事实顺序。
- **和“事实重排”的分界**：`recast/1` 只动**一条事实内部**的词序/句式；`x-reorder/1` 动**多条事实之间**的顺序。t01 的“他合上簿子，推到桌角”属于前者；t19 的“按人物归并”属于后者。

### 3.3 纠错层（独立职责，不计组织收益）

| ID | 操作 | 前置 | 允许 | 禁止 | 计数 |
| --- | --- | --- | --- | --- | --- |
| `corr-dedup/1` | 去重复 | u240 连续复述同一短语/同一事实 | 删掉重复的一次 | 删掉不同事实；把两条事实合成一条 | 纠错 1 次 |
| `corr-drop/1` | 删加料 | 片段不在事实/授权背景里，是 u240 自己续写的 | 删掉该片段 | 换成另一个编造片段；删掉事实本身 | 纠错 1 次 |
| `corr-fix/1` | 修病句 | 重复字、打结句、明显语法错 | 最小改写，保住事实 | 改事实内容；借修病句加内容 | 纠错 1 次 |

纠错层可以先用规则/检查器做，也可以单独用一个小模型；本轮只定职责，不定实现。关键是：**纠错片段在账本里必须是 `corr-*`，不能记成 `bg/coord/ref/seg/recast`。**

### 3.4 超出 v2（本轮禁止）

| ID | 操作 | 例子 | 为什么不行 | 以后怎么开 |
| --- | --- | --- | --- | --- |
| `x-reorder/1` | 事实重排 | t19 按人物归并：阿棠 f0+f2，沈砚 f1+f3 | 改变事实顺序；需要新的顺序授权和“不增加因果/时间断言”的检查 | 单独变量，先定“叙述顺序 vs 事件顺序”的许可 |
| `x-time/1` | 未授权时间/顺序 | `然后`、`接着`、`之后`、`片刻后`、`不久` | 增加事实没有的时间关系；`conn/1` 只允许已授权的“随后” | 需要时间证据/关系授权 |
| `x-simul/1` | 同时/并行 | v02 的“两人各忙各的”；`与此同时`、`一边……一边` | 增加时间/行为断言，事实里没有 | 需要时间证据或明确的小说化许可 |
| `x-pobj/1` | 人物-物件位置 | t01 的“沈砚在铜灯下” | `可见` 只授权存在，不授权位置 | 需要 `相对位置` 事实/关系 |
| `x-bgexp/1` | 背景扩写/时间状态 | t01 的“小雨落在天窗外”；v02 的“还没散” | 把原子扩写成新事件/状态；不是完整授权描述 | 世界记录增加完整描述字段，或单独许可 |
| `x-causal/1` | 因果/目的 | `为了`、`因为`、`于是`、`好让` | 增加因果/目的关系 | 需要因果事实或明确许可 |
| `x-new/1` | 新实体/新感官/新事件 | 新人物、新物件、新气味、新动作 | v1 已禁止；v2 不放 | 不放开 |

关于 `x-reorder/1`：按人物归并本身**不一定**篡改事实（t19 的替代写法就是按人物归并，事实内容没变）。本轮不放开，不是把它判成错，而是因为当前契约把事实顺序当硬约束；要放开，必须先定义“叙述顺序”和“事件顺序”的区分、允许哪些重排、以及如何防止重排顺带加上因果/时间断言。这是一项单独的权限，不在 v2 里偷开。

## 4. 判定：pass / review / reject

### 4.1 三档

| 档 | 含义 | 处理 |
| --- | --- | --- |
| `pass` | 机械条件都满足 | 可进入组织收益统计 |
| `review` | 机械条件满足，但有一处无法机械证明（指代、局部改写、`着`/`里` 的完整表达、`也/都` 的主体/对象/否定/模态/取值/范围、语义重复） | **不算通过**；需要人或判分器复核；复核通过后才计入 |
| `reject` | 硬违规：事实缺失/改写/重排、端点被合并、未授权关系、人物-物件位置、同时/因果/目的、背景扩写、新实体 | 回退到上一个合法版本 |

### 4.2 机械能查什么，不能查什么

**能查：**

- 实体白名单：新人物/地点/物件名；`他/她` 不算新实体，但必须过 `ref/1`；
- 事实覆盖与顺序：factId 是否都在、顺序是否变；
- 关系端点：是否被合句/并列/重断句跨过；
- 关系授权：`verdict`、校验器版本、方向、相邻；
- 背景原子：引用的原子必须属于本回合地点；名词短语的每个原子是否都在场景里；内容词是否都在引用的原子内；是否出现人物姓名/代词；
- 禁用词：`同时`、`与此同时`、`各忙各的`、`为了`、`因为`、`于是` 等；
- 数字/时长；
- `也/都` 的两个原有断言能否逐项对齐主体、对象、否定、模态、取值；`都` 的范围是否只含明确列出的对象；
- 账本结构：每个组织片段是否注明原文、新文、操作类型，并引用 factId/原子 ID/关系 ID。

**不能查：**

- “小雨落在天窗外”是不是一个合理的天气描写（它可能是，但当前授权没有这句话）；
- “他”到底指谁（只能数名字，不能证明读者理解）；
- “把簿子合上”改成“合上簿子”是否完全等价（需要事实对齐/人工）；
- 一条事实只写了“合上簿子”，不能从它推出“推到桌角”；每个动作/对象都要对回 fact 原文，不能靠常识补全；
- “也/都”是不是过度断言、范围是否自然；
- “着”/“里”的完整表达是否真的没有改变状态或位置关系；
- 同义改写是否等价、有没有隐含关系；
- 段落是否真的更顺、背景落点是否真的好；
- 跨主体并列有没有被读成同时（质量观察，不是合法性判定）。

所以：**`pass` 只表示“这些规则没发现问题”，不表示“事实和表达已经核验”。** 账本是**待核对声明**，不是正确性证明；指代、同义改写和隐含关系仍要人工复核。

### 4.3 账本要求

每个组织片段至少要能回答：

```
这段用了哪个操作？
原文是什么？新文是什么？
引用了哪些 factId？
引用了哪些背景原子/地点/可见物件？
引用了哪条关系授权？
它是组织还是纠错？
机械判定是 pass / review / reject？
```

没有账本，就不能把这段算成组织收益；也不能在事后把纠错说成“组织模型删得好”。账本只记录模型声明了什么，程序核对引用、顺序、端点和文本变化；声明不等于证明。

## 5. 5 例逐段归类

下面的归类不是给目标稿打分：它回答的是“这段改善能不能追到授权来源、能不能归到组织操作”。目标稿按“人写得好”的标准写，v2 按“可授权、可归因”的标准收口；两者不冲突，但前者不能直接当训练目标。

材料来自 [`manual-reachability-5.md`](manual-reachability-5.md)。下面按“操作点”归类，不按字数；一个片段可以包含多个操作点。

### 5.1 t01（沈砚三条，同主体）

A：

> 沈砚把潮汐簿缺的那页补全，指尖沾了墨，把簿子合上推到桌角。

目标：

> 小雨落在天窗外。沈砚在铜灯下把潮汐簿缺的那页补全，指尖沾了墨；他合上簿子，推到桌角。

| 片段（A → 目标） | 操作 | 类别 | 授权来源 | 判定 | 处理 |
| --- | --- | --- | --- | --- | --- |
| `（无）→ 小雨落在天窗外。` | `bg/1` | **超出 v2（背景扩写）** | 场景=`小雨`；可见=`天窗` | 内容词“落/外”不在授权原子；不是完整描述 | 删除；若要保留，世界记录需有整句 |
| `补全 → 在铜灯下补全` | `x-pobj/1` | **超出 v2（人物-物件位置）** | 可见=`铜灯`；场景=`铜灯` | 可见只授权存在；场景里的 `铜灯` 也不是位置事实 | 删除“在铜灯下” |
| `，把簿子合上 → ；他合上簿子` | `seg/1` + `ref/1` + `recast/1` | **组织（v2，复核）** | f1/f2 同主体；全段仅沈砚 | 分号只改标点；“他”唯一指代；同一事实内改句式；对象/动作/结果/顺序未变 | 保留；指代/改写进复核 |

补充两点：

- “推到桌角”在本例里**有来源**：f2 原文就是“把簿子合上推到桌角”。如果原文只到“合上”，这句就要判 `x-new/1`。这正是“机械校验只能部分”的原因：检查器不能从“合上”推出“推到”，必须逐段对回 fact 原文。
- t01 的 v2 收益是**局部衔接**（分号、代词、单事实内改写），不是背景。两段背景都越界；删掉后剩下的文本仍然是一个合法的局部衔接目标。

### 5.2 v02（阿棠／顾行舟，跨主体）

A：

> 阿棠把银鳞鱼按大小分开装进鱼筐。顾行舟把抹布拧干，手背上沾了鱼鳞。

目标：

> 清晨的薄雾还没散，棚下散着光。阿棠把银鳞鱼按大小分开，装进鱼筐。顾行舟把抹布拧干，手背上沾了鱼鳞。

| 片段（A → 目标） | 操作 | 类别 | 授权来源 | 判定 | 处理 |
| --- | --- | --- | --- | --- | --- |
| `（无）→ 清晨的薄雾` | `bg/1` | **组织（v2）** | 场景=`清晨`、`薄雾` | 两个原子都在场景里；已确认允许名词短语 | 保留 |
| `（无）→ 还没散` | `x-bgexp/1` | **超出 v2（时间状态）** | 无 | 场景原子没有“持续到现在”的状态 | 删除 |
| `（无）→ 棚下散着光` | `bg/1` | **组织（v2，复核）** | 场景=`棚下散光` | 完整原子，但“着”是状态表达 | 保留；复核 |
| `按大小分开装进鱼筐 → 按大小分开，装进鱼筐` | `seg/1` | **组织（v2）** | f0 | 只加逗号；事实不变 | 保留 |

补充：

- 目标稿**没有**把阿棠和顾行舟并成一句，也没有写“各忙各的”。它只是补了背景、加了一个停顿。按 v2，其实可以把 f0/f1 用逗号或分号并列（t19 的写法），不需要“同时”，也不需要“各忙各的”；那会是另一处 `coord/1` 收益。本文不替它写新目标，只指出这条权限已经打开。真正写“两人各忙各的”才是 `x-simul/1`，本轮不做。这也说明第 5.6 节的“12 个操作点”是**现有目标里已经用到的**，不是 v2 的全部潜力。
- 已确认：名词短语允许，不要求一个原子一句；“清晨”和“薄雾”都在场景里，所以“清晨的薄雾”通过。“棚下散着光”进复核，因为“着”是状态表达；这不是按词表豁免，而是看完整表达。

### 5.3 t19（阿棠→沈砚→阿棠→沈砚，跨主体交替）

A：

> 阿棠的袖口沾了鱼鳞。沈砚的外袍下摆沾了泥水。阿棠把银鳞鱼装进鱼筐。沈砚把油纸伞收拢靠在摊棚边。

目标：

> 清晨的薄雾里，棚下散着光。阿棠的袖口沾了鱼鳞，沈砚的外袍下摆沾了泥水。阿棠把银鳞鱼装进鱼筐；沈砚把油纸伞收拢靠在摊棚边。

| 片段（A → 目标） | 操作 | 类别 | 授权来源 | 判定 | 处理 |
| --- | --- | --- | --- | --- | --- |
| `（无）→ 清晨的薄雾里` | `bg/1` | **组织（v2）** | 场景=`清晨`、`薄雾` | 两个原子都在场景里；“里”只作当前场景框架 | 保留 |
| `（无）→ 棚下散着光` | `bg/1` | **组织（v2，复核）** | 场景=`棚下散光` | 完整原子，但“着”是状态表达 | 保留；复核 |
| `阿棠…鱼鳞。沈砚…泥水。→ 阿棠…鱼鳞，沈砚…泥水。` | `coord/1` | **组织（v2，新权限）** | f0/f1 | 相邻、异主体、姓名都在、无时间/因果/目的 | 保留 |
| `阿棠…鱼筐。沈砚…摊棚边。→ 阿棠…鱼筐；沈砚…摊棚边。` | `coord/1` | **组织（v2，新权限）** | f2/f3 | 同上；分号 | 保留 |
| `（未采用）按人物归并` | `x-reorder/1` | **超出 v2（事实重排）** | — | 会改变事实顺序；目标稿没有采用 | 留作后续变量 |

这是 5 例里唯一一份**既没有纠错片段、也没有硬违规、只带一处“着”的状态复核**的目标稿：

- 两处 `coord/1` 都保留了姓名、顺序和事实内容；
- 没有写“同时”“各忙各的”；
- 没有把两条事实按人物重排；
- 背景只用了授权场景。

它也是下一项模型任务最好的种子例：读者能看出“两个人各做了两件事”，但文本没有增加任何时间断言。

### 5.4 v05（叶知微／沈砚，铜油与灯罩）

A：

> 叶知微的袖口沾了铜油。沈砚的手背上沾了铜油。叶知微把灯罩擦得透亮，玻璃上不再有雾。塔顶的灯还亮着，什么也没有再发生。

目标：

> 叶知微的袖口沾了铜油，沈砚的手背上也沾了铜油。叶知微把灯罩擦得透亮。塔顶的灯还亮着，什么也没有再发生。

| 片段（A → 目标） | 操作 | 类别 | 授权来源 | 判定 | 处理 |
| --- | --- | --- | --- | --- | --- |
| `叶知微…铜油。沈砚…铜油。→ 叶知微…铜油，沈砚…也沾了铜油。` | `coord/1` | **组织（v2）** | f0/f1 | 相邻、异主体、姓名都在；两句的主体/对象/否定/模态/取值都保持，`也` 的范围只含这两个明确对象 | 保留 |
| `叶知微把灯罩擦得透亮，玻璃上不再有雾。→ 叶知微把灯罩擦得透亮。` | `corr-drop/1` | **纠错（删加料）** | f2 只到“透亮” | “玻璃上不再有雾”不在事实里 | 删除；不计组织收益 |

补充：

- 这一例最能说明“纠错不能冒充组织收益”：目标稿读起来更顺，一半功劳是删掉了 u240 的加料。如果把它算成组织模型的成绩，就会高估 `coord/1`。`也` 不是仅凭谓语字面相同放行：主体、对象、否定、模态、取值都要保持，范围只含这两个明确对象。
- 先做纠错、再做组织，组织模型看到的输入已经是“叶知微把灯罩擦得透亮。”，它只需要决定要不要和前面并列；不需要也不应该负责删“玻璃上不再有雾”。

目标：

补充：

| 例 | 新 v2 组织操作点 | 其中需复核 | 纠错 | 超出 v2 | 原目标稿是否 v2 合规 |

## 7. 下一项模型任务（本轮不训练）

### 7.1 任务形状

不是“规划器先出 JSON、程序装配”。旧规划器试验已经证明：模型一次都没用背景白名单，还反复把关系端点并进同句；再重试同一提示词没有意义。

v2 的任务是**带账本的组织改写**：

```
输入：
  A1（人工纠错后的稿件，只做纠错、不润色），经规则层合并/连接后的文本
  （factId、主体、文本、种类、端点标记）
  权威事实（factId、主体、种类、内容）
  授权背景原子（场景/地点/可见，带 ID）
  授权关系（before，verdict=pass）
  人物名册

输出：
  一段正文
  逐片段操作账本（原文、新文、op、factId、原子ID、关系ID、类别）
```

A1 是人工纠错条件，不是模型纠错层。账本可以由模型输出，也可以由程序对齐生成；本轮只定契约，不定实现。关键是每个组织片段都能追到来源；账本是待核对声明，不是正确性证明。

### 7.2 模型真正可以选什么

- 用哪些背景原子/允许的名词短语、放在段首/句首/段尾；`着`/`里` 的完整表达；
- 同主体块要不要重新断句（规则已经合过的，可以拆）；
- 重复姓名要不要换成“他/她”，或把重新断句后缺掉的零主语补成“他/她”；
- 相邻异主体事实要不要并列（人物-人物或物件-物件），用逗号还是分号，要不要加“也/都”；用“也/都”时逐项保持两个原有断言，`都` 的范围只含明确列出的对象；
- 一条事实内部要不要改句式（“把”字句、停顿）。

### 7.3 模型不能选什么

- 事实顺序（`x-reorder/1`）；
- 新人物/物件/动作/感官/事件（`x-new/1`）；
- 未授权时间/顺序（`x-time/1`）；只有 `conn/1` 的“随后”可以；
- “同时”“各忙各的”（`x-simul/1`）；
- 人物在具体物件下/旁（`x-pobj/1`）；
- 背景扩写/持续时间（`x-bgexp/1`）；没有完整描述就不写带谓词的背景；不能把起点天气套到终点；不能添加人物看见/感到/受影响；
- 因果/目的（`x-causal/1`）；
- 关系端点的句界和方向（`endpoint/1`、`conn/1`）。

### 7.4 对照与验收

| 臂 | 内容 |
| --- | --- |
| A0（现状） | 原始 u240＋`edit-layer/2`＋`relation-edit/1`：同主体合句＋授权“随后”；无背景、无跨主体、无指代、无重断句 |
| A1（纠错基线） | **人工纠错**后＋规则层；只去掉 u240 的重复/加料/病句，不润色，也不做 v2 组织 |
| B（v2） | 模型根据 A1、权威事实和授权背景做组织改写；规则层＋`bg/1`、`coord/1`、`ref/1`、`seg/1`、`recast/1` |

比较方式：**纠错收益看 A1 vs A0；组织收益看 B vs A1。** 不把 B 相对 A0 的总改善全算成组织收益。A1 是人工纠错条件；B 通过只证明组织能力，不代表自动端到端 workflow 已经解决质量问题。

验收分四栏，不混算：

1. **事实保真**（硬）：事实覆盖、顺序、主体、方向、结果；一条错就失败。
2. **操作合法**（硬）：每个组织片段有账本、引用的原子/关系有效、没有 `x-*`；程序核对引用、顺序、关系端点和文本变化。指代、同义改写及隐含关系仍人工复核。
3. **组织收益**（人/判分器）：先检查新增语义违规，再评价连贯性；分别记“明显改善、略有改善、持平、变差”。`review` 不算通过。用 1–5 分盲比 B vs A1，字数/句数不单独算收益；背景落点、并列顺畅、指代清楚分开记。
4. **纠错计数**（独立）：去重/删加料/修病句各多少次；不折算成组织收益。

不要求同一轮同时出现 `bg/1` 和 `ref/1`；操作出现次数不是收益。背景可能多余，指代也可能比保留姓名更差；每个操作单独评估。没有合适背景的源允许不动，不临时补背景。

20 源（含这 5 例）是第一轮**开发对照**，不是新确认集；通过后再考虑新确认集与小模型训练。**本轮不训练、不改 u240、不接服务、不加其他实验变量。**

### 7.5 为什么这比“再选合句”有实质内容

- 同主体合句已经由规则做完，5 例里没有一处收益来自它；再让模型选一次，只是复现规则。
- 背景落点、局部衔接、跨主体并列在 5 例材料里有 12 个新操作点；20 源对照会覆盖更多重复/加料样本。旧规划器一次都没用背景，说明“给了白名单不等于模型会选”。
- v2 把这三类操作明确写进任务，模型才有选择空间；同时用账本把“纠错”和“越界”挡在组织收益之外，避免再次出现“在几乎没有选择空间的情况下要求模型产生规则之外的收益”。

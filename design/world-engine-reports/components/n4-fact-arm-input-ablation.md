# 单事实臂输入消融 A/B（2026-11-04）

问题：场景里无关人物的信息，是否在干扰“谁做了什么”。用冻结检查点 `ckpt-fact`，不训练。

## 1. 先纠正一个前提

**单事实臂的输入里没有人“人物”块。** 它的输入是：

```
短句任务。
地点=… / 地点可见=… / 场景=… / 视角=<视角人物>；第三人称
事实=<事实行>
要求：…
```

整段臂的“人物”块（性格／外貌／随身）只出现在叙事任务输入里。单事实臂唯一携带无关人物的字段是 `视角=<名字>`。

所以按本意做的消融是：**把 `视角=` 行里的名字去掉，只留“第三人称”**，其余字段、顺序、内容一字不动。

## 2. 输入差异

| 项 | 值 |
| --- | --- |
| 改动单元 | 85 / 85（每个单元只有 `视角` 一行变化） |
| 改动内容 | `视角=沈砚；第三人称` → `视角=第三人称` |
| 逐行校验 | 除 `视角` 行外，每个单元与 A 完全相同（脚本内断言） |
| 场景／可见物／事实／要求 | 未变 |
| 对话对象、物件所有者 | 不在 `视角` 行，未受影响 |
| 冻结 | `n4-cf24-ablation-B.json`，sha `4b5a2b1f0154674d` |

**注意**：对当前模型，B 是输入分布变化——训练时 `视角` 行一直带名字。

## 3. 生成

同一检查点，贪心、EOS、每源 20 秒总预算、按事实顺序拼接、不筛候选。24 源全部完成。输出 `n4-cf24v2-factB.json`。

A 与 B 逐字相同只有 3/24；说明这一行确实影响了输出。

## 4. 逐源人工复核（85 条事实）

| | A（原输入） | B（去名） |
| --- | --- | --- |
| 事实支持 | 80/85 = 94.1% | **81/85 = 95.3%** |
| 遗漏 | 2 | 3 |
| 矛盾 | 1 | 1 |
| **归属错** | **2** | **0** |
| 有未经支持新增内容的源 | 4 | 4 |
| 完整源干净 | 16/24 | **17/24** |

**串人的地方是否修好**：`t08` 两处都修好了——A 把顾行舟的绕缆绳和外袍都写给阿棠，B 输出“顾行舟把缆绳绕上摊棚边的木桩……顾行舟的外袍下摆沾了泥水。”

**原本正确的事实是否变错**：`t14` 的移动事实变坏——B 写成“顾行舟把钟绳推开雾堤的木门”，没有表达“从潮渡到雾堤”。这是 2→3 条遗漏的来源。

**新增内容是否减少**：没有。A 有 4 个源带未支持内容（`t01`、`t12`、`t15`、`t23`），B 也是 4 个，但构成变了：`t23`（“在灯芯上结了锈”）修好，`t14`（“把钟绳推开木门”）新出现。

**完整源干净数**：16 → 17，`t08` 与 `t23` 转干净，`t14` 变脏。

## 5. 结论

- **归属错误 2 → 0**，两个修复点都落在 `t08`，与假设一致：`视角` 行里的无关人名确实会干扰“谁做了什么”。
- **整体保真没有退步**：支持 80 → 81，完整源干净 16 → 17。
- 但**不是净收益**：`t14` 的移动事实因为去掉视角名而变坏。这只是现象，机制未定——当时推测“这行承载了视角人物在场的信息”，后续确认集没有复现移动退化，该推测已撤回（见 `n4-ablation-confirm-result.md`）。
- 样本只有 24 源、单个检查点、单次运行，没有重复运行估波动。

按预设规则：归属减少、整体未退步 → 可以进入**新写、先冻标签的小确认集**；通过后再考虑把人物／视角筛选纳入流程。**本轮不下“可以上线”的结论**，也不继续微调删除名单（B 只删名字，没做别的裁剪）。

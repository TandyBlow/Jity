# 叙事正文判分器 v1（事实层自动，隐含层 abstain）

日期：2026-11-08（第二轮文本审查后修订）。对象：N4 叙事正文（「场景上下文 + 结构化事实 → 一段正文」）的离线判分器。范围：**不训练、不导 ONNX、不改页面**；本轮只交评测材料、判分器与误报/漏报报告。

本轮按第二审修订了 24 条标注中的 7 条，并把 `pass` 的语义写进代码返回值：**pass 只表示"现有自动规则没有发现问题"**，自然度、隐含事实、代词与身体感受都不在自动范围内，不能当作验收通过。

结论先说：这 132 条已审正文与 528 条合法变体**没有被误判成 fail**（另有 45 / 182 条 abstain，需要人看）；734 条单点负例里判出 **532** 条。对 24 条真实输出（对照修订后的标注）是：**0 误报、1 条严格漏报、8 条"人存疑、机器放行"、12 条 abstain、3 条一致**——也就是说自动判决只能挡住很小一部分坏文本。它不是验收器：事件捏造、语义搭配、空间矛盾、自然度、他人身体感受都不判。**判分器尚未通过人工复核，任何"模型合格"的结论都不能建立在它的分数上。**

## 1. 为什么先做材料再做代码

上一轮已确认评测草案要求「事实检查不依赖逐字匹配、自然度由人工核对」（`n4-training-plan.md` §4）。所以这一轮先把可判的和不可判的分开：

1. **可判**：人物归属、移动方向、明确禁述（任务目标/数值/时长/字段名）、他人内心、必述事实是否出现。
2. **不可判（abstain）**：隐含事实、代词指向、自然度、语义搭配。
3. **不能当负例的**：逐字不匹配。`n4-holdout-r1` 里 12 条模型输出有 8 条人工看确实错，但也有一条只是换了措辞；直接拿「逐字不同」当负例会把合法表达判死。

## 3. 判分器（`checker.py`）

输出 `verdict ∈ {pass, fail, uncertain}`，每条检查带 `rule`、`factId`、`span`（出错原文）、`evidence`。三类规则：

**全局禁述（fail）**：任务标语/taskId、数值面板与阿拉伯数字、明确时长、字段名。
——这里修过一次误报：`slot-arm:n4w-04` 的正文「他把铜铃挂到望雪台」与 goal 原文同形，但那是结果动作，不是泄漏。现在只有任务口吻或 taskId 才判。

**视角（fail/uncertain）**：他人姓名 + 内心词 → fail；只有代词 + 内心词 → uncertain。

**逐事实**：
- 移动：读「从X…」短语，X 归到地点（含小地点/缩写）；方向与事实相反 → fail；只写一端或场景本身在该地 → 视为允许省略。
- 结果：结果动作的内容词是否命中；本人有动作句时看归属；整段没有本人 → fail；分句主语是别人且本人没有同锚点分句 → `fact.attribution` fail。
- 外貌/个性：内容词命中 → pass，否则 uncertain（合法改写不判错）。
- 理智：只判方向；方向相反 → fail，无方向词 → uncertain。
- 无变化：出现变化措辞 → uncertain。
- 未知专名/器物：只归 uncertain（可能是普通陈设）。

不判的固定写在返回值的 `not_automated` 里：自然度、隐含事实、代词越界。

## 4. 误报 / 漏报（`eval-report.json`）

| 组 | 结果 |
| --- | --- |
| 正例 132 | **没有被误判 fail**；45 条 uncertain |
| 合法变体 528 | **0 误报**；182 条 uncertain（集中在"未知器物/地名"这类保守规则） |
| 单点负例 734 | 按预期规则判出 **532** |

分类型：

| 负例类型 | 判出 | uncertain | 漏 |
| --- | --- | --- | --- |
| 目标泄漏 | 55/55 | 0 | 0 |
| 数值面板 | 132/132 | 0 | 0 |
| 明确时长 | 132/132 | 0 | 0 |
| 他人内心 | 132/132 | 0 | 0 |
| 方向反转 | 28/29 | 1 | 0 |
| 删必述事实句 | 42/84 | 24 | 18 |
| 换动作句主语 | 11/38 | 23 | 4 |
| 未授权人名 | 0 | 132 | 0（按设计只归 uncertain） |

真实输出 24 条对照修订后的标注：

| 人工↓ / 机器→ | pass | uncertain | fail |
| --- | --- | --- | --- |
| pass（5） | 2 | 3 | 0 |
| uncertain（10） | 8 | 2 | 0 |
| fail（9） | 1 | 7 | 1 |

严格漏报 1 条（`zero-shot:n4w-05`：把「从客房里翻出旧地图」写成「把旧地图推向木床」）；"人存疑、机器放行" 8 条（世界无巷子/栈道、自然度、他人身体感受等，机器看不见）；人工判 fail 的 9 条里，机器只判出 1 条，其余 7 条 abstain。

**这张表说明**：零误报主要是靠"少判"换来的。判分器可以当"守门的下限"（它说 fail 基本可信），不能当"放行依据"（它说 pass 不代表没问题）。

**这些数字的含义**：判分器在"能不能判"的范围内是可靠的（零误报），在"判不了"的地方没有瞎判（abstain）；但漏报集中在三类——删除事实句、移动被省略后的归属、以及所有语义/事件层面的错。这三类不能靠加正则解决，得靠人工或更强的语义核对。

## 5.5 待人工裁决清单（这一轮请你复核的就是这些）

**A. 标注签字（上面 7 条）**：确认"世界设定没有的地点/器物 → uncertain""他人身体感受 → uncertain""人格事实主语不符 → fail"这三个口径，以及 n4w-10 的理由改写。

**B. 需要定政策的问题（决定这些能不能自动判）：**

1. **未授权地点/器物**（巷子、栈道、冰箱）：现在一律 uncertain。要改成 fail 吗？改成 fail 需要每个世界维护词表，并且会误伤"门/石墙/石阶"这类普通名词。
2. **他人身体感受**（心跳、体温、疼）：现在只有"姓名 + 内心词"判 fail，身体感受没有规则。要加吗？加了会误伤"他看见她发抖"这类合法观察。
3. **人格/外貌事实的主语绑定**：现在只查内容词命中，所以 n4w-07 那种"阿洛先开口"会被算成陆行 covered。要加主语绑定吗？加严会提高误报，需要你的口径。
4. **自然度**：保持"只登记不判"，还是要求机器给 uncertain 并计入 abstain？现在是后者。
5. **`pass` 的含义**：是否接受"pass = 自动规则未报警，不等于验收通过"写进验收口径，并要求人工签字的结论与自动判决分开存档？

**C. 复核方式**：由谁签（`annotations.jsonl` 的 `reviewStatus` / `reviewer` 字段）、是否要第二人抽检、抽检比例。

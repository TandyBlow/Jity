# 输入表达实验：把方向写进事实行

日期：2026-11-06。作业 241138，单卡 RTX 4090 D。**没有训练，没有改正式管线**。
原契约与原输入保持不变，新输入另立版本（`n4-explicit-r1.jsonl`，已进 pin，410 个文件）。

## 1. 两版输入怎么做的

同一批 12 条事实（6 条拥有者 + 6 条位置参照）各写两版：

- **原版**：沿用 `rolepair-r1` 的值——名称不在值里，关系没有落点（“压着的干纸滑开了”）。
- **显式版**：用自然语言写明方向——**哪个物件在哪个参照物处**，或**哪个部件属于哪个整体**；
  状态保留，不加动作、不加物件。

方向全部取自源事实：位置参照成员里“另一个物件”在前、名称在后；拥有者成员里“部件”在前、名称在后。
这两条在生成时用脚本断言过（`explicit.index(other) < explicit.index(name)`），不是事后按模型输出补写的。

所以本轮**不能**把结果归给“方向标记”单独一项。

## 2. 跑之前定的线

- 位置侧的方向错误降到 ≤1/6；
- 名称、另一物件、状态三样不比原版更差；
- 句法不比原版更差。

三条都满足，才谈“输入层值得推进”。

## 3. 结果

| 臂 | 原版通过 | 显式版通过 | 拥有者侧 | 位置侧 |
| --- | --- | --- | --- | --- |
| moved | 5/12 | 4/12 | 5/6 → 4/6 | 0/6 → 0/6 |
| ctl | 6/12 | 5/12 | **6/6 → 3/6** | 0/6 → 2/6 |
| mix | 9/12 | **5/12** | **6/6 → 3/6** | 3/6 → 2/6 |

逐项：

| 臂 | 侧 | 方向 | 名称缺 | 物件/部件缺 | 状态缺 | 句法破损 |
| --- | --- | --- | --- | --- | --- | --- |
| moved | 拥有者 原→显 | ok 5 → 5 | 0 → 0 | 1 → 1 | 0 → 1 | 0 → 1 |
| moved | 位置 原→显 | 反向 6 → 领属 5 + ok 1 | 0 → 0 | 0 → 1 | 0 → 0 | 0 → **5** |
| ctl | 拥有者 原→显 | ok 6 → 顶替 3 + ok 3 | 0 → 0 | 0 → **3** | 0 → 0 | 0 → 0 |
| ctl | 位置 原→显 | 缺名 4 + 反向 1 + ok 1 → **ok 6** | 4 → 0 | 0 → **3** | 0 → 1 | 1 → 1 |
| mix | 拥有者 原→显 | ok 6 → 顶替 3 + ok 3 | 0 → 0 | 0 → **3** | 0 → 0 | 0 → 0 |
| mix | 位置 原→显 | ok 5 + 领属 1 → ok 4 + 缺 1 + 领属 1 | 0 → 1 | 2 → 2 | 0 → 1 | 1 → **3** |

典型输出：

- moved `潮汐簿的缺页是潮汐簿的一部分。`——名称写了两次，状态“卷了边”丢了；
  moved 的位置侧五条写成 `潮汐簿的干纸压在潮汐簿上,滑开了`，名称被复制成领属者。
- ctl / mix `铜灯罩的一部分积了铜绿。`——**“罩口”被“一部分”顶掉了**；
  ctl 的 `潮汐簿上滑开了。`、`铜灯罩里的歪了。`——物件整段丢失。
- ctl 位置侧方向确实全对了（6/6 ok），但代价是 3 条丢物件、1 条丢状态。

## 4. 判定

三条事先定的线，**三个臂都没过**，而且失败点不同：

| 臂 | 方向 ≤1/6 | 三样不更差 | 句法不更差 | 结论 |
| --- | --- | --- | --- | --- |
| moved | 否（5/6 领属） | 否（状态 1、物件 1） | 否（0→5） | 不通过 |
| ctl | 是（0/6） | **否**（物件 3、状态 1） | 是 | 不通过 |
| mix | 否（2/6） | 否（名称 1、物件 2、状态 1） | 否（1→3） | 不通过 |

**结论：显式方向输入没有稳定减少错误。**唯一变好的一格是 ctl 的位置侧方向（缺名/反向 → 全对），
但它同时把物件丢了三条，属于拆东墙补西墙。

## 5. 拥有者侧被破坏了

这是本轮特意加进来检查的，结果是**明确的负面**：

- ctl 与 mix 原来拥有者侧 6/6，显式版掉到 3/6；
- 失败形态一致：把“X 是 Y 的一部分”读成“Y 的一部分”，**部件名词被“一部分”顶掉**
  （`铜灯罩的一部分积了铜绿`、`木桩的一部分,裂了一道缝`）。

也就是说，把“部件属于整体”写得越明白，模型越倾向于只留整体。这和上一轮 `t21:f0`
（“缺页”被“潮汐簿”顶掉）是同一类错误，只是这次被输入放大了。

## 6. 能力边界（按约定照实报告）

原本担心的是“只有把近乎完整的答案写进输入才有效”。实际结果**比这更差**：
输入已经把方向、两个名词、状态都写全了，模型仍然不能忠实复现——
它会复制名称造成重复、会把物件或部件换成“一部分”、会丢状态。

所以：

- 不能把这一版当成“输入层可行”的证据；
- 也不能说“模型只是缺信息”。缺的不是信息量，是**在给定两个名词与一个关系时稳定保住三个成分**的能力；
- 这一轮只检验了“整套输入表达”，长度与措辞同时变了，**不能**归因于方向标记这一项。

## 7. 边界与未验证

- 原版数据取自上一轮的归档输出（`eval-r7`），没有重跑；两轮都是 4090 D，但不同作业。
  这样比的是“同一臂、两种输入”，不是同一次运行内的并列。
- 每条一次贪心生成，没有重复采样。
- 三套评测集本轮没重跑，评分规则未改；正式管线未动。
- 判分脚本中途修过一个实现缺口：位置侧的状态原先没有真正检查（构建探针时
  `predicate` 误填成拥有者侧谓语），修好后重算，ctl 与 mix 各多出 1 条状态缺失。
  这是实现修正，不是判据变更，已在此记录。

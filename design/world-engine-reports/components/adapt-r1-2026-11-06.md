# 生产记录 → 展示事实：只读适配验证

日期：2026-11-06。只读回放，**不接产品、不训练、不新增契约字段、不放宽放行规则**。

## 0. 先修正两处结论

1. **“错误放行 0”只限上一批回放。**19.0% 改称“本轮放行率”，不是可靠率。
2. **无变化的矛盾补齐了。**上一版 8 条因范围缺失不出展示句，却有 56/56 模型句放行——
   模型句绕过了展示层的限制。这一版：无变化的记录没有范围字段时，**模型句也判“无法确认”**。
   → 放行从 257 降到 **201（14.9%）**，无法确认从 991 升到 **1047**，错误放行仍为 **0**。

## 1. 前态读取：沿 `previous_point_id`，不读最新状态

适配器只做一件事：拿当前点位 → 沿 `previous_point_id` 找前一点位 → 读**那一点**的检查点。
不开写、不读 `active_point_id` 当“前一回合”。

验证用的是一份按生产写入路径造出来的记录（见第 5 节）：

| 点位 | 做了什么 | 适配结果 |
| --- | --- | --- |
| p1 | 林川从走廊到门厅，理智 10→7 | `林川从走廊到门厅。`、`林川的理智下降（10→7）。`，来源 root_fx |
| p5 | 周宁理智 0→4 | `周宁的理智上升（0→4）。`——**0 被当作值读** |
| p4 | 空 Δ | `第4点没有实体变化。`，范围＝该点位 |
| p2 | 自己的检查点被删 | 缺口：`current checkpoint missing`，**不出任何事实句** |
| p3 | 前一点 p2 的检查点被删 | 缺口：`position change needs the predecessor state`，**不猜起点** |

**关键一条**：跑 p1 时，这个世界的最新点位是 p5（林川已回到走廊、理智 4）。
适配器给出的仍是“从走廊到门厅、10→7”——**读的是前驱，不是最新状态**。
这条写成了测试（`test_origin_comes_from_the_predecessor_not_the_head`）。

每个事实都带 `currentDigestMatchesPoint`：检查点里的状态摘要与该点位登记的摘要一致。
不一致会进缺口，不会当成事实。

## 2. 展示是否忠实

| 事实类型 | 句子 | 依据 |
| --- | --- | --- |
| 移动 | `林川从走廊到门厅。` | 前一点位的位置 + 当前点位的位置，**两侧都读过** |
| 理智 | `林川的理智下降（10→7）。` | 前一点位的数值 + 当前数值 |
| 外貌/性格 | `周宁：袖口沾了水。` | 只抄记录原文，注明 **不声称方向已验证** |
| 无变化 | `第4点没有实体变化。` | 该点位 Δ 为空，范围就是这一点位本身 |
| 任务 | — | 缺口：`task delta has no display shape yet` |

外貌与结果仍然只有原文，**没有方向**；移动和理智这次是拿两侧状态算出来的，不是从文本里读的。

## 3. 来源可追溯

每条事实附：

```
worldId, pointId, sequence, previousPointId,
currentCheckpointDigest, currentDigestMatchesPoint, previousDigestMatchesPoint,
branchLinkedFrom, entityId, fieldsRead, adapted
```

`fieldsRead` 列出真正读过的字段（例如 `['positionSet','previous.position']`），
`adapted` 说明这句是怎么来的（`origin read from root_fx` / `text copied verbatim` / `empty delta at this point`）。

## 4. 真实记录回放：结果很干净，也很空

本地真实库 `.local/world.db`：5 个世界、10 个已提交点位、78 条提交记录。

- **10 个点位的 Δ 全是空对象**；
- 适配结果：10 条 `第N点没有实体变化。`，**0 条缺口**，摘要全部对上；
- 也就是说：**真实记录里没有任何一条实体改动**，移动、理智、外貌的适配路径没有被真实记录走过。

这一点必须照实说：本轮的移动/理智/外貌句子，**全部来自按生产写入路径造出来的记录**，
不是玩家历史。造记录用的是生产 `apply_point` 与 `state_digest`，写出的摘要能被生产
`replay_state` 重放验证（p1…p5 全部通过），但它仍是夹具。

| | 上一版 | 本版 |

“正确句被拒”按你的口径拆开：

| 情况 | 条数 | 判读 |
| --- | --- | --- |
| 事实完整、无未授权内容 | **17**（只有地名或没有抵达） | **误拒** |
| 事实成立但追加了动作/物件 | **69** | **合理拦截**（`站住`、`船头/抵住`、`蹲到`、`扶着`、`抱着`） |

上一版把这两类混在一起算成 86，是错的口径。

## 7. 结论

- **前态读取成立**：沿 `previous_point_id` 取前驱检查点，最新状态没有被当成前态；
- **展示忠实**：移动和理智有两侧依据，外貌和结果只抄原文且不声称方向，范围不明就出缺口；
- **来源可追溯**：每条事实都能追到点位、前驱、实体、字段；
- **瓶颈仍在记录**：真实库里 10 个点位没有一条实体改动，方向字段仍然只存在于自由文本里。

## 8. 不声称的

- 不声称真实记录验证过移动/理智/外貌路径——那 5 条来自夹具；
- 不声称 14.9% 是产品放行率；
- 不声称“确认不符”里 69 条是模型写错——它们的事实成立，只是多说了内容；
- 不声称检查点摘要校验等于生产 `replay_state`：本轮只比对摘要字符串，**没有在适配器里重放整条链**。

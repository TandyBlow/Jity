# 只读预览的真实浏览器验收

日期：2026-11-06。只读，**不扩功能、不接模型、不训练**。

## 1. 先改的两处

### 1.1 报错分类的默认行为改成“缺口”

上一版把“不是 `LedgerMismatch`”或“不认识的消息”都归为 `unavailable`，那就等于默认允许检查点兜底。
现在反过来：

| 分类 | 判据 | 处理 |
| --- | --- | --- |
| `ledger` | 报错文本含 `differs from the committed digest` / `not a contiguous committed chain` / `did not reach the requested point` | 缺口，检查点被扣住 |
| `unavailable` | **白名单**：`Committed point has no round` | 允许用摘要一致的检查点 |
| `unknown` | **其余全部**，包括导入失败、任何没见过的消息 | 缺口，检查点被扣住 |

“未识别”不再默认放行。白名单只剩一条，写在代码里可查。

### 1.2 补了“失败优先于空 Δ”的夹具

`world_4/u3`：Δ 为空 `{}`、检查点已删、重放跑不起来（缺回合行）。
页面必须显示“该点位事实暂无法恢复”，**不能**显示“没有变化”。

### 1.3 页面补了旧请求保护

上一版连续切换没有防护：先发的请求后到，会把新选择的结果覆盖掉。
现在每个请求带序号 + `AbortController`；迟到的响应既不落地、也不清空更新的选择。

## 2. 浏览器验收怎么做的

- 真浏览器：Playwright + 本机 Chromium（headless），`frontend/scripts/preview-acceptance.mjs`；
- 页面：`next build` + `next start`，访问 `/world/preview`；
- 只读服务：脚本自己拉起 `preview_server.py`（夹具库），结束时用 `taskkill /T /F` 关掉并轮询确认端口已无响应；
- 每个用例截全页图，结果写进 `record.json`；共 12 张截图。

## 3. 逐项结果

| 用例 | 点位 | 页面显示 | 判定 |
| --- | --- | --- | --- |
| 正常变化 | `world_1/p1` | `林川从走廊到门厅。`、`林川的理智下降（10→7）。` | 句子随选择变化 |
| 空 Δ | `world_1/p4` | `第4点没有实体变化。` | 只在 Δ 为空时说“没有变化” |
| 任务未展示 | `world_1/p6` | **存在尚未展示的任务变化。** + “没有被当作没有变化” | 与空 Δ 分开 |
| 账目不一致（无检查点） | `world_1/p7` | **该点位事实暂无法恢复。** `replay found an inconsistency…` | 缺口 |
| 账目不一致（**检查点完好**） | `world_3/t2` | 同上，诊断区 `checkpointWithheld` | 兜底被拒绝 |
| 检查点兜底 | `world_4/u1` | `林川的理智下降（10→8）。`，诊断区 `"stateSource": "checkpoint"` | 重放不可用才走这条 |
| 不可恢复 | `world_4/u2` | **该点位事实暂无法恢复。** `state not recoverable` | 不猜 |
| 失败优先于空 Δ | `world_4/u3` | **该点位事实暂无法恢复。**（Δ 为空也照此） | 优先级正确 |

**快速连续切换**：连续切到 `p7 → p4 → p6 → p1 → p4`，最终显示 `第4点没有实体变化。`，与最后一次选择一致。

**慢请求不覆盖新选择**：把 `p1` 的响应人为延后 900 ms，选中 `p1` 后立刻切到 `p4`；
最终显示仍是 `p4`——迟到的 `p1` 结果被序号拦下。

**关闭预览服务**：杀掉服务后重新打开页面，显示 **“预览服务不可用：先启动 experiments/world-components/preview_server.py”**，
没有残留上一点位的句子，也没有出现“没有变化”。

**控制台**：只有一条 `net::ERR_CONNECTION_REFUSED`，就是关服务那一刻意料之中的失败请求。

## 4. 三臂方案（已建好池子，未训练）

| 臂 | 目标内容 | 改写行数 | 平均字数 |
| --- | --- | --- | --- |
| A 对照 | 池子原样 | 0 | 16.18 |
| B 保守 | 只修事实：补起点、补数量词、补限定词、去掉字段名；**所有尾句保留** | 55 | 16.62 |
| C 完整审计 | B 的修复 + 删除事实没有授权的尾句 | 106 | 14.13 |

为什么要有 B：上一轮把“修事实”和“删尾句”绑在一起做了，事后分不清哪一步带来什么。B 只修事实、保留尾句，
于是 A→B 的差可以归到“纠正事实冲突”，B→C 的差可以归到“在已修事实的基础上再删尾句”。

**B 不能声称隔离了长度。** 三个臂的平均字数是 16.18 / 16.62 / 14.13：B 比 A 还长，因为补起点和限定词本身就加字；
C 既修了事实又删了尾句。所以这套设计能分开“修事实”和“删尾句”，**分不开长度**。没有任何一臂为了对齐长度加过内容。

三条不变量（`three-arm-freeze.json` 里可查，脚本里是硬断言）：

- 三臂都是 341 行，单元 ID 顺序完全一致，`idOrder.sha256 = 09bf6b3f…`，采样器抽到的单元序列相同；
- 三臂目标序列不同，池子 bundle 哈希分别是 `48725e46…`（A）、`a528facb…`（B）、`da1062bb…`（C）；
- 起点权重固定为 u240（`ab8a9826…`），步数 240、batch 8、lr 3e-4、seed 20261102、mix 4:3:1 三臂相同。

## 5. 提交脚本（未运行）

`experiments/world-components/hpc_three_arm.sh`：

```
N4_MODEL_DIR=<u240 权重目录> bash experiments/world-components/hpc_three_arm.sh --dry-run   # 只打印
N4_MODEL_DIR=<u240 权重目录> bash experiments/world-components/hpc_three_arm.sh             # 真正训练
```

脚本做三件事：

1. **preflight**：重算起点权重 sha，重算 9 个池子文件的 sha 与行数，对照冻结记录；任何漂移直接退出。
2. **训练**：依次跑 A/B/C，参数完全一致，只有 `--pool` 指向的臂目录不同。
3. **采样自检**：训练后读三份 `train-report.json`，断言 `idSha256` 三臂相同、`targetSha256` 三臂互不相同。
   如果哪一天采样序列不一致，这一步会失败，而不是事后靠人眼发现。

dry-run 已在本机跑过：preflight 全部通过，三条命令正确，没有创建任何训练目录、没有加载模型。
评测不在这个脚本里：训练完在**同一设备**上对三个臂分别跑 cf24、final24、moved24，再各自做
overlap / score / review；moved24 单独报告。

## 6. 验收口径（先写死，训练后再看）

| 检查 | 通过条件 |
| --- | --- |
| 事实完整性（cf24、final24） | 不低于 A 臂；任何一条退化都要单独点名 |
| 修订效果 | B 优于 A 说明“纠正事实”有用；C 优于 B 说明“删尾句”在修好事实后再减少新增/复读 |
| moved24 | 单独报告，不与 final24 合并；只看移动单元有没有缺起点或加尾巴 |
| 长度 | 只记录，不当成功指标；三臂长度本来就不同 |
| 失败处理 | 若 C 仍掉事实，记录失败，不靠加步数或调参追分 |

能推翻当前解释的观测：如果 A、B、C 事实损失差不多，那原因更可能在“多训 240 步”而不是数据；
如果 B 明显好于 A，那“目标里的错误事实”就是主因；如果 C 明显差于 B，那“删尾句”本身有害。

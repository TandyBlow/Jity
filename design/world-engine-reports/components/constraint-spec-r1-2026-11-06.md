# 乙的规格：把“成分保持”做成可优化的损失

日期：2026-11-06。**本轮不训练**。这份文件只写规格：哪些错误进损失、惩罚怎么算、梯度从哪走、
两臂怎么对齐、怎么用消融确认收益来自约束本身。

先说命名规则，避免事后改名：

> 如果最终实现只是把同样的交叉熵用在重新编排过的行上，那么它叫**成组采样方案**，
> 不能叫“成分约束”。只有存在一个**对成分缺失/反向/替换直接给出惩罚的损失项**，
> 才有资格用“约束”这个词。

## 0. 现状与差距

现在的训练只有一条信号：

```
out = model(input_ids, labels=target_ids)
loss = out.loss          # 目标 token 的平均交叉熵
```

模型永远看着**正确的目标**做教师强制，所以它从来没有见过“少了名称”“关系写反”“状态没写”的
样子，也就没有哪一项梯度在专门压低这些形态。评分器里那套“名称在不在、关系方向对不对、
状态在不在”的检查，只在验收时跑，**不产生任何梯度**——按第 2 条要求，它不能算损失。

所以乙要加的东西只有两类：

1. **让错误形态进入前向**：构造该事实的“坏版本”，让模型对它算一遍概率；
2. **让正确版本相对坏版本占优**：用间隔（margin）损失把两者的概率差拉开。

## 1. 三个成分怎么对齐，哪些错误进惩罚

### 1.1 先给每条训练行建成分表

池子里现在只有 `signature`（`["moved","沈砚","潮生巷","旧灯塔"]`）和一句目标，没有位置信息。
第一步是在**建池时**给每行补一个 `components` 字段，逐个断言能在目标里找到：

```json
"components": {
  "name":     {"text": "沈砚",   "start": 0,  "end": 2},
  "other":    {"text": "旧灯塔", "start": 7,  "end": 10},
  "relation": null,
  "state":    {"text": "走进",   "start": 4,  "end": 6}
}
```

- `name`：事实主体的名字，必须出现且只按事实指定的那一个；
- `other`：另一方（移动的终点、拥有的整体、关系的参照物）；
- `relation`：只有关系类事实才有（缠/挂/系/套/盖/插/搭/卡…），值为关系词本身；
- `state`：谓语或状态短语（“断了”“滑开了”“走进”）。

断言规则（构建时跑，缺一条就报错，不静默跳过）：`target[start:end] == text`，且
`text` 在目标中出现次数 ≥1。找不到的行**不进实验池**，单独列出来。

### 1.2 错误分类与是否进惩罚

| 错误 | 例子 | 进惩罚？ |
| --- | --- | --- |
| 名称缺失 | `插着的灯芯歪了。`（缺“铜灯罩”） | 是（实体项） |
| 名称被替换 | `缺页的边缘毛糙。`（“潮汐簿”换成“缺页”） | 是（实体项） |
| 另一方缺失 | `缠着的旧缆绳断了。`（缺“木桩”） | 是（实体项） |
| 关系词缺失 | `木桩的旧缆绳断了。` | 是（关系项） |
| 关系方向反了 | `木桩靠在渡船上`（事实是“渡船靠在木桩上”） | 是（关系项） |
| 关系词被换 | 事实“系”写成“挂” | 是（关系项） |
| 状态缺失 | `排水沟里的泥。`（没有“积了”） | 是（状态项） |
| 状态被写成不变 | 理智 12→9 写成“那阵闷意没有散” | 是（状态项） |
| 方向字缺失（上/下） | 事实“下”，写成“走到” | **否**（记入统计，不进损失；这是措辞不是事实） |
| 多写一句（抵达后又做事） | `走到潮渡,船头抵住栈桥。` | **否**（另有追加门，不进损失） |
| 长度、语气、语序变化 | — | 否 |

不进的项要写进规格，否则一次改动会同时动太多东西，归因不清。

## 2. 惩罚怎么算，梯度经过哪里

### 2.1 两条损失项

**（甲）成分加权的 token 交叉熵**

对一条正确目标，把 `name`/`other`/`relation`/`state` 四个 span 内的 token 权重设为 `w=2`，
其余为 `1`，得到

```
L_span = − Σ_t w_t · log p(y_t | y_<t, x) / Σ_t w_t
```

梯度：经过输出层 logits 回到整个编码器-解码器（与现有交叉熵同一条路径），
只是把“哪几个 token 的误差更重要”改了。**它本身不惩罚缺失**——教师强制下缺失的形态
根本不在前向里出现；它的作用是让这些 token 更难被压低。

**（乙）成分定向的间隔损失（这是真正意义上的约束项）**

对每条正确目标 `y`，用规则从成分表生成三个坏版本：

| 坏版本 | 构造方式 | 检验的成分 |
| --- | --- | --- |
| `y_drop` | 删掉 `name`（或 `other`）那一段，其余不动 | 实体 |
| `y_rev` | 关系类：把关系方向反过来（用配对行的目标，或把“X 在 Y 上”改成“Y 在 X 上”）；非关系类：把关系位换成“的” | 关系方向 |
| `y_state` | 把 `state` 换成静态否定（“没有变化”）或删除 | 状态 |

对每个坏版本算**每 token 平均对数概率**

```
s(y) = (1/|y|) Σ_t log p(y_t | y_<t, x)
```

然后

```
L_margin = Σ_{c∈{drop,rev,state}} max(0, m − s(y) + s(y_c))
```

- 梯度同时经过 `y` 和 `y_c` 两条前向（两次前向、一次反传，或拼成一个 batch 一次前向）；
- 参数更新发生在共享的编码器-解码器上，**没有任何规则分支参与求导**；
- 坏版本由规则生成，规则只决定“看哪个错误”，不提供梯度。

**（丙）总损失**

```
L = L_ce + α · L_span + β · L_margin
```

初始值建议 `α=0.5`、`β=0.3`、`m=1.0`，并且**先跑一次只测损失量级的 dry run**（不更新参数），
确认 `α·L_span + β·L_margin` 不超过 `L_ce` 的 30%，否则等于换了任务。

### 2.2 长度偏差要写清楚

`s(y)` 除以了长度，所以“更短的坏句子”天然占便宜。两种归一化都要记录：

- 主口径：按 token 平均（上式）；
- 对照口径：按整句求和（`Σ log p`），此时短句更差、长句更容易被判好。

如果两种口径给出相反结论，就在报告里写“结论依赖归一化方式”，不挑一个好看的说。

## 3. 两臂怎么对齐

对齐三样东西：**事实曝光次数、目标 token 数、更新预算**。

记 `F` 为事实数（去掉测试集重叠后的训练事实），`k` 为每个事实的表达条数（本设计取 `k=4`）。

| 臂 | 数据 | 采样 | 损失 |
| --- | --- | --- | --- |
| **A1** 基线 | 每条事实 1 条表达 | 每步每事实抽 1 次 | `L_ce` |
| **A2** 同量样本 | 每条事实 k 条表达 | 每步每事实抽 1 条表达（轮转） | `L_ce` |
| **B** 约束臂 | 同 A2（同一批行、同一批 id） | 同 A2 | `L_ce + αL_span + βL_margin` |

- **事实曝光次数**：三臂都是每步每个事实恰好 1 次；`k` 只改变“用哪一条表达”，不改变事实出现频率。
- **目标 token 数**：按每步被抽中的行的目标 token 总数统计；如果 A2/B 的 k 条表达平均长度与 A1 相差
  超过 ±5%，按 `1/tokens` 给每条行加权，使每个事实贡献的 token 质量相同，并在报告里给实际数字。
- **更新预算**：优化器步数、batch 内事实数、lr、warmup 全部相同；`β>0` 会多一次前向（坏版本），
  这不算“更多更新”，但要单独记 GPU 时间。
- **损失归一化**：`L_ce` 和 `L_span` 按 token 平均；`L_margin` 按“坏版本条数”平均
  （每条事实 3 个），这样 `β` 的含义不随 `k` 变化。

## 4. 怎么证明收益来自约束

四臂消融，全部同种子、同预算、同评测：

| 对比 | 隔离出什么 | 判据 |
| --- | --- | --- |
| B vs A2 | **约束项本身**（数据、采样、预算全相同） | B 在留出集上至少高 8 个百分点，且新增事实损失为 0 |
| A2 vs A1 | 更多样本（k 条表达） | 若 A2 已达标，说明不需要约束项 |
| A1 vs 现状 | 采样编排本身 | 若 A1 与 A2 无差别，说明 k 条表达没有信息增益 |

**如果 B ≈ A2**：收益来自“每事实多条表达”，与间隔项无关——按第 0 节的命名规则，
这一支改叫**成组采样方案**，`L_margin` 撤掉，不在报告里称“成分约束”。

**如果 B ≈ A1**：约束项没有生效，先查三件事再谈效果：坏版本是否真的比正确版本得分高
（要在训练前测一次基线模型上的 `s(y) − s(y_c)` 分布，若已经 > m，损失恒为 0、没有梯度）、
`α/β` 是否让辅助项淹没主项、span 权重是否覆盖到实际被丢的 token。

**验收**：留出集必须是训练前冻结、且**没有参与任何探针或范例设计**的新事实
（12–16 条，实体对与场景都不在现有池子里）；三套回归集与现有探针只作回归；
三个预先指定的种子逐条报告损失清单，不取平均掩盖。

## 5. 现在能实现的部分 / 还缺的部分

**能直接实现的**（现有 `train_revision_arm.py` 加参数即可）：

- 读入带 `components` 的池子（需要先写建池脚本，断言 span 存在——见 1.1）；
- `L_span`：需要把 token 权重传进 `encode_training_batch`（当前只返回 `labels`）；
- `L_margin`：需要构造坏版本、多跑一次前向、加入总损失。

**还缺、必须补的**：

1. **成分表构建**：池子里现在没有 `components`，`signature` 不足以定位 span（例如“走进”属于
   state 还是 relation 需要按 `kind` 定规则）。没有这一步，`L_span` 和坏版本都无从谈起。
2. **坏版本的合法性与方向**：“方向反过来”对非关系类事实没有定义，需要按 `kind` 写死规则，
   并断言坏版本与正确版本**只差一个成分**（否则惩罚会落到别的东西上）。
3. **基线得分分布**：训练前必须测一次 `s(y) − s(y_c)`，确认间隔损失不是恒 0。
4. **曝光与 `k` 的取舍**：`k=4` 会让 341 行变成 1364 行，是否超出“同一批事实”的定义要在
   建池时说明；如果超了，就减小 `k` 或减少事实数，不能一边扩行数一边说“等预算”。

在这四项没补齐之前，乙停留在规格阶段，不与普通增补做比较。

## 6. 这一轮不做的

- 不训练、不评测、不改池子；
- 不把任何新配置提升为基线（种子重复那一轮的结论只到“对随机轨迹敏感”）；
- 不声称“成分约束有效”——它还没实现。

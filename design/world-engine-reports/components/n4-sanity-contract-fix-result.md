## 1. 契约修正

**字段顺序以训练序列化函数为准。** `write_verbalizer_corpus.py` 的输出是

```
事实=<名字>｜状态变化｜<放松|发紧>
```

我上一版文档写成 `状态变化｜<主体>｜<取值>`，顺序错了；我当时生成并跑的那批“规范输入”也按错的顺序写（`事实=状态变化｜沈砚｜发紧`）。本次全部改成正确顺序重跑，旧的错序结果保留在 `n4-sanity-{base,422,431}.json` 作为记录。

**“不保留幅度与数值”只限制 N4 的叙事输入投影**。引擎原始事实仍保留 `from/to`（如 12→9），权威状态数据不丢；只是不给模型看数值，也不要求正文写数值。

## 4. 判定

- **输入契约不一致确实是方向表达失败的主因**：三臂从 0–1/6 变成 6/6，且字段值泄露清零。
- **契约修复后 431 在两个固定诊断集上都最好**（cf24 85/85、干净 23；final24 76/76、干净 24），422 次之，基线最差；差距主要来自归属错与未支持新增，这两项与理智无关。
- **语法违规这一轴保留**：431 仍有 1 处重复“的”（`t21` / `v24`），422 有 2 处，基线 0。这说明 431 的“主体＋追加成分”模板有残留问题，但规模已经从“每个理智句都漏值词”降到“两个诊断集各 1 处”。
- **仍不能据此确定配比的因果作用**：三个检查点在理智上已无差异，本轮差异来自数据覆盖（归属、物件、移动），不是理智契约。

## 5. 默认版本的处理

按上一轮的预设，431 未通过“相对 422 无集中退化”那一关时只保留候选身份。契约修复后这一点需要重判：理智项已不再退化，剩余差异只有语法违规 1 处对 2 处。

本轮结论写成：**431 恢复为“待定候选”**，不自动晋升；422 作为质量较强的备选继续保留。是否切到 422 或 431，等语法违规这一轴单独评估之后再定——那是下一个决策点，本轮不训练、不调配比、不加表达变体。

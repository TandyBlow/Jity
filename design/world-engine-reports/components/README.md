## 目标与已确定边界

用户要求完整实现[原设计](../../browser-world-state-workflow.md)，先确定组件结构、哪些工作需要小模型及其候选。目标是每个模型几十M到几百M；组件职责可以先确定，具体权重在专项验证后定型。完整能力待办见[实施方向](../full-design-implementation-direction.md)。

- 程序继续负责时间、顺序、骰点、身份、确定性校验、应用、保存与恢复；Python是唯一状态计算权威。
- 模型承接行动、反应、结果、状态候选、继续判断和叙事等语义职责。任务拆小，不删减原功能，不把所有人物判断改成固定命令或规则效果。
- 多个任务可以共享同一编码器/生成骨干，不要求每个组件独占一份模型权重。
- 首批聚焦叙事：程序提取已提交事实 → 模型选择内容 → 模型组织表达 → 小生成模型成句 → 事实核对。保留选择、省略和视角要求，不以逐条复制固定短语作为最终目标。

## 首批交付顺序

1. **组件职责与接口表。** 为初始世界生成、行动、被迫反应、共同结果、六步变化、继续判断和叙事列出输入、输出、上下文范围、程序校验、失败处理及测试方式。明确哪些是分类/抽取/排序/回归，哪些必须生成自然语言。内部中间表示不自动扩展世界存档或服务协议。
2. **模型、训练与运行时方案表。** 每项必填具体候选、全参数量、任务头/共享方式、微调/蒸馏需求、隔离开发样本、中文能力依据，以及离线框架、导出图、量化、浏览器运行时、分词/生成循环与取消支持的结论。运行时选型是本项交付，不留成第3项开跑时才发现的问题。下载体积不是参数量，模型卡能力不代表本项目已达标。
3. **先离线的叙事拆分最小实验。** 用隔离开发样本分别验证内容选择、排序/指代及短文本成句，先在本机Python框架验证适用性，确认后再做浏览器适配。保存原始输入/输出、模型身份、各段及端到端耗时、错误和重试；离线与浏览器分别出报告，不能混报、拼接总耗时或把离线速度当浏览器结论。不抢先建立新判分门的正式留出集；不切换当前页面判分门。
4. **组件组合结论。** 给出保留/调整/训练的具体结论；对多次小推理重复输入、加载/切换和串行开销计总账，再交B接入其真实整链。不能只因为单个模型更小就宣称整体更快。

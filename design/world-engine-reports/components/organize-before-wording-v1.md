# 先组织事实、再成句：一页方案与三个实例（2026-11-06，未训练、未运行）

状态：只写方案与实例，不扩材料、不跑模型、不改服务。旧实验（整合器、规划器、P）的结论保留，不重跑。

**新假设：组织发生在成句之前，可能比对已经写好的短句再拼接，更容易兼顾连贯与保真。**

之前的整合器、规划器和 P 都接收 `u240` 写定的短句，只能在现成措辞上改写或装配；这次让组织模块直接读**权威事实**，输出带事实引用的表达计划，再由成句模块按计划写正文。成句模块允许重新措辞，不要求逐字拼接。

## 1. 交接内容与三个实例

### 1.1 计划形状（不含任何正文词句）

```
{
  "groups": [
    {"facts": ["f0","f1"], "link": "parallel"},
    {"facts": ["f2","f3"], "link": "parallel"}
  ],
  "refs":  {"f0": "name", "f1": "name", "f2": "name", "f3": "name"},
  "edges": []
}
```

- `groups`：按事实原顺序切分，**不重排**；一组＝一次连续表达。组内相邻事实的 `link` 只能取：
  - `continuation`：同一主体，下一句接着同一拍（动作→它的状态/结果，或同一拍的下一个动作）；
  - `parallel`：不同主体、同类事实、同一拍，并列而不加时间词。
- `refs`：每条的称呼形式，`name`／`omit`（承前省）／`pronoun`（仅当全源只有一个可指对象，由程序校验）。
- `edges`：只登记**已授权**的 `before`；没有授权就为空。
- 计划里没有动词、名词、标点、连接词，也没有背景片段。

成句模块的自由与边界：可自由改写措辞和句式；但每个 factId 必须出现一次、顺序不变；组内可以逗号或分号，组间至少分号；`parallel` 不得写成“同时／与此同时”；只有 `edges` 里的 `before` 可以写“随后”。

### 1.2 `t19`：跨主体组织（无授权关系）

事实（原顺序）：

```
f0 阿棠｜外观变化｜袖口沾了鱼鳞
f1 沈砚｜外观变化｜外袍下摆沾了泥水
f2 阿棠｜结果｜把银鳞鱼装进鱼筐
f3 沈砚｜结果｜把油纸伞收拢靠在摊棚边
```

计划：

```
groups: [f0,f1] parallel ／ [f2,f3] parallel
refs:   全为 name（两个人物，不能省成“他”）
edges:  []
```

预期正文（人工稿去掉背景句后的形式）：

> 阿棠的袖口沾了鱼鳞，沈砚的外袍下摆沾了泥水。阿棠把银鳞鱼装进鱼筐；沈砚把油纸伞收拢靠在摊棚边。

计划决定的是“两条外观同拍、两条动作同拍”，正文由成句模块写；第二组用逗号（`n4-edit12` 的人工版）或分号（目标稿）都合法，**标点不是计划的一部分**。

### 1.3 `t01`：同主体组织（无授权关系）

事实：

```
f0 沈砚｜结果｜把潮汐簿缺的那页补全
f1 沈砚｜外观变化｜指尖沾了墨
f2 沈砚｜结果｜把簿子合上推到桌角
```

计划：

```
groups: [f0,f1] continuation ／ [f2]
refs:   f0 name，f1 omit，f2 pronoun（全源只有沈砚一人，程序可校验）
edges:  []
```

预期正文（人工目标稿去掉“在铜灯下”）：

> 沈砚把潮汐簿缺的那页补全，指尖沾了墨；他合上簿子，推到桌角。

计划只说“f0 与 f1 同一拍、f2 另起”；“补全／沾墨／合上”这些词由成句模块自己写，计划里一个都没有。

### 1.4 `train-r1`：已有 `before` 的关系边界

事实：

```
f0 沈砚｜外观变化｜袖口沾了雨
f1 沈砚｜外观变化｜指节发白
f2 顾行舟｜外观变化｜斗篷下摆湿了一片
f3 叶知微｜外观变化｜鞋底沾了泥
f4 叶知微｜外观变化｜袖口湿到肘部
授权：before(f2 → f3)，相隔 1 秒，verdict=pass
```

计划：

```
groups: [f0,f1] continuation ／ [f2] ／ [f3,f4] continuation
refs:   name, omit, name, name, omit
edges:  before(f2 → f3)
```

预期正文：

> 沈砚的袖口沾了雨，指节发白。顾行舟的斗篷下摆湿了一片。叶知微的鞋底沾了泥，袖口湿到肘部。

关系边界被写成“f2 与 f3 不同组”，因此正文里两者不可能被逗号连起来；`f3` 以自己的姓名开头。授权允许在 `f3` 前加“随后，”，但不是必须——**计划只登记授权，不替成句模块决定要不要把关系说出来**。

## 2. 两个模块各学什么

| 模块 | 输入 | 输出 | 学的是 | 不学什么 |
| --- | --- | --- | --- | --- |
| 组织模块 | 有序事实（factId、kind、主体、事实文本）＋已授权关系＋视角 | 计划（groups／link／refs／edges） | 哪些事实共同表达、边界在哪、主体怎么衔接、称呼形式 | 不写正文，不选词，不决定标点，不加背景 |
| 成句模块 | 同一批事实＋计划＋视角 | 中文正文 | 把计划实现成完整句子：措辞、句式、组内标点、必要的承接 | 不改分组、不重排、不加事实或关系 |

**“计划不是提前写好的正文”的判据**（不靠感觉，靠两个方向的信息测试）：

1. 只给计划，写不出正文：计划里没有任何事实词句，只有 factId 和枚举；
2. 只给事实，也定不了分组：`t19` 的四条可以四句、两句或一句，`t01` 的三条可以两句或三句——分组信息只在计划里。

两条同时成立，职责才是分开的；任何一条不成立，就退回“改写”或“标点”实验，不算这次交接。

## 3. 与旧实验的区别

| 旧实验 | 它拿到的输入 | 它决定什么 | 这次的不同 |
| --- | --- | --- | --- |
| 整合器（`cohesion-split-pilot`） | `u240` 已写好的短句 | 整段改写 | 组织在成句**之前**；成句模块不从别人的措辞出发，不会被原句的断句和用词绑住 |
| 规划器（`planner-split-trial`） | 事实 | 段落、合句、省主语、背景、关系，一次全定 | 计划只定分组/衔接/称呼；背景不在范围内；关系只能引用已授权边；计划与正文分开评 |
| P（`p-boundary-run-v1`） | `u240` 已写好的短句 | 相邻边界的三档标点 | 这次决定的是**事实怎么成组**，标点交给成句模块；且允许重新措辞，不做逐字装配 |
| act/state 路由 | 同一生成器按事实种类拆开 | 谁写哪条事实 | 不是按事实种类切生成器，而是按**决定类型**切：分组 vs 措辞 |

一句话：**不是换一个提示词让通用模型改写整段，也不是让模型重新选标点，而是把“哪些事实一起说”提前到措辞之前决定。**

## 4. 怎么验证协同收益

### 4.1 三个条件，同一个成句模型

| 条件 | 成句模型的输入 | 验证什么 |
| --- | --- | --- |
| A | 事实（含顺序、kind、主体、文本）＋视角 | 基线：直接写 |
| B_h | 同一批事实＋**人工计划** | 交接本身有没有用（接口上界） |
| B_m | 同一批事实＋**模型计划** | 组织模块有没有学会 |

同一个检查点、同一提示词模板、同一解码参数与预算；三组唯一的差别是“有没有计划、计划从哪来”。

### 4.2 指标分三层，不互相抵消

1. **事实层**：逐 factId 记支持／遗漏／矛盾／归属错；未授权新增（物件、动作、关系）单列；关系边是否被跨句拆开、顺序是否保持；
2. **计划层**：计划是否覆盖全部事实、顺序不变、`edges` 只含授权边；正文对计划的遵守（组内不出现句号、组间至少分号、`parallel` 不写“同时”）；
3. **表达层**：衔接与清单感（沿用 B3/B4 的 0/1/2 口径），以及长度、耗时。

### 4.3 判定顺序（预登记）

1. **B_h 相对 A 没有改善**（表达层不升，或事实层退步）→ 交接本身没用，停止，不训练组织模块；
2. **B_h 有改善，但 B_m 明显低于 B_h** → 组织模块没学会；只能说“人工计划条件下有效”，不算系统能力；
3. **B_m 接近 B_h**（差距在预登记范围内），且两者都优于 A → 协同成立，才谈把两个模块接入流程。

**人工计划的收益一律单列，不能算系统能力。** 这一条与之前的 D1/D2 口径一致：构造条件、人工条件、模型条件分开报。

# 版本决定：契约格式重跑后的三臂比较（2026-11-04）

不训练、不加新测试。把四套固定诊断集的事实行统一成训练格式后重跑三个检查点，按统一口径重算，再做版本决定。

## 1. 契约不一致的范围（比理智一项更大）

`write_verbalizer_corpus.py` 训练时的事实行是 **`名字｜标签｜取值`**：

| 种类 | 训练格式 |
| --- | --- |
| moved | `沈砚｜移动｜潮渡→雾堤` |
| outcome | `沈砚｜结果｜把灯罩擦得透亮` |
| appearance_changed | `沈砚｜外貌变化｜袖口沾了铜油` |
| personality_changed | `沈砚｜性格变化｜…` |
| sanity_changed | `沈砚｜状态变化｜放松`／`发紧` |
| no_change | `场景｜无变化` |

我此前手拼的评估材料全部写成 **`标签｜名字｜取值`**，并且 `外观`、`无变化｜`、`理智｜…｜下降` 也与训练不同。用新加的 `fact_contract.py` 校验：**四套材料 215 个单元全部不合格**（`n4-final24.jsonl` 76/76 不符，`n4-object-train40-clean` 34/34，`n4-expand-train80-clean` 78/78）。

所以本轮把四套诊断集的事实行改写成契约格式（只改这一行，其余一字不动），重新生成，旧输出保留。**这是格式修复，不是新测试。**

## 2. 两个层级的干净源定义

按你的要求分开报，按源取错误并集：

- **事实干净**：该源所有必述事实为 S；
- **事实＋语法均合格**：在上一档基础上，该源输出不得出现语法违规（字段标签回写“外貌/外貌变化”、重复“的”、把取值词当谓语）。

## 5. 版本决定

按预设：431 若只剩局部措辞问题，采用 431 作为研发默认，保留 422 回退。

- 431 在事实干净（102/102）与事实+语法（86/102）两个层级都是第一；
- 与 422 的差异只在语法一项（+6 源），事实层打平或更好（cf24 85 对 83）；
- 431 剩余的语法问题都是标签回写与一处重复“的”，不改变含义。

**决定：`ckpt-mix431` 采用为研发默认版本；`ckpt-mix422` 保留为回退；`ckpt-fact` 退出默认位置，作为原始基线留档。**

两个都不算可交付版本：cf24 上仍有 4 个源存在标签回写或重复“的”，object18 有 9 个源同样问题。

## 6. 契约固化

| 项 | 位置 |
| --- | --- |
| 唯一序列化函数 | `fact_contract.py::serialize_fact`（标签、顺序、取值词都在这一处） |
| 输入装配 | `fact_contract.py::build_unit_input`，脚本不得手拼事实行 |
| 生成前校验 | `run_units_generic.py`、`run_contract_eval.py` 在生成前调用 `check_units`，格式不符直接退出 |
| 固定样例 | `test_fact_contract.py` 6 个用例：升/降各一条逐字符比对、其余四种格式、5 个反例必须被拒、装配后的字符串必须带正确事实行 |
| 材料改写 | `convert_contract.py` 把旧材料批量改成契约格式并逐条校验 |

自检结果：`python -X utf8 -m unittest test_fact_contract` 6/6 通过；旧材料被 `check_units` 拒绝（76 个单元全部不符），契约材料 215 单元全部通过。

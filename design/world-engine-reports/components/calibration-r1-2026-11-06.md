# 校准：24 条事实、k=2、只前向反传不更新

日期：2026-11-06。作业 241188，单卡 RTX 4090 D，权重 C（`08276c0c`）。**没有构造优化器**，
脚本里也没有 `step()`，所以权重不可能移动。这一轮只回答“这套机制能不能可靠地量出来”。

## 1. 集合

24 条事实 × k=2 = 48 行，覆盖六类：移动 6、外貌 6、结果 4、理智 4、性格 2、无变化 2。

**k=2 的口径要写清**：池子里没有同一事实的第二种表面表达，所以两行共用同一目标，只在
`地点/地点可见/场景` 三行上不同。它检验的是机械结构（批量组成、成分表、负例复用），
**不检验表面表达多样性**。真正的 k=2 表面变体需要在建池时另写，这轮没做。

## 2. 成分表与字符 span → token 映射

| 检查 | 结果 |
| --- | --- |
| `text_target` 与 `add_special_tokens=False` 的 id 序列 + EOS 是否一致 | 48/48 一致 |
| 字符 span 是否逐条落在目标里（`target[start:end] == text`） | 48/48 通过，0 失败 |
| token span 解出来是否等于字符 span | 92/100 精确；**8/100 多一个 token** |

多出来的 8 条全是 `state`：`结了` 在分词里是 `结了一层` 一个 token，`放` 是 `放在`，
`等了` 是 `等了一`。也就是说**字符边界可以落在 token 内部**。处理方式：token span 取
“最小覆盖区间”，权重会覆盖到多出来的那一个 token；这 8 条逐条列在报告的 `spanExpanded` 里，
不隐藏。

结论：映射可用，但**不能声称“成分权重只落在成分上”**——对 8% 的 span，它会多盖一个 token。

## 3. 负例：能构造的 5 类，3 类在当前阈值下完全不激活

构造规则改成按 kind 写死，并且逐个断言前缀不变；机械否定会造出病句的类直接不造。

| 负例类型 | 条数 | 说明 | m=1.0 时激活 | 间隔中位数 | 范围 |
| --- | --- | --- | --- | --- | --- |
| `name_drop`（删名称） | 44 | 主语缺失，句子仍成立 | 20（45%） | 1.052 | 0.693–2.770 |
| `other_vague`（终点→那里） | 10 | 只改终点 | 0（0%） | 1.391 | 1.137–2.093 |
| `state_negated`（移动否定：没走进） | 10 | 插入“没有” | 6（60%） | 0.999 | 0.867–1.436 |
| `state_stasis`（改成没有变化） | 20 | 理智/外貌 | 0（0%） | 2.914 | 2.178–3.710 |
| `state_event`（无变化改成事件） | 4 | 无变化事实专用 | 0（0%） | 5.926 | 5.915–6.036 |

**没能构造的类**（写进报告，不硬凑）：

- **结果（outcome）与性格（personality）**：谓语是 `把…拖了回来`、`没有再把话咽回去` 这类框架，
  机械否定会得到“沈砚把没系泊绳从浅滩拖了回来”“直接没有照做”这种病句。这两类只保留
  `name_drop`，`state` 负例不造。
- **关系方向**：这套 24 条里几乎没有关系事实（48 行里只有 2 行能找到关系词），
  **关系方向这一项在本次校准里完全没有覆盖**。要覆盖它必须用关系探针那种行，那是下一步的事。
- **无变化**：不能用“没有变化”当负例（正确目标本身就是无变化陈述），只保留事件负例。

**阈值不能统一**：`state_event` 的间隔中位数 5.93，`state_stasis` 2.91，`name_drop` 1.05。
用一个 `m=1.0` 只有 `name_drop` 和 `state_negated` 一半左右会激活，另外三类恒为 0、梯度贡献为零。
要么按类设 `m`，要么直接砍掉不激活的类。**这是校准最重要的结果。**

## 4. 梯度：损失占比 ≠ 梯度占比，系数按原提案会超预算

在一次 5 行的混合批（移动/结果/外貌/理智/性格各一）上，对三个参数张量
（`lm_head`、`encoder.block.7…wo`、`decoder.block.7…q`）分别求梯度：

| 项 | 数值 |
| --- | --- |
| 损失值 `L_ce` / `L_span` / `L_margin` | 0.0619 / 0.0672 / 0.0118 |
| 梯度范数 | 0.3765 / 0.3967 / 0.2762 |
| cos(L_ce, L_span) | **0.9445** |
| cos(L_ce, L_margin) | 0.3452 |
| cos(L_span, L_margin) | 0.2586 |
| margin 激活比例（该批） | 0.222 |

按原提案 `α=0.5`、`β=0.3`：

- 按**损失值**算，辅助项是主项的 **0.599 倍**；
- 按**梯度范数**算，是 **0.747 倍**。

也就是说，原规格里“辅助项不超过 30%”的检查用损失值算会通过（0.60 > 0.30 也不通过，但差距不大），
而真正决定更新的梯度已经到 75%。**30% 必须按梯度和方向来定，不能按损失数值。**

另外两点：

- `L_span` 与 `L_ce` 的方向余弦 0.94，几乎同向——它基本是“把同样的梯度重点压到少数 token 上”，
  不是新方向。要让它在消融里可分辨，必须单独跑 span-only 臂。
- 优化器是 AdamW，**梯度范数不会等比例变成步长**（每参数近似按二阶矩归一）。所以“梯度变大”
  的直接后果是**方向改变 + 计算量增加**，不是“有效步长同倍放大”。这一点也要写进规格，
  否则会拿范数当步长解释结果。

## 5. 随机数：额外前向确实会挪动 dropout 流，fork 能挡住

模型在 `train()` 下，同一批输入：

| 检查 | 最大绝对差 |
| --- | --- |
| 重设种子后第 1 步能否复现 | 0.0 |
| 中间插一次额外前向（不 fork），下一步与原序列比 | **59.31** |
| 中间插一次额外前向（`torch.random.fork_rng`），下一步与原序列比 | **0.0** |

所以：负例前向必须包在 `fork_rng` 里，否则 B 臂与对照臂的 dropout 序列会从第一步之后就分叉，
后面所有差异都无法归因给约束项。这条现在是硬要求，不是建议。

## 6. 这些数字对规格的修正

| 原规格 | 修正 |
| --- | --- |
| B 同时加 span 与 margin，B→A2 检验组合效果 | 增加 **B1 = A2 + margin（无 span 权重）** 与 **B2 = A2 + span（无 margin）**，B→A2 只作组合结论 |
| `α=0.5`、`β=0.3`，辅助项 ≤ 主项 30%（按损失值） | 系数按**梯度范数比**定，并记录 cos；实测 0.75，需要把 α、β 压到约 1/3 |
| 每行三个负例 | 按类构造，实测只有 `name_drop`、`state_negated` 在 m=1 有一半以上激活；其余按类设 m 或删除 |
| `1/tokens` 加权让 token 曝光相等 | 改为分别报告：事实次数、正例 token 数、负例 token 数、更新次数、前向次数与 GPU 时间；**加权只改贡献，不改曝光** |
| 未提随机数隔离 | 负例前向一律 `fork_rng`；报告里给出上面这组 0.0 / 59.31 的证据 |

## 7. 覆盖缺口（下一步要先补，不是可选）

1. 关系方向负例一条都没有——这正好是前面几轮反复出错的形状，必须单独建一小批关系行来校准；
2. 结果与性格两类没有 `state` 负例，若要用，得先人工写合法的否定句，而不是机械替换；
3. k=2 只是“换场景不换目标”，表面表达多样性没有测；真变体需要另写并逐条断言成分。

在这些补齐之前，冻结系数和消融方案都是空谈。

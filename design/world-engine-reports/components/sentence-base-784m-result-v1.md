# 784M 成句基座执行结果（2026-11-06）

## 1. 结论

**B-large-784 没有通过预登记的安全门，停止，不晋升。**

- fixed 6 个多事实组：B-only **0/6**。
- regression 13 个多事实组：B-only **2/13**（`t24` 的 f0、`v20` 的 f1）。
- 合计 **2/19**，安全门要求 0；失败。
- 不训练 A-large-784，不训练 B-small-784，不追加步数、配比、第二个基座或组织模块。
- `u240`、服务和编辑层未改。

这不是“784M 整体不如 77M”的结论。它只说明：**在这个 784M 基座、这套 80 源、120 次更新、最终检查点和当前评价材料下，没有清掉 B-large-77 的两个确定安全损失，且没有显示出可接受的安全收益。**

## 3. 训练与复放

- 480 次 B-large 调用，**逐次按参考顺序复放**；134 个唯一调用；120 次优化器更新。
- 优化配置沿用 B-large-77：batch 1、累积 4、AdamW fp32、lr 5e-4、12 次 warmup、greedy、最终点、不选点。
- 目标 token **8,323**，事实曝光 **831**，与参考日志一致；target token 逐条相同。
- 最大输入 **232** token、最大目标 **35** token；超过 512/128 的条数 **0**；无截断。
- 训练墙钟 **87.18 s**；峰值显存 **16,469,425,152 bytes**（约 15.3 GiB）；Slurm job 总墙钟约 3 分 25 秒。
- 任务返回码 0；HPC 日志中只有 `past_key_values` 和 generation config 的库版本警告，没有异常。

## 4. 评价生成记录

- fixed 25 次、regression 20 次，共 **45 次**生成。
- 全部在 128 token 上限前遇到 EOS：**45 EOS / 0 触顶 / 0 超时**。
- 单次生成 token 数：fixed 7–21（均值 14.36），regression 17–28（均值 21.6）。
- 原始输出、每次 token 数、停止原因、耗时都在 `sentence-base-784m-run-v1/results.json` 的 `calls` 字段；没有把截断或超时静默算成完成。

## 5. 安全结果

### fixed（6 个多事实组）

6/6 组通过人工复核，B-only **0/6**。没有观察到固定的新增人物、方向或结果错误。

### regression（13 个多事实组）

| 源 | 组 | 结果 | 说明 |
| --- | --- | --- | --- |
| `t24` | f0+f1 | **失败** | f0 写成「纸灯笼的衣角被风扯破一角」，新增了事实中没有的「衣角」；B77 的 f0 原本正确。同源 f2+f3 这次把「沈砚把纸灯笼扶正」补回来了，但整组仍因 f0 失败。 |
| `v20` | f0+f1+f2 | **失败** | f1（理智 9→12）缺失；f2「把渡船推离栈桥」这次写出来了。A77 的理智方向也错（写「发紧」），但 A 的错误另记，不抵消 B 缺 f1。 |
| `t22` | f0+f1 | 事实通过 | 「木桩的缠着的旧缆绳断了」多了一个「的」，语法退步；事实未丢。 |
| `v07` | f0+f1 | 事实通过 | B77 省了「潮汐簿」所有者，B784 写成「潮汐簿的封面」；按完整上下文，B77 不构成事实损失，B784 只是更明确。 |
| 其余 9 组 | — | 通过 | 没有新增遗漏。 |

- regression B-only **2/13**；合计 **2/19**。
- `t24` 和 `v20` 都没有变成整组通过：`t24` 的旧 f2 遗漏消除了，但另一组 `[f0,f1]` 新增「衣角」；`v20` 补了 f2 却丢掉 f1。按组算安全收益为 **0 组**；两处失败的位置和错误类型已经分开记录。
- 因此预登记的「B-only = 0」未满足；本路线按停止条件结束。

## 6. 与 B-large-77 的逐例比较

25 个源中 **21 个完整装配文本字节相同**，只有 4 个 regression 源不同：

- `t22`：B784 的「木桩的缠着」比 B77 的「木桩缠着」多一个「的」，语法更差。
- `t24`：B784 补出 f2，但 f0 新增「衣角」；B77 的问题是漏 f2，B784 的问题换成 f0 新增内容，组级仍失败。
- `v07`：B784 显式写「潮汐簿」，比 B77 的省略更清楚；按此前复核，B77 不算事实损失。
- `v20`：B784 补出 f2，但丢掉 f1；B77 有 f1 但方向写错且漏 f2；两版都失败，B784 没有组级安全收益。

所以：**没有证据表明 784M 在这批材料和配方下改善了组级安全；表达上只有 1 处明确更好（v07），另有 1 处语法退步（t22）和 1 处新增内容（t24）。**

## 7. 限制

- 只训练了一个基座、一个种子、最终点；没有选点，也没有多次运行。
- B-large-784 在 HPC 的 torch 2.5.1 / transformers 4.51.3 上训练；B-large-77 在本地 torch 2.7.0 / transformers 4.57.3 上训练。这是环境差异，不能当作数值完全相同的重跑。
- tokenizer 字节相同，因此 token 数和接口相同；但模型初始化、预训练数据和显存行为不同。
- 没有 A-large-784，也没有 B-small-784；不能据此声称“784M 下组级优于逐事实”。
- 最终权重保存在 HPC；仓库只保存权重/config/tokenizer 哈希和原始结果，不把 3 GB 权重提交进 Git。

## 8. 停止

按冻结协议停止：

- 不补 `t24` / `v20` 的答案。
- 不加训练步数、不改配比、不选检查点。
- 不自动换第二个基座。
- 不训练内容组织模块。
- 不替换服务，不改 `u240` 和编辑层。

本结果只把“784M 基座在当前 80 源/120 更新/最终点下的离线联合成句”记为**未通过安全门**；不外推到其他基座、数据规模或整个组件协作流程。
> 事后拟合诊断（不训练）：训练组 134/134 组、231/231 事实通过；fixed 25/25 组、31/31 事实通过；regression 只剩 `v20` 一个遗漏，`t24` 是另一组的新增「衣角」。见 [sentence-base-784m-fit-diagnostic-v1.md](sentence-base-784m-fit-diagnostic-v1.md)。

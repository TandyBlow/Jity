不改配比、不加移动样本。这一轮只做四件事：统一缺陷账、补跑两条缺失的比较、给出采样账、把材料检查前置。

## 2. 前置硬校验

`precheck.py` 现在四项一起查，训练前跑：

| 检查 | 内容 |
| --- | --- |
| entity | 事实里的名字必须存在于 `world.json`；moved 的起终点必须是地名 |
| visibility | 主体物件与引用物件必须在 `地点可见` 或视角人物随身里 |
| authorisation | 主体必须是人物／物品／已列场景特征；`no_change` 不得带主体 |
| whole/part | 部件只能来自 `整体 → 部件` 登记表，且整体必须可见 |

匹配按最长优先，`铜灯` 不会在 `铜灯罩` 里被误命中。四个数据集跑完后 `clean` 版本 0 问题。

## 3. 补跑的两条比较

### 3.1 物件确认集（18 条有效）

| | 冻结基线 | 扩容臂1（4+4） | 扩容臂2（4+2+2） |
| --- | --- | --- | --- |
| 事实支持 | 10/18 | 14/18 | **18/18** |
| 错类型 | 1 缺失 / 4 相反 / 3 归属错 | 3 缺失 / 1 相反 / 0 | 0 |

成对得失：

- 基线 → 臂1：得 `qa1B`、`qa3A`、`qa3B`、`qc2B`、`qd2B`、`qd3A`（6 条），**失 `qa2B`、`qb1B`（2 条）**——臂1 在这两条上退化成“没有新的变化”和“灯影被擦得发亮”。
- 臂1 → 臂2：得 `qa2B`、`qb1B`、`qb2A`、`qd3B`（4 条），**失 0 条**。

所以物件数据的增量收益是真的：**臂1 14/18 → 臂2 18/18，且没有反向损失**。臂1 相对基线只提高了 4 条，还丢 2 条。

## 5. 判定

- **物件收益是否值得保留**：值得。臂2 相对臂1 在物件集上 14→18、无反向损失；在确认40 上两者持平。
- **代价**：移动表达从 10/10 掉到 7/10，且这个代价不能用采样比例解释。

下一步按预设规则走：物件确有明显增量收益，所以做**清洗数据下的配比对照 4+2+2 对 4+3+1**，其他条件不变，不同时补“从 X 到 Y”样本。对照组要专门看移动表达是否回来。

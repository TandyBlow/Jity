## 1. 任务定义

输入：已提交事实表（编号 1..n）＋视角规则。输出：**要写进正文的事实编号集合**。

- 输出是选择，不是新事实：编号以外的内容不接受，未知编号记为无效 token。
- 三类标注（程序定义，不由模型产生）：
  - `must` 必述：主角自己的行动、玩家正在推进的任务结果或其理智变化；
  - `forbidden` 视角不可知：他处的变化、他人他处的私事；
  - `omittable` 可省：其余全部（由 `全部 - must - forbidden` 推导，不手工挑，避免标注遗漏）；
  - `target` 理想选择（must ＋ 显著性事实），用于算精度/召回。
- **"全选"不是选择能力**：`selectAll` 单独记录，判据不以它为准。

## 2. 判据（程序，跑前固定）

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| `mustRecall` | \|must∩sel\| / \|must\| | 硬性：必须 1.0 |
| `forbiddenHits` | \|forbidden∩sel\| | 硬性：必须 0 |
| `precision`/`recall`/`F1` | 对 `target` 计算 | 质量 |
| `selectAll` | sel ⊇ 全部事实 | 记录，不算通过 |
| `invalid` | 非编号内容（含"编号＋解释"）、空输出、越界编号 | **硬性**：有即 fail |
| `pass` | 无 invalid 且 mustRecall=1 且 forbiddenHits=0 且 F1 ≥ **0.6** | 首轮开发阈值，**不是**冻结验收门 |

严格格式：允许可选 `编号：` 前缀，其后只允许数字与逗号/顿号/分号分隔，末尾可有一个句号；其它任何文字都会使该答案失效（v1 曾让"编号＋文字"通过，已修）。

## 3. 开发集（v2）

`experiments/world-components/n2_selection/items.jsonl`（v1 保留为 `items-v1.jsonl` 供追溯）：16 项，第三人称新词表（裴行舟/沈拾/岑半夏/…，石阶码头/旧钟铺/…），每项 5–6 条事实，四类结构：

- A 主角移动后视角：自身移动＋任务必述，目的地变化可选，**他处变化与他人的情绪不可知**（4 项）；
- B 地点受限视角：本地任务/理智必述，本地变化可选，他处移动不可知（4 项）；
- C 全知视角：无禁止项，冗余时间/空点/他人情绪可省（4 项）；
- D 主角视角＋**同地他人任务**：同地他人行动可见（不得误当禁止），他处任务不可知（4 项）。

标签全部由可见性规则推导：`必须 = 视角人物自身行动/任务/理智`；`禁止 = 规则判为不可见`；`可省 = 其余`；`target = 必须 ∪ 显著可见事实`。构造期断言姓名↔ID 一致、视角人物有自身事实、target 不含禁止项。

- 事实数 5–6；must 2、target 3.25、omittable 2.75、forbidden 1.0（均值）；12/16 项含禁止事实。
- 隔离：`check_isolation.py` v2，15 个来源、3890 条串（含短串），**0 命中、0 缺失**；自检确认 3 字人名与 2 字串都能被抓。

### 4.3 观察（按 v2 证据）

1. 全选仍被判据正确扣分（16 次禁止项命中，pass 4/16）。
2. 视角规则**可以**由程序严格实现：`P1-rule` 只读视角与事实位置即 16/16，且对标签改动免疫——这是"可实现"的证据，不是模型能力。
3. 补齐视角信息后，Qwen3-0.6B 仍 4/16、9 次禁止项命中、must 覆盖 0.875：它会给编号、会筛掉一部分，但没有把"视角不可见"当硬约束，且漏掉部分必述事实。
4. Randeng 两种提示形态均 0/16（16 项全部被判"非编号内容"）：T5 基座不适合"生成编号"这一输出形状。
5. 成本：0.6B 单次约 24s（CPU），程序规则为 0；若每回合跑一次选择，总账必须先算清。

## 5. 结论与下一步

- **N2 未通过**：没有任何模型在修正后的设计上达到判据。
- 视角约束本身是**程序可判定**的（P1-rule 证据），所以 N2 的价值在**显著性与省略判断**：哪些可见事实必须写、哪些可以省。当前 `target` 由构造规则定义，尚未验证"人类是否同意这个显著性口径"，这是下一轮要先解决的口径问题。
- 模型路线建议（待下一轮验证）：编码器打分头（事实条目×视角→保留/丢弃），输入含视角字段与事实位置；生成编号的形态（M1/M2）两轮均未通过，不优先。
- 数据纪律：训练与调参用开发集；**N4 独立留出集保持封存**，不与 N2 混用。
- 在预登记判据与独立留出前，不宣布 N2 通过。

## 6. N3 组织表达承接安排（结构化计划，不生成正文）

N3 的既有契约是**组织计划**，不是成句：输出有序句组、每组的事实 ID 与指代建议，由 N4 负责写正文。上一版方案让基线直接合句生成正文，跨入了 N4 职责，本轮更正。

| 项 | 安排 |
| --- | --- |
| 输入 | 已选事实（N2 输出的子集，**只含事实 ID 与事实内容**）＋视角（人物/ID/所在地/规则） |
| 输出结构（与既有契约一致） | `sentences: [{index, factIds:[...], coreference:[{mention, refersTo}]}]`；只做分组、排序、指代，**不含任何正文文字** |
| 程序基线 B1 | 按 kind 优先级（位置→任务→人格→理智→外貌→时间→空点）分组，同人多事实合入同句组；指代建议：同句组内第二次提及用姓名，不生成代词 |
| 程序基线 B2 | 保留计划原始顺序，每条事实一个句组 |
| 指标 | ① 事实覆盖不变（句组 factIds 的并集＝输入集合）；② 顺序违例（跨组顺序与 kind 优先级冲突数）；③ 分组正确率（同人多事实是否同组）；④ 指代先行词正确率；⑤ 人工可读性抽验 |
| 判据 | 事实覆盖复用 N4 的 `corpus_check` 语义（只核 factIds，不做文本核对）；顺序/指代另加程序检查；不新建第二套事实判据 |
| 模型候选 | 先量 B1/B2；再测 0.6B instruct 是否在"给定事实、只排顺序并合句"上优于基线；T5 若要参与须微调 |
| 前置 | 先冻结"选中事实→组织计划"的接口字段（与 N2 的 factId 口径一致），再实现 B1/B2 |

**复核轮 20 实现（B1/B2 已落地，首轮归档）**：`n2_selection/n3_plan.py`（计划构造＋两个硬不变量检查）、`run_n3_baselines.py`（在 16 项 v2 开发集上运行）。

| 项 | 结果 |
| --- | --- |
| 硬不变量 | I1 覆盖不变（句组 factIds 并集＝选中集合）、I2 指代先行锚定（refersTo 锚在本句组事实、mention＝查表人名）、I3 B1 句组级优先级单调——16/16 项零违规 |
| 基线数字 | B1 共 **36 句组**（facts/组均值 1.46；actor 内聚），B2 共 **52 句组**（每事实一组）；这是后续模型臂必须优化的对照，不是成绩 |

# 甲的第二轮：堵住已知错误放行，核对真实契约

日期：2026-11-06。离线修正，**不接产品、不训练、不重跑模型**。旧版结果保留，新版单独报告。

## 1. 撤掉了哪条放行口子

上一版有一句判据：**主体在、状态词有重合 → 放行**。`t24:f1` 就是从这儿过去的：

- 事实：`排水沟`，状态文本 `里面积了泥`；
- 句子：`排水沟里的泥在墙根上蹭了泥。`
- 主体在、`泥`字重合 → 放行。**但这句话说的是另一件事。**

这一版把这条口子整个删掉：**没有结构化字段、也不在支持句式里的句子，一律“无法确认”**。
代价立刻显出来，见第 4 节。

新增 14 条反例测试（`test_display_checker.py`），全部通过：

| 反例 | 判为 | 理由 |
| --- | --- | --- |
| `排水沟里的泥在墙根上蹭了泥。` | 无法确认 | 词重合不再授权放行 |
| `沈砚的指尖没有沾墨。` | 确认不符 | 事实被否定 |
| `潮汐簿压着的干纸滑开了。` | 确认不符 | 关系方向反了 |
| `压在潮汐簿上的干纸滑开了。` | 可放行 | 支持句式 |
| `石缸压在石缸上的木板裂了。` | 无法确认 | 记录没说哪一侧是处所 |
| `沈砚从潮渡过来,船头抵住雾堤的栈桥。` | 确认不符 | 抵达成立，但添了“船头”“抵住” |
| `沈砚从潮渡过来,在雾堤站住。` | 确认不符 | 抵达成立，但添了姿态 |
| `沈砚从潮渡走到雾堤。` | 可放行 | 干净抵达 |
| `沈砚从潮渡走进档案馆。` | 可放行（注明缩写） | 只接受末尾三字以上的缩写 |
| `沈砚离开雾堤,沿着雾堤的墙边。` | 确认不符 | 只有地名，没有抵达 |

## 2. 生产端契约：不是归档文件缺字段，是契约真的没有

翻到 `backend/app/schemas/world/contracts.py` 的 `EntityDelta`，一个点位的实体改动只有六个字段：

```
entityId, positionSet, appearanceChanges, personalityChanges, sanitySet, tasksAchieved, subtasksAdded
```

逐条对照：

| 我们需要的 | 生产契约里有什么 | 结论 |
| --- | --- | --- |
| 关系、锚点、哪一侧是处所 | **没有**。`appearanceChanges[].text` 是一句自由文本，方向只存在于字里 | **契约缺字段**，不是归档文件缺 |
| 移动的起点 | **没有**。`positionSet` 是绝对位置（`containerId` + 可选 `slotId`/`relativeTo`） | 起点只能读上一个点位，不是本点位字段 |
| 理智的前值 | **没有**。`sanitySet` 只给新值 | 前值只能读上一个点位 |
| “这一回合没有变化” | **没有这种实体**。空 Δ 是唯一信号 | 无法区分“整个回合无事”与“某个实体无事” |

两件必须写清楚的事：

1. **方向字段若确需新增，应由 Python 在写状态事件时一并写出**，来源是状态事件本身（谁在谁的哪一侧），
   **不能从模型输出推断**，也不能回填覆盖已冻结的输入文件；
2. 起终点、理智前后值**不需要新字段**，它们靠 `previousPointId` 读上一个点位得到——
   这也正是接口文档里写的方式。但**展示层必须真的去读那一次**，否则只能展示“到了哪”“现在是几点”，
   说不了“从哪来”“掉了多少”。本轮原型用的是单元文件里已经备好的 from/to，**没有验证过这次读取**。

## 3. 展示收紧两处

1. **“有完整字符串”不再写成“已验证”。** 150 条外貌/结果事实没有结构化关系字段时，展示句是
   `主体：原事实文本。`——忠实，但**不声称方向已验证**。渲染结果现在带
   `the direction is not verified` 的注记，不再只写“没有方向字段”。
2. **“这一回合没有新的变化”不再默认成立。** 记录里没有范围字段，就不能从“某个实体/某次动作没事”
   扩成“整个回合没事”。这 8 条现在**列为契约缺口**，不出句。
   → 展示完整数从 205/205 降到 **197/205，8 条缺口**。

## 4. 同批回放：旧版 vs 新版（同一批 1351 句）

| | 旧版 | 新版 |
| --- | --- | --- |
| 可放行 | 1164（86.2%） | **257（19.0%）** |
| 确认不符 | 64（4.7%） | 103（7.6%） |
| 无法确认 | 123（9.1%） | **991（73.4%）** |
| **错误句被放行** | **1** | **0** |
| 正确句被拒绝 | 47 | 86 |

**错误放行先清零了。** `t24:f1` 现在落在“无法确认”。

### 放行率为什么掉到 19%

按事实类型拆开（1351 句）：

| 事实类型 | 句数 | 可放行 | 确认不符 | 无法确认 |
| --- | --- | --- | --- | --- |
| 移动 | 287 | 201（70%） | 86 | 0 |
| 无变化 | 56 | 56 | 0 | 0 |
| 理智 | 42 | **0** | 11 | 31 |
| 外貌 | 441 | **0** | 6 | 435 |
| 结果 | 525 | **0** | 0 | 525 |

**966 句（71.5%）背后的事实没有结构化字段**——外貌和结果只有一句自由文本，
理智只有两个数。没有可对照的结构，就没有可放行的依据。这不是模型变差，是**记录不够**。

理智那一档更细：31 条无法确认是“方向既没被确认也没被否定”，因为我们只查了“写成没变”和
“写成反向”两种明确矛盾，没查“确实掉了 3 点”。

### 重新审查上一轮那 47 条

| 上一轮被拒的 47 条 | 新版判为 | 条数 |
| --- | --- | --- |
| 地名缩写 | 可放行（注明缩写） | 2 |
| 地名缩写 | 确认不符：只有地名，没有抵达 | 17 |
| 抵达缺动词 | 可放行 | 1 |
| 抵达缺动词 | 确认不符：抵达成立，但添了“站住” | 12 |
| 抵达缺动词 | 确认不符：抵达成立，但添了“船头/抵住” | 8 |
| 抵达缺动词 | 确认不符：抵达成立，但添了“蹲到” | 7 |

**按“抵达是否成立／是否追加事件”分开判之后**：抵达成立的 29 条里，只有 3 条能放行——
其余 27 条都在抵达之外多说了姿态、接触或物件。这类句子**不能整体授权**，只能展示确定性事实句。

### 新增的“正确句被拒绝”从 47 升到 86

多出来的 39 条，全是上一版因为“抵达＋没触发旧黑名单”而放行、这一版因为黑名单扩到
`扶着`（27）、`抱着/一叠`（7）、`船头/抵住`（10）而被拒的。**这是收紧的代价，不是新发现的错误。**

## 5. 结论

- **错误放行：0 / 1351。** 优先项达成；
- **可靠放行率只有 19.0%**，不是 86.2%。上一版那个数字里有一半以上靠词重合撑着，不能当产品指标；
- 73.4% 的句子“无法确认”，其中 **966 句是因为记录没有结构字段**——瓶颈在记录，不在模型；
- 页面能说的话目前只靠展示句：移动和无变化能说清楚，外貌/结果只能说“主体：原事实文本”，
  且不声称方向已验证；理智能说方向但不能核对具体数值。

## 6. 契约缺口（更新）

| 缺口 | 影响 | 谁来补 |
| --- | --- | --- |
| 关系事实没有锚点、关系词、哪一侧是处所 | 441 条外貌句无法放行，也说不清方向 | Python 写状态事件时一并写，新增字段 |
| 结果类只有一句谓语文本 | 525 条结果句无法核对 | 契约层面定义“结果”的字段，或承认只能展示原文 |
| 理智只有新值 | 前值须读上一点位；展示说不了“掉了多少” | 读 `previousPointId`，不是新字段 |
| 移动只有绝对位置 | 起点须读上一点位 | 同上 |
| 无变化没有范围 | 8 条无法出句 | 契约层面定义范围 |

## 7. 不声称的

- 不声称 19.0% 就是产品放行率：这 1351 句来自同一批单元、同一批场景；
- 不声称“确认不符”都判对了：其中 86 条是事实成立但句子多说了内容，属于“不能整体授权”，
  不等于事实错；
- 不声称展示层已经真的读过上一个点位：本轮原型用的是单元文件里预置的 from/to；
- 不声称新增关系字段之后模型就会写对：那要另测。

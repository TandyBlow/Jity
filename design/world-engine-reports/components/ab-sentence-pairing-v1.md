## 2. 计划与正文的边界（沿用并修正上一页）

计划只含四样东西：

```
{"groups":[{"facts":["f0"]},{"facts":["f1","f2"],"links":["continuation"]}],
 "refs":{"f0":"name","f1":"name","f2":"omit"},
 "edges":[]}
```

- `groups`：按事实原顺序切分，不重排；一组＝一次连续表达；
- `links`：`continuation`＝**同主体组合**，`parallel`＝**跨主体并列**；两者都只表示表达上的组合方式，**不表示事件同时、先后或因果**；
- `refs`：只有 `name`／`omit`；本轮不写“他/她”，唯一人物只能支持省略主语；
- `edges`：只登记已授权的 `before`，每条带 `mode=optional|required`；`required` 没写出先后关系只记“计划未实现”。

正文由成句模块自由写；计划里没有动词、名词、标点、连接词、背景片段。**计划形式分开只证明接口分开了，不证明职责拆分有效**——有效与否看第 4 节的对照。

一个完整配对（`v02`）：

```
事实（两臂相同）：
f0 阿棠｜结果｜把银鳞鱼按大小分开装进鱼筐
f1 顾行舟｜结果｜把抹布拧干
f2 顾行舟｜外观变化｜手背上沾了鱼鳞
共同语境：地点=早市；可见=银鳞鱼、鱼筐、案板、抹布、帆布棚、石板；场景=清晨；薄雾；棚下散光；视角=阿棠；第三人称

A 的输入：上面这些，没有计划。
B_h 的输入：上面这些 ＋ 计划 {"groups":[{"facts":["f0"]},{"facts":["f1","f2"],"links":["continuation"]}],
                                "refs":{"f0":"name","f1":"name","f2":"omit"},"edges":[]}

目标正文：阿棠把银鳞鱼按大小分开装进鱼筐。顾行舟把抹布拧干，手背上沾了鱼鳞。
```

## 3. 固定训练协议（启动前冻结；本轮不启动）

| 项 | 固定值 |
| --- | --- |
| 基座 | 默认沿用 N4 的 77M T5（本地已有、浏览器可跑）；若不可用，换一个 ≤0.5B 中文模型。两臂必须同一基座，启动前记录权重哈希 |
| 词表/模板/截断 | 两臂完全相同；prompt 模板只差“计划块”有无 |
| 训练源 | 上表 5 个 train 源；每个源一条，逐源曝光＝每 epoch 每条各一次，不做上采样 |
| 目标正文 | 同一源两臂完全相同，逐字一致 |
| 共同信息 | 地点、可见、场景、视角、授权关系两臂都可见；不能只给 B_h |
| 优化 | AdamW；77M 用 5e-4、0.5B 用 1e-4；同 schedule、同 seed、同精度（fp32 或 bf16 二选一，两臂一致） |
| 曝光 | batch=1 个源；固定 epoch 数（建议 20）；两臂相同；不做臂单独的 early stop |
| 解码 | greedy；max new tokens＝训练目标最长 token×1.5；无长度奖励、无重复惩罚、无禁词表 |
| 记录 | 数据文件哈希、权重哈希、完整配置、逐源原始输出与耗时 |

两臂唯一的差别：B_h 的 prompt 多一个计划块。A 的 prompt 也要写“不新增关系、不写代词”，这是共同契约，不是计划。

## 4. 评价与判定

### 4.1 三层分开

1. **事实层**：逐 factId 记支持／遗漏／矛盾／归属错；未授权新增（物件、动作、关系）；关系端点是否跨句拆开、顺序是否保持。
2. **计划层**：计划本身是否覆盖全部事实、顺序不变、`edges` 只含授权边；正文是否遵守计划（组内不出现句号、组间至少分号、`parallel` 不写“同时”、`required` 边是否写出）。A 没有计划，只记事实层与表达层。
3. **表达层**：沿用 B3/B4 的 0/1/2 口径；另记长度与耗时。

**表达改善不能抵消新增事实错误**：事实层退步时，表达分再高也判该条不通过。

### 4.2 判定顺序（预登记）

1. 先看留出集（雾堤 3 源）上 B_h 相对 A：表达层是否升、事实层是否不退；
2. 若没有改善，先查两件事再下结论：
   - B_h 的正文有没有跟着计划走（计划层遵守率、A/B_h 输出的差异度）；
   - 若计划被忽略 → 是训练或模板没让模型学会这个条件，**不能宣布职责协作无效**；
   - 若计划被遵守但仍无改善 → 这份计划没提供有用信息，接口价值不成立；
3. 若 B_h 有改善 → 才进入下一步：训练组织模块，用 B_m 对 B_h；
4. 人工计划条件下的收益是**接口上界**，不是系统能力；B_m 接近 B_h 才谈系统能力。

### 4.3 样本量先说清

train 5 源 / dev 3 / holdout 3 只够做**管线试跑**：能看出“计划有没有改变成句行为”，不足以证明泛化收益。要判断收益，需要把池子扩到至少 20 个 train 源（补齐被排除的 6 源或新增来源），这是材料工作，不在本轮。若在 5 源上就出现“事实退步”，可以直接停，不必扩池。

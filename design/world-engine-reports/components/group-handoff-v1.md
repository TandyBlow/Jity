# 组级交接 v1：设计、对照与复用决定（2026-11-06）

**决定先说：这套“组织模块给组 → 程序逐组调用 → 成句模块只写本组 → 程序装配”的机制，与历史“人工计划条件下的句组臂”实质相同；历史结果已经回答了核心问题，本轮不训练、不新建材料、不换名字重跑。** 本文只交可执行设计和复用依据。唯一明确的新变量是 `before` 端点隔离与程序插入“随后”，它是窄扩展，不足以改变组内失败。

## 1. 机制

1. 组织模块（或人工隔离条件）输出有序组：`G1=[f0,f1]`、`G2=[f2]`……每组带事实 ID、组序、称谓授权（`name`/`omit`）和关系边。
2. 程序按组循环，每次只把**本组事实**、场景上下文、组序和本组需要的授权传给成句模型；不传整份计划，不传其他组的事实。
3. 成句模型只写本组正文；组内可以联合表达多条事实，可以用逗号/分号，但不负责组间边界。
4. 程序去掉每组末尾句号，按组序用一个“。”连接；`before` 的端点组保持分开，程序在目标组前插入“随后，”。不写“同时”。
5. 每组独立验收：事实齐全、主体/对象正确、无未授权新增、无代词越权、无复读。任何一组失败，整源记失败，不用模板或规则补写。

组输入形状：

```
叙事任务。地点=… 场景=… 视角=…
本组=G1/3
授权关系=…（只有本组起始边需要时）
事实（只列本组，按顺序）：
f0｜…
f1｜…
称呼=姓名/承前省略
要求：只写本组；组内可联合多条事实；组间边界由程序负责；不新增人物、物品、地点、动作、关系；不写代词、数字、字段名。
正文：
```

## 2. 三个实例

### 例 1：同主体组合（`t02`）

计划：`[f0,f1,f2]`，一次调用。

| 组 | 输入事实 | 目标正文 |
| --- | --- | --- |
| G1 | f0 阿棠把银鳞鱼按大小分开装进两只鱼筐；f1 阿棠袖口沾了鱼鳞；f2 阿棠把空鱼筐摞到摊棚边上 | 阿棠把银鳞鱼按大小分开装进两只鱼筐，袖口沾了鱼鳞，把空鱼筐摞到摊棚边上。 |

装配结果：同上一句。程序只加末尾句号。组内三条事实都保留，主体始终是阿棠。

### 例 2：跨主体并列（`t11`）

计划：`[f0,f1] / [f2,f3]`，两次调用。

| 组 | 输入事实 | 目标正文 |
| --- | --- | --- |
| G1 | f0 沈砚从潮生巷走到旧灯塔；f1 叶知微把灯罩擦得透亮 | 沈砚从潮生巷走到旧灯塔，叶知微把灯罩擦得透亮。 |
| G2 | f2 沈砚换好塔顶的灯芯；f3 叶知微的袖口沾了铜油 | 沈砚换好塔顶的灯芯，叶知微的袖口沾了铜油。 |

装配结果：`沈砚从潮生巷走到旧灯塔，叶知微把灯罩擦得透亮。沈砚换好塔顶的灯芯，叶知微的袖口沾了铜油。`

两个组各一次调用；组间句号由程序加。`parallel` 只表示同组并列或跨组并列，不写“同时”，不表示先后。

### 例 3：带关系端点（`fixture-r5`）

计划：`[f0,f1] / [f2] / [f3] / [f4]`；边 `f2 before f3`，`required`。四次调用；f2/f3 分开，f3/f4 也分开。

| 组 | 输入事实 | 目标正文 |
| --- | --- | --- |
| G1 | f0 林川的帽檐压出折痕；f1 林川的脚踝肿了一块 | 林川的帽檐压出折痕，脚踝肿了一块。 |
| G2 | f2 周宁的衣领被雨浸透 | 周宁的衣领被雨浸透。 |
| G3 | f3 陈默的指尖磨出茧 | 陈默的指尖磨出茧。 |
| G4 | f4 陈默的膝盖沾了泥 | 陈默的膝盖沾了泥。 |

装配结果：`林川的帽檐压出折痕，脚踝肿了一块。周宁的衣领被雨浸透。随后，陈默的指尖磨出茧。陈默的膝盖沾了泥。`

程序在 G3 前插入“随后，”；G2/G3 分开，G3/G4 分开。模型不写“随后”，避免重复；端点隔离由程序保证，不靠模型记忆整份计划。

## 3. 与历史句组臂的对照

历史实验：`n4-group-arm-result.md`（人工计划条件下的句组臂，2026-11-04）。

| 项 | 历史句组臂 | 本设计 |
| --- | --- | --- |
| 每次调用只写一组 | 是 | 是 |
| 输入只含本组事实 | 是 | 是 |
| 组内联合多条事实 | 是（157 组：85 整源组、16 合并组、56 单事实组） | 是 |
| 程序装配组间边界 | 是（逐组生成后 join） | 是 |
| 人工计划作为隔离条件 | 是 | 是（组织模型未训练时） |
| `before` 端点隔离＋程序插入“随后” | 未作为独立约束 | **新增，唯一明确变量** |

历史结果（同一 77M 基座，132 个训练组单元，120 次曝光，选中 epoch 10）：

- 测试 12 源 21 条事实：事实支持 **18/21**，完整源干净 **9/12**。
- cf24 固定诊断 24 源 85 条事实：支持 **59/85**，完整源干净 **2/24**；≥12 字重复片段 **11/24**；延迟 **20.98 s**。
- 目标修订后 cf24 仍是 **57/85**，复读和延迟没有可靠改善。
- 典型失败：`t01` 把同一句连写十几遍，`t16` 退化到预算耗尽；组内一旦复读，整源不可读。

所以“旧规划器只装配现成短句、这里才允许组内联合表达”这个区别不成立：历史句组臂已经允许组内多事实，也已经由程序逐组调用和装配。**核心机制相同，历史结果已经回答“程序落实边界后，小模型能否安全、自然地写一个事实组”：不能稳定做到。**

## 4. 复用决定

- **不训练**：不新训组级成句模型，不训练组织模块。
- **不新建材料**：三个实例都取自现有 `pairs-v2` / `controllability-v1` 的事实与目标。
- **不换名字重跑**：本设计不构成新实验；它是对历史句组臂的重新表述。唯一新增的 `before` 端点规则是窄扩展；历史失败发生在组内（漏事实、串主体、复读），端点规则不解决这些，不能据此期待翻盘。
- 若以后要验证端点规则，应在解释/修正组内失败之后做小消融，而不是作为新主线重跑。

**下一步的合格门槛**不是再跑一次同样的组级调用，而是先回答：为什么同一种“1–2 条事实＋组目标”的输入，在单事实臂上稳定，在组臂上会复读和漏事实。这个问题没有答案之前，训练组织模块没有可靠的下游接收者。

## 5. 边界

- 程序保证句界，不保证事实安全；组内仍可能漏事实、串主体、加料，必须逐组验收。
- 人工分组仍是隔离条件，不能算组织模型能力。
- 历史句组臂的 cf24 有 `可见：` 为空等输入缺陷；目标修订也没有可靠改善，但这不改变“组内生成不稳”的结论，只限制它的成因解释。
- 本文件不宣布“组级交接永远不可行”，只宣布：**这套机制已被历史实验覆盖，当前不重复训练。**

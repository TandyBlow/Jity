# N2 独立标注 rubric v1（联合决策 D1）

日期：2026-10-29。对象：N2 开发集 v2 的 16 项、92 条事实。用途：两人独立三分类标注，κ≥0.7 后冻结 v3，替换 v2 的程序 `must` 作为 N2 判据的必述口径。

**本文件在标注开始前定稿并哈希。** 哈希、盲表哈希、标注文件哈希统一记录在
`experiments/world-components/n2_selection/annotation/manifest.json`。标注者只拿本 rubric、盲表
（`items-blind.jsonl` / `sheet.md`）和空白标签模板；不阅读 `items.jsonl` 里的
`must/target/omittable/forbidden`，不阅读 `run_n2.py`、`n3_plan.py` 或任何臂的逐项输出。
实现者此前在修复过程中看过 v2 标签与汇总输出，这一暴露在 manifest 中如实记录；审查者必须是盲标。

## 1. 三分类

对每条事实只给一个标签：

| 标签 | 含义 | 是否可写进正文 |
| --- | --- | --- |
| `must` | 必述。漏写即内容失败。 | 必须写 |
| `omit` | 不写。视角不可见，或仅涉及他人。 | 不应写 |
| `may` | 可写可不写。可见、非必述、也不是“仅他人/不可见”。 | 允许写，允许省 |

## 2. 判定顺序（必须按此顺序）

1. **可见性**：按视角规则判断这条事实是否可知。不可见 → `omit`。
2. **仅他人**：事实主体不是视角人物（`entityId` 不同）→ `omit`，除非满足第 3 条“在追任务”。
3. **must 四条**（任一满足即 `must`）：
   - **主角目标**：视角人物自己的任务达成（`task_achieved`，主体＝视角人物）。
   - **安全**：视角人物的理智变化（`sanity_changed`，主体＝视角人物），或事实文本明确写出主角受伤/身处危险。
   - **位置**：视角人物的移动/所在位置（`moved` / `positioned_at`，主体＝视角人物）。
   - **在追任务**：视角人物正在追踪/推进的任务结果；即使最后由他人完成，只要事实文本明确是同一目标/同一委托，也标 `must`。仅凭“看起来重要”不算。
4. 其余可见、非仅他人的事实 → `may`。

## 3. 可见性操作规则

- `viewpoint.type == "omniscient"`：全部可见。
- 其他视角：满足任一即可见：
  - 事实的 `at` 等于视角人物所在地 `viewpoint.at`；
  - 事实主体 `entityId` 等于视角人物 `entityId`（自己的行动/状态）；
  - `kind == "time"`（全局时间推进）。
- `at` 为 `null` 的 `time` 视为全局可见。
- `no_change` 的 `scope`/`at` 在他处、视角人物不在该处 → 不可见 → `omit`。
- 事实缺 `at` 且主体不是视角人物 → 按不可见处理（标注备注说明）。

## 4. 全知视角（无单一视角人物）

全知视角没有“视角人物”。本批以事实表中出现**位置变化**（`moved` / `positioned_at`）的人物为
**共同焦点**：

- 焦点人物的位置/目标/安全/在追任务 → `must`；
- 焦点人物的其余可见事实（人格、地点外貌、时间、无变化）→ `may`；
- 非焦点人物的私事 → `omit`。
- 若整项没有任何位置事实，标注者选“行动事实最多的人物”为焦点并在备注写明；仍按同一规则。

## 5. 逐 kind 速查

| kind | 视角人物 / 焦点人物 | 其他人物（可见） | 不可见 |
| --- | --- | --- | --- |
| `moved` | `must`（位置） | `omit`（仅他人） | `omit` |
| `positioned_at` | `must`（位置） | `omit`（仅他人）；全知焦点按 `must` | `omit` |
| `task_achieved` | `must`（目标/在追任务） | `omit`；明确在追同一任务 → `must` | `omit` |
| `sanity_changed` | `must`（安全） | `omit`（仅他人） | `omit` |
| `personality_changed` | `may` | `omit`（仅他人） | `omit` |
| `appearance_changed`（人物） | `may` | `omit`（仅他人） | `omit` |
| `appearance_changed`（地点/物件） | `may`（场景细节） | — | `omit` |
| `time` | `may` | `may` | 全局，不适用 |
| `no_change` | `may` | `may`（全局/同处） | `omit` |

注意：

- 人格变化、地点外貌、时间、无变化都**不是**四条 must；不要因为“叙事上需要”升为 `must`。
- `appearance_changed` 的主体是地点（`loc_*`）时按“地点/物件”行；主体是人物时按“人物”行。
- 同一事实同时满足 must 与 omit：`must` 优先（典型是“在追任务”）。

## 6. 边界与不确定

- “仅他人”看事实主体 `entityId`，不看文本里是否提到主角。
- “安全”必须有理智变化或明确危险文本；不得从普通移动/任务臆测危险。
- 不引入 rubric 之外的产品偏好（例如“这段写起来好看”“时间必须出现”）。
- 不确定时仍必须给一个标签，并在 `note` 写“不确定 + 原因”；裁决时优先看备注。

## 7. 标注文件格式

`labels-<annotator>.jsonl`，每行一条，顺序与盲表一致：

```json
{"itemId": "n2-01", "factId": "f1", "label": "must", "note": ""}
```

必须覆盖盲表全部 92 条事实，不得增删 `itemId/factId`，`label` 只能是 `must` / `omit` / `may`。
不得查看另一标注者的标签文件后再修改自己的标签。审查者负责对分歧做最终裁决
（`labels-adjudicated.jsonl`，只含分歧项）。

## 8. 冻结与门

- 两人独立标完后计算 Cohen's κ（三分类，92 条）。κ≥0.7 才允许冻结 v3；<0.7 回到 rubric 讨论，不强行冻结。
- v3 = 两人一致项 + 审查者裁决项。
- 门：v3 与 v2 的 `must` 集合按项比较；差异项 > 2/16 则重建 N3 的 16 项输入，否则沿用现有 16 项。
- N2 的判据按联合决策 D1：must recall ≥0.95（硬）+ must precision ≥0.85；may 选择率只报告；
  `target` 精确匹配降为诊断。预登记失败分支见 D1，不在标注阶段改写。

## 2. 旧格式：只用于旧权重兼容

格式标识在制品清单中记为 `yuyan-prose-legacy-v1`，这是本次为既有格式登记的名称，不是原文件已含的字段。标识不追加到入模文本。

结构化 X 保留四字段：视角、上回合状态、本回合变化、本回合状态。`split_xy.build_text` 使用 `json.dumps(x, ensure_ascii=False)`，因此 `xText` 自身有 JSON 空格；不能误将它直接当作 YuYan 的实际输入。现有模型消费的是 `render_row` 生成的 `xProse`。

下列换行仅为说明段落边界，实际拼接没有这些换行：

```text
【视角】<视角>
【地点】<地点句>…
【人物】<人物句>…
【物品】<物品句>…
【变化】时间推进<时间>。<变化句>…
【正文】
```

没有对应实体时省略该类标题。旧版没有结果块；不增加空白、指令、角色消息、禁止直述清单或新标题。无实体变化时，变化段在时间句之后固定接 `这一回合没有结算出变化。`。

| 项目 | 实际旧规则 |
|---|---|
| 视角 | `squash(视角).split("；")[0]`；分号之后的限制语不在实际入模串里 |
| 地点/人物/物品/变化实体顺序 | 分别使用 Python `sorted(...items())`，按名字码点序 |
| 列表顺序 | 外貌、个性和任务列表保留源顺序，不另排序 |
| 文本列表 | 每项经过 `squash`，剥离末尾 `。；，`，以 `、` 拼接 |
| 地点和物品句 | `名称（在<位于>里）：<外貌>。`，缺父地点或外貌时省相应部分；这里读取 `位于`，并未读取物品的 `位置` |
| 人物句 | `名称：在<位置>，精神值<值>，外貌<列表>，个性<列表>，任务<任务串>。`；缺字段省对应部分 |
| 任务串 | 大任务在前，再依小任务列表顺序；每条为 `目标（状态）`，以 `；` 分隔 |
| 实体变化句 | `名称（类型）：<操作短句>，… 。`，实际不含示意中的空格 |
| 操作短句顺序 | 移动到、精神值变成、去掉外貌、多出外貌、去掉个性、多出个性、完成、新任务 |
| 正文目标 | 段落之间用词表内 `※`，展示时恢复；输入结束于 `【正文】` |

上表用于阅读，逐字节依据仍是对应哈希的函数，不是照表另写一份“差不多”的实现。旧 `squash` 只处理普通空格、制表符和全角空格，并不是完整空白/OOV 校验；当前 199 行无空白不能证明任意运行输入安全。新增边界检查应拒绝不能安全编码的输入，并保留原值；不得静默拼接有歧义的词或数字。

旧 `describe_change` 通过分组表判断类型，而平铺结果不能补齐该分组；类型缺失时默认人物。旧 `place_line` 对物品 `位置` 的处理也不完整。这些属于需要金标与字段覆盖检查的风险，不能把“输出里出现实体名”当作字段已经表达。

## 3. 结果块缺陷：选择 A，版本化修复

新训练采用方案 A，拟登记为 `yuyan-prose-result-v2`：修复结果渲染，重新生成训练输入、核验并训练/验证；是否继续使用 YuYan 由完整 goal 的方法选择决定。本次仅固定修复要求，尚未改来源代码、生成新版数据或提交 HPC 作业。

1. 保留旧文件、旧权重和旧对照，不就地覆盖现有 `rows-yuyan.jsonl`。
2. 新格式保留原顺序，在变化之后、正文之前增加明确的 `【本回合状态】` 结果块，只在结果非空时输出。
3. `本回合状态` 是“实体名→发生变化字段的已结算值”。从实体注册表及投影确定类型；字段缺失表示本结果未携带该字段，不表示删除或零值。未知实体或类型歧义直接报错。
4. 结果按类型的固定顺序、类型内名字码点序输出，仅渲染实际存在的字段。精神值为 0、空外貌列表、空个性列表等也必须明确表达，不能用真值判断丢掉；任务仅携带已登记的变化任务结果，保留父子关系。
5. 位置变化必须具有结果位置，涵盖人物与物品；不能照搬只展示外貌的 `place_line`。当前 `rows_common.build_result` 的非人物分支也没有拷贝位置，应与新版渲染一起补齐，不能只修 `render_state` 就宣布字段完整。
6. 固定每个字段的最终句式与空值表示后生成金标。类型、标题、句式或字段投影再次变化均另立格式版本；新格式不得用于宣称旧权重同条件复现。
7. 只有确需完整合并后视图时，才从已提交 before＋delta/after 构造并登记新的输入版本。本次补回部分结果并不等于模型获得了完整最终快照。

训练清单同时登记 `projectionVersion/serializerVersion/modelTemplateVersion/tokenizerHash` 和源数据/转换代码哈希。旧 baseline 不作废，只是不代表新版本质量。改用 instruct 模型时另登记该基座 chat template，并重建其训练输入。

格式修复保留同行集合、行 id、目标与 `splits/v1.json`，新增数据另立版本；旧格式与新格式各用匹配权重，在同一批冻结公开样本上配对报告。若要将变化归因到结果块本身，还需同条件重训旧格式的受控对照，不能仅比较历史与新 checkpoint。具体解码控制、归因边界与验收要求见 goal 第 6 节。

## 4. 投影、槽位与名称

可见性单位采用最内层 `location`；沿人物或物品容器链定位，`slot` 只是容器内部细节。同一最内层地点可在同一场景，不同子地点不因共用父地点就自动互见。路明非的 `lane/wall` 与诺诺的 `lane/entry` 属于同一服务巷；进入子地点才改变这一边界。

现有数据 README 的取数口径是：变化实体进入；人物以主角结束时同小地点为可见范围；收取人物位置所指的小地点、必要的上级名称及主角出发地点；物品只收本回合变化的物品。它没有规定收全体兄弟地点或同地点所有物品。README 中“所有变化实体”与“仅同地点人物”的先后关系不够明确，运行时按以下方式显式拆开，补入新投影向量：

- 输入实体集保留所有已结算变化实体，另外纳入主角及结束时同地点人物；原位置、目标位置和引用需要的地点作为依赖纳入。收哪些父层描述按源样本核对，不默认展开全部祖先和同级。
- 输入包含的离场人物、异地变化或后台字段并不自动获得正文可直述权限。可见集单独计算和记录，不能拿“已被序列化”证明“主角已经知道”。
- 保留的变化与结果必须一一对应。哪些字段需要上回合值，按原数据语义取数；不能用结束位置冒充变化前位置。

开局没有 delta，而旧规则可能不纳入任何物品。需要介绍可操作物品时，必须单列“开局投影”的数据与检查，或在新版统一扩展相关物品取数并重建训练数据；不能虚构一次物品变化来把开局伪装成旧训练行。完整世界不缩减，投影不得直接转储全部实体。

同一字段引用使用实体全称；位置里的槽位以其标签和所属地点消歧，不把槽位裸 ID 送进模型。完整实体表保留给程序处理，最长匹配用于检出误认。“钟楼”本身也是合法地点名，不能只因为它是“钟楼门厅”的前缀就一律禁用；应核对该次引用的实际实体与位置层级。

槽位按 `(containerId, slotId)` 定位，不使用混合的裸 ID 索引。本展示素材的槽位统一使用 `slot_` 前缀，包含 `slot_cage` 和 `slot_upper_stairs`，并检查槽位 ID 不与任何实体 ID 重名；全面扫描也发现 `top`、`empty_bed` 等其他跨类型重名，不能只改两个就宣称消除这一类误用。这是一条素材约束，不改变通用世界状态 schema。改动后重新登记资产哈希。

本次重新构建后的文件 SHA-256 为 `6262d5fcf088959bb427fbd2dfef7472bcf2cbf78edb9c76b98d4ea2b25db92e`，`stateDigest` 为 `3f65452daf352c636ac4b24dcefcfb1cc8633ee811a6613a34ce5c43ef233f4e`。现有 Pydantic 契约、导出 JSON Schema 与 S₀ 重建比较均通过；全部 108 个槽位（包含人物与物品内部槽位）已加前缀，槽位/实体 ID 重名为 0。26 个地点、14 个人物、74 件物品、73 个任务不变。此前 `59ed85ce…` 的文件哈希对应改名前版本，不能继续用它指代新文件。

## 5. 长输入与视角输出边界

实测训练输入中位 334、最大 741 字。此前自由一日开局约 1,227 字的估计已由用户确认采用了过大的取数范围，不能再作为实际投影长度依据；运行时入口尚未实现，实际长度待测。字数分布、真实 tokenizer 的输入 token 数和输入＋目标窗口是三个不同指标，分别记录。加入结果块后需重新统计整个分布。按 goal 第 6、7 节冻结公开投影的上四分位阈值，并单列长输入质量，不能只测速度。

不默认“取前 N 条”就安全：实体位置、已发生变化及其结果、涉及的时间/精神值、任务达成和新增任务、解释本轮行为所需的前提均受保护。其他描述只有在固定、可复核的相关性策略下才可省略，日志逐项登记 `entity/field/originalValue/reason` 和省略前后字符/token 数；只保留 ID 或字段名不足以追溯。任务上下文不能只保子任务而抹掉解释其含义的大任务。

裁剪策略属于投影版本，必须同时用于对应训练样本，不能只在运行时临时删个性和任务。受保护事实仍装不下时，应更换输入策略、上下文或模型并验证，或明确报告当前输入不受支持；不以反复丢字段伪装支持大世界。补充 900–1,300 字等长输入样本可作为开发方向，仍需按实际新分布、模型 tokenizer 和完整目标留足空间，不能只凑字数。

先保留数据已有的全知输入，约束和核验放在输出侧。个性、任务和历史信息在输入中出现，不等于其他人物可以公开说出，也不等于主角已经知道。以同一已提交状态、当前视角、合法前文导出输出许可与禁止直述项，逐条标注来源和原因；不能把所有他人心理一律判泄露，也不能把任务目标当已发生事实。

这些是只读运行/评测元数据，不创建新的长期知识真值库，不添加事实，不进入旧权重入模串。逐次记录泄露项、原文、事实来源和许可依据；候选最终按实际启用的检查/重试路径验收，并计入端到端耗时。若全知输入路线仍无法达到视角要求，允许改成主角已知投影，但必须版本化、重新生成训练输入并验证，不能因兼容旧格式豁免质量。

## 6. 七项检查及其准确含义

| 检查 | 要求 |
|---|---|
| 往返 | 结构化投影的无损 JSON 往返必须成立。旧自然语言格式会删除空白、标点和部分字段，不具备通用无损反解析能力，不能虚报。新版以显式字段映射/渲染账本验证受支持语义；若声称可反解析，必须先定义转义及歧义处理并实际测试 |
| 覆盖 | 每个保留的变化字段与结果字段映射到具体文本区间；无多出的事实。结果为 0、空列表、物品移动和任务层级单列负例；不是只查名字出现 |
| 集合相等 | 分别断言投影实体集、场景可见集、允许直述事实集与各自预期完全相同；这些集合不是同一个集合。公开反例涵盖离场、异地变化、不同子地点、同地点不同槽位 |
| 名称 | 名称全称和角色/地点层级正确；程序使用注册表，文本用最长匹配辅助检查。不得将一个合法父地点名因其也是前缀而误拒，也不以字符串全局搜索断言“任何英文都是 ID” |
| 长度 | 输入、目标和合计 token 数分别记录；任何语义裁剪按固定版本记录具体删项，禁止静默截断。超过训练分布另作质量压力测试，不能只看上下文是否装得下 |
| 确定性 | 同一已冻结输入产生相同 UTF-8 字节与 SHA-256；明确无 BOM、无末尾换行、名称码点排序、数组顺序和数字表示。旧版规范化仍按旧版，不暗加 NFC 或新标点处理 |
| 实现一致 | 同源实现优先；若有 TS 移植，以冻结 Python 金标向量逐字段、逐字节及 token 序列差分。金标本身也需与真实历史输出核验；通过有限向量不等于证明所有输入都等价 |

Python 字符串排序和 JS 默认 UTF-16 排序对非 BMP 字符可能不同，不能仅因常见汉字样本一致就认定实现等价；数字格式、布尔/空值、转义、空白和 CR/LF 也要明确处理。所有异常路径应有稳定错误类别，不让错误输入产生部分合法正文。

覆盖历史真实行（含 `row-0006` 和无变化行）、位置/物品归属、各类外貌/个性增删、精神值 0、任务完成/新增/层级、空列表结果、同地点不同槽位、同上级不同子地点、离场与异地变化、名称前缀和非 BMP 排序、空白/OOV、未知实体和长输入。负例不要求强行渲染，应精确比对拒绝原因。来自自由一日的向量必须走真实世界投影入口，不能靠人工先写好 X 来证明入口正确。

## 5. 失败是怎么来的

**主要机制是“句子变短”，而修订把这件事推得更远。**

- 输出长度：u240 平均 13.0 字、15/85 带第二小句；对照组 13.4 字、16/85；实验组 12.2 字、**6/85**。
- 训练目标平均长度：修订池 16.7 字，原池 18.5 字（只改了 50 条，最短从 10 字降到 8 字）。
- 新增文本 6 → 2 → 0 和这个缩短同步出现；对照组没改目标也把新增从 6 降到 2，**说明“少写”主要是多训 240 步的效果，不是修订的效果**。

**事实损失集中在 4 条“目标和自己的事实不一致”的训练行上。** 这 4 条在原池里就不一致
（机器覆盖率只有 0.29–0.38，人工确认是把“塔顶的灯芯”写成“备用灯芯”、把“一叠干纸”写成“干纸”）：

| 训练行 | 事实 | 修订后的目标 | 出现的错误输出 |
| --- | --- | --- | --- |
| `vb:n4n-01:f1` | 换好了塔顶的灯芯 | 沈砚换好备用灯芯。 | cf24 `t11:f2` 待复核、`t23:f3` 遗漏、final24 `v13:f1` 待复核 |
| `vb:n4n-67:f0`、`vb:n4n-78:f1` | 把一叠干纸放在桌角 | 阿棠把干纸放到桌角。 | cf24 `t09:f2`、`t13:f1` 待复核（两臂都有） |

对照组也踩了后两条（所以它也掉了 2 条事实），但它的目标更长，没有把“备用灯芯”当成完整答案；
实验组删掉尾句后，这条错误名词成了整条目标，模型学得更干净、用得更随意。

**不能把这件事归成“修订本身有害”**：两臂都掉事实，区别在 4 条不一致的训练行被缩短后更容易被复制。
这是数据审计问题，不是配比或步数问题。

## 6. 口径修正（上轮报告）

- 上轮把 74 条写成“独立”过强。准确说法是**事实签名未重叠**：签名 = 种类 + 主体 + 值，或 种类 + 主体 + 起点 + 终点；它不能排除短语级记忆（`t12:f0` 的新增“一叠纸”就来自别的地点场景）。本轮表格改称“签名未重叠”。
- 上轮说“这是训练数据缺陷，不是模型能力问题”也超出了证据。准确说法是：**新增尾句与训练目标高度吻合，支持“记忆迁移”的解释；但同一现象也可能是模型偏好短句+复制的行为，现有数据不足以排除后者。** 本轮的缩短效应正好说明“生成倾向”和“数据内容”两者都参与。

## 7. HPC 训练命令（给能提交作业的环境）

```bash
# 1) 取分支
git fetch origin && git checkout world-components-next && git pull   # 或按你们的合并方式

# 2) 两条等预算命令，只有 --pool/--run-dir/--arm 不同
python -X utf8 -B experiments/world-components/train_revision_arm.py \
  --base <u240 权重目录> \
  --pool experiments/world-components/n4_narrative_dev/verbalizer_pairs.jsonl \
  --pool artifacts/next-inputs/world-components/n4-expand78-unified.jsonl \
  --pool artifacts/next-inputs/world-components/n4-object34-unified.jsonl \
  --steps 240 --batch 8 --mix 4,3,1 --run-dir <运行目录>/cf24-arm-control --arm control-original-targets

python -X utf8 -B experiments/world-components/train_revision_arm.py \
  --base <u240 权重目录> \
  --pool artifacts/target-revision-r1/verbalizer-revised.jsonl \
  --pool artifacts/target-revision-r1/expand78-revised.jsonl \
  --pool artifacts/target-revision-r1/object34-revised.jsonl \
  --steps 240 --batch 8 --mix 4,3,1 --run-dir <运行目录>/cf24-arm-treatment --arm treatment-revised-targets
```

训练后必须校验：两份 `train-report.json` 的 `sampling.idSha256` 相同、`targetSha256` 不同。
权重各自输出，u240 只读。评测在 CPU 上跑，命令与第 1 节一致；HPC 上训练完把三个 ckpt 取回本机评测，
保证三个模型同一设备口径。

## 8. 局限

- 单世界、单检查点、单次运行、单种子；训练在本机 GPU，评测在 CPU；没有第二个种子重复。
- 验证集 76 条里只有 1 条移动单元，**移动类退化在验证集上几乎测不出来**，只能靠 cf24（开发回归）。
- final24 有 25 条事实签名与 cf24 重叠，实验组在 `v13:f1` 的退化恰好是 cf24 也测过的事实类型，两者不完全互证。
- 机械判定仍有一个已修的 bug 记录：`other-place` 曾把“可见”清单里的物件当成未授权地点，本轮已修并重算。
- 人工判读一人完成，每条带原文。

## 9. 下一轮建议

1. **先做目标/事实一致性审计，再谈训练。** 规则：每条训练目标对自身事实值的机器覆盖率低于 0.5 就必须人工复核；本轮 4 条确认不一致，另外 27 条是合理改写，需逐条判定。
2. 重写而不是删除：把“备用灯芯”改回“塔顶的灯芯”、“干纸”补回“一叠”，保持目标长度接近原分布，避免把“变短”当成疗效。
3. 保持两臂等预算与同采样序列的做法；验证集要补移动单元，否则移动类退化不可见。
4. 修复后仍用同一套 cf24 + final24 复跑；不达标就继续记录失败，不靠加步数追分。

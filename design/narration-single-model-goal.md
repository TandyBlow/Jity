**可交给执行模型的 goal 正文**

你的目标是交付一个完整可玩的 Jity 浏览器版本：从静态文件载入初始世界后，玩家输入行动，浏览器本地完成行动判断、目标识别、被迫反应、共同结算、六阶段状态更新、继续推进和叙事生成；支持连续游玩、历史查看、进度恢复及叙事缓存重生。玩家能够在真实页面看到实时生成的中文正文，符合已结算事实与视角边界，风格接近训练材料中的优质范文。服务器只能保存与读取进度，断开该服务后仍可继续游玩与本地保存。交付并通过完整功能、事实、文风与浏览器实测后，才可宣布 goal 完成。

实现方法以结果为准：允许单模型、多模型、共享骨干、微调、提示词、程序规则、约束解码、检索与编辑等组合，按本地可运行性、完整语义能力、事实正确与文风效果选择。单模型微调是已有候选路线，不是完成条件；改用多模型不需要因模型数量单独请示。可以使用程序和模板作为生成的一部分，但它们也要在未见场景与连续回合上达到同样质量，不能用固定答案、检索考卷正文或只支持少数命令的流程伪装通用完成。任务拆分和训练本身不是交付结果。

允许事实范围约束：限定可引用的实体、事件、关系和状态，不能把输入中的词随意组合成新事实，也不能禁止用户允许的文学润色。约束接口只表达允许范围和失败原因，不暗藏题目答案。明确记录模型、程序、检索、模板、编辑和重试各自贡献，最终产品按实际启用的整条路径验收，不要求把程序辅助包装成“纯模型能力”。

输入规格与处置记录见 `design/world-engine-reports/components/narration-input-adapter.md`。已核对现有 199 行：结果块有 198 行非空，但旧 YuYan `render_state(after)` 对全部平铺结果均输出空串，实际输入只有“视角＋上回合状态＋本回合变化＋正文标记”。旧权重复现必须逐字节兼容这一路径；新训练采用修复结果块的独立版本，重建数据并训练/验证，禁止将新格式直接用于旧权重后声称同条件比较。旧基线保留为历史对照，不删除，也不预先认定漏写导致了短文或捏造。

实现统一、可复用的输入适配入口，让同一版本的训练、离线生成、浏览器生成共享投影与序列化规则。直接复用可执行的同源实现，或移植到浏览器并以 Python 金标向量逐字节校验；不得新增运行时 Python 服务器依赖。任何字段、词序、长度裁剪、视角输入或模型模板变动均版本化并重建对应训练输入。禁止静默截断：实际输入和目标的 token 长度、截断与停止原因都要记录。投影不包含参考答案或评测标注。

可见范围按最内层地点判断，槽位只表示地点内位置，不切断可见范围；上级相同但子地点不同仍分别处理。实体取数集、输入中的后台事实与允许写进正文的事实分开核验。旧数据并非“当前地点＋全部祖先＋所有同级＋全部在场物品”，不得将此当作已有规则。先保持数据已有的全知字段作为输入，对其他人物的未公开心理、任务和往事设置来源明确的输出限制与逐条泄露检查；这些核验元数据不得偷偷追加到旧权重的入模串，也不建立第二套人物知识真值库。若该路线未达标，可按证据改为主角已知输入并同步重建数据和训练，事实与视角门槛不降低。

换用 instruct 基座时，使用该模型自带的对话模板和特殊 token 约定，按新模板重新生成训练输入，并核对浏览器推理路径使用相同模板；旧 YuYan 的“X 中不加指令”是历史对照设置，不随换基座继承。规范、视角及状态可进入指令或上下文，参考答案只作训练目标并正确计算 loss mask；参考答案和评测标注始终不得混入模型输入。模板变换保留原始状态、语义等价检查和数据版本，不把换模板误当成新事实。

如使用现有 YuYan 路径，适配后的最终入模字符串必须不含空格、换行及任何词表外字符；对普通空格、制表符、CR/LF、全角空格与其他空白字符逐一处理或拒绝，并检查 tokenizer 实际可编码性。旧记录报告非法字符会使运行时抛出 `invalid unordered_map<K, T> key`，不能把它当作仅影响段落的显示问题。保留原始输入，明确规范化是否改变字段含义；不能为通过字符检查静默破坏标识、数值或对白。段落标记须在词表内、能往返，且不与正文原字符冲突。为正常输入、含空白输入、词表外字符、段落恢复写针对性检查，并在真实浏览器走一次。该限制针对实际 YuYan 词表与运行时，不泛化成所有新基座都不能使用空白。

若任务需要玩家原话、上一段叙事、已发生的说话或失败事件等上下文，检查这些信息是否存在、来源是什么、是否进入训练。存在则只读接入；不存在则明确记缺口，并在新版本数据中补登记合成上下文。不能靠模型猜测缺失的因果关系，也不能把人工编写的材料冒充数据库中的真实玩家历史。不得为所有样本强加长篇前文；只给当前叙事所需的信息。

人物和任务层级、位置、物品归属、外貌增删、个性增删、精神变化方向及时间关系都必须正确。非叙事部分生成候选，浏览器内统一状态内核负责校验、preview、应用、合并、提交与回放；叙事只读已提交结果，不回写世界。任务目标不等于已执行动作或已完成结果；人物个性也不直接证明此刻心理。

游戏运行不能调用服务器进行行动推理、结算、骰点、身份分配、状态计算、语义核验或叙事生成。现有 Python 内核可作开发期参考、差分测试依据或迁移来源，最终运行采用浏览器可执行的一套权威实现，例如移植或 WebAssembly 运行，技术路线自行验证；不能在浏览器失败时悄悄回退 Python 计算。

浏览器维护世界 S₀、Δ、工作态、已冻结行动、骰点、输入消费状态、进度版本和可恢复缓存；本地持久化可用 IndexedDB 等机制。服务器只接收、存储和返回浏览器已产生的进度，不替用户计算或改写事实。断开保存服务后仍可推进和本地保存；恢复连接后同步进度，检查版本冲突、避免旧进度覆盖新状态。刷新、重复提交、取消恢复与多标签页需保证不会重掷骰点、重复行动或重复应用增量。服务器进度副本不是第二套游戏计算权威。

进度同步使用不可变快照标识、父快照标识与服务端单调递增的保存修订号；同一内容的重复上传幂等。修订号只表示保存顺序，不能替代祖先关系判断。正常推进云端头指针时，本地快照必须是当前云端快照的后代，附可核对的父链，并用“预期云端头＋预期修订号”作原子条件写入；服务器只核对存储元数据，不执行游戏计算。相同快照无须再写；本地是云端祖先时不反向覆盖，提示可载入较新云进度；双方互不为祖先或条件写入失败时，重新读取并判断，不按时间戳或版本数大小强行覆盖。

确认为分叉时，保留本地和云端两支完整副本，展示分叉位置与各自进度，由玩家显式选择后续使用哪一支；选择只改变活跃进度指针，不静默删除另一支，也不自动合并游戏事实。首次上传没有云端基线时用空头条件建立，显式导入的无共同祖先进度视作另一分支。单列两设备从同一进度离线推进、并发上传、分叉选择、另一支可恢复以及重试不重复结算的测试；保存接口不得退回“最后写入覆盖全部”。

静态世界文件记录路径、格式版本与哈希，载入后校验实体引用、位置图、任务树和状态约束，通过后封存为 S₀ 并持久化初始记录。缺字段、循环引用或不支持版本要明确报错，不让模型临时补写初始事实。未通过校验不得开始回合；进入游戏后的变化走正常内核，不能直接改静态初值。开局不需要世界生成模型、对应训练数据或生成等待额度。浏览器加载器还必须独立重算状态摘要（`state_digest` 为对 `model_dump` 结果做规范化字节编码后取 SHA-256：键排序、键限 ASCII、只接受安全整数、非 ASCII 原样输出、只转义引号、反斜杠与控制字符），与素材登记值比对；不一致即拒绝开始回合，不是警告。摘要匹配只证明该份状态在所测路径上编码一致，不证明所有输入的解析、校验和后续结算等价；边界与拒绝路径仍按既有契约验证。

静态文件格式已经由用户确定为项目现有世界状态格式，不再设计第二套 schema。当前公开展示样例是 `data/worlds/dragon-raja-free-day.world.json`，直接使用 `backend/app/schemas/world/contracts.py` 的完整 `WorldState`；其 `initial` 是既有 `WorldInitialState`，状态 schemaVersion 保持 1，与协议响应版本分开。题材为“自由一日·钟楼争夺战”，包含丰富且参与实际观察、决策与变化的地点、人物关系、物品与任务；新增内容须说明用途，不能用空洞描述或重复目标凑数。样例和一页格式/书写说明见 `data/worlds/README.md`，构建校验入口为 `scripts/build_free_day_world.py`；这些是公开开发素材，不是独立终验。

**3. 叙事质量及创作边界**

正文应像一个完整的叙事段落或场景，能理解谁在做什么、为什么接上这一句、人物之间是什么关系。允许按剧情需要有长短变化；不为凑字数添加对白，不把短句、对白比例、段落数或词句重合率当成质量本身。

以优质范文的表达方式为参照：环境服务于当前人物和事件，对白有上下文，动作和停顿承载情绪，心理符合视角与已知背景。避免机械罗列字段、重复绕圈、人物突然换动机、答非所问、把状态面板写进小说，以及为了保守而什么也没说的空段落。范文也要接受事实和风格审核，不能因为进过训练集就一律判对。

不要求把每个变化逐条念出来。先按样本语义登记影响玩家理解的关键结果、可以省略的背景变化和禁止泄露的内容；关键结果必须表达清楚，可选变化允许自然省略。不要直接沿用旧版“每个字段都是必述”的判据。

允许不改变已结算状态和剧情判断的眼神、停顿、细微动作、对白措辞与视角人物的合理心理润色。不得借此新增线索、证据、具名人物、重要道具、关系、关键往事、任务完成、物品转移或会影响后续决策的承诺。对白里的事实主张也要有输入依据，不能因它是角色说的话就免于核验。能否改变玩家对局势或可行动作的判断，是区分润色与新增剧情事实的重要依据。

对存疑的训练样本写明问题与处理方式：补充已有可核对依据、排除样本，或建立经审核的修订版本；保留原始版本。不得为迁就模型输出反过来放宽边界。同名人物若属于不同合成世界，不强行改成同一设定；若确属同一世界的连续回合，则检查跨回合一致性。

**4. 执行路线与 HPC 使用**

先用现有整段叙事权重生成一批有代表性的完整输出，建立可复跑基线。同时尽早确认该架构、分词器和目标上下文能在浏览器实际执行；不要长时间训练完成后才发现无法导出或浏览器运行不了。

同时核对非叙事分支的真实实现与测试：任务书、模拟端口、接口通过不能算相应游戏能力已经完成。先完成静态世界读取与内核基础，再接通普通行动的本地全链、目标→反应→共同结果与六阶段依赖，随后扩到至少 20 次输入。允许交错优化叙事和非叙事，用同一状态内核、相同实体与数据投影反复集成；不为证明“组件都存在”分别交付一批互不兼容的实验。任何阶段缺口仍保留在能力表中，不能仅普通回合通过就结束整个 goal。

优化开始前先冻结任务边界、评分规则、公开开发集及来源登记；开发题可由执行 agent 准备，但必须标为公开测试，永久不得改名为独立终验。可以立即复现基线、修训练代码、适配输入并准备浏览器运行，不要求用户先写完终验题、正向锚点或回归提示。独立终验包及备用包可由用户或隔离评审方随后提供，冻结时点与访问边界见第 6 节；缺包只影响最终验收，不阻止公开材料上的开发与训练。任一新基座在提交训练前，必须先用该基座的真实浏览器量化路径通过第 7 节的容量与速度准入。

设置早期可行性检查点，不规定它必须占几天：先完成基线完整生成复现、数据问题归类、浏览器状态内核迁移与已有非叙事成果核对，以及目标浏览器速度/容量准入，提供主要缺口和下一轮最有依据的干预。这个检查点先不做新增微调；推理若使用 HPC GPU，应如实记录资源使用，不能声称“不训练就不消耗 GPU”。报告供用户及时调整方向，不是预算申请，也不因等待回复而停工；在当前授权和要求内继续实现、修复与必要训练，只有实际需要改变游戏语义、事实边界或降低验收标准时才请求用户决定。模型数量、提示词或是否微调按证据自主选择。

向用户或独立出题方索要全链输入包之前，先提供现有 `WorldState` schema 的准确引用、已通过校验的静态展示文件和简明书写/读取说明；无需用户猜新格式，也不让独立出题方先替开发方排格式错误。优先使用本轮已经准备的自由一日样例说明格式，独立输入和世界选择仍按第 6 节保持隔离；格式样例可公开，终验题不可因此公开。

按结果定位问题：输入是否被读取、序列化是否缺信息、监督正文是否越界、数据覆盖是否不足、模型是否只学到文风、分词器是否损坏段落、解码是否循环或提前停。每轮有明确待验证的问题和可比较结果，再决定补数据、修改训练、调整模型容量或换基座；不要无目的铺开超参数搜索，也不要反复换提示词而不训练和复测。

不固定旧 77M、YuYan 或某一种生成方式。根据全流程功能、正文质量、浏览器资源共存与实测等待选择模型和程序组合；不继承旧实验的参数量上限、固定组件数、4090 禁用或“不训练”限制。本任务允许在 HPC 上训练叙事及非叙事候选，但已有模型或程序达到要求就直接复用，不为完成某种技术路线而强行训练。需要外部模型或运行库资料时查官方来源，并记录版本与许可。

微调训练在 HPC 的计算作业中进行。复用现有连接、上传、提交、轮询和取回机制，运行时读取凭据，不在文档、日志或版本库写入密钥。提交前检查已有作业，记录 job ID、运行目录、数据和代码哈希、基座与 tokenizer 身份、训练配置、checkpoint。使用本任务独立的远端结果目录，保护其他任务的环境和运行中作业。

正式训练前先做必要的短程验证，确认数据、loss mask、结束符、段落编码、保存和重新加载正确。尤其验证“保存后重新加载的模型”能复现被评估的模型，避免只存 adapter 却遗漏其他可训练权重。训练曲线用于诊断；晋升模型要看实际自由生成的正文。

不设置预定的训练次数、GPU 小时或总工期上限；冒烟与正式训练按验证需要开展，不因跑到某个人为数字而停工。保留可恢复的实验记录：run ID、job ID、用途、基座、数据与配置、起止时间、实际设备、运行结果和下一步依据，用来避免重复提交与无效试错，不作为预算审批台账。集群单个作业的 walltime 按调度要求申请，支持 checkpoint 续跑；作业时限不是整个 goal 的停工条件。

换基座须有可核对的开发证据：先检查状态/监督一致性、分词和截断、loss mask、结束符、保存加载、输入是否被使用，记录关键失败、已做干预、训练集与隔离 dev 的差异，以及为何怀疑容量、预训练适配或浏览器运行限制。已知硬性不兼容时可以直接排除，不必为满足次数凑训练。训练集也拟合失败与“训练拟合但 dev 失败”分别分析，后者不能直接推成容量不足；容量归因按证据强度表述，不能假装已证明。不设更换次数上限，但每次都要比继续修数据或运行路径更有依据，禁止循环回到已证伪且条件未变的候选。所有判断基于公开开发材料，不能先看终验答案再决定路线。

训练前固定 5 条与本任务无关的公开中文续写提示，可由执行 agent 从适合的材料中准备并登记来源，覆盖说明文、议论文、日常应用文字等表达；与训练语料隔离，固定提示、解码和种子，不将其加入训练。训练前保存基座输出，候选定稿后保存微调输出，再对最终浏览器量化版复测；不采用正文范围约束掩盖能力退化。准备与运行不等待用户先出题，最终由人按成句能力、语义连贯、中文表达与循环情况并排比较，不以变得更像训练文风当作进步。任一项出现基座原本没有的明显崩坏、持续循环或普遍无法成句，即回归失败、不得交付。保留 5 条原始对照与人审记录；单条旧保持能力探针不能替代这组检查。

上述“不以变得更像训练文风当作进步”只适用于这 5 条非叙事提示的通用中文能力回归，不适用于游戏叙事正文。叙事正文按第 6 节文风维度评价，向训练优质范文的读感靠拢正是交付目标。

失败后继续定位和修复。HPC 作业有三个等待窗口，每个都要检查可推进的工作，不能只轮询：

1. 已提交、尚未获配资源，即排队中。
2. 作业运行中，结果尚未产出。
3. 作业结束，但结果尚未取回或尚未评估。

提交每个 HPC 作业前，在本轮实验记录中列出等待期间要做的 2–3 件具体任务，写明各自的依赖、可中断步骤和预期产出（文件、数字或判定）。任务从下方常驻清单中选，优先做能改变下一轮决策的验证，不以纯整理替代。预计任一等待窗口超过 20 分钟时，必须先开始其中一件，不能以“窗口太短”为由空等；窗口更短也要按可中断步骤推进，不能等满 20 分钟才开始。20 分钟只用于安排等待工作，不是 goal 或作业的运行上限。

评估准备不能等到 checkpoint 取回才开始：在提交前或作业运行期间准备好评测脚本、冻结的公开开发样本 ID、解码配置、统计口径、检查过的模型加载接口和结果目录，使“取回 → 评估”可以用一条已准备的命令完成。若是独立终验，提前准备运行入口和判分版本，未公开题包仍由保管方掌握，不为并行准备而破坏隔离。评估若因实际产物异常失败，立即修复并记录，不能将加载失败当作模型质量结论。提前备好有条件的下一轮候选配置或数据版本，但等本轮评估后再选择，不能机械地按预案连续提交。作业结果可用时优先取回和评估，旁支任务不得拖出新的空档。

HPC 状态轮询从 5 分钟间隔起步，长时间无状态变化时逐步延长；不短于 5 分钟一次，复用可用连接，不在多个进程重复轮询同一作业。登录节点的连接频率限制应按现有工具和实际反馈处理，避免密集重连。已有完成通知或提交工具主动返回完成时可立即取回，不为凑轮询间隔拖延。轮询间隔用于做其他工作；确需等待时使用可恢复、可响应用户输入的短时等待，不以长时间阻塞命令占住会话。

每次取回作业后补齐等待日志：`runId/jobId/submittedAt/allocatedAt/finishedAt/fetchedAt/firstEvaluatedAt`、各窗口实际时长、计划任务、实际产出路径或数字、未完成原因和首个评估结论。调度时间无法取得时如实写未知及原因，不猜测。计划任务没有完成要写具体依赖或中断原因，不能只写“在等”。日志与对应实验记录关联，用户能看出排队、运行和取回评估各花了什么时间。

不依赖新 checkpoint 的常驻工作清单：

- 浏览器：统一状态内核、页面与运行器、模型及 tokenizer 打包、真实流式切片、取消恢复、本地保存、云进度同步，以及显存和全回合计时；先用现有公开权重验证，不等待新 checkpoint。
- 评测：评测器正反例自检、评分锚点候选、公开开发场景的编写与版本冻结、四类跨回合检查的账本和记录格式。独立终验题的编写与保管仍遵守第 6 节，公开开发题不能转成终验题。
- 数据：审校与补行、`verify_rows.py`、`audit_rows.py`、泄漏预检、划分与哈希登记；运行中作业的输入副本保持不变，新材料另存版本。
- 输入适配：序列化语义、YuYan 词表字符检查、段落标记往返，以及含空白或词表外字符的处理和拒绝路径。
- 非叙事：静态世界读取校验、行动与目标、反应准入、组冻结、共同结果、六阶段更新和继续判断的接口、未见输入回归及状态差分；在本任务独立工作树集成，不修改来源工作树。
- 基座能力回归：5 条公开中文续写提示及基座首次输出必须在该基座正式训练前固定并保存；后续可并行做不可变基座的加载复核、浏览器侧采样和对比工具准备，不能把首次基座采样拖到训练后补做。
- 基线复现：用已有 adapter 生成完整正文并分类核验；这是推理任务，仍需检查设备占用，不抢占正在运行作业的资源或擅自在登录节点做重计算。
- 解码与约束原型：在现有公开权重上比较重复惩罚、n-gram 禁重复和实体/事件范围约束，记录重复、误拒合法表达与事实越界，不把仅有实体名正确当成事件正确。

若确实凑不出两件可推进任务，提交前逐类检查上述清单，记录已完成项和剩余项的具体阻断，不编造忙碌。三个窗口中若确实没有可推进工作，可以等待和轮询，但须保留这份排查记录；不能把排队当完成，也不得为了“看起来在工作”重复提交相同配置。缺凭据、网络权限、硬件不可达等外部阻断应准确说明并保留恢复点；仍有独立工作时继续推进，不无限重复同一失败操作。

防止无效循环：同一个关键能力项、同一类失败判据，在固定的公开开发对照上连续三轮没有实质改善时，禁止继续用同类小幅调参或同类微调重跑。轮次按完成了可比较评估的实验计算，不按 job ID 计数，也不能换样本、改判据或只换实验名重置连续失败。“实质改善”的主指标和判断依据在比较前登记，以对应语义错误减少或能力恢复为依据；loss 下降、输出变长、开头更通顺或只修好某一道题不能单独算实质改善。

触发后先写决策记录：三轮输入/配置与原始证据、分别排除了什么、还剩哪些未经检验的假设（数据覆盖、序列化、监督越界、解码退化、容量或预训练适配）、按证据强度选择的新方向，以及能证实或否定它的最小下一步实验。换方向必须改变待检验的解释或干预方式，不能把同类微调换名；有新证据确实改变旧假设前提时，可以说明后重访，避免无条件封死可能修复的路线。若替代方向也有充分失败证据，及时向用户说明需要改变的范围；不擅自降低验收要求，继续推进其余授权内可完成的工作。这条规则约束无效重复，不是训练次数、GPU 用量或总工期上限。

完成早期可行性检查后，继续按证据推进到完整验收；阶段报告、作业结束或已有一版可读输出均不是整个 goal 的停工条件。若平台实际出现配额、调度、权限或运行限制，则如实处理并保留恢复点，不提前假定这些限制存在，也不把外部限制写成验收通过。

**6. 评测集与验收方式**

将公开开发测试与独立终验分开。优化开始前冻结任务要求、rubric 和公开开发批次；执行 agent 可以自己出开发题、修题或增加覆盖，但新增批次都在使用前登记版本与来源，旧题和失败不得删除，所有这类题永久属于公开测试。不能把训练执行方自编题的高分作为最终独立通过依据。

最终验收题目由用户或与训练执行方隔离、未参与该候选优化的出题/评审方准备，按预先固定的覆盖和抽样规则取题；可在开发期间或候选冻结后提供，不要求用户开工前完成。终验协议在优化前确定；每个终验包的输入、参考叙事、关键结果/可省略/禁止内容标注及哈希清单，必须在接触该候选的测试输出、评分或专项反馈之前冻结。晚提供的题包不能依据候选暴露的弱点或强项临时挑题，也不能把失败题换成易题。参考叙事只供评审，不要求逐字复现。

完整题包由用户或评审方保管，训练执行方在候选权重、tokenizer、输入适配、约束、解码和代码哈希冻结前，只拿覆盖统计和清单摘要。独立题包未到时继续公开开发，不暂停训练等考卷；到最终验收时才需要独立包。正式评测只把实际运行所需输入交给推理路径，参考正文和答案标注不进入模型。文件哈希只能证明冻结后未改，不能证明训练方未见过考卷；无法隔离访问时如实记为公开测试，正式独立终验由用户保管未公开包完成。

训练集用于学习，dev 用于调参和选模型，test 只用于最终判断。已经被看过、用于探针或反复比较的旧 test 降为诊断材料；不因为文件名叫 test 就声称它独立。

格式换代只更换已登记的序列化与结果块，不改变已有行集合、行 id、目标正文与冻结的 `splits/v1.json`；先登记这些文件的哈希，转换后逐项核对行 id 和划分归属。新增样本或确需修复划分隔离问题时另立数据/划分版本并保留原版；不得为结果好看重抽已有行，也不能把不同划分的数字当作格式改善证据。旧划分若已暴露或存在泄漏，保留作开发对照，不能因冻结而追认其独立性。

格式换代另设配对诊断臂：同一批冻结公开样本、相同解码配置（含种子、停止条件与生成上限）和评测口径，旧权重使用 `yuyan-prose-legacy-v1`，新权重使用 `yuyan-prose-result-v2`；逐样本并列完整输入与输出、正文字数、事实错误、回声次数和四项读感分。禁止跨格式混喂后比较，也不能只报新臂就宣称改进。诊断不替代独立终验；若新格式在 dev 上明显较差，先查结果块句式、覆盖、长度和训练/推理一致性，再决定修复或另立版本，不能直接否定结果信息本身。

上述历史旧权重与新权重的对照只证明两套实际方案的差异，不能单独证明“结果块导致改善”。若要作结果块的因果归因，补充同基座、同行与目标、同划分、同训练配置和步数/种子的旧格式重训对照，明确其余变更；若还同时修复物品位置等字段，分别记录或设置消融。没有受控对照时如实保留归因未决，不为得到归因而阻塞已达标产品的其他工作。

现有语料包含重复名字、地点和相近情节，不能仅凭行号不同断言世界隔离。审计实体、地点、事件骨架和目标文本近重复，并按实际可实现的世界族或场景族划分。如只能地点隔离，就报告人物和措辞重合，不能写成完全隔离。另建新世界族测试泛化，合成来源如实登记。数据清洗和新测试都不覆盖旧归档。

本稿建议的终验集为 20 个独立新场景，加 3 组每组 5 个连续回合，共 35 次完整生成。连续组有登记的状态、事件与上下文来源，不是把 5 条互不相关的旧行拼起来。模型在第 2 回合起使用自己上一回合实际生成的正文，检查错误是否累积。题目覆盖普通互动、多人物与指代、移动、任务结果、外貌与个性变化、精神方向、物品归属、视角不可见信息、无变化或少变化等情形，不要求每题覆盖全部类型。

取消“至少 10 个真实玩家场景”的配额。验收状态必须可追溯到浏览器实际校验、结算、提交、本地持久化并重新读回的记录，以及对应前后状态、输入和变化。已有 Python 数据库中的 `world_points` / `world_advances` 可用于迁移、差分与开发参考，但不能代替最终浏览器状态路径的验证。有真人输入的优先，没有则用真实页面或脚本驱动浏览器产生轮次，明确标注为夹具。可编写测试初值和输入，不能手写前后状态 JSON 冒充运行结果；叙事作者不能修改已提交事实迁就正文。

准备阶段先积累至少 5 个独立场景和 1 组 5 回合连续结算的公开开发材料；已有服务可作迁移前参考，在浏览器内核可用后必须复跑并读回，不把参考环境通过误写成最终本地链通过。最终 35 次叙事验收保持独立；至少 18 次来自未用于训练的新世界族，具有人名与地点隔离，不以只改名的同一事件骨架充数。逐题登记 `caseId/worldFamily/sourceKind/sourcePath/sessionId/pointId/author/frozenAt` 及来源哈希。真人游玩、脚本/页面夹具和人工参考叙事分别记录，可为已登记状态另写经核验的参考正文，但不能冒充真实玩家原文或用旧流水账模板当风格标尺。

完整流程另设至少 20 次真实页面输入验收，“测试驱动输入”只表示执行方式，不代表执行 agent 有权自己挑全套题。至少 10 次为用户或隔离评审方提供的未参与实现/调参的玩家输入，连同初始静态世界文件、文件哈希、骰点种子及输入的执行顺序/独立会话边界一起冻结；其余公开回归输入标明身份，不与独立题混报。优先在实现开始前取得并冻结这 10 次输入包；若独立包尚未提供，仍按本节既有规则开展公开开发，独立方后来按预先固定的覆盖/抽样规则准备，必须在接触候选输出和专项反馈前冻结，不按实现擅长的命令挑题。候选冻结后才向运行路径提供未公开输入，查看后修改实现须换独立批次。

该输入包依赖已可读取的世界状态格式；先交付第 4 节的 schema 引用、通过校验的样例与说明，再请出题方按同一格式提供。公开自由一日世界只用来展示格式与开发，不能作为唯一外部非叙事标准。当前至少 10 次独立输入仍是草案下限，不能擅自声称已有人审标签集或把 42 条待复核 AI 草稿当作外部标准；是否扩为全部 20 次独立输入由定稿决定。

独立输入不要求用户预写唯一结果；执行 agent 记录实际决定及理由作技术初审，独立评审方再按原设计、初始世界、骰点和前后状态核对合法性、因果与目标一致性，不由实现者自签全部通过。初始世界、骰点和输入冻结不等于预写行动、结果或叙事答案，最终必须运行实际交付的本地路径。

20 次输入覆盖普通行动、合法失败/部分成功、多人物连锁反应、被迫行动未准入、已行动人物不重复反应、共同结果、六阶段依赖、时间推进、自动继续与交还，以及重载恢复、历史和叙事缓存重生。全人物任务/个性扫描、合法无变化、静态世界读取校验与封存均有对应案例。结构与动态决定的语义分别留证；未自然触发的 R 项补场景，不将未覆盖项记完成。35 份叙事与整链测试可共享符合条件的证据，但明确覆盖关系。

明确允许确定性测试装置：固定静态世界文件＋固定骰点种子＋预先登记的脚本化玩家输入，由浏览器实际执行调度、校验、结算、提交和持久化，再读回状态记录，用于覆盖任务完成、精神变化、外貌增删等指定形状。可以事先选择初值与输入以触发边界，不能事后手写目标前后状态冒充实际结果、篡改骰点或给待验收路径注入预写候选。若装置为内核单测直接传入固定候选，则只证明内核，不算动态非叙事或独立整链通过；该覆盖类别需另有实际运行决定的案例。装置、运行输出、生成正文和独立题的来源分别登记，公开装置不升级成未见终验。

机器泄漏检查改为两条同时执行，覆盖终验参考叙事、给模型的历史正文，与所有实际参与过训练的叙事、前文和增强/改写版本：

1. 实体/数字锚定硬检查：出现连续长度至少 8 个字符的相同片段，且片段包含一个完整匹配的专名、数字值或日期/时间表达，即判冲突。专名按来源实体及明确登记的别名识别，数值与日期规则预先固定，保存命中的锚点及双方位置；不能事后为通过而删词表。普通功能词或“他说”等句法本身不触发这条。锚点必须位于同一相同片段内，不能因整篇其他位置存在数字就判任意公共短句泄漏。
2. 12 字重合比例：逐篇参考/历史正文与每一篇训练叙事计算全部相同 12 字片段，按其在考核正文中覆盖的字符位置取并集，除以该考核正文字符总数；单对比例不得超过 5%。不用相同片段数量直接相加重复计覆盖，不将不同训练篇的片段拼成一篇。正文不足 12 字时该项记不适用，仍做锚定与语义检查。报告每篇最大比例、命中训练来源、全量配对分布及算法版本，不再因一处无锚点的 12 字通用措辞直接删训练行。

两条均固定 Unicode NFC 规范化，分别检查原文与移除空白/标点后的文本并报告结果；数值和日期在规范化前解析，保留其字符位置映射，不把“1.5”去点变成“15”再解释。片段按字符计数、不跨独立记录拼接。固定语料范围、文件哈希、命中位置和退出码；不设事后白名单或缩小对照语料。字面检查不能证明语义独立，改名同构和事件骨架检查保留。模型输出的训练复述另行报告，不把测试参考文的泄漏检查变成禁止模型使用正常中文句法。

终验包提供后，由保管方对照该候选全部实际训练语料及公开开发材料核对来源隔离与上述泄漏规则；后续增加训练材料也要复核。题包可以晚到，但不能以删除已训练文件追认候选干净。泄漏失败时由保管方按预先登记的取题规则处理，不向训练方泄露参考正文，不按候选表现换题。训练方只接收必要的冲突来源与状态，禁止凭多轮查询反推未公开考卷；同一规则用于备用批次。

连续回合另做四类硬检查，并预先在状态/事件账本中登记其适用前提：

| 检查 | 失败判据 |
|---|---|
| 人物在场不倒退 | 已离场且未登记返回的人，被后文当成当前在场；允许明确的回忆或引用，不能误判为返场 |
| 任务状态不倒退 | 已完成且未登记重开/撤销的任务，又被当作当前待办或要求重新完成 |
| 物品认知不倒退 | 同一视角已发现、见到或明确得知的物品，后文无遗忘或新变化依据却再次写成首次发现；先区分世界里存在与人物已知 |
| 事件时间不倒退 | 前后文对同一事件的先后、已发生/未发生关系冲突；明确回忆、转述和倒叙不按表面词序误判 |

每个可适用检查保存结构化结果：`groupId/turn/check/status/conflictsWithTurn/earlierQuote/currentQuote/sourceRefs/note`。无冲突也登记 `pass`，不适用写 `not_applicable` 并给依据；存疑写 `undetermined`，不能跳过或按通过计。程序核对权威账本，语义评审核对原文，不能用关键词出现或未出现单独判定。四类至少各有一个真正可能触发的跨回合案例及一对正反自检，所有连续组无确认的倒退或未决项才通过。

所有终验使用冻结的实际交付策略，包括模型路由、程序处理、检索、解码、核验、编辑和重试。一次正常请求可以包含该策略规定的多个步骤，先报告各阶段原始结果，再报告最终正文、调用次数、等待与失败；不能暗中追加抽样只展示最好的一稿，也不能把模板回退算成原模型能力通过。若模板或程序方案本身就是产品实现，其最终正文同样接受事实和文风验收，不能仅因来源是模板而豁免或判失败。所有步骤均纳入完整回合耗时。

先验证评测器本身：给它人物对调、方向反转、捏造线索、承诺、不可见信息、合理同义改写和允许的细微动作等正反例。旧 `narration-alignment.ts`、`score_rows.py` 等只能按其真实覆盖范围使用；关键词没报警不等于整段无误。模型给自己的输出打低 loss、参考文本重合度高、风格统计相近，都不能替代语义核验和玩家读感。

冻结读感 rubric，逐维保存评分、原文证据及扣分原因：1 分为无法正常阅读，2 分为严重错乱或大段循环，3 分为需实质改写，4 分为可直接给玩家读且只需可选润色，5 分为表达成熟。使用“起点基线”中的真实失败锚点：同一件事无进展地反复讲述，连贯维度必须不高于 3；受伤人物或说话者归属漂移，人物与对白维度必须不高于 3；无依据往事另外触发事实硬失败，不能靠其他维度的高分抵消。内容只写到目标约六成且出现遗漏、提前收尾或打转，相关完整性/连贯维度不高于 3；单纯篇幅较短但内容完整不自动扣分。

用户的文风要求单独落到评分依据：以训练材料中经核验的优质范文为参照，比较叙述语气、对白节奏、动作与情绪表达、场景铺陈和段落组织。目标是读感相似且适合当前场景，不要求复刻某篇情节、人名或原句；短句占比、对白比例、长度及 n-gram 分数仅作诊断，不能替代文风读评。事实正确的流水账仍可能文风失败，文风相似的捏造正文仍是事实失败。

公开开发阶段，执行 agent 可从已有优质范文中选至少一份 4 分、一份 5 分的候选正向锚点，登记四个维度的判断依据，与上述负例一起用于调试评测器；不等待用户先写新文案。用于最终判分的锚点须由用户或未参与训练的评审方确认，且在终验评分前冻结；未确认时开发自评分如实标为暂定。机器/模型评审须先通过固定锚点及正反例，再用于终验；执行模型不能一边优化生成一边修改 rubric 或自签最终读感成绩。终验评审不显示候选身份和训练配置，可查看事实依据，但不能把参考文措辞当唯一正确写法。另一模型独立打分是辅助证据，10 份真人读评保留；缺独立读评只影响最终验收，不阻止其他开发。

本稿建议按以下规则验收：

| 验收项 | 通过条件 |
|---|---|
| 关键事实与视角 | 全部终验输出无已确认的重大事实错误、关键结果遗漏、越权剧情事实或视角泄露；存疑项完成核查，不能按通过计 |
| 完整性 | 无重复循环、空输出、未完成句被当成成功、靠硬截断冒充自然收尾；允许合理长短，不统一卡固定字数 |
| 叙事读感 | 按冻结锚点评四个维度：连贯、中文自然且文风接近训练范文、人物与对白合理、场景与上下文衔接；35 次中至少 32 次四项均达到 4 分，不能用总平均分掩盖单项不合格 |
| 连续回合 | 人物在场、任务状态、物品认知、时间关系四类检查均留证，无确认倒退或未决项；不能仅用“整组还算连贯”代替 |
| 输入依赖 | 一组配对诊断改变主体、结果、可见性或任务状态时，输出在对应语义上随之正确变化；不能只换几个名字、正文逻辑照旧。配对输入必须本身自洽，并登记两份投影及差异：进出实体、字段值和裁剪项。在采样前冻结预期语义及其必要派生差异，断言其余投影相同；可见性变化必然引起的实体进出不算额外干扰。存在未解释差异时不能作为该单一语义的受控证据 |
| 输入适配一致 | 实际交付路径采用同源实现或经差分核验的移植版，均须与冻结金标的 UTF-8 字节和同 tokenizer 下的 token 序列一致；覆盖空列表、0 值、物品移动、任务层级、非 BMP 排序、长输入与拒绝路径。拒绝案例核对错误类别，不要求强行输出文本。不一致即阻塞交付，不得以现象相似放行 |
| 长输入质量 | 按第 7 节先实测并冻结长度分层；建议在 35 次中至少包含 3 个超过实际公开投影分布上四分位阈值的案例，逐题和按子集报告事实/视角问题及四项读感分，并按同一冻结质量规则核验，不仅计时、不用平均分掩盖失效 |
| 人工读评 | 按预先固定的覆盖规则抽取 10 份浏览器原始输出，包括连续上下文；向用户提供可读正文和简短问题，至少 9 份获“可直接给玩家阅读”的评价，且重大事实问题全部解决 |
| 基座能力保留 | 对实际微调的生成基座完成 5 条固定中文续写前后对照，再核对浏览器量化版；未训练的组件登记来源并做导出与本地运行回归，不为满足流程强行训练 |
| 非叙事完整性 | R01–R16 逐项覆盖，至少 20 次页面输入和必要补充场景通过，动态决定语义与状态不变量均核验，缺项不能用叙事高分抵消 |
| 本地运行 | 禁用全部远程模型与游戏计算端点后功能不变；保存服务断开仍可连续推进与本地保存，重连正确同步；服务器请求只用于进度存取 |

35 次、90%、10 份、9 份及至少 3 个长输入案例是本稿建议的验收规模和阈值。执行前随本稿定稿冻结；执行中不能因结果差自行缩小样本、删除失败题、降低阈值。评分记录标明评价者及方法；执行模型自评、另一个模型评分和真实人工读评分别记，不互相冒充。

最终 test 一旦用于指导修复，就成为开发材料。修复后使用未参与该候选选择的独立备用批次；可以按同一覆盖和抽样规则由隔离评审方随后准备，但须在接触该候选输出与专项反馈前冻结、通过隔离及泄漏检查。没有备用包时继续开发和公开回归，等待最终独立验证，不能自己临时编题宣布通过。旧失败保留为必须复测的公开回归题；登记全部批次、冻结时间、启用顺序和失败，不反复换题直至偶然通过，不从多次终验中挑最好的一批报告。

**7. 浏览器运行与时间验收**

最终所有游戏推理与计算在浏览器内完成，包括非叙事决定、状态内核与正文生成。HPC 或 Python/远程服务计算结果再传回网页，均不能算通过。HPC 只用于开发训练，服务器游戏期间只提供进度存取；静态页面、运行库和模型的首次取得可以通过静态分发或手工导入，安装并缓存后不依赖远端资源继续运行。浏览器本地可使用 WebGPU、WASM 或其他实际可用路径，不因方法选择另加纯模型或纯 GPU 要求。

在真实页面禁用全部远程推理与游戏计算请求，并断开进度服务器，运行新的未缓存回合：输入、行动/反应、骰点与组结算、状态变化、正文流式、本地保存与重载恢复均须成功。不能回放预生成文本假装在线生成。恢复保存服务后，实际验证上传、读回、版本冲突及新旧进度处理；保留请求清单和浏览器运行证据，证明服务器没有代做游戏计算。断开保存服务时页面不得卡在等待请求，不能丢失已结算进度。

沿用此前建议的 RTX 4060 Laptop 8GB 笔记本、Chrome 或 Edge 作为待定稿验收设备，不能自行换成训练服务器。开工记录 CPU、系统内存、系统、浏览器准确版本、驱动、电源模式和实际本地运行时，选择一个主验收浏览器并固定；若宣称两个都支持，则分别验证。设备不明或不可访问时性能验收未完成，其他开发继续。

**按实际部署路线验证导出与精度变化**

记录从来源模型到浏览器实际资产的转换链，分别检查格式/算子导出的正确性和量化/降精度造成的行为退化；两者不能混成一个“数值门”。不强制 ONNX、GGUF、4 比特或半精度，不要求所有步骤都发生，也不假定转换一定无声改变数值。每项仅在实际采用时适用；未采用的步骤登记 `not_applicable` 及原因。直接复用已打包资产时核对身份、可得的上游证据及实际行为，明确不能独立验证的部分，不为补表强行重做全部工具链。

采用导出/算子移植时，在可对照的精度、输入、权重和计算条件下检查转换前后结果。例如 PyTorch fp32→ONNX fp32 可作为一条对照路线，不成为其他部署方式的必选前置步骤。先核对形状、有限值、掩码、位置编码和缓存语义，对选定输出与定位异常所需的对应张量记录尺度、`atol/rtol`、最大及分位绝对/相对误差，并按任务补充 logits 分布、Top-1 或其他可比较指标；不要求所有融合图暴露同名中间张量。容差按模型、精度、张量尺度和影响预先登记，不用 `1e-3` 或 `0.1` 作为跨模型通用的通过/判错线。异常需调查其来源与后续解码影响，不能仅凭一个最大绝对误差断言具体实现 bug，也不能仅凭 Top-1 未变忽略缓存等问题。已证实的实现错误必须修复；有证据表明检查本身不适用时，允许修订标准并留存旧结果及复测理由，不伪造旧门通过。

固定种子的少量合成输入仅作冒烟检查，证明所测案例的局部一致性，不证明两个实现对所有输入是同一函数。后续用冻结真实输入覆盖不同长度、填充与掩码、预填及带 KV cache 的多步解码；没有缓存或不相关的组件注明不适用。异常优先定位到会影响实际任务的路径，不为凑中间张量检查阻塞其他可推进工作。

实际采用量化或降精度时，在同一批冻结真实输入上比较实际部署资产与可用参照，按组件选择必要指标：生成组件可用分布/KL、困惑度、Top-1 和完整生成读评，分类/数值组件使用对应字段与任务正确率；不强迫所有组件计算全部指标。指标、抽样和可接受退化在候选比较前登记；允许有界的数值/行为差异，但不能降低本轮事实、文风、完整语义和等待要求。导出或精度变化验证均不替代真实浏览器端到端验收，最终以实际交付资产和整条运行策略核验。

此前草案建议的资源参数为完整推理包不超过 1,000,000,000 字节、显存峰值不超过 6 GiB（6 × 2^30 字节）；它们仍待定稿，不能把某个参数失败等同于用户已否定全部技术路线。若采用这些参数，应按所有叙事与非叙事组件的实际交付总量计算文件，不以压缩或拆分隐藏体积；按整个运行峰值计算权重、KV cache、临时缓冲和加载/编译开销，不只挑某一个模型测显存。记录系统内存与 GPU 占用、基线和测量边界；采用 WASM/CPU 的路径也要计其实际内存，不能声称“没有显存占用所以资源无限”。无法测量的指标标为未验证，不能自填通过。

用户提供的历史参考：YuYan-700M Q4_K_M 文件约 489 MB，浏览器预填约 310–407 token/秒、解码约 15–28 token/秒，上下文 4096 时额外显存约 1233 MB。设计时未核对原始归档、设备、单位或运行配置，必须开工复测，不能引用这些范围直接报验收通过，也不能据此断言任意 1.5B 以上模型一定失败。

选定基座并训练前，在目标设备用实际量化权重、tokenizer、运行时和拟用上下文测预填/解码，覆盖典型及最长允许输入、典型及最长预计输出，不能只测几 token。将非叙事调用、状态处理、模型加载/切换和叙事生成串成完整等待估算，再用完整开发回合校验；单个模型首字快不能证明整条链快。先验证可本地运行与用户等待要求，核对选定的资源参数，避免训练完才发现架构运行不了；通过准入不替代最终组合复测。

长输入必须同时测质量。先用真实投影入口量出自由一日开局及冻结公开开发回合的实际输入字符数、token 数和裁剪记录，不沿用已被指出口径错误的约 1,227 字估计；加入结果块后重新统计。按相同投影、序列化与 tokenizer 版本，从这些公开样本的最终输入 token 数冻结上四分位阈值及分位数算法（升序排列取第 `ceil(0.75*n)` 项），并登记样本来源与哈希；字符数另报。终验长输入按大于该阈值且实际支持的输入定义，在查看候选终验输出前由独立保管方按既定覆盖规则纳入，不根据得分挑样本。建议 35 次中至少 3 个，逐题报告四项读感分、事实/视角错误、首段/整段时间、裁剪项，并单列长输入子集的通过情况；不能只用最长输入测速或整体平均分代替。若实测上四分位输入仍未超过训练分布，另列真实大世界的超训练分布压力测试，不能把相对较长自动称为分布外；投影或 tokenizer 版本变化时重算并保留旧统计。

从玩家提交一次正常行动开始计时，包含行动、反应、结算、状态处理、继续判断及为显示本点正文所必需的所有调用：运行资源就绪时，60 秒内显示有实际叙事内容的可读片段。不能等非叙事算完再重置计时。状态提示、加载条、占位符、单个标点不算正文；随后持续真实流式追加，不能等全段生成完才模拟打字。记录逐阶段时间、首 token、首个可读片段、最长流式空档及本点整段完成时间。自动推进链逐点计时且记录从玩家输入到交还的总账，不把多个点压成一个含糊平均数。

本稿新增预叙事阶段的执行配额：从玩家提交到首个可叙述时间点合法提交，合计不超过 40 秒，给正文预填、产生可读片段和渲染保留剩余 20 秒；40 秒是本稿建议在定稿时冻结的子门槛，不冒充用户原话，也不是 agent 工作时间预算。实现前按所选架构登记行动/目标、反应/共同组、结果、六阶段应用与必要校验的分项配额，合计不得超过 40 秒；实测逐项对照。连续点从前一点正文完成、获准推进开始记录相应处理时间，不重置或隐去本轮总等待。若最终采用该子门槛，任一正常有效案例超出都须调整调用组织、模型、程序分工或数据，不靠正文后半段更快补报通过，不只报平均值。

首个时间点完成全部适用的六阶段更新、合并校验并原子提交后，立即将该点送入叙事路径并流式显示；不等待整轮后续人物/后续时间点和全部自动链跑完。后续段按原设计的叙事门与关联点边界逐段推进，正文展示只读取各自已提交事实。不能在同一时间点的六阶段未完成时展示部分候选，不能拆开尚未闭合的共同结算组、改变时间语义或造一个无内容提交来抢首字。与本点已提交正文无依赖的后续继续判断，不得平白阻塞首段。记录 `inputAt/pointCommittedAt/narrationStartedAt/firstReadableAt/pointTextFinishedAt` 和各阶段调用时间，能核对 40 秒处理、立即进入叙事与 60 秒首片段三件事。

将“五分钟以上不可接受”落实为本稿的整段完成上限 300 秒；60 秒是开始可读输出的等待上限，不误写成整段必须 60 秒完成。若流式长期停顿到明显破坏阅读，即使总时长勉强通过也要修复，不能靠先吐几个字绕过要求。

此前建议的缓存后冷启动上限为 120 秒：从页面初始化到权重读取、tokenizer、本地运行库编译和必要 warm-up 完成、可接受正常请求。静态世界读取、校验、S₀ 封存和首个页面可玩状态均记录时间；初始化不得调用世界生成模型。按最终组合至少测 3 次独立启动，不拿热会话冒充冷启动，并显示真实阶段或字节进度。资源就绪后的开局首段叙事沿用 60 秒首个可读片段、300 秒完整正文标准，内容来自静态 S₀；从冷态直接点击开始时另报包括启动在内的总等待。没有动态世界草稿生成阶段，也不再为它设置等待上限或索要训练数据；启动体验不等于 agent 总工期限制。

首次网络取得静态资源另列网络条件、大小、下载时间与进度，不并入缓存后冷启动，也不承诺任意网络下下载加启动都在 120 秒内。明确安装、缓存或手工导入方式，测首次取得与后续本地加载；不得用预置测量冒充在线下载体验。模型准备好后，游戏不因外部模型仓库或分发服务器不可达而停工；进度服务的可用性也不能成为游戏计算前提。

最终质量与时间必须用浏览器实际交付的模型、量化版本、tokenizer、程序与生成策略验证。离线通过而浏览器版退化，仍未完成。35 次叙事终验及完整流程验收在浏览器执行，逐次保存输出与时间，报告最大值、p50、p95；任一普通有效请求超过用户等待上限或已定稿的其他硬门槛都需解决。测试环境故障单独列明，不能把模型慢归为环境故障排除。

提供真正可玩的浏览器入口：生成/载入世界、玩家输入、实时正文、状态展示、暂停取消、历史、保存和恢复均可操作；状态直输的叙事调试入口可保留，但不能替代游戏入口。复用现有页面和运行器，正常阅读区保持清楚，调试信息另存日志。连续回合、取消重试、页面重载、断开保存服务与重连同步均实测，确认无失控内存增长、重复结算或无法恢复的状态。

**8. 迭代、交付与停工条件**

每轮保留：问题假设、所改变量、数据与模型版本、完整输入和原始生成、质量核验、时间与内存、结论和下一步。修复应服务于稳定的任务类别，不写针对测试名字或固定措辞的特殊分支。某条路线连续没有收益时转向有证据支持的下一条路线，不用重复提交相同配置维持“在工作”的表象。

首要交付是可运行的浏览器产品：用户打开交付入口、准备好本地资源后，输入行动即可玩完整流程，看到现场生成、符合事实且文风接近训练材料的叙事；远程游戏计算与模型 API 不可用时仍能运行，进度服务器只存取进度。下面的版本与证据是帮助用户取得、复现和确认该产品，不能用“材料齐全”代替实际玩起来达标。

最终交付报告写明具体代码提交、浏览器入口或安装包、模型与数据清单哈希、完整复现命令和验证设备；分支远端可检出。模型可在早于最终页面提交的代码上训练，必须通过清单明确训练代码提交、训练数据/配置、checkpoint、导出/量化、最终运行提交与验收结果的对应关系；不要求为每次纯文档改动重训，但不能交付与验收不同的模型或运行路径。大权重和原始日志走可获取的制品路径，哈希与取得方法留在提交中。

在本任务独立工作树建立交付清单与验收报告，例如 `artifacts/local-game-delivery/manifest.json` 和 `design/world-engine-reports/local-game-acceptance.md`（这些是后续目标路径，不表示当前已存在）。逐项记录 `status/pathOrArtifact/sha256/codeCommit/verifiedBy/evidence`，状态为未完成、待核验或通过，不能笼统写“已提供”。最低核对项：

| 核对项 | 需要定位的实际内容 |
|---|---|
| 浏览器产品 | 可玩入口、安装/静态资源取得、本地资源准备与启动步骤 |
| 游戏流程与状态内核 | R01–R16 对应实现、回合调度、校验/应用/回放的唯一实际路径 |

| 数据与输入适配 | 初始静态世界文件与哈希、浏览器重算的 `stateDigest`、数据版本、行 id 与隔离划分哈希、来源和泄漏核对、所有任务的实际输入投影；逐模型登记 `projectionVersion / serializerVersion / modelTemplateVersion / tokenizerHash`，以及冻结金标、实际入模字节/token 和一致性报告；实际转换链及适用的导出/精度变化验证记录（误差与任务指标、比较条件、标准及实测值、修订依据）；未采用步骤明确记不适用，复用资产的证据缺口如实登记 |

执行 agent 完成技术自检、交付定位和修复；独立评审方按固定规则提供未参与优化的判断；用户在实际浏览器检查完整流程与事实/文风读感。最终报告写各方结论和证据，用户未验收或仍有硬性未完成项时，不替用户签通过。

只在以下条件全部满足时将 goal 标记为完成：

1. 浏览器本地完整游戏路径已实现，R01–R16 及至少 20 次页面输入和必要补充场景通过；行动、反应、结算、状态更新与继续判断不依赖远程计算，不用固定输出跳过职责。交付的输入适配实现与冻结金标逐字节及同 tokenizer 的 token 序列一致，拒绝路径符合冻结预期，差异未解决不得交付。
2. 独立且通过泄漏检查的叙事验收、评分锚点、输入依赖、四类连续回合核验及实际需要的基座回归通过；用户确认正文符合事实且风格接近训练材料。
3. 实际交付的全部模型与程序组合在目标浏览器运行，真实流式输出，一分钟内出现可读正文、单点整段不超过五分钟；启动与资源参数按定稿标准核对，不能用单模型离线速度冒充整链体验。实际采用的导出/移植与量化/降精度已按第 7 节验证，记录与交付资产一致、没有影响本轮要求而未解决的异常；未采用的步骤不要求补做，不将某一框架或旧工程门禁当作所有路线的完成条件。
4. 静态世界读取校验与 S₀ 封存、暂停取消、重载恢复、历史与叙事重生、本地持久化、保存服务断开后游玩及含双设备分叉的同步通过，服务器只承担进度存取。
5. 浏览器入口、可检出的代码提交和资产指针齐全，核对表逐项留证，失败与限制如实披露，用户能取得并复现验收过的实际版本；报告与文件的存在不替代产品通过。

“训练跑完”“loss 降了”“文件生成了”“旧门禁变绿”“挑出的几篇读起来不错”“CPU 离线能跑”“网页能显示服务器正文”，均不足以宣布完成。不要在交付方案、脚本或阶段报告后主动结束整个目标，也不因自行假设的次数、预算或运行时间到限而停工。保留简短持续进度，让用户知道当前卡在事实、读感、浏览器还是速度。用户主动停止或真正外部阻断时如实保留未完成状态，不将它改写成验收通过；凡仍有当前授权内可推进的工作，继续推进。

# E35 编辑解码 v1：字符级保留/删除标注器

**Question.** 把输出约束为"事实的子序列"（零编造），学习 E34 的删除动作，
能到多少 overlap，产物是否可读？（编辑式解码的最小形态）

**Setup.** `span_keep.py`：oracle 计划拼接的从句文本（≤600 字）为输入；
对每个字符标注"是否出现在目标"（对齐自目标正文，SequenceMatcher 块 ≥1 字）；
字符级 Transformer（96 维、4 头、3 层，**446,497 参数**），40 轮 BCE；
按事实集分组留出（279 训练 / 69 测试）；解码取 p≥0.5 的字符按原序拼接。

**Results.**
- charF1 均值 **0.465**（min 0.282、max 0.771）——显著高于程序 0.208、
  选择 0.265、oracle 拼接 0.290、自由生成 0.332。
- 保真度由构造保证：计划覆盖率 1.0、编造字符 0（输出是事实子序列）。
- **但可读性失败**：保留串是字级错序碎片（"路明非着墙往材棚轻，。路"），
  因为字符级掩码允许从不同词里各留一个字；charF1 对词序不敏感，正好掩盖
  了这种破坏。

**Interpretation.** 零编造与高 overlap 能同时成立，但字级掩码不是可用的
编辑解码器：删除必须发生在**词或短语 span 粒度**，并配合连接词插入与局部
替换（E34：删除 63.8%、替换 22.6%、插入 2.1%）。这正好回到 v3 候选指针
机制：候选 = 从句内的短语 span，`<e>` 指针选片段，替换与连接作为附加动作。
下一步按 span 粒度重做，评价以"词序完整 + 保真度"为主、charF1 退为辅助。

**Caveats.** oracle 计划输入；单世界单风格；69 段分组留出；charF1 对顺序
不敏感（本实验的教训本身）。

**Artifacts.** `span_keep.py`、`span-keep-run.log`、`span-keep-summary.json`。E35。

# E31 程序式重建基线：编辑工作流的地板在哪

**Question.** 不训练任何模型，用"事实从句 + 固定顺序"直接拼正文，能接近人写
目标多少？给出微型生成器必须超过的地板，并定位剩余差距在规划还是措辞。

**Setup.** `reconstruct_baseline.py`：348 段 v13 语料；从句去前缀后用「。」
拼接。两个方案：
- A 程序计划：全部从句按类型固定排序（行动 → 位置 → NPC 结果 → 场景 → 外观，
  跳过时间）；
- B oracle 计划：人类实际选择的从句、人类实际顺序（E30 v2 的 selected）。
对照指标：与目标正文的字符级 `SequenceMatcher` 比值、字符集 F1（均段落均值）。

**Results.**
- A 程序计划：ratio 0.148、charF1 0.208；
- B oracle 计划：ratio 0.212、charF1 **0.290**。
即使在"选择与顺序完全正确"的理想输入下，纯拼接只能拿回约三成字符——**措辞与
句内改写才是主要工作量**（与 E28 的复制 58%/改写 13.5% 对照：事实原文与目标
措辞的表面差异很大，从句里还夹着结算格式）。

**Interpretation.** 编辑式工作流的难点排序要修正：不是"选择 > 措辞"，而是
选择与措辞都重——选择决定写什么（58.7% 的从句被选），措辞决定怎么写（oracle
计划下仍有 ~70% 字符差异）。这为阶段三定下两个可分解的指标：规划错误用
oracle 计划隔离，措辞错误用 oracle 选择+固定顺序隔离。微型生成器（v3 类短序列
解码）首先要在这两条曲线上超过 0.21/0.29 的地板。

**Caveats.** 句内改写与换序未被建模（拼接不换序、不拆句）；字符 F1 对词序
不敏感，ratio 对长度敏感；语料为目标质量人写正文，非文学性上限测试。

**Artifacts.** `reconstruct_baseline.py`、`reconstruct-summary.json`。E31。

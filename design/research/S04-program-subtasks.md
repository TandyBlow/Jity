# S04 子任务提案：LLM 在重复同一条，程序模板先接管

**Question.** 现有 subtasks 阶段每回合调用 0.6B（二十输入 29/33 次），它到底新增了什么？能否用程序模板 + 既有过滤器替换，并保留合法新增？

**Method.** 读冻结八场景与二十输入的 subtasks 调用（`submission.calls[stage=subtasks].raw`、最终任务集合），统计新增与重复。实现 `micro/subtasks.ts`：从事实的结构化标记生成候选，父任务按词面/实体相关性门控，去重后交给既有 `readSubtaskProposals`（重复/他人物/复述事实/无根据四道过滤仍在）。`?subtasks=program` 臂接入 `stageSubtasks`，LLM 不再被调用。

## 1. 混合臂的实际行为

冻结八场景 8 回合：

- `caesar` 的任务每回合都被提议新增「确认红蓝两方是否仍能通行跨溪小桥」；程序因重复只接受一次，最终状态里多出 `task_22`。同一条提案在 8 个回合里重复出现 17 次（每点一次）。
- 其他提案包括「在演习照片的拍摄机会中使用路线情报」「在自己不被淘汰的前提下用路线情报换到演习照片的拍摄机会」等，挂在 `t1` 下，与父任务关系弱，部分是复述或换皮。
- 结论：29 次/20 回合的 subtasks LLM 调用里，真正留下的新任务极少，重复与噪声占多数。

## 2. 程序模板

`micro/subtasks.ts` 的四类候选（只从已结算事实的结构化标记取）：

| 标记 | 候选目标 |
|---|---|
| `确认…的通行/路况/情况` | `确认X是否仍能通行` |
| `信息=entity:clause` | `查看<实体名>上的内容` |
| `环境=entity:已被部分X` | `把<实体名>完全X` |
| `去向=…` 且事实为「只完成一部分」 | `到达<地点名>` |

约束：

- 父任务必须是受影响人物下的 pending 任务；候选与父目标必须词面重叠或共享登记实体；
- 同一候选只提一次；已有任务同文（normalize 后）不再提；
- 每回合最多给每个父任务一条；返回空是合法结果，`stage` 记为 `program`，不回落 LLM；
- 既有四道拒绝仍在 `readSubtaskProposals` 里执行，拒绝原因进证据。

## 3. 验收口径

- subtasks 阶段 `source=program`、LLM 调用 0；
- 与混合臂比较最终任务集合：新增、缺失、重复；
- 明确报告「被跳过的合法新增」（例如模板覆盖不到的目标）与被错误新增的目标；
- 不以减少新增换成功率。

**Artifacts.** `micro/subtasks.ts`、`subtasks.test.ts`、`stageSubtasks` 接入；臂 `?subtasks=program`。S04。

## 4. 页面运行（goal + program 双臂，冻结八场景）

臂：`?micro=1&taskStage=goal&subtasks=program`。前 6 回合观察：

- 每回合 subtasks 阶段全部 `source=program`，LLM 调用 0；
- 程序模板没有新增任何子任务（任务总数保持 73）；
- 混合臂在同一夹具新增 `task_22`（确认跨溪小桥是否仍能通行），程序臂缺失，记为**被跳过的合法新增** 1 条。

原因初判：模板只从事实的结构化标记生成候选，而这次小桥信息来自「凯撒确认了跨溪小桥的通行情况」这类事实；需要补一条“父目标含 `查明X是否…` 且事实点名 X → 确认X是否…”的模板，才能恢复。

最终状态与对比见跑完后补记。

## 5. 完整八场景结果

证据 `smoke-goal-subtasks-frozen8-20261128.json`：**8/8 COMPLETED、0 failures**；subtasks 阶段 16/16 次 `source=program`，**0 次 LLM**。回合等待 37.5–77.5 s，accepted 8.3–27.0 s。

与严格任务臂（`smoke-goal-frozen8-20261128.json`）的达成集合完全一致：turn1 四个任务、turn6 `task_lu_route`，没有 kit。最终任务集合 73 vs 混合臂 74，唯一差异是 `task_22`（确认跨溪小桥是否仍能通行）。

`task_22` 的合法性：混合臂在 8 个回合里重复提出同一条 17 次；程序臂没有新增。它不是确定的“合法新增”，需要事实级 grounding 核查（该点事实是否点名跨溪小桥、父任务是否受影响）。在核查前按“差异”记录，不计成功也不计损失。

**结论**：subtasks 阶段的 LLM 已被程序模板完全替换，任务达成集合不变；代价是少一条重复提案。补齐 grounded 模板（父目标 `查明X是否…` + 事实点名 X）已实现并通过单测，但本轮冻结夹具没有触发（该信息不在此回合事实里），留待新增场景验证。

## 6. 用户复核后的修正

用户指出父任务派生模板（`查明X是否…` → `确认X是否…`）可能只是父任务的重复表达，独立游戏价值不足。已删除该模板及单测；程序子任务只保留从事实结构化标记生成、且与父任务不同的候选。`task_22` 的缺失因此是有意行为，不再记为“被跳过的合法新增”，除非后续事实级核查证明它是独立目标。

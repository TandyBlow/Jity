# E46 1.7B LoRA 数据曲线：290 行 .709，加 49 行反而 .671

**Question.** 在 1.7B LoRA（产品当前默认的叙事模型）上，只加手写数据
（290 → 339 行训练），同一 58 条留出提示、同一配方，指标怎么动？

**Setup.** 从 v13 的 348 行里按 E38 的 32 组哈希留出 58 行，再用剩下的 290
行训练 `narr_c290`；`narr_c339` = 290 + 49 行手写行（13 行因基准事实在留出
集而剔除）。两轮都 5 epoch、lr 1e-4、同样的 ChatML 前缀；`eval_lora.py`
用同一前缀贪心生成（max_new 256），对人工目标算 charF1、词序、覆盖、
编造词。

**Results.**
- 290 行：charF1 **0.709**、wordRatio **0.575**、覆盖 **0.829**、编造 **4.8**
- 339 行：charF1 **0.671**、wordRatio **0.528**、覆盖 **0.796**、编造 **5.5**
- 四条指标全部朝差的方向动；两次生成都没有空输出。

**Interpretation.** 至少在这个配方、这个留出集上，"再补 49 条同分布变体"
没有收益，反而略降。可能是新行的变体风格（短、稀疏、很多"没发生"）稀释
了正文风格，也可能是单次训练的方差。无论哪种，它削弱了"数据量是主因"的
说法，支持 D-140：结构与任务定义要和数据规模一起测。

**Caveats.** 两个种子（见下），但每个种子只训练一次；留出集只有 58
条且来自同一世界；贪心解码、无束搜索；评估用的是"复制训练格式的完整事实
块"，与产品页面上的紧凑投影并不完全一致。

**Artifacts.** `.local/narr-train/eval_lora.py`、HPC
`~/narr_eval/out_narr_c290.txt`、`out_narr_c339.txt`；训练目录
`narr_c290`、`narr_c339`。E46。

**种子 1 复测（2026-11-28）.** 同配方、seed=1：290 行 charF1 0.690 / 覆盖 0.802 /
编造 5.6；339 行 0.690 / 0.830 / 4.9。两个种子合看：charF1 290 均值 0.6995、
339 均值 0.6805；覆盖 0.8155 vs 0.813；编造 5.2 vs 5.2——**两档数据在统计上
分不开**。先前"339 全面变差"的读法应撤回：那是单种子方差。可写的结论是
"在这个规模加 49 条没有可测收益，也没有可测损害"，而不是"加数据有害"。

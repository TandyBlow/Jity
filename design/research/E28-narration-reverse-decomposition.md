# E28 叙事逆向分解 v1/v2：六类操作与开放生成占比

**Question.** 人写叙事正文能否由"结算事实 + 六类局部操作"重建：原词复制、
同义替换、词/句重排、连接词插入、指代与省略、局部短语补全？其中真正需要
开放式生成的字符占多少？（goal 阶段一，阈值 30%）

**Setup.** 语料 `.local/narr-train/sft-v13.jsonl`（348 条 v13 人写目标正文，
prompt 内嵌该回合结算事实）；按 id 排序取前 240 段、12,237 字符。工具
`artifacts/goal/narration-decomp/decompose{,2}.py`：
- v1 字符级 `difflib` 对齐（≥2 字匹配块），未匹配片段按虚词/指代/连接词/
  粘连/短编辑/开放六类规则划分；
- v2 词级 `jieba` 对齐：与事实词表相同的词记复制（并检查词序变化），
  有字符重叠的未匹配词记改写，无重叠记开放；同时统计事实词被正文使用率
  （遗漏率）。

**Results.**
- v1（字符级）：覆盖 57.7%，开放 23.7%（片段多为跨词碎片：如"伸手去拿"被
  切成匹配+碎片）。
- v2（词级）：复制 54.7%（其中约 25.6% 出现次序变化）、改写 17.1%、
  功能词 21.2%、开放 4.2%；**事实词遗漏率 65.6%**。
- 开放词表前列是泛化动词与意图改写（拿 54x、想 45x、看 31x、站 30x），不是
  新事实；"想"对应玩家行动意图的改写（"递给阿豹"→"想交给阿豹"）。
- 人工抽查 8 段（`spot-check.md`）：真正凭空新增仅细节级（如"推拉门留着
  回服务巷的缝"），未见新人物、新事件、新数字；自动口径的 4.2% 是上界，
  真实开放生成约 1–2%。

**Interpretation.** 叙事文本几乎完全由"选择 + 改写 + 组织"构成，自由生成
是零头——与 goal 的编辑式工作流假设一致，开放生成比例远低于 30% 阈值。
工作量真正的所在不是"写句子"，而是**选择**（66% 的事实根本不进正文）与
**改写/词序**（26% 的复制词序发生变化），即规划层。下一步：
1) 30 段人工标注统计（每段开放/改写/复制占比 + 操作清单），校准自动口径；
2) 把"选择"建模为任务：给定事实集，预测哪些事实、按什么顺序、用什么关系
   （因果/转折/时间）进入正文——这就是规划模型（0.1–5M）的任务定义；
3) 改写词典与词序模型的数据形式，直接用 v13 语料的事实→正文对齐导出。

**30 段人工标注（工作流并行标注，`annotate/annotations-30.json`）.** 四桶：复制 877/1467 = 59.8%、改写 192 = 13.1%、功能词 345 = 23.5%、开放 53 = **3.6%**。与自动 v2（开放 4.2%）一致，自动口径可用作代理。开放片段的类型集中在四类：事实未陈述的缺失/否定（巷里没有阿豹、没有追问、没有得到答案）、未写出的手势与站位（站回原处、转头、一边、一旁）、单个未给出的属性（故障、妥当）、以及行动意图的改写（想）。这些正是规划层的任务定义素材。

**Conditions.** 单一世界的 v13 目标正文；自动对齐是近似（jieba 分词、词序
指标粗糙）；人工抽查仅 8 段，尚不足以给出最终开放比例；未做正文"多表达
多样性"统计（alt-targets-all.jsonl 留作下一步）。

**Artifacts.** `decompose.py`、`decompose2.py`、`decomp-v1.{json,md}`、
`decomp-v2.{json,md}`、`spot-check.md`。E28。

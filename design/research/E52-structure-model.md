# E52 结构预测模型：1.24M 端到端学不出句式，瓶颈是片段选择不是句式

**Question.** 用 E51 的 160 条帧训练一个百万级模型，直接输出"句式编号 + 事实片段
指针"，能否学会？失败时应归因到句式选择还是片段选择？

**Setup.** 数据 `frames-v2-all.jsonl`（160 帧、50 条句式库存）。按事实串完全相同
分组，20% 组进测试：128 组 → 132 训练 / 28 测试，seed 0。字符级 Transformer 编码
器，两个头：50 类句式分类、每槽位 start/end 指针（最多 7 槽位，序列上限 384 字）。
主臂 d=160 / 4 层 / ff=512 = **1,235,538** 参数；小臂 d=48 / 2 层 / ff=128 =
92,994。消融：oracle 句式——测试时给真句式，只学指针。全部在 RTX 4060 上训练
300 epoch，单次 <1 分钟。

**Results.**

| 臂 | 参数 | 句式准确率 训练/测试 | charF1 训练/测试 | 预测长度/参考长度 |
|---|---|---|---|---|
| 多数基线 | — | — / 0.107 | — | — |
| 主臂 | 1,235,538 | 0.167 / **0.036** | 0.311 / 0.351 | 72.6 / 20.7 |
| 小臂 | 92,994 | 0.795 / **0.250** | 0.661 / 0.636 | 35.4 / 20.7 |
| oracle 小臂 | 92,994 | 1.0 / 1.0（给定） | 0.655 / **0.706** | 28.1 / 20.7 |
| oracle 主臂 | 1,235,538 | 1.0 / 1.0（给定） | 0.338 / 0.429 | 80.6 / 20.7 |

- 零编造成立：四臂 `renderValid = 1.0`，指针永远落在事实串内，没有生成新字。
- 主臂连训练集都没拟合（0.167），小臂拟合到 0.795 但测试掉到 0.250——132 条样本
  上，参数多 13 倍反而更差。
- 给真句式只把 charF1 从 0.636 抬到 0.706：**句式选择不是主要瓶颈，片段选择才是**。
- 预测长度是参考的 1.4–3.9 倍：模型倾向把整条事实从句倒出来（样例仍是
  "秦越把器材笼钥匙扣回腰环，低声说：‘扣回腰环’"这类错槽位）。

**Interpretation.** 端到端"字符 → 句式 + 指针"在百条样本上不成立。可行的分解是
三步：从句选择（E32 的 0.1M 模型 F1 0.906 已够）→ 按从句类型选模板（小闭集）→
确定性填充；把 50 路分类和 384 字符上的指针回归塞进一个模型，是当前数据量下
错误的目标形式。

**Caveats.** 28 条测试，1 条 = 3.6 个百分点；单种子；charF1 奖励复制，必须结合
长度比读；只有 160 帧，失败结论的边界是"此数据量"，不是"此架构永远不行"。

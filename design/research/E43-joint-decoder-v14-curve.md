# E43 加 49 段训练数据：charF1 +5 点，覆盖与编造同时变差，坍塌没解决

**Question.** 在 E38 的联合解码器上只加手写数据（290 → 339 行训练），固定同一
58 行留出集，指标怎么动？这是 D-140 要求的"数据规模作为一条轴"的第一个点。

**Setup.** `joint_decoder.py`（1.75M 词级 seq2seq）+ `planning-examples-v14`；
留出集沿用 E38 的 32 组哈希（`joint-hold-v13.json`），新行按 baseId 映射，13 行
因基准事实在留出集而剔除；训练 290 → **339** 行，测试 58 行不变；同种子、
贪心解码、40 轮。

**Results.**
- charF1 0.280 → **0.330**（+0.050）
- 词序 wordRatio 0.232 → 0.212（−0.020）
- 计划覆盖 0.424 → **0.325**（−0.099）
- 计划外词 13.1 → **18.9**（+5.8）
- 测试集前 3 条生成的正文**完全相同**（同一句训练集句子）——E38 的模式坍塌
  没有因为 +17% 数据而消失。

**Interpretation.** 这个增量既不是"加数据有效"，也不是"加数据无效"：
charF1 升了，但覆盖降、编造升、多样性为零，说明模型更像在背诵一句训练集
正文，而不是学会按计划选词。至少在这个规模（339 行）和这个架构（1.75M
自由解码）上，数据量不是唯一瓶颈——与 D-140 的判断一致。下一步不是继续
堆同分布数据，而是：1）指针/复制约束（E45，零编造）；2）句级上下文；
3）把"选择"和"措辞"分开报告，避免 charF1 掩盖覆盖损失。

**Caveats.** 单世界；339 行仍是小样本；新行是同一批基准事实的变体，分布
与基准一致；贪心解码无重复惩罚，坍塌的"一句"可能是解码策略的产物，换
采样/束搜索需另测。

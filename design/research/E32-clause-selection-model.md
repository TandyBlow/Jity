# E32 规划第一步：从句选择器（0.1M 级）

**Question.** "哪些事实从句进入正文"能否被一个 0.1M 级模型学会？学会后
用固定类型顺序拼接，能到 E31 的哪条线上？（goal 阶段三的规划模型首实验）

**Setup.** `selection_model.py`：E30 v2 的 5,001 个从句（正例 58.7%）；特征为
字符 bigram（HashingVectorizer 2^16）+ 类型 one-hot + 位置/长度；逻辑回归
（约 0.1M 权重）。5 折**按相同事实集分组**的交叉验证（同事实不跨折）。
对照：类型先验（按类型多数类）与 E31 的程序/ oracle 重建分数。

**Results.**
- 选择 F1：**0.906 ± 0.008**（分组 CV）；类型先验基线 0.764——文本特征把
  选择从类型先验上又抬了一截。
- 模型选择率 63.6%（人类 58.7%），略偏多选。
- 用模型选择 + 固定类型顺序拼接：charF1 **0.265**，介于程序全选（0.208）
  与 oracle 计划（0.290）之间，已拿到 oracle 增益的约七成。

**Interpretation.** 在单世界语料上，选择这一步对 0.1M 级模型是友好的；
重建曲线的上限瓶颈仍是措辞（oracle 也只有 0.29），与 E31 一致。下一步：
（1）把措辞单独建模——同义改写/词序的编辑模型（0.5–5M）；（2）跨世界/跨
风格泛化检验选择器的真实难度（当前语料同源同风格，F1 偏乐观）；（3）把
选择器接进 E31 的两条误差曲线，报告规划误差与措辞误差分开的端到端分解。

**Caveats.** 单世界、同一作者风格，类型与措辞高度相关，F1 属乐观上界；
拼接未做句内改写；oracle/程序对照来自 E31 同一批 348 段。

**Artifacts.** `selection_model.py`、`selection-summary.json`。E32。

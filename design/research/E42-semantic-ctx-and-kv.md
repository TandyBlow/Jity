# E42 语义上下文该多大：64k 次真实调用的 token 分布与 KV 账

**Question.** 0.6B 语义模型配置 `n_ctx=12288`、KV q8_0 是否过大？页面归属内存
724MB → 回合结束 1,918MB 的增量里，KV 占多少？（用户 2026-11-28 提问核查）

**Setup.** 1）从 `Qwen3-0.6B-Q4_K_M.gguf` 元数据读出 28 层、8 个 KV 头、
key/value 维度 128；q8_0 每元素 1.0625 字节。2）`semantic_tokens.py` 扫描
`artifacts/goal/**/*.json` 里 312 个运行文件的 76,142 条 generation 记录，
统计各引擎真实 prompt token 数。3）对照 E29 的页面归属内存采样
（`measureUserAgentSpecificMemory`）与进程 RSS 采样脚本。

**Results.**
- KV 账：每 token 2×28×8×128 = 57,344 元素 ≈ 59.5 KiB；`n_ctx` 12288 /
  8192 / 4096 对应 **749 / 499 / 250 MB**。
- 语义调用 64,423 次：p50 441、p95 1,965、p99 2,821、**max 6,797** token；
  超过 8192 的 **0 次**，超过 4096 的 207 次（0.32%），超过 6144 的 111 次。
- 叙事调用 11,719 次：max 1,477 token，现有 2048 的叙事上下文够用。
- 内存：E29 的页面归属值 724MB（就绪）→ 1,918MB（首回合结束），增量
  1.19GB ≈ KV 749MB + 计算/暂存缓冲；回合结束后 90s、180s 两次采样仍为
  1,918MB，**该窗口内没有继续增长**，但只测了一个回合。
- 5,928MB 是"所有 msedge 进程 WorkingSet 之和"（`sample-process-memory.ps1`
  直接 Sum），含用户其他 Edge 窗口与共享页重复计数；开机基线 0.93–1.15GB。
  页面归属的 1,918MB 才是可归因于本页的数字。

**Implication.** 12288 对观测到的 64k 次调用没有任何一次接近上限，降到 8192
在证据范围内无风险，省约 250MB KV；降到 4096 省约 500MB，但需要为 0.32% 的
长调用加"上下文溢出→截断/重试"兜底。是否再降取决于 A/B：同一页面用
`?semanticCtx=` 覆盖，分别在就绪后与首回合结束后采页面归属内存，验证
"增量 = KV + 计算缓冲"这一假设；多回合是否继续增长需要 10 回合以上的采样。

**Caveats.** token 数来自多个提示形态与多个臂（含手机单引擎叙事），最大值
所在运行的提示构造可能已改变；页面归属采样单次约 25s、样本稀疏；只测了一个
回合、一个设备。

`semantic-token-stats.json`。E42。

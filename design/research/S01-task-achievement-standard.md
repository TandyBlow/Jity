# S01 任务达成判定标准（暂行提案）

状态：proposed（语义分支，待用户裁决与实验平台独立核查）。日期：2026-11-28。历史编号：E54–E57 保留不变，语义研究从此使用 S 前缀。

## 1. 问题

E55/E56 的人工读评发现：现系统的任务达成判定普遍宽松。120 条真实样本严格读评只有 3 条 yes、6 条 partial、111 条 no；`task_lu_kit`（“在进入交火区前拿到可用的护目镜与演习装备”）仅因为走了某个房间就被判定达成；`task_nono_squad` / `task_fingel_help` 的条件只剩 `target：路明非`，任何提到主角的事实都能满足。E57 的行为克隆模型在开发集上 91.4%，在严格读评上 14.8%——它复现的是旧错误，不是正确判断。

## 2. 暂行标准（严格语义）

一条任务只有同时满足下列条件才算 `achieved`：

1. **目标全部子句**：目标文本里的动作、对象、地点、数量/程度、时间/前置条件都被已提交事实覆盖；“在…前”是前置条件，不是要完成的动作。
2. **结果状态**：事实必须来自已结算结果，且结果为 completed；attempt、partial、blocked、unaffected、玩家意图、叙事正文都不算达成。
3. **否定约束**：目标里的“而不是/不把/不让”等否定约束必须被事实明确遵守；只字未提不算遵守，不能当达成。
4. **证据状态**：事实与目标的关系必须是 present；insufficient（没核验）与 conflict（与既有状态矛盾）一律不达成，不参与训练负例。
5. **他人事实**：其他人物的事实只有在确实让该任务条件成立时才算，不能因为“提到了任务负责人”就归到该任务。

判定输出沿用 `yes / partial / no`；只有 `yes` 提交达成，`partial` 与 `no` 都保持 pending，并在证据里记录缺了哪些子句。

## 3. 旧标准的位置

现系统（混合臂与 `taskStage=llm`）的判定保留为**对照臂**：

- 冻结八场景的 14/14、二十输入的状态断言继续跑，作为“行为差异”证据，不再作为语义正确性证据。
- E57 的 `taskStage=goal`（行为克隆模型）只作对照，不升级为默认；它的价值是证明“10M 级模型能复现旧行为”，不是“任务判断正确”。
- 新的严格裁决器必须同时报告：严格金标准确率、旧标准一致率、被跳过的合法达成、被错误提交的达成。

## 4. 金标与独立核查

- `artifacts/goal/semantic-micro/bench-v1.jsonl`：120 条人工严格读评（yes 3 / partial 6 / no 111），作为第一版硬负例集；正例不足，需扩充。
- 扩充方式：从 73 个世界任务出发，为每个任务设计「达成 / 部分 / 未达成 / 否定」四类输入，跑真实页面采集事实；冻结八场景与二十输入不进入训练或阈值。
- 独立核查：由实验平台 Agent 对新增金标做第二遍读评；分歧样本由两份读评并排记录，按世界目标文本裁决。语义 Agent 不单独定案。
- 用户裁决点：严格标准会改变“14/14”的旧成绩口径；在用户确认前，产品默认不切换，仅新增严格评测报告。

## 5. 对当前代码的含义

- E56 的程序修复（候选物品、前置从句、最早动词）对两种标准都成立，保留。
- `microGoalTasks` 端口保留为实验臂；在严格金标足够前，不作为默认任务阶段。
- 训练数据：严格标准下，旧提交状态只能作 `silver_legacy`，不能作 yes 金标；E57 模型标注为 behavior-clone control。

## 6. 待决

- 用户是否同意把严格标准作为任务达成的新验收口径（影响 14/14 的解释）。
- 平台 Agent 的独立读评计划与样本分配。
- 严格金标达到多少条（暂定 ≥200 条，正例 ≥60）才训练新裁决器。

# E57 目标级任务裁决器 v1：行为克隆可行，语义修正未完成

> 2026-11-28（S01）：本模型正式定位为 **behavior-clone control**，不升级为默认；严格任务标准见 S01。

**Question.** 一个 1e7 参数的微型模型能否接管任务达成判断？它在冻结场景与严格人类读评上分别什么表现？

**Method.** 用 E55 的真实回合配对数据（train 192 / val 54 / test 81，冻结八场景与二十输入不进训练）微调 MiniRBT-H256 + 2 类头；输入 `目标 ␟ 事实`，标签为提交状态（yes=任务达成/支持被接受，no=仍待办）。早停按 val F1，导出 ONNX 动态 int8。脚本 `artifacts/goal/semantic-micro/train_goal_verifier.py`。

**模型**：10,345,730 参数；int8 10,549,932 字节；单条 CPU 推理时间未测（浏览器接入后补）。

**结果**

| 集合 | n | yes | acc | yes P | yes R | 说明 |
|---|---|---|---|---|---|---|
| val | 54 | 21 | 0.889 | 0.857 | 0.857 | 阈值 0.5，最佳 epoch 2 |
| test | 81 | 20 | 0.914 | 0.933 | 0.700 | 60 TN / 1 FP / 6 FN / 14 TP |
| eval_frozen（verifier cases） | 3 | 3 | 0.667 | 1.000 | 0.667 | 阈值 0.5 时 0/3；0.3 时 2/3 |
| bench-v1（严格人工） | 108 | 3 | 0.148 | 0.024 | 0.667 | 行为克隆复刻宽松判定，不是语义修正 |

阈值扫描（test）：0.4 → P .64/R .70；0.5 → P .92/R .60；0.6 → P .91/R .50。选 0.5。

**Parity**：PyTorch↔ONNX int8 在 test 81 条上 79 条一致（97.5%），2 条边界分歧；浏览器一致性待补。

**结论**

1. 行为克隆可行：test 91.4%，比对验证器（55.6%）与条件头（45.7%）好，接近 logistic（90.1%）但精度更高。
2. 它学的是**现系统的判定**，包括宽松情形；严格读评只有 14.8%。这印证 E56 的判断：任务语义本身有缺陷，不是换模型能自动修好的。
3. 冻结 recall 不足（3 条 yes 里只中 2 条，阈值 0.5 时 0 条）说明训练分布与冻结场景不同；上线前必须在冻结夹具上做页面验收，必要时补采场景数据（不进冻结集本身）。
4. tasks 阶段的 LLM 调用不只是裁决：它还负责**提出候选**。只换验证器不能消除 20 次 tasks LLM；需要一个候选生成器（pending 任务 × 事实 + 目标级打分），离线模拟见 `simulate_task_stage.py`（当前因点级快照缺失，结论暂不可用）。

**下一步**

1. 在 TS 侧实现 goal-verifier 端口与候选生成（pending × 事实，词面预筛 + 模型打分），接在 `stageTasks` 的 LLM 之前，用 `?taskStage=goal` 臂。
2. 单回合冒烟 → 八场景夹具，与混合臂比较任务数与状态。
3. 阈值与弃权：低于 yes 阈值不达成并记 `abstain_reason`；已提交支持被拒不丢证据。

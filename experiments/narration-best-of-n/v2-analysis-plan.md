# b01-template-v2 分析计划（在看到任何 v2 输出之前）

预注册：`preregistration.v2.json`，SHA-256 `ea077908046461c695076403e8c59f8b1c6b2dcb537c3efc8b820746ed9dc5fd`。
本文件只规定拿到 v2 输出后怎么看，不改预注册、不改 01 的 rubric。

## 先回答的问题

v2 只改 user turn 的固定写作指令；case、模型、种子、采样、上限、rubric 与 b01 相同。所以 v2 的任何差别只能归因于**提示词是否要求写正文**（以及采样噪声），不能归因于 N，也不能归因于模型换了。

## 逐样本必须记录的字段

- seed、原文、码点/内容字数、finishReason、首 token、总耗时；
- 01 的 fact/style/review findings 及必述覆盖；
- 三个关键必述项是否表达：4 分钟、温执到还书处、黎知微“答应留一只没登记过的旧箱”；
- 是否出现 b01 的错误形态：第一人称“我”、无据往事（如“十年前火灾”）、自相矛盾（同时写垫木板和锈穿）；
- 是否是状态清单/逐项外貌复述，而不是场景。

## 结果分型与下一步

| v2 结果 | 解释 | 下一步 |
|---|---|---|
| ≥2 份事实合格，且 ≥2 个合格簇 | 指令补上了“写正文”任务；模板假说成立 | 用同一指令跑 b02 五类泛化；b02 过门后才做 N=1/2/4 全子集 arm |
| 事实合格但全部同簇/高度重复 | 模型会写但表达单一 | 先查温度/重复惩罚/解码，另立预注册；不先加 N |
| 有事实合格但仍有 1–2 类固定漏项 | 指令部分有效 | 按漏项分类分析；b02 只跑能覆盖的类别，或改指令另立 v4 |
| 0 事实合格，漏项与 b01 相同 | 指令不是主因，模型/训练是瓶颈 | 停止这条模板线；交 02/06 走 beats/产品路径，不扩大 N |
| 为了满足“必须写变化”而编造 | 指令过强 | 记录为模板副作用；下一版改成“只写实际存在的变化”，不把编造算模型收益 |
| 全部触到 240 token 上限或截断 | 长度/上限不匹配 | 报告截断；另立上限实验，不混入本轮通过率 |

## 不许做的归因

- 不把“更长”当“更好”；不把 01 机械 checker 的 0 style finding 当文风合格；人工读评仍 pending。
- 不把 v2 的 6 个样本和 b01 的 6 个样本合并聚类或合并通过率；`compare-b01-v2.ts` 只并排，不池化。
- 不因为 v2 有 2 份合格就宣称 best-of-N 有收益；N=1 条件下没有 N 的比较。
- 不把 HPC 的 6 次调用时间当浏览器 60 s/300 s 证据；09 尚未实测。
- 不删除 b01 的 4 簇/0 合格结果，也不改口径把它重算成收益。

## 成本记录

v2 raw 会记录 `startedAtMs/endedAtMs/gapBeforeMs`，env 记录 `runWallMs`。报告必须同时给：

- 6 次调用的首 token/总耗时；
- 调用间空档（如有）；
- 整作业墙钟；
- 实际并发（本批为串行 1）；
- 与 b01 的 76 s 墙钟并排，但注明 b01 的 44 s 空档是 runner/driver stall，不是 GPU 计算。

## 判定边界

- `factQualified = decision != 'fail'` 只表示没有硬事实错误；`readableQualified = decision === 'pass'` 才表示机械意义上可读。
- v2 gate 只看事实合格数和合格簇数，因为 best-of-N 的选择器首先筛事实；文风合格率另报，不拿来放宽 gate。
- 任何一类为 0 事实合格，b02 的 arm gate 都不通过；不通过就不算收益。

# 完整场景与连续回合正文（05 线，第一批）

这是 05 线交给叙事训练、浏览器叙事和事实/候选路线消费的**完整场景正文材料**，不是模型、不是候选权重、不是质量评测报告，也不是浏览器实跑记录。第一批 3 条连续序列、11 个回合，正文 168–296 字，全部由人从已结算变化写成，逐行读过输入与正文。

它和 01 线的分工：01 写 60–160 字的稀疏短场景；这里写多角色同场、连续回合、离场再回来、任务完成后的情绪变化，并给出每一回合完整可核查的输入和合法前文。

## 文件

| 文件 | 作用 |
|---|---|
| `world/tide-watch.json` | 自带的开发世界：潮汐站的地点、人物、物品、任务，以及三条分支的起始快照 |
| `sequences/*.json` | 三条连续序列的逐回合变化、正文、视角边界和禁止补写项 |
| `build_corpus.py` | 把变化应用到状态、检查事实落实、生成 `generated/` 下的消费文件 |
| `generated/rows.jsonl` | 主材料；一行一个回合，含完整输入、`targetText`、`priorText` 和检查元数据 |
| `generated/rows-xy.jsonl` | 只含 `x`/`y` 与序列定位的轻量版本，供训练管线直接读 |
| `generated/splits.json` | train/dev 划分；连续回合只在同一序列内按顺序使用 |
| `generated/manifest.json` | 源文件哈希、生成物哈希、字段统计、事实检查与外部校验结果 |
| `generated/preview.md` | 逐回合人工阅读稿：先列结算变化，再读正文 |
| `.gitattributes` | 固定 JSON/JSONL/Markdown/Python 为 LF |

重建：

```bash
python -X utf8 experiments/narration-quality/corpus-scenes/build_corpus.py
```

## 来源与隔离

- 世界是本次新编的开发世界 `tide-watch-1998`，人物、地点、物品、任务均为新写；没有借用旧 199 行的输入或正文，也没有改冻结数据、旧 splits。
- 三条序列从同一世界的三个明确起始快照出发（`branches.*.premise`），每条序列内部的回合是连续的，必须按 `turnIndex` 顺序使用。分支起始快照是**作者设定的开发用前情**，不是浏览器记录；不要把 `premise` 当成页面已经发生过的历史。
- `sourceRowId` 统一写成 `authored:tide-watch-<branch>#t<n>`，表示这是新写材料，不是旧行改写。如果以后把旧 199 行的目标改成更忠实版本，应保留旧 `row-XXXX` 作为 `sourceRowId`，并把原输入原样放进 `input`。
- 本批不含独立终验素材；`tide-watch-radio` 标记为 `dev`，只是新世界内的留出序列，不是旧数据集的 dev/test，也不是最终用户验收集。

## 一行长什么样

必填字段：

| 字段 | 含义 |
|---|---|
| `id` | 本材料内的唯一 id |
| `sourceRowId` | 作者来源标记；本批为 `authored:...` |
| `sourceEvidence` | 世界分支、序列回合位置、分支前情或上一回合 id |
| `input` | 五键输入：`视角`、`上回合状态`、`本回合变化`、`本回合状态`；与训练行同形 |
| `targetText` | 人手写的完整场景正文 |
| `targetChars` | `targetText` 的码点数 |
| `inputSha256` | `input` 规范化 JSON 的 SHA-256，便于核对 |
| `priorText` / `priorTextId` | 同一序列上一回合的合法正文；首回合为 `null`，前情在 `sourceEvidence` 的 `premise:` 行 |
| `requiredFacts` | 本回合必须落实的已结算事实：时间、移动、物品/外貌、任务、个性 |
| `licensedDetails` | 正文里允许出现的、有输入依据的细节和细微动作 |
| `knowledgeBoundary` | 视角是谁、能看到什么、不能替谁说出什么 |
| `forbiddenInventions` | 本回合明确禁止补写的往事、线索、物品、人物或事件 |
| `categories` | 本回合覆盖的写作类型 |
| `worldFamily` / `sequenceId` / `turnIndex` | 世界族、序列、回合序号 |
| `split` | `train` 或 `dev` |
| `styleReferenceIds` | 可参考节奏/对白/人物反应的旧行；不是事实来源 |
| `notes` | 本回合的写作取舍 |

**模型输入只应使用 `input`，训练目标只应使用 `targetText`。** `requiredFacts`、`licensedDetails`、`knowledgeBoundary`、`forbiddenInventions`、`styleReferenceIds` 是检查/审计元数据，不能拼进 prompt，也不能作为参考答案喂给模型。

## 三条序列

| 序列 | 回合 | split | 内容 |
|---|---:|---|---|
| `tide-watch-duty` | 5 | train | 值班室：罗平回来又离开、陈漪去电报间又带着完成的预警回来、阿茂报告新任务、潮位计修好并转手、沈砚最终上观测平台 |
| `tide-watch-pier` | 3 | train | 栈桥：阿茂把浮标拖出来、水尺刷漆、两人各完成一件任务、沈砚改变对阿茂的判断、浮标和人都回工具棚 |
| `tide-watch-radio` | 3 | dev | 电报间：无变化的两分钟、陈漪译电码并改变说话方式、底稿和两人回到值班室 |

连续回合专门检查“后一回合不能重新发现前一回合已经发生的事”：

- 潮位计在第 3 回合已修好并带回值班室，第 5 回合只能是“这只调准的潮位计”，不能再写成刚发现故障。
- 第 1 回合陈漪已经去了电报间，第 3 回合她仍在电报间；第 4 回合她回来时，不重新介绍她是谁。
- 第 1 回合记录纸卷已经从档案角取出，第 2 回合它就在长桌上，不能再“找到纸卷”。
- 栈桥序列里缆绳已解开、拖环已擦干，后一回合只能写“绳还没上、明天挂桩”，不能写成还没解。
- 电报序列里底稿已译好并画了三道线，最后一回合只能写“译好的底稿”，不能重新开始抄。

## 事实纪律

- 任务完成必须把任务目标原样写进正文，并带完成语（做完/办完/完成）；这是下游 beat 契约的逐字要求。
- 个性变化必须原样写出新增的个性文本；被替换掉的旧个性不要求逐字回引。
- 外貌新增/解除必须原样写出对应文本；物品转移必须写出物品名、来源地和目的地。
- 每次时间推进都必须在正文里写出（如“六分钟过去了”），不能只留在状态面板。
- 视角固定为主角沈砚。其他人物可以有可观察的动作、语气、出汗、手抖，但不能写他们的内心判断、秘密或未来打算。
- 正文只使用输入里已有的地点、人物、物品、外貌、任务和上一回合已经写过的内容；不补往事、承诺、线索、新人物、新物件。

本批**故意不写精神值变化**：当前 02 线对齐器要求精神值变化句同时出现 from/to 两个数字（`sanity_changed`），否则算未落实；把这套数字塞进正文会让正文变成状态逐项复述。情绪变化改由个性文本承担（沈砚愿意拿出手记、陈漪承认怕雷、沈砚开始信年轻人的眼力、陈漪说话慢下来）。如果后续对齐器接受行为层面的精神变化，再补一组带精神值的场景。

## 旧行忠实改写（3 行）

另有一小组**冻结 train 行**的忠实改写，放在 `rewrites/`：

| 文件 | 作用 |
|---|---|
| `rewrites/targets.json` | 3 行的 `sourceRowId`、正文、允许细节、边界、禁止补写项和改写理由 |
| `rewrites/build_rewrites.py` | 读冻结 `rows-xy.jsonl`，核对输入未变、split 为 train，检查事实并生成 |
| `rewrites/generated/rows.jsonl` | 改写主材料，`input` 是原 `x` 原样，只有 `targetText` 变了 |
| `rewrites/generated/rows-xy.jsonl` | 轻量 `x`/`y` |
| `rewrites/generated/preview.md` | 逐行阅读稿 |

覆盖：

- `row-0164`：一人去借阅台、主角完成“把抄本和原本对一遍”、7 分钟；补上原 y 没写清的移动和时间。
- `row-0188`：同场两人各完成一件封面任务，主角新增“把抄下来的那份签字交出去”，24 分钟；补上原 y 没写清的两件任务。
- `row-0181`：主角按索书号找齐十一本，并新增“决定这一排自己一排一排核”，18 分钟；补上原 y 没写清的任务完成和个性变化。

这些行的旧长 `y` 只作风格参考，不作为事实来源；旧输入、旧 splits、旧数据集都没有修改。`sourceInputSha256` 是冻结 `x` 的规范化哈希，构建器会重算并拒绝改过的输入。3 行都通过 02 线提交 `211fd463` 的真实校验器（0 hard issue）。

改写过程中也确认了当前校验器的三个误判，供 02 复核：

1. 任务目标里的“那一天”“十年前”会被时长解析当成 1 天 / 10 年，和本回合的 2 分钟 / 5 分钟冲突。`row-0002`、`row-0003` 的目标含这类词，忠实改写无法同时满足“逐字引用目标”和“时长达标”，所以这次没有 ship 这两行。
2. 复合中文时长“二十四分钟”“十八分钟”被解析成 4 分钟 / 8 分钟；本批改写改用 `24 分钟`、`18 分钟` 的阿拉伯写法。
3. 地点名后面紧跟“到”会被当成移动，例如“二层西侧书架高到天花板”；本批改写改成“很高，几乎碰着天花板”。

## 检查结果

构建器逐行检查：时间词、移动的来源/目的地、物品名与来源/目的地、任务目标与完成语、外貌/个性原文、禁用人物名、阿拉伯数字。11 行全部通过，`manifest.json` 的 `checks.factCheck = pass`。

另外用 02 线**提交 `211fd463`** 的真实校验器做了一次外部硬错误检查（`verify.ts` + `ledger.ts` + `narration-alignment.ts` + `committed-narration.ts` 的临时只读拷贝，跑完删除）：11 行全部没有 hard issue，23 个强制事实全部落实，没有重复句/重复小句，没有回声上一回合（bigram 重叠 0.08–0.14），没有越界人物或知识泄漏。大量 `unverified_sentence` 是预期的：场景里多数句子本来就不绑定单条事实。这是机械硬错误检查，不是质量评分。

## 给 10（训练）的消费方式

- 直接把 `input` + `targetText` 当完整场景样本；`targetText` 是 168–296 字的场景，不是逐事实的一两句 beat。
- 连续回合必须按 `sequenceId` + `turnIndex` 顺序取；训练时把 `priorText` 作为上一回合正文一并给模型（或至少保留在上下文里），不要打乱顺序，也不要把不同序列的回合拼在一起。
- 需要 beat 目标时，从 `requiredFacts` 选事实另写 beat 文本；不要把 `requiredFacts` 原样拼进 prompt，也不要把整段 `targetText` 机械切成一事实一句。
- `styleReferenceIds` 指向旧长行；只借节奏、对白密度和人物反应，不搬事件。
- `tide-watch-radio` 是 `dev`，不要混进训练；它用于检查模型在没见过的连续序列上的表现。
- 本批没有真实模型输出、没有浏览器 GPU 数据、没有候选权重；不要把它当成模型质量证据。

## 给 02（浏览器叙事）的消费方式

- 用这批材料检查三件事：多角色同场时每个已结算变化是否落实；连续回合是否出现“重新发现/重新介绍”；任务完成后是否写出情绪/个性变化而不是只报状态。
- 目标文本是一种实现，不是唯一措辞；允许同义改写，但任务目标、新增个性、外貌增删这些冻结文本必须逐字出现（当前对齐器的约束）。
- 当前对齐器的几个硬约束已在写作时绕开，供 02 复核：任务/个性句必须在本句内出现人物名；任务目标不能含地点名（否则会被其他在场人物的 `at` 事实误判为站位冲突）；个性文本不要含另一个人物名（否则会被判 actor swap）；物品转移句要避免“到+地点”的移动句式（对齐器没有物品事实，会误判为人物移动）。这些不是正文质量问题，是对齐器的已知边界。
- 如果真实模型在这些场景上失败，把原始输入、生成文本、错误类型发回 05；不要用规则模板替换失败场景后声明通过。

## 已知限制

- 正文 168–296 字，比旧 199 行的 700–1500 字短；这是“有节奏的完整场景”，不是长篇小说片段。下一批会按真实缺口补更长的多拍场景。
- 没有精神值变化；原因见上。
- 没有物品整体出现/消失，只有物品转移、外貌新增/解除；下一批补“物品出现/消失”要另建合法状态变化。
- 分支起始快照是作者设定，不是浏览器记录；本批不能替代真实页面 E2E。
- 外部校验用的是 02 线提交 `211fd463` 的校验器临时拷贝；02 线之后若改校验逻辑，结论需要重跑。
- 没有自评分、没有质量合格声明；最终接受仍要看用户真实试玩和读评。

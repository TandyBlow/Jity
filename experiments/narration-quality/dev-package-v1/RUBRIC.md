# 叙事质量 rubric v1（公开开发包）

冻结者：01-input。冻结时间：2026-11-10。这版 rubric 在看到 11/12 任何候选输出**之前**写定；之后只在另立版本时修改，旧结果保留。
适用包：`cases.jsonl`（15 例，manifest 里登记输入/参考/包哈希）。这是**公开开发回归**，不是独立终验。

## 0. 怎么用

1. 候选模型对每例 `input` 生成正文；模型输入只有 `input`，不含 `requiredFacts`、`notes`、`reference`。
2. 用同一 rubric 判每例，输出每例一条 JSON（见 §5）。
3. 比较必须同条件：同一 `cases.jsonl` 哈希、同一模板、同一 temperature/top_p、同一 max tokens、同一停止条件。换条件即换版本，不与旧结果混比。
4. 允许候选先跑子集，但**子集必须在看到结果前声明**并写进自己的 `preregistration.json`；事后挑例不算。

## 1. 硬错误（出现即该例不合格）

逐句对 `input`（视角 / 上回合状态 / 本回合变化 / 本回合状态）核查。

| 类别 | 判错条件 | 例 |
|---|---|---|
| 已结算事实写错 | 人物去向、时间、数字、物品归属与 `本回合变化` 不一致 | 结算 天台→楼梯间，写成"从楼梯间出来" |
| 已结算事实漏写 | `requiredFacts` 里的必述项没表达（同义改写算表达；换个话题不算） | 时间推进 6 分钟全篇不提 |
| 无据人物 | 出现输入里没有的人名/身份并参与场景 | 凭空出现"值班员"并说话 |
| 无据物品 | 出现输入里没有的物件并产生影响 | 凭空"一串钥匙"打开柜子 |
| 无据动作/事件 | 写了会改变世界状态的动作（进入、拿起、递给、打开、攻击、奔跑等），而该回合没有结算 | 没人移动却写"脚步声远去" |
| 无据往事/线索/承诺 | 引入输入未给出的过去事件、线索、约定 | "他记得她以前最恨这台机器" |
| 无据结果 | 写出未结算的后果（"锁开了""火灭了""他答应了"） | 只结算"走向门口"，写成"门被推开" |
| 性别/指代错 | 代词、称谓指到错误人物；同场多人时歧义未消解 | 男性角色被写成"她" |
| 视角/知识越界 | 以非视角人物的内心、未公开信息、视角外场景作叙述 | 视角人物在门外，写出屋内另一人的想法 |
| 关键行动缺依据 | 对剧情有影响的行动/决定/线索必须有输入依据（用户允许的细微动作除外） | 无结算却"决定了参赛" |

**允许的润色**（不算错）：细微动作（坐下、抬头、放下杯子、合上簿子）、对白措辞、情绪与生理反应（喉咙发紧、呼吸一顿）、比喻、视角人物的推测（明确写成推测）、输入里已给的外貌/环境细节的复述。

## 2. 文风不合格（blocking，出现即该例不能算"可读正文合格"）

- 状态面板腔：逐字段播报（`X把「…」这件事做完了`、`X的精神值从 A 变成了 B`、`X身上多了一点变化：…`）。
- 任务/个性原文整句照抄，句中不带叙事动作。
- 空话填充：删除后不影响信息与画面的句子成段出现。
- 模板重复：同一句式（"XX过去了""XX站在原地"）在一篇内反复；结尾与前文/前回合动作逐字重复。
- 复读前文：与前文（`priorTexts`）连续 12 字以上重合，或开头逐字相同。
- 名单播报：把在场人物按顺序各写一句"XX站在YY"。
- 截断/未完：句子断在半句、承诺"接下来"却不写。
- 元叙述：出现"根据输入""结算""状态""这一段"等出戏词汇。

## 3. 待人工读评（pending，不算通过）

- 同义表达是否准确表达必述事实（如"把护目镜推上去"表达"戴好"）。
- 心理/情绪反应是否与精神值变化方向一致。
- 指代在多人场景里是否真的能被读者消解。
- 文风是否达到"小说读感"——这只能由真人读评，AI 只能给 `unverified`。

`pending` 既不通过也不失败；汇总时单列，不能混入通过率。

## 4. 每例判定

```
不合格 = 任一硬错误
文风不合格 = 无硬错误，但命中 §2 任一条
待读 = 无硬错误、无 §2 命中，但 §3 有未决句
合格 = 无硬错误、无 §2 命中、§3 无未决项
```

## 5. 每例输出格式（候选方产出，评审方复核）

```json
{"caseId":"...","inputSha256":"...","model":"...","template":"...","seed":1,
 "text":"完整原文",
 "decision":"pass|style_fail|fail|pending",
 "violations":[{"sentence":"...","kind":"fact.direction_reversed","basis":"本回合变化：...","note":"..."}],
 "pending":[{"sentence":"...","question":"..."}],
 "elapsedMs":{"firstToken":0,"done":0}}
```

`decision` 由候选方自评；01/05/03 独立复核时重判，不采信自评。

## 6. 晋级门（质量部分）

- **模型搜索（11）**：同一冻结包上，无硬错误的例数 ≥ 10/15，且文风不合格 ≤ 3，且没有任何一例出现"无据事件/人物/物品"；相对当前基线（Qwen3-1.7B 现有输出）在**同条件**下有可说明的正文收益（至少 2 例从 `style_fail/fail` 变为 `pass`，不能靠删检查）。只过 3 例不算。
- **best-of-N（12）**：单次基线与 6 seed 同条件；6 份里至少 2 份**事实合格且表达不同质**（不同叙述结构/节奏/细节组织，不只是换同义词），且相对单次基线有可复核改进；有效重复率 `1 - distinctRealizationClusters/6` 要报出，> 80% 且连续可比实验无改善则停。
- 任何"删必述项/降严重度/换更松检查器"得到的提升一律不算，按失败记录。

## 7. 不可用作终验的声明

本包所有例子来源：01 自写短场景（10 例）、05 连续片段（3 例）、冻结 199 行训练材料（1 例）、01 手写夹具（1 例）。写过这些材料的人（01、05）以及针对性调过参的人不能把它们当独立终验；换评审人也不改变这一点。独立终验须另立冻结批次并做泄漏检查。

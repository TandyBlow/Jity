# 短场景事实监督（01 线）

这是 01 线交给叙事训练/浏览器路线消费的**短场景正文材料**，不是模型、不是候选权重、不是质量评测报告。共 71 行，正文 61–152 字：51 行来自旧图书馆 train（21 行原样 + 4 行另外选行的手写长正文 + 25 行另外选行的短正文 + 1 行明确标记的 2 分钟时间对照），另有 20 行是产品世界 `dragon-raja-free-day` 的 authored 短场景。全部由人从已结算变化写成，逐行读过输入与正文。

## 文件

| 文件 | 作用 |
|---|---|
| `rows.jsonl` | 主材料；一行一个短场景，含完整输入、`targetText` 和检查元数据 |
| `rows-authored.jsonl` | 20 行产品世界行，由 `authored/scenes.json` 生成；与 `rows.jsonl` 中的 authored 段一致，便于单独检查 |
| `authored/scenes.json` | 产品世界的 20 个 authored 场景定义：状态选择、变化、正文和边界 |
| `authored/build_authored.py` | 从世界文件初始快照生成产品世界行，并重建 `rows.jsonl` 的 authored 段 |
| `long/scenes.json` | 4 行 120–160 字长正文的写作定义，挂在冻结 train 行 row-0117/0132/0137/0183 上 |
| `long/build_long.py` | 读取冻结 `x`、重算哈希、把 `short-long-*` 行写回 `rows.jsonl`，其他行逐字节保留 |
| `short/scenes.json` / `short/build_short.py` | 另外 25 行冻结 `x` 的短正文定义与写回脚本（`short2-*`），覆盖物品、任务、移动、个性和精神 |
| `first/scenes.json` / `first/build_first.py` | 首批 22 行短正文（含 2 分钟派生对照）的正文定义与写回脚本；只改 `targetText`，冻结输入不变 |
| `index.json` | 批次索引、来源、可消费字段、世界族/类别/长度统计 |
| `review.md` | 逐行人工阅读记录：变化是否落实、边界是否守住、字数 |
| `check_corpus.py` | 结构检查：冻结输入是否原样、authored 来源/SHA 是否对、是否只用 train、长度/字段是否合格 |
| `README.md` | 本说明 |

重建顺序（改过任一段的正文或场景定义后）：

```bash
cd experiments/narration-quality/corpus-short
python -X utf8 first/build_first.py
python -X utf8 authored/build_authored.py
python -X utf8 long/build_long.py
python -X utf8 short/build_short.py
python -X utf8 check_corpus.py
```

四个写回脚本都只改自己负责的行，其他行逐字节保留；按这个顺序重建出来的 `rows.jsonl` 与当前提交逐字节一致。

## 来源与隔离

- 51 行旧材料来自 `narration-dataset-v1` 的 `rows-xy.jsonl`，源提交 `1ab6ca791f97529a7bffed1f4837bf81a28badcb`；只用 **train** 划分，没有使用 dev/test 行。旧 199 行和 `splits/v1.json` 均未修改。4 行长正文（`short-long-0117`/`0132`/`0137`/`0183`）只是给另外四行冻结 `x` 写更长的手写目标；`short2-*` 是另外 25 行冻结 `x` 的短正文，`input` 都是原样。
- 20 行产品材料来自 `frontend/public/worlds/dragon-raja-free-day.world.json` 的初始快照，源提交 `865ae64e0901a70c3db4f1d0eb2af60268943c53`，文件 SHA-256 `0a8b63be2932ceb5d597adf332123d8cfb584c2fd92ddd351770d4a9fa09f24a`。每行只落一个 authored 的本回合变化；不是浏览器会话，不声称前几回合发生过。人物、地点、物品、任务全部来自该世界文件，没有新造产品人物。
- 旧行 `input` 是 `x` 的原样拷贝；产品行由 `authored/build_authored.py` 从世界初始快照生成，`sourceInputSha256` 都是规范化 JSON 的 SHA-256，`check_corpus.py` 会逐行重算。
- 两类材料都标 `sourceSplit: train`；旧行从未见过的 dev/test 输入不进入训练，产品行是新开发材料。`worldFamily` 用于按世界族补样本和隔离独立终验。
- 旧行里的长 `y` 只作为文风参考（见 `styleReferenceIds`），**不作为事实来源**。有些长 `y` 与 `本回合变化` 不一致（例如 `row-0182` 让两人在走廊对话并说去借阅台，但变化只让柏清和去长桌区、温暮留走廊；`row-0199` 让方既白去装订间，但变化只让叶暮去楼梯间、方既白留天台并新增问名字任务）。本批正文按变化写，不按长 `y` 搬事件。
- **1 行派生对照**：`short-0008-two-minute-no-change` 以 `row-0008` 为底，只把 `本回合变化.时间推进` 从 20 分钟改成 2 分钟，其余输入和状态不变；`sourceRowId=derived:row-0008`、`sourceEvidence.derived=true`、`baseRowId=row-0008`，并写明 derivation。它的 `sourceRowId` 故意不写成 `row-0008`，这样 10 线按 `sourceRowId` join `rows-v2` 时会自然跳过它，不需要额外分支。它来自 09 这批真实运行里 `elapsed-two-minutes` 仍然让模型开盒子的失败，只训练“两分钟过去、没有新事件”，不是旧 199 行中的冻结行。检查脚本会验证它相对底行只改了时间。
- **20 行产品世界 authored**：`dr-0001` 到 `dr-0008`、`dr-0010` 到 `dr-0021`（`dr-0009` 是重复的数字变体，已删除）。前 8 行是 60–81 字短场景，覆盖无变化、移动、任务完成、外貌、个性、精神、两人分开、任务新增；`dr-0010`–`dr-0014` 是 103–136 字的两事实场景（开笼搬担架、过桥报告、备床、换弹匣、凯撒进庭院）；`dr-0015`–`dr-0018` 直接对着 04 这批真实失败写：移动但不写姿势、两人同场每句用名字开头、检查门闩但不给路线答案、把门闩事实说清但不替人决定路线；`dr-0019`–`dr-0020` 补医护休息区的症状问答和东回廊的备用弹匣确认；`dr-0021` 针对 04 realizer 在无变化点给三个人各编一次移动/站位，写三人留在原位、无姿势、无事件。所有精神值变化都写出前后两个数字，任务目标用「」原样带出。
- **4 行旧行长正文**：`short-long-0117`/`0132`/`0137`/`0183`，`input` 仍是冻结 `x` 原样，`targetText` 是新写的 109–136 字版本，用来补 120 字上下的两三事实场景。

## 一行长什么样

必填字段：

| 字段 | 含义 |
|---|---|
| `id` | 本材料内的唯一 id |
| `sourceRowId` | 旧行 id（如 `row-0008`）或 authored id（如 `authored:dragon-raja-free-day#...`）；长正文行用 `short-long-*` 作本行 id、原 `row-*` 作来源 |
| `sourceEvidence` | 数据集、源提交、源文件/世界 SHA、train 划分；authored 行另有 `authored=true` 和 `premise` |
| `sourceSplit` | 固定 `train` |
| `sourceInputSha256` | 本行 `input` 的规范化 SHA-256 |
| `worldFamily` | 旧馆内区域族（如 `library-news`）或 `dragon-raja-free-day` |
| `categories` | 本行覆盖的变化类型，例如 `movement`、`task_complete`、`sanity_change` |
| `input` | 完整四键输入：视角、上回合状态、本回合变化、本回合状态 |
| `targetText` | 人手写的 60–160 字自然中文叙事 |
| `targetChars` | `len(targetText)`（码点） |
| `requiredFacts` | 这行必须落实的已结算事实：时间、移动、物品/外貌、任务、精神值等 |
| `licensedDetails` | 正文里允许出现的、有输入依据的细节和细微动作 |
| `knowledgeBoundary` | 视角是谁、能知道什么、不能替谁说出什么秘密 |
| `forbiddenInventions` | 本行明确禁止补写的往事、线索、物品或事件 |
| `styleReferenceIds` | 可参考节奏/对白/人物反应的旧行；不是事实来源 |
| `notes` | 本行的写作取舍 |
| `variant` | 可选的检查变体；目前只有 `sanity-literal` |

**模型输入只应使用 `input`，训练目标只应使用 `targetText`。** `requiredFacts`、`licensedDetails`、`knowledgeBoundary`、`forbiddenInventions`、`styleReferenceIds` 是检查/审计元数据，不能拼进 prompt，也不能作为参考答案喂给模型。

## 给 10（训练）的消费方式

- 直接把 `input` + `targetText` 当作 `yShort` 样本；`targetText` 是 61–152 字的短文，不是逐事实的一两句 beat。产品 20 行可直接补卡塞尔学院世界，不要再只学旧图书馆的实体映射。
- 如果要做 beat 目标，可从 `requiredFacts` 拆，但 beat 文本要另写；不要把 `requiredFacts` 原样拼进 prompt。
- `styleReferenceIds` 指向旧长文；只借节奏、对白密度和人物反应，不搬事件。
- 本批可以按 `worldFamily` 分组混入；旧 51 行没有使用旧 dev/test，产品 20 行是新 authored 材料，不会把独立终验的输入带进训练。
- 本批没有连续回合；`sequenceId`/`turnIndex` 为 `null`。需要连续回合时由 05 线或后续批次提供，不要把这 71 行误当连续序列。
- 所有精神值变化都写出 from/to 两个数字；没有单独的 `variant` 行，也不再保留重复的数字对照。

## 给 02（浏览器叙事）的消费方式

- 这 71 行是“事实不漏、边界不越、读起来像正文”的参照，不是候选模型输出。产品 20 行可以直接检查卡塞尔学院实体上的移动、任务、装备、分开和物品转移。
- 对照 `requiredFacts` 看：关键动作/结果有没有漏；对照 `knowledgeBoundary`/`forbiddenInventions` 看：有没有替角色说出不知道的秘密、有没有补重大往事/线索。
- 如果某条真实生成在这些行上出错，把输入、输出和错误类型交给 01，下一批按同类世界族补，不要用规则模板替换失败样本。`dr-0001` 是无变化对照，`dr-0002`/`dr-0007`/`dr-0011`/`dr-0014` 是移动+分开对照，`dr-0008` 是“新增任务但不给答案”的对照，`dr-0010` 是“物品转移但登记没完成”的对照。

## 验证

```bash
python -X utf8 experiments/narration-quality/corpus-short/check_corpus.py
```

当前结果：71 行；长度 61–152（15 行 60–79、49 行 80–119、7 行 120–160）；51 行旧材料（21 行原样 + 4 行另外选行的长正文 + 25 行另外选行的短正文 + 1 行派生对照只改时间）+ 20 行产品世界 authored；旧行全部 train，authored 行标 train；世界文件 SHA、行哈希、authored 变化与结果状态一致性、姿势词（输入里有依据的除外）、未授权实体、事件动词和 requiredFacts 检查重算通过。语义层面的“变化是否落实、边界是否守住”由 `review.md` 的逐行记录负责，脚本不替代人工阅读。

事实绑定：按 10 线 `narration_rules.build_facts`/`binds` 只读重算，71 行的 84 条强制事实（移动、任务完成、个性变化、精神值变化）全部能绑定到正文句子；按 10 线 `projection_v2`/`v2_render` 重算，71 行都能序列化，只有 2 分钟派生行与底行 `xProse` 按设计只差时间。任务目标必须在正文里原样出现（`「查清…」` 加“办完/做完”），精神值变化必须同时出现 from/to 两个数字；这两条会让个别句子偏“任务播报”，是当前对齐器的硬要求，不由本线单方面放宽。

## 结构检查现在挡什么

`check_corpus.py` 除了原来的冻结输入/来源/长度检查，还加了两条直接来自真实失败的规则：

1. **姿势词**：正文不能写“站在/坐着/蹲下/躺/跪/靠/起身”等没有结算的姿势。04 这批浏览器运行里，程序 realizer 产出“路明非站在西侧服务巷”，被自己的校验判成没有事实支持的站位；本材料全部改成“在/留在/走到/停在”等位置写法。
2. **未授权实体**：产品行正文里出现的世界实体名，必须在输入里出现过；否则算新增地点/人物/物品。04 的 realizer 写了输入没有的“跨溪小桥”，这条规则会把同类问题挡在材料外。

两条规则现在都通过；它们只检查这两类硬问题，不判断文笔或事实是否说得自然。

## 已知限制

- 本批没有 GPU 生成，也没有模型训练；正文是人手写的监督材料。
- 没有自动语义评分；`requiredFacts` 是检查清单，不是可机器判定的完整逻辑。
- 旧馆 51 行 + 产品世界 20 行；产品行只来自一个初始快照，只覆盖部分人物/地点，不是全类别、全人物、全地点的平衡采样。
- 正文长度 61–152 字，已补 7 行 120–160；140 字以上只有 1 行，且是两个事实，不是密集多事实场景。
- 旧长 `y` 有事实错误，未作为事实来源；本批不修改旧数据，也不重新划分旧 splits。
- `licensedDetails` 中含少量空间/动作具体化（如杯口朝向、门虚掩、用裤缝擦手），均不改变已结算事实；如果训练侧要求更严，可逐行删。
- 产品 20 行是 authored 开发材料，不是浏览器记录；`short-long-*` 长正文是同一冻结输入的第二个实现，不改变旧行。

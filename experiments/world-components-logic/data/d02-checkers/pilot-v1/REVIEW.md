# 试点数据助手复核记录

日期：2026-11-10。复核者：助手（不是人审，不代签）。范围：`samples.jsonl` 全部 120 条（100 条针对性＋20 条 API 自然首输出）。

## 复核方法

1. 逐条打印原文、步骤、提及、角色、实体、诊断角色、M2 标签和问题跨度。
2. 用程序校验器核对文本哈希、步骤边界、跨度切片、角色状态、实体类型、主体是否包含当前执行人、结果问题的作用域。
3. 对每条针对性样本核对五个变体（clean／actor-swap／result／special／role）是否互相隔离；对自然样本核对是否只按同一规则标注。
4. 复核发现的问题直接改数据构造器并重建，不修改 API 原始输出。

## 本轮发现并修正

| 问题 | 修正 |
|---|---|
| `印章` 同时是 `印章` 与 `旧印章` 的别名，导致 clean 样本实际有歧义 | 移除冲突别名；歧义样本改用无先行词的“它”并显式给两个候选 |
| `workshop-newentity:special` 用“修好”断言结果，却只标未登记工具 | 改为“试着用铜齿轮修搅拌棒”，隔离未知实体 |
| `workshop-newentity:role` 用“撬开”带结果，和类型错误混在一起 | 改为“试着用连笙撬动染料碗”，隔离类型错误 |
| 来源案例用“取回”，同时含结果语义 | 改为“从……取”，隔离 source 诊断角色 |
| 条件样本把“清楚／正常／空着”写成 `success_word_in_condition`，词不达意 | 改用 `condition_scope`，并新增真正的“如果放置成功”条件样本 |
| 自然样本 `signal-gate` 的“闸门”是别名，原标注未显式登记 | world 增加 `闸门` 合法别名，样本用 alias basis 并升级复核 |
| 自然样本重复出现同一实体但只标一次 | 逐步骤补齐提及，保留代词和省略主体 |
| 结果案例的后半句引入未绑定实体 | 简化结果从句，确保 M1 干净、只有 M2 失败 |

## 检查结果

- 120 条全部通过程序契约校验，预期决策与校验器一致。
- 20 个场景组，组内 5 条针对性变体；组不跨 split；切分 72/12/12/24。
- M1 升级 52 条、M2 升级 29 条、组合升级 76 条；其余 44 条预期接受。
- 三条语义角色困难样本保留：来源→接收人、静态场所→目的地、别名／指代升级。
- 所有标签仍为 `assistant_draft_pending_human`；本复核不能替代人审或封存测试。

## 尚未解决的分歧

1. **完成体动词**：本批把“拿起／放进／递给”当作计划步骤，把“已经……／……好了／到位／接过／封好”当作结果。该界线需要人审定稿。
2. **诊断角色自动采纳**：首版对仅诊断角色的提及一律升级；是否允许 source／static_location 自动通过，需要单独任务定义。
3. **别名**：本批识别合法别名但一律升级；无歧义别名是否可自动采纳尚未决定。
4. **共同主体**：联合行动允许多个 `subject`；请求他人行动、共同行动者与接收人的边界仍需人审。
5. **自然集规模**：20 条只作下一轮种子，不能估计自然分布或线上错误率。
6. **封存污染**：20 条 sealed 试点已被 API 代理检查打开，最终验收必须新建封存集。

# 叙事数据集 v1：行格式与取数规则

日期：2026-11-08。分支 `world-components`。本目录的样本都是**造出来的**，不读数据库。

## 一行是什么

五个字段：`上回合状态`、`本回合变化`、`本回合状态`、`视角`、`叙事`。

- 状态是模型可读的投影：`地点`（含 `位于` 上级地点、`外貌`）、`人物`（`位置`、`精神值`、`外貌`、`个性`、`任务`）、`物品`（`位置`、`外貌`）。
- 任务的层级是 `大任务` + `小任务` 列表，不拍平。
- `个性` 是文字条目列表，人物之间、人物与地点/物品之间的关系写在这里（例如“和温既明是同乡”“那副灯架是搭档最后倒下的地方”）。
- 不给实体 id、不给变化条目 id、不给 `supersedes` 指向的 id。名字就是键。
- `本回合变化` 按 A/B 的 `EntityDelta` 字段一对一翻译：`位置`←`positionSet`、`新增外貌`/`解除外貌`←`appearanceChanges`、`精神值`←`sanitySet`、`完成任务`←`tasksAchieved`、`新增小任务`←`subtasksAdded`、`新增个性`/`解除个性`←`personalityChanges`；`时间推进`←`timeAdvance`。没有发生的操作不写。

## 取数规则（可见性）

一行只放本回合涉及的实体：

1. 本回合发生变化的实体全部进入（人、地点、物品）。
2. 人物只收**和主角在本回合结束后处于同一个小地点**的人。上级地点相同不算，例如同在“天台”但一个在平台、一个在“天台楼梯间”，彼此不可见。
3. 地点收这些人的位置所指向的小地点，以及它的上级地点名；主角出发时所在的地点也收，因为上回合状态里她的位置指向那里。
4. 物品只收本回合变化的那件；同一地点里没变的物品不进。
5. 其余人物、地点、物品留在世界里，不进行。

样本 `row-scene-only.jsonl` 按这套规则生成：3 个人（韩知微、温既明、顾书言）、2 个地点（二层走廊、天台）、1 件物品（天台灯架）；叶照在“天台楼梯间”，不可见，因此不在行内。

## 叙事

- 视角是一句：`主角视角（<名字>）；只表达已结算的世界事实`。
- 目标文本是小说写法：不逐条复述事实，允许不写全部变化，允许未登记的细微动作（例如一个眼神）。这比“逐条事实对齐”的模板宽，判分时要分开看。

## 生成脚本

- `make_delta_contract_sample.py`：当前口径。产出全状态 `row-delta-contract.jsonl` 和按可见性裁剪的 `row-scene-only.jsonl`，同一回合、同一叙事。
- `make_full_state_sample.py`、`make_large_sample.py`：早期口径（无个性关系、任务拍平、范围规则不同），只作历史对照。

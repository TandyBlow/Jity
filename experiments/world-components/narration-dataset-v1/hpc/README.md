# 叙事行训练：HPC 提交包

日期：2026-11-09。分支 `world-components`。这一包只做**管线接通**，不做质量结论。

## 包里有什么

| 文件 | 用途 |
| --- | --- |
| `rows-xy.jsonl` | 20 行数据，字段 `id / x / y / xText`；`xText` 就是喂给模型的整段字符串，没有任何指令文字 |
| `preflight.py` | 不碰 CUDA，在登录节点先跑：检查基座三个文件在不在、数据能不能解析、统计 token 长度 |
| `train_narration_rows.py` | 训练 + 贪婪生成 + 写 `report.json`（含数据与基座哈希、每个 epoch 的 loss 与显存、生成样本原文） |
| `submit.sbatch` | slurm 提交脚本，默认 8 epochs / lr 3e-4 / 留出 `row-0010,row-0017` |
| `run-direct.sh` | 没有 slurm、直接拿到 GPU 节点时用同一个 run |

数据哈希：`rows-xy.jsonl` sha256 `761036e1d3595c40cca97aec4313f95bc6895a5fa530d1dadbd1a5f0d97018fc`

## 怎么提交

```bash
cd narration-dataset-v1/hpc
sbatch submit.sbatch            # 或： BASE=~/n4v2_run/base/randeng-t5-77m bash run-direct.sh
```

脚本里标了 `# CHANGE` 的三处按集群实际情况改：`--partition`、`BASE`（基座目录）、`PY`（解释器）。基座目录必须是含 `config.json`、`model.safetensors`、`spiece.model` 三个文件的目录。

计算节点没有外网。若缺 `sentencepiece` / `protobuf`，在登录节点装一次（这是上一轮记录过的做法）。

## 这一跑能回答什么

1. 分词器与模型能否吃下最长 1,260 token 的输入、1,128 token 的目标；
2. 单步耗时与显存；
3. loss 是否下降；
4. 训练结束后贪婪解码出来的东西长什么样，包括它在**训练过的行**上是否是背下来的。

## 这一跑不能回答什么

- 不能证明模型学会了这种写法。18 行训练数据只会过拟合，留出 2 行的输出必然很差；
- 不能报质量分数、不能报泛化；
- 不能当作产品延迟结论（这里是 4090D 离线，不是浏览器）。

## 本机预跑结果（RTX 4060 8GB，仅供确认管线可用）

- `preflight.py`：20 行；输入 303–1260 token（均值 667），目标 261–1128 token（均值 570）；`OK`
- 1 epoch（18 行）：loss 4.8572，7.3 秒
- 训练后贪婪生成 3 条：每条都写满 1,151 token 仍没有输出结束符，单条约 51 秒

第三条是关键信号：**1 个 epoch 之后模型不会自己停**。正式跑要么加结束符约束，要么在解码时按长度截断并记录 `stopReason`，不能把“写满上限”当成完成。

## 与既有记录的关系

此前 N4 的语料是“一条事实 → 一句短句”，入模样本 ≤128 token。这一批是整段多人物场景，输入可达 1,260 token、目标可达 1,128 token，量级完全不同；旧 checkpoint（`ckpt-mix431`、`u240`）不能直接拿来当这一任务的基线，只能当“换任务前的旧模型”。

| 行 | 训练过 | 目标 | 输出 | token | 秒 |

**三条都写满上限、没有一条输出结束符。** 内容全部退化成重复循环：`row-0016` 里「「从前走。」」重复 222 次，`row-0010` 里「你怎么知道」重复 40 次，`row-0017` 里「「你怎么知道。」」重复到底。开头还能照抄输入里的地点外貌（「岗亭里放着一台老式电暖器，玻璃上贴着值班表。」），一两句之后就开始打转。

另一处：输出里的逗号变成了半角 `,`（全角 `，` 出现 0 次），目标文本里全是全角。这是 T5 分词器往返把全角逗号转半角，旧记录里也有同一条，训练时没处理，所以生成时跟着错。

结论：**管线通了，质量没有。** 18 行数据 + 8 个 epoch（144 步）不够，输出先是复制输入、然后进入重复循环；同时缺结束符约束，长文本一定会写满上限。下一轮必须先补这两件（数据量、解码约束），再谈质量。

## 40 轮 + 三个改动（作业 247472、247474）

`247472`：40 轮，不改任何东西，只加“训练集/留出集分开算 loss”和“目标结尾处的结束符概率”。

| epoch | 训练集 TF | 留出集 TF |
| --- | --- | --- |
| 1 | 3.862 | 4.136 |
| 5 | 2.762 | 3.711 |
| 10 | 2.048 | 3.795 |
| 20 | 1.081 | 4.528 |
| 30 | 0.560 | 5.238 |
| 40 | 0.326 | 6.431 |

训练集压到 0.33，留出集第 5 轮见底（3.71）之后一路上涨到 6.43，比基座还差。结束符探测：喂正确前文到目标结尾，模型给 `</s>` 的概率只有 0.012–0.035，它最想接的是「（下一句对白）。

`247474`：加结束符 id、重复惩罚 1.3、禁止 4-gram 重复、AdamW weight decay 0.01（只作用在权重上，偏置和 LayerNorm 不衰减）。

- 结束符生效了：五条生成全部停在 `eos`，不再写满上限。
- 但停得太早：输出 59–186 token（目标 725–986 字），内容散架，例如「缩微胶片室的灯光响亮」「空气里有轻微的光味」。
- 4-gram 覆盖率（目标里有多少个连续四字片段在输出里出现过）：0.001–0.031，连训练过的行也没有复现。
- L2 基本没起作用：训练集 0.309 vs 0.326，留出集 6.444 vs 6.431，两条曲线与不加正则几乎重合。77M 参数、40 轮、18 行，weight decay 0.01 的力度太小。
- **本次报告有 bug**：`finalEpoch` 那两条样本实际仍是第 7 轮（最优）的权重，因为取出最优权重后没有再装回最终权重。看数字时以 `best(epoch 7)` 为准，`finalEpoch` 一行作废。

## 分词器修好之后（作业 247712）

问题：这套 T5 分词器往返会吃掉两样东西——

- `\n\n` 解码成 `" "`，段落分隔消失；
- `，` 和 `,` 编码成同样的两个 id（`[259, 261]`），解码回来永远是半角 `,`。

模型在训练里从没见过段落，也没法输出全角逗号，所以之前所有生成都是“一整段、半角逗号”。

改法（`narration_text.py`，训练和探针共用）：段落分隔在送入分词器前替换成 `||`（这套词表里正好是单个 token，id 2108，往返不变），解码后再换回 `\n\n`；半角标点按左右是不是汉字转回全角。

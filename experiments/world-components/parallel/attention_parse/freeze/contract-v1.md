# c1 → N2 关注粒度契约 v1（冻结稿）

日期：2026-11-08。冻结时**尚未实现** v2 解析器；本文件只定接口与验收样本，接线实验另行开跑。
对应原设计：R11（只叙述玩家当前可知道、且值得说的已提交事实）的输入侧。

## 1. 为什么需要这层

c1 第一轮（`runs/r1/`）只输出对象：`person_a`、`box`。玩家说“林川的袖口湿了吗”，对象层只能给出“林川”这个名字。若 N2 拿“林川”去筛事实，会把林川本回合的全部可选事实都留下（位置、任务、性格、外观），这比玩家的关注范围大。

所以要给每个对象再带一个**范围（scope）**：关心的是整人／他的位置／他的外观／他的任务／他身上的某个局部。范围决定 N2 能保留哪些种类的可选事实。

## 2. 目标形状

一个目标（target）：

```json
{
  "entityId": "item_key",
  "scope": "part",
  "part": "表面",
  "partAnchored": true,
  "surface": "钥匙",
  "scopeCue": "表面"
}
```

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `entityId` | 是 | 提交状态里的实体 id；必须是 roster 中的对象，不接受自由文本 |
| `scope` | 是 | `object` / `position` / `appearance` / `task` / `part` 之一 |
| `part` | 仅 `part` | 玩家说的局部词，字面保存（如 `袖口`），不做同义改写 |
| `partAnchored` | 仅 `part` | 该局部词是否能在该实体的提交文本里找到（`freeze/anchors-v1.json`） |
| `surface` | 是 | 原话里指向这个实体的说法（`林川` / `穿灰衣` / `盒盖`） |
| `scopeCue` | `object` 时可为空 | 原话里决定范围的说法（`在哪儿` / `穿的` / `任务` / `袖口`） |

一个原话可以有多个目标，每个目标各自带范围。

## 3. 范围与 N2 可保留的事实种类

| scope | 玩家在问什么 | N2 只允许保留这些 kind 的可选事实 |
| --- | --- | --- |
| `object` | 这个对象整体 | 该对象的全部 kind |
| `position` | 在哪、去了哪、还站在这吗 | `moved`、`positioned_at`、`position_relative`、`slot_changed` |
| `appearance` | 穿什么、长什么样、外观变了没 | `appearance_changed`、`appearance_removed` |
| `task` | 任务做完了吗、目标进展 | `task_achieved`、`subtask_added` |
| `part` | 局部（袖口、表面、盒盖） | `appearance_changed` / `appearance_removed` 且 `text` 含 `part` 字面 |

规则：

- 必述事实（`must`）**不受**关注范围影响，照旧全选。
- 可选事实只有在“实体匹配 + kind 在范围内 + （part 时）文本含 part 字面”三条同时成立时才保留。
- 同一事实被多个目标命中只保留一次。
- `part` 未锚定时（该实体提交文本里没有这个词）仍然保留这个 part 词：N2 按字面匹配，匹配不到就不选。**禁止退化成 `object`**，否则就是把“只问袖口”放大成“整个林川”。

## 4. 范围怎么定（声明式词表，不是模型）

按优先级取第一个命中的：

1. **part**：原话出现 `part` 词表里的词（`表面`、`盒盖`、`袖口`、`指节`、`额头`、`斗篷`、`鞋底`、`下摆`、`柜门`、`储物柜`、`窗纸`、`风铃`、`檐角`、`桅杆`、`衣角`）。是否锚定另算，不影响它是 part 请求。
2. **task**：原话出现任务线索词（`任务`、`目标`、`做完`、`完成`、`办完`、`进度`），或出现该实体任务 `goal` 的连续 ≥2 字片段。
3. **appearance**：原话出现外观线索词（`穿`、`穿的`、`样子`、`外观`、`打扮`、`身上`、`衣服`）。
4. **position**：原话出现位置线索词（`在哪儿`、`在哪`、`哪里`、`位置`、`走到`、`去了`、`到了`、`待在`、`站在`）。
5. 都没有 → **object**。

词表是固定清单，判据是字面命中；不理解“他看起来怎么样”这类没有线索词的问法，这种会落到 `object`。

## 5. 三种解析状态（与 r1 一致，语义收紧）

| 状态 | 含义 | 输出要求 |
| --- | --- | --- |
| `resolved` | 目标都有实体和范围 | `targets` 非空 |
| `ambiguous` | 某个说法同时指向 ≥2 个实体（含完全相同名字、共用词干、代词多前驱、描述词不唯一） | `targets` 为空，`ambiguousCandidates` 列出被争用的实体 |
| `unresolved` | 提到了对象但匹配不上实体（昵称、未登记称呼） | `targets` 为空，`unresolvedMentions` 列出原话里的说法 |
| `none` | 没有提任何对象 | `targets` 为空，且没有候选、没有提及 |

`ambiguous` / `unresolved` / `none` 三者的共同点：下游拿到的 `targets` 都是空。区别只在诊断字段，方便复核为什么空。

## 6. N2 侧契约（本轮只写，不实现）

- `targets` 为空（含三种状态）时，可选事实 **一条都不选**；必述事实照旧。这不是“没有约束”，是“不给额外许可”。
- `targets` 非空时，可选事实按 §3 的表过滤。
- N2 不重新解释原话，也不自己补词；它只消费 `entityId` + `scope` + `part`。
- 若某实体在 target 里出现多次（如 `object` 和 `position` 同时命中），取**更窄**的范围。

## 7. 与第一轮（r1）的关系

- `runs/r1/` 是对象层的原始证据，**保持不动**，也不被本契约改写。
- 本契约改变的是带字段线索的原话的期望：r1 的 S01“林川现在在哪儿？”在 v2 下应为 `person_a / position`，S09 的任务目标提及在 v2 下应为 `person_c / task`。这不是 r1 跑错，是粒度升级，记录在案。
- 因此 v2 的验收样本单独冻结在 `freeze/acceptance-v1.json`，不复用 r1 的 10 条。

## 8. 本批不覆盖（列入下一轮）

1. 任务 `goal` 原句 → `ownerId / task` 的映射（r1 S09 的 v2 版本）：本批 10 条没有占位，下一批补。
2. 一句话里既有整人又有局部（“林川怎么样了，他的袖口呢”）时的合并规则。
3. `part` 词表之外的局部（“他手背上的划痕”）：只会落到 `object` 或 `appearance`，会放大范围；需要下一轮把词表来源改成“从提交文本里抽部位词”。
4. 同一实体的 `appearance` 与 `part` 同时命中时谁优先。
5. 浏览器侧性能：本轮没有模型，不涉及。

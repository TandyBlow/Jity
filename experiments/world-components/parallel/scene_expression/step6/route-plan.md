# 段落生成路线方案（先方案，后实验）

日期：2026-11-08。状态：**方案**，未训练、未生成。范围只到“能否写出合格段落”，背景素材 A/B/C 对照暂停。

## 1. 现状：为什么这批文本不合格

已观察到的失败（`step3/drafts.jsonl`、`step5/`）：

| 失败类型 | 实例 | 根因 |
|---|---|---|
| 字段名进正文 | `学生B的性格变化变得健谈`、`钥匙外貌的变化` | 单事实模型把输入标签当措辞材料；“事实行 → 一句话”训练目标没有教它区分标签与叙述 |
| 给事实补未授权动作 | `把钥匙从门外挪到两侧`、`把钥匙放在柜子里` | 单句生成只看一条事实和场景头，没有“这一步世界没发生什么”的约束；移动事实把“钥匙可见”误当许可 |
| 目的地丢失 | `学生A从走廊过来`（无大厅） | 模型只被要求写“一句像样的话”，没有“必述要素齐全”的检查，也没有组内计划 |
| 句子之间没有衔接 | 时间句、任务句、模型句直接相连；三臂的拼接完全一样 | 拼接是字符串连接，没有组织层（N3 的角色没有进入这条链路） |
| 面板内容混进正文 | `理智值升为12`、`完成了任务「…」` | 判分器要求句内出现数值/目标文本，与“读起来像故事”冲突 |

关键事实：u240 是**逐事实短句模型**（训练输入 145–181 token，目标是单句），它没有段落级训练，也没有跨事实计划。直接拼接不可能得到合格段落；这不是“再调一下提示词”能解决的。

## 2. 验收标准（**草稿，未冻结**）

以下只是候选判据，尚未登记为门槛；先要拿三段参照验一遍，确认它们区分得开“合格/不合格”，再谈冻结。

| 编号 | 判据 | 检查方式 |
|---|---|---|
| Q1 事实完整 | 该点全部必述事实在**正文＋面板合起来**成立；数值与任务状态允许只在面板 | 分栏核对表：叙事事实查正文，数值/状态查面板 |
| Q2 三类分开判 | (a) 玩家未授权的主动行为 → 违规；(b) 改变世界、但没有已提交 Δ 的事件 → 违规；(c) 不改变世界的姿态/表情/身体反应 → 允许作为“描写”，但不得引入新实体、新道具、新动作结果，且必须与已提交事实一致 | 逐句来源表按三类标注，不把 (c) 与 (a)(b) 合并计数 |
| Q3 主语明确 | 每个分句能指出“谁/什么”，无字段名作主语 | 分句检查表 |
| Q4 衔接成立 | 相邻分句至少有一条已授权关系（时间、地点、同一主体、先后）；**并列事实也算成立**，不要求因果 | 组织计划可核对，不逼模型编因果 |
| Q5 文体 | 数值、任务状态、字段名不进故事句 | 词表 + 人工 |
| Q6 长度有据 | 段落长度由素材量决定，无填充性描写 | 人工对照参照文本 |
| Q7 读感 | 需要先定评分尺度与对应示例，再定阈值；暂不写死分数 | 每批 ≤10 题，独立评分 |

门槛状态：**未冻结**。Q7 缺评分尺度和锚点示例；Q1–Q6 也要先用三题参照试判。等级划分与阈值确定后另起版本。

## 3. 输出契约（v2，已定）
正文承担叙事，面板承担精确数值（理智等）与任务状态；两部分合起来检查信息完整性。面板是实际交付内容，不是说明文字，但**由程序从已提交状态生成，模型不写面板**；N4 的输出目标只是正文，面板与正文分别验收。样例见 `references/reference-paragraphs-v2.md`。旧冻结规则与失败结论保持不变，新契约另起版本。

## 3a. 与 N4 已有工作的复用（先盘点，不另起炉灶）

`world-components` 已有 N4.0 结构化输入装配（`design/world-engine-reports/components/n4-input-packing.md`）、N4 训练方案（`n4-training-plan.md`）、12 例已审开发材料与 88 例手工改写材料。C6 不应再建一套平行语料，顺序应是：

1. 核对 N4.0 的输入契约（事实记录格式、场景字段、fail-closed 条件）能否直接承载“正文”；面板不在模型输出里，由程序生成（见 `step6/n4-input-gap.md`）；
2. 核对已有 12＋88 例的事实来源、授权范围和适用范围，标出可复用/需重写；
3. 只补缺口：玩家输入、事件记录（说话/失败/交接）、上一段正文；
4. 确认格式后再谈规模与训练。

## 3c. 已知数据交接缺口（决定路线可行性）

- 真实记录里 `world_advances.input_text` 曾为 NULL（`design/world-engine-reports/components/interaction-sample-v1.md`）；
- N4.0 的 `resultText` 来源尚未正式接线（`n4-input-packing.md` 已知缺口 2）；
- 因此“玩家原话＋已确认事件＋前后状态＋上一段正文”的完整链路在正式流程里还没有闭环；本场景是人工编写的格式样例，不能当作运行证据。

## 4. 三条候选路线

| 路线 | 做法 | 成本 | 预期 | 主要风险 |
|---|---|---|---|---|
| A 组装层（不训练） | 保留 u240 逐事实成句；新增 N3 组织计划（分组、顺序、连接词、指代）＋逐句门控＋字段名/数值过滤 | 低（CPU、几天） | 能改善衔接与字段名；**改不了**“补未授权动作”这类内容错误 | 门控只能拒绝，不能生成正确内容；拒绝率会很高 |
| B 段落级生成（训练） | 复用 N4.0 结构化输入（事实 + 场景 + 视角 + 任务背景）→ 正文（面板由程序生成） | 中（需人工参照语料） | 有机会同时解决衔接与文体 | 参照语料必须人工写/审；模型可能抄训练句式；质量未测 |
| C 约束解码＋逐句核验 | 生成时限制句式（主语在前、谓词来自授权集合），每句过核验，失败重生成，预算固定 | 中（工程为主） | 能硬性压掉字段名和部分补全 | “重生成”会带来模板味；需要新的重试预算协议（现行冻结禁止重试） |

**建议**：B 为主路线，A 作为对照基线（用来证明“只加组装层不够”），C 的门控作为 B 的评测与兜底，不作为主生成方式。

## 5. 数据方案

1. **参照段落**：本轮已交三题（`step6/references/`），每句带来源。需扩到 **20–30 题**，由人写或人审；执行方起草的文本必须经产品负责人确认后才能进参照集。
2. **训练语料**：从已提交状态构造“结构化输入 → 段落”对。段落目标只能来自人工写作/审定的参照，**不得用模型输出回灌**；每个段落必须能逐句追到 `entityId`/`fieldPath`。
3. **评测隔离**：现有十题（`NARRATION_SPLIT_SAMPLES`）只做评测，不进训练；另备新题做留出。
4. **负例**：为 Q2/Q3 准备对抗样本（错主体、反方向、新增动作、字段名作主语），用于检查核验器而不是模型。
5. **规模与算力**：参照 20–30 段不足以训练，需要先估“每题可扩几个变体”；在语料规模确定前不申请 GPU 训练。

## 6. 评测与报告

- 自动：必述项、逐句来源、未授权动作、字段名/数值检测。
- 人工：Q3–Q7 检查表，每批 ≤10 段。
- 报告分开写：事实完整率、违规数、衔接成立率、读感分；不得合成为一个“总分”。
- 与参照文本对照：先证明“能写出合格段落”，再谈素材增益。

## 8. 未决问题

1. **面板与正文的判分口径**：已定“数值进面板”，但判分器尚未支持分栏检查；需要新的“正文＋面板”完整性口径，不能沿用本轮的字符串必述。
2. 参照文本的作者身份：执行方起草不算“人工金标”，需要产品负责人逐条确认或另请人写。
3. u240 77M 的容量能否支撑段落级输出未知；R3 就是用来回答这个问题的。
4. 重试/门控预算：现行协议禁止重试；路线 C 需要新协议（固定次数、失败即回退），未批不准实施。
5. 本轮失败结论不改变既有冻结记录：`step3/`、`step4/`、`step5/` 原样保留，不追改。
6. 浏览器长段落性能未测：C9 分支测的是另一份 77M 权重、短句输出，速度与内存结论不能直接搬到本方案；R3 必须对新权重、新输出长度单独测量。

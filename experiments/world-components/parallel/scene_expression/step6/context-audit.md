## 2. 那“触发”到底记在哪

- `ns-pers-1`：触发是**状态层的共现规则**（同点内 `task_intro` 达成 → 才允许个性变化），不是一次可叙述的行动。写“为什么突然健谈”需要因果关系，而记录里只有共现。
- `ns-multi-1`：`p_multi` 只出现在物品变化的 `sourcePointId` 里；按样本内容无法查到 p_multi 里发生了什么。学生A的移动与钥匙蒙灰是**并列事实**，没有先后或因果记录。
- `ns-loc-appear-1`：柜子关闭没有来源点，也没有“谁关的”。

这正是上一版参照反复越界的原因：素材只支持“状态播报”，任何“因为……所以……”都要靠编。

## 4. 结论

1. 这十题（含本次三题）**适合测事实表达**（必述、遗漏、越权、字段口径），**不能单独用来验收叙事质量**——缺玩家输入、上一段文本和触发事件，段落只能靠状态播报或编因果。
2. v2 三段保留为“状态播报基线”，不再当叙事金标；继续在孤立状态点上润色，只会在“干巴巴”和“自行补情节”之间摆动。
3. 要立叙事标尺，需要从**有完整上下文的真实记录**里选片段，条件至少是：
   - 玩家输入是自然语言，不是“走到走廊”这类测试指令；
   - 该点有完整 before/after/Δ；
   - 前一个点有可读的叙事文本（作“上一段”）；
   - 点是真实流程产生的，没有测试标记（“验收输入”等）。
4. 按上面的条件筛查现有 `.local/` 数据库：**当前没有满足的片段**。在拿到这样的片段之前，不扩训练语料、不选路线、不追加模型调用。

## 5. 本轮不做什么

- 不修改 `step3/`–`step5/` 任何冻结产物与结论。
- 不用测试库里的机械句冒充叙事标尺。
- 不把 v2 的状态播报改写成故事。

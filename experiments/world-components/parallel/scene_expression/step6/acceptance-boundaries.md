# 样例与验收边界（C6）

日期：2026-11-08。状态：草稿，未冻结。用于区分“测一致性”和“测叙事质量”，并固定面板与玩家对话的权限。

## 1. 样例分两类，不混用

| 类型 | 用途 | 当前样例 |
|---|---|---|
| 一致性样例 | 事件 ↔ Δ ↔ 面板能否对齐；玩家动作是否越权；失败/交接是否落账 | `step6/scenes/campus-three-points.md`（v3） |
| 叙事质量样例 | 人物声音是否有区别、场景是否可感、玩家控制是否清楚、收尾是否留下可行动的下一步 | `step6/scenes/art-room-three-points.md`（v2）：**开发草稿，待人工文本评价**；未纳入合格参照集 |

一致性样例合格，不代表叙事质量合格；叙事质量样例也不拿来当 Δ 核对表。

## 2. 判分范围

- **Q1（事实完整）**：按“正文＋面板合起来”核对。叙事事实（移动、说话、失败、交接、外貌变化）必须能在正文里读到；数值、任务状态允许只在面板。
- **Q5（数值不进正文）**：数值与任务标题只出现在面板；正文不写“理智 12”“任务已完成”。
- **Q9（面板正确）**：面板由**程序**从已提交状态生成，模型不生成面板，也不生成数值。验收时把面板与状态逐项比对，不让模型自证。
  - 现状：这是**设计要求，尚未实现**。目前两份样例的面板都是手工编写，不能据此声称“程序生成/自动核验已通过”；在该程序落地并跑过样例之前，Q9 记为 `not_implemented`。

## 3. Q2 三类分开判（与 route-plan 一致）

| 类别 | 判定 | 例子 |
|---|---|---|
| (a) 玩家未授权的主动行为 | 违规 | 输入只说“去大厅”，却写主角拧柜门把手 |
| (b) 改变世界但没有已提交 Δ 的事件 | 违规 | 写“管理员打开了柜门”，Δ 里却没有柜门状态 |
| (c) 不改变世界的姿态/表情/身体反应 | 允许作“描写”，但须与已提交事实一致；不得引入新实体、新道具、新动作结果 | 写“学生A没抬头”“学生B偏了偏头”，只要事实里有这句话或该反应 |

(c) 不计入 (a)(b) 的违规数，也不因为 (c) 的存在就把整段判成“新增事件”。

## 4. 玩家对话授权

默认**严格模式**：

- 模型只能转述玩家输入里已有的意图与内容；不得替玩家补充具体承诺、地点、人名、数字、条件。
- 系统若以后允许“把简略表达补全为具体台词”，必须另立书面规则，并且只允许用玩家已见/已知的事实补全；补全算“表达细化”，不算新事件，也不得反过来当作玩家授权了某个动作。
- 本样例采用严格模式：点 3 的柜位写进了玩家输入，不由系统补全。

## 5. 收尾要求（只对叙事质量样例）

- 叙事质量样例的每个点（至少最后一点）应留下一个新的问题、变化或可选择的行动，让玩家知道下一步能做什么。
- 一致性样例不强制收尾钩子；任务闭环本身是合法的测试目标。

## 6. 叙事质量样例的准入条件（下一份）

1. 玩家输入是自然语言，不是“走到走廊”这类测试指令；
2. 事件里有说话、受阻或失败、物品/信息交接，且全部进入事实记录；
3. 有 before/after/Δ，且与事件逐条对得上；
4. 第二点起承接前一点正文；
5. 至少两个人物有可区分的声音（用词、句长、反应方式），不是只有“说了什么”；
6. 场景有可感的细节，但不新增未登记实体；
7. 收尾留下可行动的问题或选择；
8. 明确标为“编写的实验样例”，不冒充真实记录，不参与旧十题统计。

# 要求行整体干预（real-batch-v3）

日期：2026-11-08。分支 `exp/c-round-composition`。

**一句话结论：换掉 N4.0 要求行后，10/10 首次调用都不再截断、不再回显小节标签或记录行、不再写对话，但硬门通过仍是 0/10——模型改用自己的措辞，而门要求的是事实的原话形态（「从 A 来到 B」、权威结果原文）。**

## 1. 只改了一个东西：要求行

| 项目 | 与 v2 的关系 |
| --- | --- |
| 样本 | 同一份文件（字节相同，登记里记哈希） |
| 模型 | 同一 digest（登记时重新读取 ollama tag，不同就拒绝） |
| 预算 | 384，不变 |
| 判定器 | `judge_v3` 冻结，未改词表、未改帧 |
| 重试/回退 | 相同（2 次，第 2 次带上一轮问题） |
| **要求行** | **整体替换**（唯一变量） |

原行（packer 固定输出）：

```text
要求：写场景、行动与视角人物心理；不写任务标题、数值面板、具体时长、字段名；不新增未列出的具名人物/物品/地点；他人只写可见动作。
```

新行（预登记逐字固定，SHA-256 `f187a4c59163…`）：

```text
要求：只输出一段完整正文，最多六句；写场景、行动与视角人物心理；不写任务标题、数值面板、具体时长、字段名；不回显记录行、编号或小节标签；不写对话；完整表达下列每一条事实，移动要交代起点和终点；不新增未列出的具名人物/物品/地点或事件；他人只写可见动作，不写他人内心。
```

替换规则写死在 `real_batch_v3.py`：打包后的输入里必须**恰好存在一行**以「要求：」开头、且等于登记原文，否则整批停止；替换后的文本与原文都进归档。**归因限制**：这是整体干预，结果只能归因于这一组指令，不能细分到哪一句起作用。

## 2. 开跑前的一次失败（已记勘误）

第一次 v3 运行有个运行器缺陷：提示词实际发送的是**原始**要求行，而归档记录的是替换后的文本——10 个样本的 `eval_count` 与 v2 完全一致（246/272/215/384/384/340/376/384/325/274）才暴露出来。该次运行保留为 `out/real-batch-v3-aborted-no-intervention.json`（`aborted=true`），登记改为 revision 2（记录了修复后的运行器哈希），勘误见 `fixtures/errata-v3.json`。修正后重跑，提示词里确认是新要求行。

## 3. 结果（主结果 = 首次调用）

| 指标 | v1（128） | v2（384） | **v3（384 + 新要求行）** |
| --- | --- | --- | --- |
| 首次调用自然结束 | 0/10 | 8/10 | **10/10** |
| 首次调用触顶 | 10/10 | 2/10 | **0/10** |
| 输出 tokens（首次调用） | 全部 128 | 215–384 | **77–121** |
| 首节标签/记录行回显 | — | 3 例 | **0 例** |
| 对话 | 2 例 | 3 例 | **0 例** |
| 硬门通过（首次） | 0/10 | 0/10 | **0/10** |
| 硬门通过（重试后） | 0/10 | 0/10 | **0/10** |
| N6 通过 | 0/10 | 0/10 | **0/10** |
| 调用耗时 | 2.8–3.2 s | 均值 7.4 s | 均值 4.3 s |
| 触发线（失败样本 ≥3） | 触发 | 触发 | 触发（10 ≥ 3） |

**要求行确实被遵守的部分**：一段完整正文、篇幅收敛（77–121 tokens）、没有再回显「场景：/行动与心理：」这类小节标签、没有再抄记录行、没有对话、没有触顶。这一组指令在「形态」上是有效的。

**没有解决的部分**：移动事实仍然几乎不写「从 A 来到 B」。6 个带移动事实的样本里，**语义上完整传达移动的是 0 个**，只有 `rb-same-name` 给了起点（「他从管线镇出发」）却没写到达。硬门因此继续全灭。

## 5. D4 与 N6（v3）

- D4（专名规则）：10/10 已检查，**0 条专名**。`镇中心的新广场`、`旧工厂区`、`井盖` 属物件/地点描写，按 E5 归 N6，不计入 D4。
- N6：10/10 已执行、**0 pass / 10 fail / 0 undetermined**；复核绑定**首次调用**（`reviewedAttempt=1`），重试正文未复核（`qualityFinal` 全部 `pending`）。N6 与 N5 分开：正则没匹配到的记在 `n5Formal`，N6 只判语义——所以「结果已传达但形式没对上」被如实记录，而不是拿来当 N6 的失败理由。
- 语义上已被传达的事实：8 个样本里的结果/外貌/理智/时间等（见上表），它们仍然挂硬门，因为门要求原话形态。

## 6. 这一批证明了什么、没证明什么

**已证明**
1. 要求行整体干预能改变输出形态：触顶 0/10、回显 0/10、对话 0/10、篇幅从 215–384 降到 77–121 tokens。
2. 形态改善没有带来硬门通过：仍是 0/10。也就是说，在「说清形态」之后，剩下的主要差距是**措辞与帧**，而不是长度或格式。
3. 模型能按指令收敛篇幅与格式，但在「移动要交代起点和终点」上只做到一半（给了起点，没有到达），在 POV 上仍会写第一人称与他人内心。

**没有证明**
1. 只改要求行、不改帧，模型是否可能过门——本批的答案是「没有」，但这是单模型、单 prompt、10 个样本的结论，不能外推到其他模型。
2. 哪一句指令起了作用——整体干预，不能细分。
3. 质量结论：N6 全 fail，单一复核者。

## 7. 建议的下一步（需裁决）

1. **帧的对照批**（下一个单变量实验）：只放宽「移动」与「结果」两个帧（允许「走进/抵达/到了」与结果同义转述），样本、模型、预算、要求行全部冻结；预期能看到硬门通过率首次非零，同时把「措辞差异」与「事实错误」分开。
2. **POV/他人内心**：本批仍有 1 例第一人称、2 例他人内心；按要求行已明说「不写他人内心」，模型仍违反。是否升硬门，需要单独裁决。
3. 如果帧对照批仍为 0，再考虑换模型或训练，而不是继续加要求行。

# N4 输入组织设计稿（待审，未登记、未实现）

日期：2026-11-09。范围：**N4.0 的输入组织**。模型、解码参数、N1/N2/N3 输出、写作约束、判定器都冻结。本稿不是预登记：审查通过、渲染器与独立标注完成后再写登记文件。

**变量口径（按 2026-11-09 裁决更正）**：B 组同时改变了事实排列、字段名称与组内要求，因此是一次**组合改动**。A/B 只能比较整体效果，不能单独证明哪一项改动有效；本次按组合改动登记，不再拆成更多实验。

## 1. 要解决的问题

v3 的 10 个样本里，22 条必述事实只有 10 条在语义上出现；9 条移动事实没有一条完整；4 条结果事实全部只是换了措辞。输入现在把事实和句组计划分开列（`事实：…` 与 `分组：G1｜f0 f1`），模型拿到的是一张清单，而不是「这一段必须交代哪几件事」。

对照实验要回答一个问题：**把事实按句组重排、让每组自带必述槽位，能不能提高事实覆盖，而不改变其他任何变量。**

## 2. 输入格式（草案）

以 `rb-move-outcome` 为例，事实不再单列，句组直接承载内容：

```text
叙事任务。
场景：
地点=钟楼
地点外貌=旧
人物：
管线甲｜性格=沉稳｜外貌=常态｜随身=无
可见：
无

句组 G1
叙述视角：管线甲，第三人称限知

f0｜已发生的移动
人物：管线甲
起点：管线镇
终点：钟楼

f1｜已完成的结果
人物：管线甲
结果：把铜铃挂回了钟楼

写作要求：
在正文里完整表达以上事实。
移动需要交代起点、终点和人物。
允许补充与权威状态一致的环境描写和人物感受。
不得新增行动、人物、任务或对话。
正文：
```

**全局约束原样保留**：场景、人物、可见、`视角：…`、`要求：…` 五行由旧 `packer.py` 逐字复用，位置在句组之前；句组只增加「事实表达说明」，不再重复或改写禁止项。测试 `test_n4_groups.py::test_ab_invariants` 逐字比较 A/B 两侧应当一致的部分（场景、人物、可见、视角行、要求行），而不是只比较 B 的快照。

与 v3 的差异只有：事实按组就近排列、字段名换成读得懂的中文槽位、每组加一句事实表达说明。

## 3. 需要设计稿回答的四个问题

### 3.1 句组之间如何衔接

- 句组按 N3 计划顺序渲染，组号连续（G1、G2…），每组只列该组的事实。
- **允许一组多句**：不要求一句对应一个句组，也不要求逐项机械说明；只要求各组事实的出现顺序符合 N3，且不得把 G2 的事实写到 G1 前面。
- 时间事实（`f2｜时间`）渲染在它所归属的组内，组头保留旧装配器的 `｜组后时间=过去了一会儿` 后缀；没有分配给任何句组的时间事实不得丢失，按旧行为追加 `全局时间=过去了一会儿`。两种时间情形都有测试（`test_time_handling`）。
- 组间不新增过渡事件：衔接只能靠已选事实与环境描写。

### 3.2 同名人物如何区分

- 若同一显示名对应两个实体，每个事实块必须带一条**来自权威状态**的识别描述，写在**对应事实块内**，并绑定 `entityId` 与来源字段，例如 `人物：管线乙（性格=急躁）`。
- 来源统一为角色状态：当前 `personalityChanges` 的最后一条，否则 `initialPersonality`；外貌同理。`rb-same-name` 里 `char_pb=急躁`、`char_pc=沉默` 就取自这里。渲染器 `n4_groups.py::descriptor()` 已实现这条，判定器 v4.1 校验的是「这个描述是否贴着这个人」。
- 识别资料由 `character_identity.build_identities(state)` 统一准备，N4 与 N5 读同一个对象；每条记录带 `entityId` 与状态路径来源。
- 两人描述相同、或权威状态里没有可区分描述时，N4.0 **不得编造**：该事实标 `descriptors-identical` / `descriptor-missing` 并阻断；N5 v4.2 对同样情况返回 `undetermined`。

### 3.3 哪些描写属于允许的补充

允许：

- 与场景状态一致的环境描写（地点外貌、天气、光线，仅限已给字段的范围内）。
- 视角人物的感受与身体反应，不改变任何状态。

不允许：

- 新增行动、事件、人物、物品、地点、任务、对话。
- 新增数值、时长、字段名、编号或记录行回显。
- 他人的内心状态；他人的动作只写可见部分。
- 对事实的元叙述（「完成了任务指令中的移动」）。

### 3.4 某个事实无法安全表达时怎么办

- 该事实标 `blocked-fact`，原因写进渲染结果（`missing-field` / `same-name-indistinguishable` / `frame-unavailable`）。
- 该组其余事实照常渲染，**用于诊断，不静默丢弃**；但整行 `productQualified = False`，**部分正文不得作为合格产物**。
- 阻断原因必须单独记录，**不能记成模型漏述**：N5 报 `uncovered` 时，报告要标出该事实是阻断还是模型未写。

## 4. 冻结清单（对照实验的变量范围）

| 项目 | 处理 |
| --- | --- |
| 10 个样本 | 不变（开发集） |
| 模型与解码 | 不变；digest 由 `runner_guards.preflight()` 在推理前重读 |
| N1 事实、N2 选择、N3 计划 | 不变；对照批开始前把三者的输出哈希写进登记 |
| 写作约束（禁止项） | 逐字不变 |
| 判定器 | N5 v4 冻结；N6 由人工/独立复核者做，不进判定器 |
| 输出预算 | 不变（384） |
| 重试与回退 | 不变；重试正文单独统计 |
| **N4.0 渲染** | **本次实验的变量**（组合：排列 + 字段名 + 组内要求） |

两臂：A = v3 的渲染（事实单列 + 分组行）；B = 本稿的按组渲染。同一批样本、同一模型、同一预算、同一判定器。

**已实现的 B 组**：`n4_groups.py`（`n4-groups-v0.2`）。它把 `packer.py` 的视角行与要求行原样放在句组之前，只把事实搬进句组并加一句事实表达说明；A/B 不变部分由 `test_ab_invariants` 逐字校验。

## 5. 验收协议（登记前需审）

### 5.0 判定口径（按 2026-11-09 裁决）

**移动是否完整**：人物、起点、终点，以及「已发生的移动关系」都能从正文读出，且没有相反信息。可以跨句表达，可以使用代词，但代词指谁不能含糊。以下都**不算**完整移动：正文已经处于目的地；远远看见目的地；只提到移动指令或计划。

**`undetermined`**：证据不足以判断真假。它不算通过，也不直接算模型错误。报告必须分开列出**通过 / 失败 / 无法判定 / 调用异常**四类，并保留总体样本分母；正式验收时，`undetermined` 不计入合格数量。

### 5.1 主要指标

1. **22 条必述事实的语义覆盖**：每条判「传达 / 未传达 / 无法判定」，附正文证据；两臂比较。
2. **9 条移动事实的完整率**：起点+终点+人物三者齐全才算完整。
3. **错误归属**：事实被写到错误人物身上的条数。
4. **新增事件**：正文中出现、权威状态里没有的事件条数。
5. **叙事可读性**：1–5 分，只作描述，不进通过判定。

### 5.2 辅助指标

- N5 v4 硬门通过率（`judged` 且全门真）。
- `needs-semantic-review` 与 `undetermined` 的比例——它们不是通过。
- 输出 tokens、截断数、重试数、回退数。

### 5.3 统计口径

- 主结果只看**首次调用**；重试与回退单独列，不混入主指标。
- 截断样本留在分母里。
- 22 条事实的分母按样本内的实际事实数计，不按样本数计。

### 5.4 开发集与留出集

- 现有 10 个样本已反复参与调整，**只作开发集**。
- 设计定稿后另备**未参与调试的新样本**做独立验收；新样本在对照批开始前登记，不参与任何调参。

## 6. 本实验不做的事

- 不改提示词要求行、不改 N3 计划、不改事实选择、不改预算、不改判定器。
- 不用正则通过率替代语义覆盖。
- 不在本实验里评价浏览器耗时或回退文本可用性（另立实验）。

## 7. 待审问题

1. 一组是否允许拆成多句？草案允许，只约束顺序与组内归属。
2. `起点/终点` 分两行是否比一行 `管线镇→钟楼` 更好？草案选分两行，理由是槽位显式、便于模型逐个交代。
3. 时间事实是否要写「不要写具体时长」？草案沿用要求行里的禁止项，不在组内重复。
4. 同名识别描述放在 `人物：` 行还是事实块内？草案放事实块内，避免模型把它当成人物的新属性。
5. `blocked-fact` 的组是否仍然渲染？草案渲染其余事实并标注原因。

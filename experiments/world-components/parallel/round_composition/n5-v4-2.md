# N5 v4.2：与渲染器共用同一份人物识别资料

日期：2026-11-09。`judge_v4_2.py`（`n5-v4.2`）。v4.1 与 `out/archive-rejudge-v4-1.json` 保留，v4.2 另存 `out/archive-rejudge-v4-2.json`。

## 1. 修的是接口，不是正则

评审指出：`n4_groups.py` 从角色状态读「急躁 / 沉默」写进提示词，而 `judge_v4_1.py` 的 G4 仍从事实对象的 `text`/`appearance` 读。`rb-same-name` 的三条移动事实没有这些字段，于是渲染器有信息、判定器没有，G4 必然返回无法判定。

新增 `character_identity.py` 作为**唯一准备步骤**：

```python
ids = character_identity.build_identities(state)
ids["entries"]["char_pb"] = {
    "entityId": "char_pb", "name": "管线乙", "descriptor": "急躁",
    "field": "性格",
    "source": "initial.characters.char_pb.initialPersonality",
}
ids["sameName"]["管线乙"] = {"char_pb": "急躁", "char_pc": "沉默"}
ids["indistinguishable"] = {}   # 两人描述相同时才会出现
```

- 来源顺序：`personalityChanges` 最后一条 → `initialPersonality` → `appearanceChanges` 最后一条 → `initialAppearance`（`常态` 不算描述）。
- 每条记录都带 `entityId` 与具体状态路径，渲染器和判定器读的是同一个对象。
- **描述相同不能当证据**：`same_name_descriptors()` 在两人描述相同时返回 `descriptors-identical`，两边都会拒绝，而不是各自「看见描述就放行」。

`judge_v4_2.judge(..., identities=ids)`：

- 传入识别资料时，G4 只从这个对象取描述；
- 两人的描述相同 → `undetermined`（`same-name-descriptors-identical`）；
- 描述没有贴在自己那段证据上 → `undetermined`（`descriptor-not-next-to-actor`）；
- 同名事实没有任何匹配片段（模型没写）→ `undetermined`（`same-name-evidence-missing`），而不是因为「名字出现过」就过；
- 不传识别资料时保留 v4.1 的事实字段回退，仅用于旧调用；流程里必须传。

## 2. 测试

`test_judge_v4_2.py`：

| 组 | 覆盖 |
| --- | --- |
| 共用识别资料 | 描述不同且贴对 → 通过；不传资料 → `undetermined`；描述互换 → `undetermined` |
| 相同描述 | 两人都是「急躁」→ `undetermined`，原因 `descriptors-identical` |
| 构建器 | `build_identities` 把相同特征标进 `indistinguishable`，不再提供 `sameName` 映射 |
| v4.1 行为保持 | 旁观者归属拒绝、先失败后成功覆盖、否定拒绝、无主体送审、目标泄漏硬判、结束原因四种 |

`test_judge_v4_1.py`、`test_judge_v4.py`、`test_judge_v3.py` 以及渲染器、守卫、触发线测试全部照旧通过。

# N5 v4.3：确认失败与身份存疑分开报告

日期：2026-11-09。`judge_v4_3.py`（`n5-v4.3`）。v4.2 与 `out/archive-rejudge-v4-2.json` 保留，v4.3 另存 `out/archive-rejudge-v4-3.json`。

## 1. 问题

同名人物无法区分、同时正文又被 `length` 截断时，v4.2 的整行状态是 `undetermined`。报告会把它统计成「无法判定」，把已经确认的错误（截断）藏起来。

## 2. 改法

- 保留逐条事实状态（`covered` / `reject` / `review` / `uncovered`）。
- 新增 `failureKinds`，逐个列出确认的失败：`finish-length`、`finish-load`、`uncovered:<factId>`、`fact-rejected:<factId>`。
- 同名身份存疑记为 `same-name-undetermined`，单独一条。
- 状态优先级：
  1. 有确认失败 → `judged`（失败），G4 仍写 `"undetermined"`，两类都列出；
  2. 只有身份存疑、其余全过 → `undetermined`；
  3. 有「需语义复核」且无确认失败 → `needs-semantic-review`。

## 3. 测试

`test_judge_v4_3.py` 五项：

| 用例 | 期望 |
| --- | --- |
| 截断、其余全过 | `judged`，`failureKinds=["finish-length"]` |
| 同名同描述、事实都覆盖 | `undetermined`，只有 `same-name-undetermined` |
| 同名同描述 + 截断 | `judged`，同时有 `finish-length` 与 `same-name-undetermined`，G4 为 `undetermined` |
| 同名 + 有一条事实没写 | `judged`，`uncovered:f1` 与身份存疑都列出 |
| 干净句 | 通过，`failureKinds` 为空 |

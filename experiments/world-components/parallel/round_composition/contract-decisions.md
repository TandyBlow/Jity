## D1 任务标题：N4.0 禁止写标题，N5 要求逐字引用目标

**契约原文**

- N4.0 输入（`n4_input_renderer/packer.py`）每份输入的倒数第二行写死：`不写任务标题、数值面板、具体时长、字段名`。
- 同一份输入里该事实的记录是 `f1｜任务达成｜管线甲｜把铜铃挂回钟楼`（带目标原文）。
- 冻结的 v2 对齐器（`n4_corpus_v2/eval_n4_v2.py` → `fact_patterns`）对该类事实只有一种帧：`{主体}(已经|已)?(完成|达成|办妥)了?任务「目标原文」`。

**证据**

- `out/composition-run.json` → `cases[caseId=normal-move-task]`：`stages.n4Input.input` 含那行要求；`stages.n4n5.attempts[0].output` 是 `管线甲完成了任务「把铜铃挂回钟楼」。`；`n5.gates.G1_alignment=true`。
- `out/contract-probes.json` → `task-title-quoted`（pass） vs `task-title-paraphrased`（`uncovered:f1:task_achieved`）。
- `out/contract-probes.json` → `syntheticProbes[0] = outcome-kind-unsupported`：把同一事实改写成 `outcome` + `resultText` 后，判定器直接抛 `no v2 pattern for kind outcome`（`pass=null`，即**无法判定**，不是失败）。N2 已把视角人物自己的 `outcome` 判为必述（`self-outcome`），N4.0 也把它渲染成 `结果｜把铜铃挂回了钟楼`，只有判定器缺这一帧。

**现在会怎样**

同时满足两份契约的文本不存在：照 N4.0 写（不写标题、把结果写成动作）必挂 G1；照 N5 写（逐字引用目标）就违反 N4.0。4 个 `ok` 场景中带任务类事实的两个（`normal-move-task`、`retry-n5-success`）都选了后者。另外，「换成结果表述」这条本来最自然的路，现在连判定都没有。

**选项**

- **A 改 N5（旧链就地换帧）**：任务类事实接受 `outcome`/结果表述，`task_achieved` 的标题帧废弃。代价：旧语料与旧成绩的解释全变，N4 v2 的 64/66 与组合归档都要重判；历史归档无法与新判定直接比较。
- **B 改 N4.0（放开标题）**：删掉「不写任务标题」，改成「目标只能以引号原样出现」。代价：叙事会持续出现任务日志式句子，与已审的 N4 叙事语料 v0（「goal 只作隐藏动机」）直接冲突。
- **C 分层（建议）**：旧 v2 链和旧判定器保持冻结；新叙事路径只走 `outcome` + `resultText`，并在一份**新判定版本**里为 `outcome` 增加帧。旧归档的解释范围不变，新链接新门。

**建议与代价**

建议 **C**。理由：只有 C 能同时满足「不重算旧成绩」和「叙事不出现任务标题」。

若选 C，需要做：

1. 定义 `outcome` 的帧与覆盖规则（主体 + resultText 需在同一句出现；允许「把/了/好」等中缀变化，但不得用 goal 原文冒充）。
2. 给判定器加版本标记（例如 `n5-v3`），旧调用显式走 `n5-v2`，避免同一份归档被两套帧静默重判。
3. 19 场景在新版本下重跑，作为**新归档**（旧归档保留，不改）。
4. 明确旧 v2 门是否继续服务页面：若继续，页面门仍会拒掉不含标题的文本。

验收判据：新版本下 `task-title-paraphrased` 通过、`outcome-kind-unsupported` 变成可判定（pass/fail 而非抛错）；旧归档 `b594c008…` 保持不变。

## D2 时间表达：N4.0 强制模糊，N5 强制精确数值

**契约原文**

- N4.0 把时间事实渲染成 `f2｜时间｜时间经过`，组后统一写 `组后时间=过去了一会儿`；`n4-input-packing.md` 的记录规则表写明 `time | 时间经过 | amount/unit 不进入输入`，要求行同时禁止「具体时长」。
- v2 G3 要求：计划里的时间事实必须在正文出现 `数字 + 单位`，且解析值与单位与计划完全相等，否则 `uncovered`。

**证据**

- `out/composition-run.json` → `contract-time-conflict`：`uncovered:f2:time`、`G3_time=false`。
- `out/contract-probes.json` → `time-vague`（G3=false） vs `time-exact`（`前后大约八分钟过去了。`，pass）。同一组事实，只有写死数值才过门。

**现在会怎样**

N4 端看不到时长（有意设计），合规输出必然挂 G3；含时间推进的点在合规文本下无法通过任何判定。

**选项**

- **A（建议）放宽 G3**：时间事实接受「与计划一致」的模糊表达（约/前后/过了一会儿/半晌…），精确性交给 N1 与契约层；只有正文真的写了数值时才校验数值与单位，写错仍失败。
- **B 把数值放回 N4.0**：模型能看到 amount/unit 并被要求写出。代价：与 N4.0 契约、叙事语料 v0 的「不打印数值面板」冲突。
- **C 按事实分档**：纯时间推进允许模糊；时间与任务/位置同组时要求精确。代价：需要一条「这一拍的时间是否影响事实」的判定规则，目前没有，且仍然让模型输出数值。

**建议与代价**

建议 **A**。模型从未见过数值，因此它无法「写错」；把数值正确性留给有数值的地方（N1 已保证来源），G3 只负责「不许把时间写成没有时间」。

若选 A，需要做：

1. 改 G3 判定：`vague-time` 与 `exact-time` 都算覆盖；出现数值但与计划不符仍判 `mismatch`。
2. 明确哪些模糊表达可接受（给出词表，避免「很久很久」这种无信息表达也算覆盖）。
3. 重跑 19 场景（`contract-time-conflict` 的期望要从 `n5-rejected` 改成 `ok`），并检查 v2 旧归档里含 time 的行是否需要重判。

验收判据：`time-vague` 与 `time-exact` 均通过；构造一条 `十小时`（计划是八分钟）仍失败。

## D3 两套 N5 程序核，口径不一致

**契约原文**

- 组合判定用 v2 对齐器 `eval_n4_v2.judge_row`（G1/G2/G3/G4/G5/G6）。
- 另一套是 v7 识别器 `n4_corpus/corpus_check.check_narration`（由 `narration_pipeline.verify_text` 调用）：必述无对应表达、未被识别器覆盖的内容记为 **review**，且**没有截断规则**。

**证据**（`out/composition-run.json` → `stages.n5CrossCheck.result`）

- `reject-n5` 第 2 次正文（顺断、`finishReason=length`）：v2 `G6=false`；v7 `fails=[] reviews=0`。
- `fail-n5-extra-actor`：v2 `residue-name:管线甲`（两次）→ `G2=false`；v7 `fails=[] reviews=1`。

**现在会怎样**

「N5 拒绝了」这句话的真假取决于用哪套核；两套都由程序实现，但一套把「未覆盖」当失败，另一套当复核。

**选项**

- **A 指定 v2 为唯一门**，v7 降级为诊断并在文档里改名。代价：把「需要语义判断的项」彻底排除在门之外，等于承认这些项不判。
- **B（建议）分层**：N5 = 程序可判定项（必述覆盖、残留人名/目标、截断、数值一致）；N6 = 语义复核（归因、隐含事件、新实体）。两套核各归其层，v7 识别器的 review 输出成为 N6 的输入候选。
- **C 合并成一套**：把 v7 的 review 全部升级为硬失败。代价：更严格，但会把「措辞不同但事实正确」也判失败，需要重算全部成绩。

**建议与代价**

建议 **B**。理由是这次暴露的差异正好是「硬失败 vs 复核」的分界，合并会把不可判定的东西写成硬门。

若选 B，需要做：

1. 文档与命名：`corpus_check` 的产出改称诊断/N6 候选，不再自称 N5。
2. 明确 N5 硬门清单（四个程序项）与 N6 的输入契约（谁审、审什么、结果存哪）。
3. B 侧页面门归属：页面用 N5 还是 N5+N6，需要 B 给出声明。

验收判据：任何报告里出现「N5 通过」时，都必须同时写明是 N5（硬门）还是 N5+N6。

## D4 新增具名人物没有硬门

**契约原文**

- N4.0 要求行写着「不新增未列出的具名人物/物品/地点」。
- v2 G2 只扫 `facts` 里**已登记**的人物名与任务目标在匹配区间外的残留；正文出现一个从未登记的新名字，不在扫描范围。
- v7 识别器会把「未被识别器覆盖的内容」记为 review，但不失败。

**证据**

- `out/composition-run.json` → `n5-false-pass-unregistered-actor`：正文多出「这时管线丙从巷口走来」，v2 全部硬门 `true`；v7 `fails=[] reviews=1`。该案例的 `n5-false-pass` 来自夹具自带的 `annotations.addsUnregisteredEntity`，不是任何判定器发现的。

**现在会怎样**

「不新增具名人物」目前没有任何程序门；真实模型编造人物会被放行。

**选项**

- **A 硬拒**：检测到未登记专名即失败。代价：需要专名识别，中文人名/地名误判会伤正常文本；今天没有实现。
- **B 标记待核**：检测到就进入「待核」状态，既不算成功也不算失败，交人工/模型复核。代价：需要检测；放行速度受影响。
- **C（建议作为过渡）放行并计数**：不拦，但每次真模型运行必须报告未登记专名的出现次数与原文片段。代价：仍然放行编造，只是可测。

**建议与代价**

建议 **C 作为过渡、B 作为目标**，顺序不能颠倒：先声明策略并开始计数，再实现检测。

若选 C，需要做：

1. 书面声明：真模型实验里「未登记具名人物」属放行项，但必须计数。
2. 定义什么算「未登记具名人物」（专有名词、且不在状态的 characters/items/locations 名表里、且不在场景外貌原文里；代词、身体部位、普通名词不算）。
3. 真模型报告新增两个字段：`unregisteredNames: []`（原文片段 + 出现位置）与 `count`。

若之后升级 B，需要做：专名候选提取 + 登记表差分 + 待核状态入档；误判率需要单独测量（拿 19 场景的已知文本做负例）。

验收判据（C 阶段）：每条真模型运行记录都带这两个字段；19 个离线场景不必重跑。

## D5 G4/G5 的触发依赖 `rowId` 子串

**现状**

`judge_row` 用 `case = row["rowId"].split(":")[1]`，`if "conflict" in case` 才执行 G4，`if "same-name" in case` 才执行 G5。这两个门由**案例命名**触发，不由数据触发。

**证据**

- `out/composition-run.json` → 只有 `contract-time-conflict` 出现 `G4_conflict_names`，值 `true`。它触发是因为 caseId 含 `conflict`；该案例只有一个人物（两条事实都是管线甲），G4 走的是「同一名字多次出现」分支 `text.count(名字) >= 2`。**这是意外触发，不是验证。**
- 19 个场景里没有 caseId 含 `same-name`，`G5_same_name_bare` 一次都没执行。
- `out/contract-probes.json` → 两个时间探针同样带 `G4_conflict_names=true`（同一个 caseId 触发），再次说明触发条件是命名。
- 逐门执行次数与涉及案例见 `fixtures/manifest.json` 的 `n5GateCoverage`（从归档实测）。

**现在会怎样**

G4/G5 是否运转取决于案例怎么起名字；生产链的 `rowId` 不是这样生成的，所以这两门在生产路径上不会触发。

**选项**

- **A（建议）改数据触发**：G4 在「计划里出现同名多实体且都是必述」时执行；G5 在「同名实体获得称谓授权」时执行。
- **B 宣布只用于离线**：明确 G4/G5 只服务离线评测的特定样本族，生产门不包含它们，并删掉文档里「生产硬门」的措辞。
- **C 先补样本族再改**：先预登记冲突/同名样本，再按 A 改造。可作为 A 的前置。

**建议与代价**

建议 **C → A**：先补一个预登记的冲突/同名样本族（这也是 D1/D2 之外唯一缺少的样本类型），再改触发条件。

若选此路，需要做：

1. 预登记两类样本：两名同名角色完成同一目标（G4）；同名角色获得代词授权（G5）。
2. 改触发条件为数据判定，写清与 `caseId` 解耦。
3. 19 场景在新触发下重跑（G4/G5 会在更多案例上执行，结果可能与旧归档不同），作为新归档。

验收判据：G4 在「两个不同名字的人同组」时**不**触发；在「同名两人」时触发且未署名则失败；G5 在同名 + 有授权时触发且失败。

## 6. 真模型实验前的门槛（D4 相关）

**必须书面声明的**：第一次接真实模型之前，D4 的策略必须已经定下来（建议「放行并计数」），否则编造人物会被静默放行，而实验报告看起来一切正常。

**可以后置的**：检测实现。声明策略不需要检测器；但声明之后，报告必须人工给出未登记专名清单。

**进真模型批次的最低条件**

1. D1、D2 已裁决（否则任务类与时间类事实的叙事全部无法通过判定）。
2. D4 策略已声明，且报告模板已包含 `unregisteredNames` 与 `count`。
3. D3 已定层次（否则「通过」无法解释）。
4. D5 至少已声明范围（生产门是否包含 G4/G5）。

满足上面四条之前的真模型数据，只能算「管线跑通」的证明，不能算质量数据。

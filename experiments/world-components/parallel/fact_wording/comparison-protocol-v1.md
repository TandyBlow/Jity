## 1. 冻结的东西

### 1.1 权重（唯一允许的检查点）

| 项 | 冻结值 |
|---|---|
| 文件 | `.local/models/u240-model.safetensors` |
| sha256 | `ab8a98264ee6b4f83eba17d624d7b92b23522c8eacef07d07a5be960e390184a` |
| 字节 | 309,783,976 |
| config.json | `cd553527a919b8292894d4e8cc043fcb1a45c60586f9dfa4399f7b2b2e657a9e` |
| spiece.model | `c65feffa65ff0378759778193852083d23349cb1b40c906e9463a12f8076ff32` |
| 参数量 | 77,440,384（190 张量，全 F32） |

运行前必须重算一次权重 sha256 并与上表逐字符相等；不等就停，不换权重。禁止用 `route-control-u240recipe`、`ckpt-group`、新训练臂或 784M 权重替代——它们都不是 u240。

### 1.2 设备与数值精度

| 项 | 冻结值 | 理由 |
|---|---|---|
| 设备 | **CPU** | 现有 u240 的 cf24 基线在 CPU 上产生（85 条、110.5 s）；GPU 数字不能和它混表 |
| 精度 | fp32 | 与基线一致 |
| 线程 | 4 | 与 `cf24-baseline.json` 的 `environment.threads` 一致 |
| 批次 | 1 | 避免批内影响 token 生成顺序 |
| 环境 | python 3.12.3、torch 2.7.0+cu126、transformers 4.57.3 | 取自 cf24 基线的 `environment` 字段；版本不同必须标注“不可严格对比” |

GPU 只能作为**另开的第二张表**，标注设备，不参与本轮判定。

### 1.3 解码 A：贪心

- 每步取 argmax；遇 EOS 停止；无长度上限；单条 20 秒墙钟预算。
- 与 `cf24-baseline.json` 的 `decode.policy`（`greedy, EOS or wall-clock budget, no length cap`）一致。

### 1.4 解码 B：束宽 2（本轮新写的实现）

历史那批 305 条对照的束搜索脚本没有留下来，`beam-cache-equivalence.json` 里两套实现的分数差最大 72.1，说明“束宽 2”当时本身就不是同一个算法。因此本轮**重新写死一个实现**，并且：

> **B 的数字不能叫作“复现旧束宽 2 结果”。** 它只能和同一次运行里的 A 对比。

本轮的 B 定义：

| 项 | 规则 |
|---|---|
| 宽度 | 2（保留累计对数概率最高的 2 条部分假设） |
| 每步扩展 | 每条假设取 next-token 概率前 2，合并成 4 个候选，按累计对数概率排序取前 2 |
| 长度归一 | **不做**（用原始累计对数概率） |
| 结束 | 某条假设生成 EOS 即记为完成；完成 2 条后停止扩展；若 20 秒内不足 2 条完成，按已完成里的最高分取，`complete=false` |
| 输出 | 已完成假设中累计对数概率最高的一条 |
| 排序稳定性 | 分数相同按“先生成者优先”，再按 token id 升序；实现里必须显式写死，不依赖框架默认 |
| 预算 | 单条 20 秒，与 A 相同 |

候选数、是否触顶、累计分数都要按条记录（§5）。

### 1.5 超时与失败

| 情况 | 处理 |
|---|---|
| 到达 20 秒预算仍未 EOS | `stopReason=budget`，保留已生成文本，判定记 **U（无法判断）**，不重跑 |
| 进程/加载/OOM 等基础设施错误 | 允许 **1 次** 重试，记录 `retryReason`；第二次仍失败则该单元记 U 并标 `armIncomplete` |
| 输出为空或只有标点 | 记 U，`fallbackReason=empty-output` |
| 任何情况 | **不允许**用另一臂的文本、模板句或规则句顶替；不允许只重跑失败的那一臂而不记录 |

重试规则是为了排除机器故障，不是为了提高成绩；所有重试都要出现在结果表里。

### 1.6 输入一致性

两臂必须吃**完全相同的字节**。程序对每条单元渲染一次输入，算 sha256，然后把同一份字符串喂给 A 和 B。运行记录里两臂的 `inputSha256` 必须逐条相等；出现不等立即停止整轮，不修补。

## 2. 第一轮比什么、不比什么

**比：** 同一输入下，贪心 vs 束宽 2 的原文差异，以及两者各自的事实正确率、新增、复述、语病。

**不比（都放到后续轮次，且各自要单独冻结）：**

- 输入表达改动（字段顺序、称呼补充、要求句改写、可见清单精简）——另立协议，因为改动会同时影响两臂，不能和“解码差异”混在一起归因；
- 提示词／模板变体、覆盖重排、候选打分选择器；
- 任何形式的回退句、规则拼装句；
- GPU 结果与 CPU 结果的跨表比较；
- 与旧 305 条表（贪心／束宽 2）的名次比较——那批输出没有检查点身份，见 `freeze/evidence-inventory-v1.json`。

第一轮的用途是**回答“在这份权重和这套输入下，两个解码谁的错误更少、少在哪类”**，不是“重新验证旧表”。

## 4. 判定规则（先写死，后看结果）

每个单元、每个臂单独判一次，判的人只看「事实 + 输入 + 这条输出」，**不看它是贪心还是束宽**（盲判）。判定码：

| 码 | 名称 | 成立条件 | 例 |
|---|---|---|---|
| `PASS` | 合格 | 满足事实、无新增、无复述、无语病 | `沈砚把潮汐簿缺的那页补全。` |
| `F-ATTRIB` | 归属错 | 事实主体没出现，或动作/结果被安到别人身上 | 事实主体是阿棠，写成“陆行把鱼筐推过去” |
| `F-DIR` | 方向矛盾 | 写出的高低方向与 `方向` 字段冲突 | `方向=上` 却写“下去”；`方向=平` 却写“登上／下来”并断言了高低变化 |
| `F-NUM` | 数值含义错 | 理智事实的方向写反；或直接写出数字／百分比 | `12→9` 写成“理智回到 12”；写“理智下降三点” |
| `F-POS` | 位置超出授权 | 只给了物件存在（可见清单），却断言主体到了该物件的“边／下／里” | 可见清单有钟架，写成“走到钟架下” |
| `A-ADD` | 未授权新增 | 出现事实、场景内容之外的人物／物件／动作／状态／属性 | 移动事实后加“蹲到钟架下”“抬头看了看塔身”；给可见物件补“鱼鳞” |
| `D-REP` | 复述 | 同一内容在一句里说了两次 | “玻璃罩透亮，玻璃又透亮” |
| `D-GRAM` | 语病 | 双层“的”、所有格错位等结构性病句 | “潮汐簿的缺页的边缘”、“排水沟的里面” |
| `U` | 无法判断 | 证据不足、输出被截断、判定人之间不一致 | 到 20 秒预算仍无 EOS；两判不一且无法裁决 |

### 4.1 与第 2 步已归档分类的关系

第 2 步已经冻结了 cf24 的七类口径（`freeze/failure-taxonomy-v1.json`）。本协议不另造一套分类，只给同一批类别加机器标签：

| 本协议码 | 第 2 步类别 | 差异说明 |
|---|---|---|
| `F-ATTRIB` | `subject` | 只判**核心事实**的主体／对象归属；新增小句里“鞋底站住”这类病态主语不算核心归属错 |
| `F-DIR` | `direction` | 起终点与高低措辞分开判；未覆盖关系双方互换 |
| `F-NUM` | `sanity_value` | 只判方向／数值含义；输入本身隐去数字时，数值保真记 U |
| `F-POS` | `position` | 物件存在不授权人物在其旁停留 |
| `A-ADD` | `extra_action_state` | 新动作与新状态都算，不只数动作 |
| `D-REP` | `repetition` | — |
| `D-GRAM` | `language` | — |
| `U` | `undetermined` | 与 `failed` 分开统计 |

两条沿用第 2 步的限制：类别可以重叠，**数量不能相加当成失败条数**；不得用姓名反推 `entityId`／`pointId`／世界 `fieldPath`。

补充约定：

1. **`方向=平` 的措辞风险单列。** 写“上来／下去”而不改变起终点，按归档口径记为措辞风险 `R-DIR`，不是事实错；该单元判 `undetermined`，**不算通过**，同时保留 `R-DIR` 单独计数，便于和旧四格表对照。
2. **`U` 永远不算通过。** 统计时分母单独列出，不能悄悄并进合格或不合格。
3. **源级干净** = 该源所有单元 `PASS`，且全源无 `A-ADD`。源级与单元级分别报，二者不可互相替换。
4. 机械规则只做第一遍筛。`cf24-baseline-2026-11-05.md` §7 已记录：机械规则看不见尾句、复读、语病，且会被“含终点的尾句”绕过。**最终判定以人工盲判为准**，机械结果只用于定位可疑项。
5. 人工核验每批 ≤ 10 条，编号固定（`unitId + arm`），可重复评审；同一批不得只看一臂。
6. 判定人只有一人时，必须在结果里写明“单判定人、无第二人复核”。

## 5. 每条要保存什么

每次生成（单元 × 臂）一行 JSON，字段固定：

| 字段 | 说明 |
|---|---|
| `unitId`, `arm` | 单元与臂（`greedy` / `beam2`） |
| `inputSha256` | 该单元的渲染输入哈希（两臂必须相同） |
| `text` | 原文，逐字保存，不改标点 |
| `newTokens` | 生成 token 数 |
| `seconds` | 墙钟耗时（秒） |
| `stopReason` | `eos` / `budget` / `error` |
| `fallbackReason` | 无则 `null`；`empty-output`、`budget-timeout`、`infra-error-after-retry` 等 |
| `retryCount`, `retryReason` | 重试次数与原因 |
| `beam`（仅 B 臂） | `candidates`、`complete`、`cumulativeScore`、`finishedHypotheses` |
| `verdict`, `flags`, `reviewer`, `reviewBatch` | 判定结果、附加标记、判定人、批次号 |

运行级再存一份 `run.json`：权重/config/tokenizer 哈希、输入文件哈希与逐条输入哈希、解码参数、环境版本、设备、线程、起止时间、脚本自身哈希、c4 树提交号。

保存位置：本任务独占目录下的 `artifacts/fact-wording/decode-r1/`（`raw.jsonl`、`run.json`、`index.json`、`review-*.json`）。**原始文件运行后不再修改**；后续判定另存新文件，用 `unitId` 关联。

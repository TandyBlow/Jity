# 输入与事实不一致的两个单元：t12:f2 / t24:f3 核验

目的：把“完整事实是否被支持”和“模型实际收到的输入是否支持”分开核验。r1 的原始输入与结果不改。

---

## 1. 并列展示

### t12:f2

| 项 | 内容 |
|---|---|
| 完整事实 | `{"kind":"outcome","name":"阿棠","resultText":"把鱼筐放在门槛边"}` |
| 实际输入 | 地点=潮生巷；地点可见=`油纸伞、鱼筐、石板、纸灯笼、排水沟、墙根、水洼`；场景=入夜；小雨；纸灯笼；视角=沈砚；事实=`阿棠｜结果｜把鱼筐放在门槛边` |
| 输入要求句 | “只用地点可见里的物件与场景给的现象……不新增人物、物品、地点” |
| 贪心输出 | `阿棠把鱼筐放在门槛边。` |
| 束宽 2 输出 | `阿棠把鱼筐放在门槛边。` |
| r1 判定 | 两臂同：**pass**，flag `fact_visible_conflict` |

### t24:f3

| 项 | 内容 |
|---|---|
| 完整事实 | `{"kind":"outcome","name":"阿棠","resultText":"把鱼筐放在门槛边"}` |
| 实际输入 | 地点=潮生巷；地点可见=`鱼筐、石板、纸灯笼、排水沟、墙根、水洼`；场景=雨后；雨停；纸灯笼；视角=沈砚；事实=`阿棠｜结果｜把鱼筐放在门槛边` |
| 输入要求句 | 同上 |
| 贪心输出 | `阿棠把鱼筐放在门槛边。` |
| 束宽 2 输出 | `阿棠把鱼筐放在门槛边。` |
| r1 判定 | 两臂同：**pass**，flag `fact_visible_conflict` |

`门槛` 在两条输入的可见清单里都**不存在**；`门槛` 在潮汐档案馆的场景里存在（world.json 里档案馆写“门槛磨得发亮”），潮生巷没有。

---

## 2. 两种“支持”的区分

| 口径 | 结论 | 依据 |
|---|---|---|
| **完整事实支持** | 支持 | 输出逐字表达了 `resultText` 的全部内容（动作、对象、位置），主体是阿棠 |
| **输入支持** | **不支持** | 输入的可见清单没有“门槛”；要求句又禁止“新增物品、地点”。模型若要严格遵守可见清单，就没法写出这条事实 |

也就是说：这条事实**不可能同时满足“事实完整”和“只用可见清单”**。模型选择忠实于事实。这不是生成缺陷，是输入与事实自相矛盾；两臂输出相同，因此这两个单元也不能用来区分解码方式。

## 3. 范围扫描

对 cf24 85 条逐条检查“事实里点名的物件是否出现在该条可见清单”：

- 事实点名、可见清单缺失的**场景物件**只有 `门槛`，即 t12:f2、t24:f3 两条；
- 其余缺失词是人物或物件自身的属性（外袍、泥水、鱼鳞、盐雾），由事实本身授权，不属于场景物件，不构成同类问题。

结论：这是两条孤立的输入缺陷，不是普遍现象。

## 4. 修复方案（新版本，不用于 r1）

**不采用“把事实改成 `把鱼筐放在墙根`”的方案**——那会改变事实本身，等于用改题掩盖输入缺陷。两个冲突单元保持原样，继续按 `fact_visible_conflict` 记输入缺陷。

后续若要修，只能修**输入侧**，且另立版本：

| 方向 | 内容 | 代价 |
|---|---|---|
| 修可见清单 | 让可见清单包含事实已授权的场景物件（如门槛） | 需要世界记录支持；潮生巷当前场景里没有门槛，不能凭空补 |
| 修要求句 | 让要求句允许表达“事实已授权的物件与位置”，而不是只允许可见清单里的物件 | 影响全部输入，应与 T1 一类模板改动一起评估，不能顺手改 |

无论走哪条，都必须新建契约版本、冻结新哈希；旧契约、r1 原始输入与结果保持不变，两版结果不混表。

**本轮不生成任何修复版本。**
